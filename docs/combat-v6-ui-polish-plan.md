# V6 战斗页面打磨：确认方案与分阶段验收

状态：实施中。方案于 2026-09-16 经用户确认；本文是本轮开发与验收的范围依据。

## 1. 目标与不可退让的约束

玩家无需打开详情，即可认出自己、当前操作对象、灵兽物种与剩余下令时间；无需阅读说明即可完成普通下令；需要解释战果时可以查到足够的信息。

- 以头像建立辨识，以直接操作和战斗反馈传递信息，以文字解释必要的结果。
- 保留文字斗法、水墨主题、独立 CombatV6Layout、权威状态与差量播放。禁止为了 UI 重新推演伤害、命中、资源或结算。
- 不把主流程 HUD、导航壳或完整角色面板搬进战斗。
- 数值使用 font-mono，图片/图标统一通过 GameIcon 和注册表；人物与灵兽统一遵守写意墨像规范。
- 保持阵容槽位稳定；死亡、召回不引起其他单位重新排序。单人战不固定占满编四列，不保留无信息的跨阵营占位行。
- 30 秒收令沿用擂台宿主的服务端截止时间。无时限训练/PVE 不添加虚构计时；统一所有宿主的限时规则不属于本轮。
- 保留权限、公开比例资源条、修订号、指令组提交、Redis CAS、结算/回放归档边界。
- 不增加前后端服务单元测试或一次性烟测脚本；纯共享展示转换可写确定性契约测试。
- 每阶段先实施、再执行该阶段验收；有失败就修正并复验，不用下一阶段掩盖上一阶段未通过。

## 2. 审查基线与已知缺口

2026-09-16 初轮检查覆盖桌面、360px、360×640 触屏模拟，实际完成单体和三体木桩人物＋灵兽的一回合操作。满编联机与真机触屏当时未验证。

1. 窄屏固定四列，单人阵容仅占一列；对方灵兽占位制造空行。
2. 360×640 触屏下阵容需内部滚动才能看到完整灵兽行；战报约 95px。
3. 播放时指令栏从约 195px 缩到 56px，阵容和日志跟随位移。
4. 点击名字与血条分别承担详情/选目标；人物草稿到灵兽的切换反馈弱。
5. 当前状态仅显示首项加数量，关键控制可能被普通增益掩盖。
6. 日志忽略 hit 的暴击/狂暴与伤害类型；护盾/解除原因表达不足，连击重复句式过多。
7. 主要按钮、捕捉、辅助操作、详情与回放样式不一致；部分数字/图标未遵循公共规范。
8. 联机时间和收令状态分散；阵容没有逐人就绪提示，同名单位与日志编号不一致。
9. 展示单位没有头像身份信息。现有 15 个灵兽物种中 8 个图片、7 个 emoji；人物有男女通用墨像。

## 3. 信息与交互设计

### 3.1 展示层级

| 层级 | 内容 | 表达 |
| --- | --- | --- |
| 常驻 | 单位身份、资源条、关键状态、回合/限时时间、指令、近期战报 | 头像、固定位置、少量标记 |
| 决策时 | 当前单位必要资源、技能消耗/范围、指令草稿 | 操作区、技能抽屉、按需摘要 |
| 查询时 | 全部属性、状态时长/层数、逐段伤害、历史回合 | 详情、展开战报 |

界面效果已表达的内容不重复堆砌说明。视觉隐藏的说明仍可作为可访问名称。不得将关键数据一律隐藏在 Tooltip。

### 3.2 单位与头像

- 所有在场单位具有预留尺寸的头像空间；使用可信的资源标识，不能按单位名字猜物种或拼路径。
- 自己的角色有常驻“我”标记；操作高亮与身份标记分离，操作灵兽时仍可定位自己。
- 主人与灵兽成组相邻；短名称与同名编号在阵容、目标选择、日志中一致。
- 自定义灵兽名字不替代物种身份；详情可查看物种。人物沿用墨像，灵兽沿用物种插画，通过容器与留白协调。
- 覆盖开场、召唤、召回、倒地、复起、观战和回放；旧会话/旧回放使用明确回退，不破坏读取。
- 按用户后续明确收敛：本轮复用已有物种图片和 emoji，不生成新素材。7 个尚无图片物种继续使用其现有 emoji，图片补齐另行安排，不作为本轮验收阻塞项。

### 3.3 响应式骨架

- 桌面：顶部统一状态，我方—战报—敌方，底部固定操作区；单人适度放大头像并收紧宽度，满编紧凑显示。
- 窄屏：敌方—近期战报—我方—操作区。实际阵容决定列数；满编四组主人/灵兽槽位，所有单位入口可见。
- 压缩装饰、普通状态和历史日志，优先保证单位辨识与可操作性；避免各阵容内部单独滚动。
- 下令/等待/播放的操作区保持稳定占位；图片加载不引发布局跳动。

### 3.4 下令与阶段

- 定向行动：选行动后点击整个单位主体选目标；详情使用独立入口；合法/已选/不可选状态明确。
- 人物与灵兽使用紧凑头像步骤入口；人物已选仅是草稿，可返回修改，指令组真正成功后才标记已提交。
- 攻击/神通/器诀优先，防御/保护/灵兽次之；逃跑/放弃为次级操作，捕捉在相关场景显式出现。
- 自作用/自动选目标技能直接完成选择；不为普通操作增加确认弹窗。消耗与范围在技能选择时可知。
- 提交中/已提交/失败/恢复中区别明确；失败可恢复，不把网络错误表现成角色无法行动。
- 回合、倒计时、收令/锁定/播放/恢复状态在一个稳定状态区表达。就绪标记就近落在单位上。
- 剩余 10 秒加强强调，最后 5 秒再强化，避免持续闪烁；已提交仍可见时间。服务端时间校准，刷新/重连不重置；归零等待服务端推进。

### 3.5 播放、日志与终局

- 行动者强调→目标反馈→资源条更新→当前战报，全部跟随权威播放帧；提供减少动态效果适配。
- 普通命中轻量；暴击、保护、倒地、复起更突出；不全屏闪烁，不让动效阻塞操作。
- 简报保留行动结果和转折，详情保留消耗、逐段与机制原因；补齐暴击/狂暴/类型、允许公开的护盾/解除原因。
- 连击可汇总但不得丢失保护、转火、击倒等分界；“机缘判定”必须有具体语境，否则仅留必要机制结果。
- 当前关键状态优先于普通增益；具体时长/层数可查询。公开信息不因更丰富展示而泄露。
- 玩家上翻时停止自动跟随，新增信息轻提示；历史按回合展开。窗口化以长局实测为依据，不先引入新依赖。
- 观战统一青方/赤方，包括同名标签。结束后一个结果中心，保留战报、结算状态与明确结束入口。
- 实战提速不在首轮修改，避免与联机服务端播放窗口冲突；保留既有回放速度控制。
