# Phase 10I：人物面板与现实资源统一 V6

## 已确认边界

角色 HUD、道身概览、根基属性、加点／洗点展示、创建预览和查看他人属性统一使用 V6 面板。现实 HP/MP 初始化、自然恢复、灵泉及丹药资源计算使用同一 V6 投影。保留永久六维、自然恢复倍率、丹药效果与成本、突破规则及非战斗状态。

无宗门角色使用 V6 裸身与修炼投影；有宗门角色使用当前道装、功法、宗门构筑。已入宗但构筑缺失或无效时明确报错，不退回 V5 或裸身面板。派生面板只作为读取结果返回，不持久化到角色六维或 condition。

不修改 V6 战斗公式，不重做后台模拟器，不删除历史表，不扩大到全仓 V5 引擎、旧聊天分享和旧造物退役。

## 实施方案

- `cultivatorDisplay` 定义六维名称、15 项 V6 面板及展示格式。服务端调用现有 V6 完整构筑投影；`MultiSectV5ToCombatV6` 名称中的 V5 是 V6 投影修订版，不是旧 battle-v5 引擎。
- `player.condition.combatV6` 返回面板、资源上限与恢复暂停标记；客户端复用资源订阅和自然恢复时钟，不重新装配战斗构筑。查看他人属性使用服务端 `combatPanel`。
- profile／V6 build 变更在原事务中检查资源上限。上限变化时先按旧上限结算已过去的恢复，再裁剪到新上限并建立新时间基准，避免把旧恢复时间追溯应用到新上限。
- 入宗触发构筑失效通知。入宗／转宗可正常进入既有构筑初始化流程：待初始化时不在事件提交中强行生成面板；读取仍明确报未就绪，初始化完成后再重算现实资源，不使用旧面板兜底。
- condition 写入事件转为读取失效通知，避免数据库原始 condition 覆盖带 V6 注解的客户端读模型；同角色同事务去重。无关货币事件不额外刷新面板。
- 上限提高不补满已有 HP/MP，上限下降只裁剪溢出。丹药先结算自然恢复，执行药效后按新属性／修炼重算上限；灵泉明确恢复到 V6 满值。构筑重算上下文仅留在服务端，不下发、不持久化。
- 保留战斗占用期间暂停自然恢复的规则。移除状态注册表中无人调用的旧战斗修饰钩子，并纠正伤势／虚弱及六维说明；伤势原有自然恢复倍率保留。

## 验收标准

1. 同构筑的角色面板、HUD、灵泉与 V6 战斗入口数值一致；仅暴击／狂暴率以百分比展示，命中／封印为面板点数。
2. 正式加点、道装／功法／宗门构筑变更、修炼改变后，服务端重算且现有资源事件驱动刷新。
3. 上限提高、降低和刷新不能额外治疗；过去的恢复按旧上限结算，未来恢复按新上限计算。
4. 裸身、完整宗门构筑、非法构筑、生命根基、占用暂停均有确定性逻辑覆盖；不把命格／旧状态战斗修饰重新带入 V6。
5. 无数据库 schema 变更；lint、build、共享测试与实际页面验证通过，未执行的场景明确记录。
