# 百兽崖接入方案：宗门主题、神通、经脉与灵兽协同

日期：2026-10-28。状态：设计评审稿，尚未实施。本轮采用宗门主题**百兽崖**，建议稳定ID为`baishou`，尚未持久化。宗名、心法、神通、道途与状态均使用本宗设定；经脉节点名暂时保留原名。

狮驼岭仅作为研发原型出现在来源与对照栏，不作为游戏内宗名。主题适配不改变本稿已有的技能机制、数值、行动预算与范围。本稿不继承此前已废弃方案的命名、七心法或独立驯兽设计。

## 1. 接入结论与范围

### 1.1 宗门设定

百兽崖门人沿山野观兽，从奔走、搏击、守御与生息中学取修行之法。他们以气血炼身，临敌显出兽相，取爪牙之利、振翼之势、重踏之威施展武技；也与灵兽同修同行，在一次次合猎中熟悉彼此的进退。

> 取百兽之长，结生死之伴。

宗门简介：

> 百兽崖以观兽炼身为法，以并肩同行为契。门人临阵显相，爪锋凌厉，步势沉猛；与灵兽相伴日久，往往一人起势，另一方便知该往何处。山中传授的，是搏杀之术，也是生死之间不离不弃的情分。

入门特色词：**观兽炼身／显相搏杀／人兽同行**。组织称谓可采用崖主、传功师、巡山使、门人，复用现有宗门职能。

“兽相”是修士运转功法时的身法、爪影与翼势表现，施术者仍是本人，不另造可选中的兽影单位。首版只有一个统一兽相状态，不增加虎、象、鹏等独立形态、切换按钮或对应物种要求。“契”描述既有伙伴的相知，不增加持久契约养成。爪牙、山风和重踏的意象也不自动附带流血、元素伤害或击退。

### 1.2 两条道途

百兽崖保留“显相准备、强物理爆发、调息代价”的战斗节奏，两条道途分别突出本体连续攻势与本人的灵兽协同：

| 项目 | 浴血横行 | 山海同契 |
| --- | --- | --- |
| 道途文案 | 以气血催发兽相，搏杀间饮血续力；一旦扑住破绽，便以凶猛攻势压住敌阵。 | 与灵兽相知相伴，以裂爪引出攻势，以合猎相互接应；有进有退，彼此照应。 |
| 原型／建议ID | 嗜血狂魔／`baishou.path.blood` | 万兽之王／`baishou.path.bond` |
| 主要输出 | 本人掠岭、逐命、裂爪 | 本人裂爪与已有灵兽的正常行动 |
| 节奏 | 管理兽相、吸血、调息与爆发机会 | 让灵兽存活、积累猎意、选择联合攻击窗口 |
| 机制保留 | 追猎、燃血、完整经脉树 | 两树共用基础技能、猎意关系、完整经脉树 |
| 主要改编 | 天气节点、缺失外部系统 | 驯兽全部改为自有灵兽的增益、恢复与协作 |
| 无灵兽时 | 可正常发挥本体技能 | 仍可用基础攻击；需要灵兽的能力明确不可用 |

只实现这两条道途；不接入狂怒斗兽及其专属狂怒循环。保持本项目六心法、两流派、每流派19个可选节点与2项自动奖励的结构，共42槽。原版另列的第8、9层奖励映射到本项目第七层左右自动奖励，这是进度结构适配。

**不增加幼狮、临时驯兽、额外单位栏或第二只出战灵兽。** 不改变灵兽捕捉、资质、技能、培养或归属。山海同契所有“同行灵兽”称谓，都只指`ownerId`为本人的当前出战灵兽；下文“猎意”是战内状态，不是新养成资源。

有来源的数值优先保留；因宿主机制不同而修改的数值独立标记。特别是，普通灵兽已经拥有完整技能和独立行动，不能再把原幼狮的免费行动、整套面板和全部追击叠上去。

## 3. 六心法设定与数值映射

不为新宗门扩大七槽协议。合并原来不直接提供面板成长的魔兽神功与阴阳二气诀，保留另外五门独立等级；这样避免改造所有宗门的入宗、升级和转宗结构。

| 槽位／心法／ID后缀 | 心法文案 | 原门技能 | 承载内容 | 面板接入建议 |
| --- | --- | --- | --- | --- |
| 1 主《百兽观》／`canon` | 观百兽行止，调自身气血；先定心息，再将所悟炼成兽相。 | 魔兽神功＋阴阳二气诀 | 显相、追猎、裂霄啸、守魄、长息及流派根基 | 不额外添加面板收益。两个原门等级统一引用此等级，属于**改**。 |
| 2《搏杀谱》／`combat` | 记山野搏杀之法，取爪击、重踏与振翼掠阵之势，一招出手，须知进退。 | 生死搏 | 裂爪、掠岭、踏山、燃血；山海同契替换后的纵猎 | 物攻每级+0.5，**暂**，沿项目现有同类心法量级。 |
| 3《结契书》／`taming` | 辨兽性，识灵息；威势用于制敌，心意用于照应同行灵兽。 | 训兽诀 | 伏兽、续契 | 原灵力不能直接等于精神属性；首版取法防每级+0.4，**改／暂**。 |

`P`始终指本项目人物战斗等级，当前境界映射端点为5与180；`L`指技能所属心法等级。为保持原型公式可对照，`L狂`和`L鹏`仍作为研发记号，分别指第4槽《逐猎诀》与第5槽《凌风步》，不作为玩家可见名称。心法最高180，沿用人物等级+10的上限。原公式中的“伤害力”对应战内物攻，“伤害结果”对应减防、修炼后伤害修正；不可将两者混用，也不可修改人物永久六维。

面板初值不是梦幻原值；原训兽诀对应《结契书》后只映射法防，尤其会损失原灵力的法伤含义，需在面板贡献说明中记录。若后续决定同时映射法攻、法防，单独调整心法投影，不能擅自给每级加两份现有面板值。《结契书》及“续契”不增加灵兽契约养成，也不延长灵兽寿命。

### 4.3 山海同契流派根基与技能替换

原版幼狮最初需要召唤，2022年改入战随行；主人发令与幼狮自动行动有独立机会成本。2023年放任自流替换天魔解体。这些历史事实用于分析，不把原幼狮视为本游戏的灵兽模型。

本项目采用以下替换，数值均为**改／暂**，只有明确标出的历史回合／冷却保留：

| 本宗机制（原型） | 自有灵兽版 |
| --- | --- |
| 灵犀相照（原：驯兽·幼狮） | 改为“灵犀相照”根基，自动识别本人的当前出战宠。**不召唤、不附送属性模板、夜战、必带技能或第二次行动**。 |
| 灵兽既有行动（原：幼狮之搏／主人发令） | 由灵兽现有普通攻击或主动技能承担。法宠可以参与联合目标攻击；猎意、狂化、钢牙等物理加成仍只强化物理部分。 |
| 猎意（原：狮魂） | 改为“猎意”：0～5层，每层物理直接伤害结果+2%。主人裂爪击倒非灵兽敌人且本人宠站立，或合猎联合攻击击倒目标时，增加1层；每主人每轮至多1层。原资料的“非召唤物”不等于“非召唤兽”，本稿把普通裂爪击倒敌宠获得猎意排除，是明确的**强度改编**；合猎击倒敌宠仍可获得猎意。宠倒地／离场即清空；换宠不继承，重连不重置。根基不免费给初始层数。 |
| 续契（原：驯兽重生） | 流派授予“续契”：200MP、CD8，复起本人的在场倒地灵兽至20%最大HP。尊重禁复活、减疗、伤势与合法归属；不修复伤势、不补发已过的行动窗口，不额外附赠原幼狮减伤。 |

| 合猎（由最佳搭档节点授予） | 详见第7节。保留500MP、CD8、入战CD4与兽相前置；宠的协同收益移入其下个正常行动。 |

猎意加的是既有灵兽的一部分物理伤害，不强化反震、反击、DOT、派生伤害和法术。狮王把每层2%提高为2.5%；图腾把当前猎意加成的一半赋给主人的裂爪。**狮王与图腾同层互斥**，实际构筑不会同时得到二者。

### 4.5 经脉节点保留，节点说明改用本宗术语

节点名保留不代表旧技能文案一并保留。第5、6节的“原型数值／条件”只供研发核对，玩家说明由“接入决定”结合当前编译结果生成。例如：

## 7. 合猎与行动预算

推荐采用“主人先打并制造机会，灵兽在自己的正常窗口兑现”的方式。它保留原版联合点杀目的，适配两名本来就能独立行动的单位。

1. 指令预检：本人处于兽相状态、本人宠在场站立、目标合法、500MP充足、冷却结束。没有宠时不能选取或扣费。
2. 主人在自己的速度窗口施展一次裂爪；只收500MP，不再重复扣裂爪30MP。本段不能被队友保护分摊；仍受命中、护盾、减伤及独立免疫影响。
3. 若目标仍站立，发放一份绑定`ownerId + petId + targetId`的联合机会，有效期到下轮结束。宠换出／任一方倒地／目标倒地／战局结束时失效；其他同门不可消费。
4. 宠的**下一个正常攻击行动**若以该目标为主目标，主目标直接伤害结果+50%，并只对该主目标绕过保护；副目标、法连、反击、DOT和子技能不受益。主目标多段同享这一次机会，行动结束统一消费，不能每段消费或叠一次50%。
5. 下一个正常行动若选择其他攻击目标，机会同样作废；防御、召回及因控制完全没有出手的窗口不触发伤害，机会按原期限到期。自动策略应优先完成合法联合目标，但不得违背手动命令。
6. 宠比主人快时不回放本轮行动，联合机会等待下一轮。主人先出手则可在同轮完成。两种情形都不改变速度，也不令队友失去行动。
7. 主人该次裂爪直接击倒目标，或宠在消费联合机会的正常行动中击倒同一目标，获得1层猎意；只发一次，受每轮1层总预算限制。已经死亡的敌人不再重选为另一个联合目标。

回光、复仇、合猎统一使用一个“临时协作增强槽”：同一宠同时持有多种机会时，只保留最新合法机会，**不相加、不连乘、不排队补发**；新的机会允许覆盖旧目标。三种数值均为+50%，合猎可用于物理／法术主目标，另外两种只接受物理攻击；不符合类型的攻击消费机会但不获加成。此规则须在玩家详情写明，避免隐藏浪费。

这样每轮仍只有主人和灵兽各自原有的正常行动；合猎新增的是一次有限的伤害机会，而不是另一个宠物行动。一次普通单体宠伤害为`D宠`时，其新增收益最多约`0.5D宠`／8轮；法宠群攻只强化主目标，不能按整场群攻合计放大。

## 8. 恢复、倒地与资源规则

### 8.1 治疗计算

育养、报恩使用一次符合条件的正常行动造成的**实际HP损失总量**，排除护盾、溢出、反震、反击、DOT和派生；各自只进行一次30%判定。未触发时不扣治疗预算；触发后治疗受每轮预算、减疗、伤势上限与缺血夹取。

羁绊可以转发一次普通治疗、吸血或育养／报恩产生的有效恢复，但转发结果标为“羁绊派生”，不能再次转发，也不能借复活初始HP或修复伤势产生额外收益。预算按主人－宠双方分别记录，换宠、复起和重连均不刷新当轮已经用掉的治疗预算。

### 8.2 救主结算顺序

回合末依次检查：战斗尚未结束 → 主人确实倒地且可复起 → 本人的在场灵兽站立 → 主人战意至少80 → 尚有尝试次数且未成功救主。满足后消耗1次尝试、用种子RNG判50%；成功才原子扣80战意并恢复20%最大HP。

禁复活、不可治疗、成本不足、目标已复起或战局已经结束时，不抽签、不扣费、不耗尝试。失败仅消耗尝试，下一合法回合末可继续，最多3次。20%恢复受现有减疗和伤势上限，若有效复起条件不成立则不得支付；不清除伤势、不移除禁复活、不补回本轮已失去的行动。

不添加“宠失去20%HP”成本：当前`loseHp`属于伤害，受承伤管道与受击监听影响，不能当精确的非致死支付；避免为一个节点新增跨单位双成本交易。

主人倒地、宠仍站立时，本项目当前胜负规则允许继续战斗。若最后单位已经被击倒、引擎已发`BattleEnd`，之后即使收到回合末钩子也不能救主。救主不是覆写灭队结果的复活保险。

### 8.3 层数与失效

猎意属于当前宠的战内状态，不属于主人持久养成。宠倒地／召回清除猎意；主人倒地时猎意暂存但不提供门派增益，救主后可恢复有效；宠的复仇机会是特许保留的倒地响应，兑现时主人仍倒地则只允许复仇自身的+50%，不恢复其他需要主人站立的加成。

同种状态刷新不重置次数预算。救主成功／尝试、复仇发放次数、逞凶人物记录等属主人本场战斗事实，不能通过换宠重置。猎意满层时合猎仍可用，但不伪造“新增一层”触发护盾。

## 9. 首版强度预算与合法构筑验算

本轮保留可核原值，不承诺实战伤害等同梦幻。协同版需要比较的是“同等养成的人＋宠”总收益，不能把本来就有的灵兽独立行动算成宗门新增价值。

### 9.1 先控制收益来源

- 不增加行动数，不复制幼狮面板，不赠夜战、成长或新技能。
- 猎意基础最高10%，狮王最高12.5%；宠倒地／换宠损失积累。
- 护盾从`12L狂`降到`4L狂`，不叠、每轮一次；协同25%降12.5%，嗜血30%降15%。
- 吸血保留30%与18%，同时加有效治疗与每轮预算；羁绊只转发一跳。
- 反应攻击改为下一个正常行动的有限机会；救主每战最多一次成功且支付80战意。
- 同一行动中的本宗常规伤害加成加算后进入现有伤害管道；“协作增强机会”作为一次1.5结果系数，不能由三个机会重复乘算。普通暴击、修炼和其他既有机制继续按全局规则计算。

### 9.2 必须用真实连通路线比较

示例路线A：`狮王(1左)→育养(2左)→狂化(3中)→协同(4左)→报恩(5中)→逞凶(6中)→最佳搭档(7中)`。所有相邻层列差不大于1，是合法路线，不能再把图腾、矫健、护盾或钢牙的收益算进去。

以普通单体宠、满层猎意、封印目标为例：常规本宗加成是12.5%猎意＋12.5%协同＝25%。纵猎生效时再加15%，为1.40；狂化若本次是单段物理，期望倍率1.12，故该阶段约`1.40×1.12=1.568`倍。联合机会只在一次行动上再×1.5，约2.352倍。这是条件满足时的单段期望，不是一次暴击的最高倍率；没有封印目标、未满层猎意、法宠或多段时均不得照搬。

此值说明改编仍有可见爆发，**不能宣称已经平衡**。纵猎消耗主人施放与休息两个输出窗口，灵兽可能早于主人、联合目标可能死亡，这些机会成本必须一起计入；合猎500MP与开场4轮冷却也不能忽略。

示例路线B：`图腾(1右)→守势(2右)→矫健(3右)→嗜血(4右)→钢牙(5右)→救主(6右)→最佳搭档(7中)`。这条路线没有狮王、狂化、协同、育养、报恩或羁绊；满层猎意、血线≥70%、双金装备时常规物理加成为10%＋10%＋10%=30%，击倒人物的3轮再+15%。不能用PvE击倒小怪常驻嗜血，也不能借救主取得左路治疗。

### 9.3 验证目标，不当作已通过结果

固定同等级、装备预算、修炼与灵兽，比较红尘剑宗、浴血横行、山海同契在单体／多目标、4／8／16轮中的总伤害、有效恢复、护盾吸收、失去行动数与MP消耗；覆盖物宠、法宠和无宠。至少分离开场、零猎意和满层猎意，不以满层猎意开局代替真实循环。

初步评审线：常态“人＋宠”平均伤害增幅以10%～20%为观察区间，条件爆发可以超过，但不应以额外行动或恢复循环长期取得优势。这是**平衡观察目标**，不是全局硬上限，也不是对本稿已达标的保证。超标时优先改本稿新增的猎意、放任和协作50%倍率，再考虑有来源的原数值；偏弱则先检查主人行动成本和猎意获取条件。

## 10. 工程接入方案

### 10.1 已有能力与最小缺口

按当前源码核实，不采用仍引用`packages/shared`／battle-v5／Bun的旧`docs/sect-authoring-guide.md`作为入口。

| 领域 | 可复用能力 | 本次需要做的事 |
| --- | --- | --- |
| 兽相／休息 | `StatusDef`、技能前置、`statusRounds`、`modifyStatusDuration`、`skipNextAction`、`recoverySkipChance` | 新增内容定义；不能复用红尘休息附带的封印免疫，百兽崖没有自动获得此免疫。 |
| 多段／多目标 | `physicalHit.hits/coeff/resultFactors`、`targeting.count` | 费用按已冻结目标／段数预检，多段目标倒地早停；踏山下一轮限制单独定义。 |
| 主宠归属 | 现有`ownerId`、`sourceIsOwnedPet`、`effectSource:eventSource`、`ownerStatusKinds` | 增加通用“目标为本人出战宠”关系筛选，供可选目标、执行、预检与AI共用；仅`side:ally + kind:pet`会误选队友宠。 |
| 根行动与联合机会 | `afterAction`、主目标过滤、来源过滤、状态／战斗事实 | 明确正常根指令的行动scope；现`rootActionOnly`不足以排除所有`invokeSkill`子调用。联合机会在行动开始锁定、整次主目标多段生效、结束消费；不能第一段就移除。 |
| 猎意层数 | 状态层数、有限状态编译 | 优先编译0～5档有限状态，避免只写`maxStacks:5`却把2%固定乘一次；宠死亡／召回清除，快照保留。 |
| 有效恢复与羁绊 | 现有治疗、吸血、`restoreHp`与减疗／伤势夹取 | 当前没有覆盖所有恢复入口的入账后有效恢复钩子，`OnHealCalc`只是入账前计算。补通用成功HP恢复事实（有效值、来源、根行动、是否复起／派生），让羁绊一跳与预算按真正入账量结算；不能用尝试治疗量冒充有效恢复。 |
| 成本与复起 | 既有还魂、战意资源、复活禁用、表达式`combatEnded/reviveBlocked` | 续契走普通主动成本；救主需支持对倒地主人的合法80战意支付＋复起作为一次成功结算，不走物品／DB。 |
| 解封事件 | 状态真实解除事件 | 背水依真实来源与封印解除结果触发；清心的净化分类须包含新可解控制，不能只设`dispellable:true`。 |
| 反震延迟倒地 | 反震来源与行动结束事件 | 狂袭若无现成原语，需小型通用“指定反震来源致死延后至当前行动结束”支持。只延迟死亡，不使后续每段都重新回复1HP；行动结束必结算且只发一次倒地。 |
| 装备事实 | 已有`element`与装备贡献投影 | 新增武器／衣服恰为金的计数0～2；复用现有暴击等级换算。 |

`sourceBound`只区分状态施加者，并不自动在施加者倒地时失效；`ownerStatusKinds`也不会代替主人站立检查。绝大多数同契监听必须显式要求本人站立；复仇的倒地发放与后续兑现、救主是明确例外。

主人倒地当前会清状态与护盾，但不清战意资源，救主80战意具有支付对象；它不经过普通主动施法。灵兽死亡可能是`dead`而非人物的`downed`，续契的归属筛选必须允许在场、未逃跑、未被召回的本人死亡宠，不能错误套用站立宠目标池。鬼魂／禁复活／拒绝HP恢复仍按现有规则处理。

不为本宗创建单位类型、召唤协议、灵兽专用数据库表或特定宗门ID的核心分支。上述新增原语均需说明现有组合不足的具体反例；能用内容／规则层组合的，不扩核心。

### 必测矩阵

- **等级／费用**：心法20/30/35/40/120/150/170/180边界；掠岭2～6目标与扩目标，逐命2～7段、目标提前倒地、MP恰好够与少1；消耗失败不能先发增益。
- **行动时序**：施展显相、迅捷替换、兽相剩余0/1/2；掠岭休息、乱击减时、肝胆免休息；踏山本人只禁神通与目标下一轮失去行动，先手／后手都检查。
- **物理结算**：临时物攻与伤害结果分层；裂爪不带手游忽防；普通暴击、狂化、反震与追猎不递归；狂袭致死在行动结束只结一次。
- **经脉与奖励**：42槽真实效果；每层互斥、相邻连线、后层截断、七层自动奖励；原先六宗编译／转宗不回归。
- **宠归属**：两个同门各带宠、队友宠、无宠、板凳宠、宠死亡／鬼魂／复起／换宠；本人倒地不继续提供站立加成；恢复快照不重发入场或次数。
- **联合攻击**：主人快／宠快；敌方先死；手动改目标；宠被控；物宠多段、法宠单法／群法／法连、反击／子调用；整次主目标增强但副目标不增强；重振／寻仇／合猎之机覆盖只留一份。
- **治疗与复起**：护盾全吸收、过量伤害、满HP、禁疗、减疗、伤势上限；羁绊最多一跳；每轮治疗预算不因换宠刷新；救主成功／失败、尝试上限、80战意恰好与不足、禁复活、别人先救起、已终局。
- **PvE/PvP与策略**：唯一同门、封印目标与普通减益、双金装备；原只对人物击倒的节点不得靠小怪刷；AI准备显相、节约MP、协同对象、不能攻击对象与休息期间均合法。

纯确定性用例只放`packages/*/src`；组合在game-rules，不让core反向依赖宗门内容。API／Web／DB不写单测，不新增一次性烟测、种子或压测脚本。真实本地请求按`docs/testing.md`验证完整客户端负载、预算／revision、非法输入、提交值和随后resource读取，并恢复准备数据。

实施后按改动范围执行`pnpm run lint`、`pnpm run typecheck`、共享包定向测试；跨核心／内容／投影时再跑`pnpm run test`与`pnpm run build`。本轮只有文档，不运行应用测试。
