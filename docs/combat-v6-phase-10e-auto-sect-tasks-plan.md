# Phase 10E：统一自动托管与宗门任务战斗迁移

> 2026-09-08：用户确认将自动战斗简化为客户端计时、服务端单次 AUTO 选招。此方案替代此前的服务端持续托管设计；取消离页／断线继续、服务端开关与到期调度要求。宗门任务迁移仍在实施中。
> 上位设计：[总路线图](./combat-v6-mhxy-redesign-roadmap.md)。

## 1. 交付顺序与边界

先交付 10E-1 统一自动托管，再交付 10E-2 宗门任务战斗。两部分分别验收，前序阶段遗留验收不会自动通过。

托管统一开放于练功房、野外、秘境、幻境、擂台及本阶段宗门任务，公共操作面板不设置玩法开放白名单或功能开关。不同 Host 仅保留原有资源、收令和结算职责。天骄榜已自动结算，无需交互托管；回放与观战没有操作权限。

宗门范围为矿脉巡逻、每周演武、外宗悬赏和长老试炼。保留领取、次数、任务奖励、贡献及晋升规则，不重做扫地、采矿小游戏、物品交付、组织经济。突破试炼、后台模拟器、全站面板和全仓 v5 删除另行安排。

## 2. 自动按钮与本地状态

- 公共战斗面板一级操作区展示「自动」，启用后显示「取消自动」及明确的自动状态；不能只用颜色表达。
- 每场默认手动。自动开关仅存在当前战斗页面的 React 状态中，不存服务端或浏览器持久存储。刷新、重新进入及新战斗均恢复手动；人物与在场灵兽共用开关。
- 开启后，在可下令且播放结束时等待 3 秒，再发送一次 AUTO 请求。已提交的手动指令保留；擂台本人已交令时等待下一轮收令。未提交的本地选择草稿清除。
- 取消只清除本地定时器，不向服务端发送取消请求。已经发出的 AUTO 请求可以完成当前回合；擂台已经接收的具体指令按普通指令处理，不撤回。
- 离开页面或关闭标签页停止后续提交；已发出的请求不撤销。断网不能继续自动，后台标签页可能被浏览器节流。请求失败后停止自动，恢复战况后由玩家重新开启。
- 终局停止，不自动领取任务、领奖、重试、探索、进入下一场或选择幻境祝福。

## 3. 客户端节奏与多人语义

公共战斗组件使用单次 setTimeout，等待 3 秒提交 AUTO；等待当前请求返回及本轮播放完成，才安排下一次。取消、终局、卸载清除定时器。手动／自动共用已有 pending 和请求互斥，避免并发提交。3 秒是客户端操作节奏，不作为服务端强制限速。

单人 POST /sessions/:id/auto 请求携带 type: AUTO、round、expectedRevision。服务端核验角色归属、回合和版本，生成具体指令后在既有 Host 更新边界内提交并结算一次。旧版本重试不能推进下一回合。

擂台复用 /:battleId/commands，请求的 commands 可为 AUTO，继续使用既有 round 和 requestId。已接收请求先命中回执，不重新选招；同回合其他玩家交令不使本人的请求因全局 revision 变化而失效。具体指令经过普通所有权和合法性检查，战报只记录实际动作。

擂台原有收令超时、断线兜底及 resolving/playback 调度不变。取消只影响客户端后续请求。删除显式托管专用的服务端开关、到期索引和补招扫描，不影响原有多人推进。

## 4. 固定策略

使用确定性纯逻辑策略，不调用 LLM，不提供首版策略编辑器。五宗门两流派均需默认策略；可复用 NPC 选招基础能力，但玩家策略独立定义，不直接照搬敌人轮转。

- 按流派配置选择合法技能和目标，允许治疗、复活及消耗战意的器诀。
- 治疗、复活有明确触发条件；避免满血治疗、无目标复活和无效重复状态。
- 不自动召唤、换宠、逃跑、捕捉或使用药品。无在场灵兽时只控制人物。
- 技能不可用依次尝试后续候选，最终普攻；无法合法攻击则防御。倒地等无法行动单位遵循原有规则。
- 候选顺序、阈值、目标排序与平局裁决必须固定并有版本；同一快照得到相同选择，不消耗引擎战斗 RNG 来反复试选。
- 策略位于内容／Host 层，core 不按宗门或技能 ID 分支。生成指令仍经过普通指令合法性与所有权校验。

技能候选来自开场冻结的构筑，策略由服务端当前固定实现决定，不提供跨部署策略版本路由。已接受的指令不因请求重试重新选择；回放消费实际行动事实，不按当前策略重算。首版不承诺最优策略。

## 5. 实现落点

CombatV6Battle 保存本地开关与单次定时器；CombatV6Commands 提供一级自动／取消按钮。useCombatV6Session 与 useArenaV6Session 只发送单次请求，不持久化开关、不轮询自动状态。

共享 automaticCommands 为本人及在场灵兽选择普通指令。单人 Host 在原有 CAS／角色锁内处理一次 AUTO，擂台在既有收令及请求回执内展开 AUTO。没有新增通用后台调度器、Redis 托管注册名单、停用扫描或恢复任务。

幻境终局先保存事实，再通过既有事务提交奖励和回放；保留回放幂等保护。结算失败通过页面“重试结算”重试同一终局，不依赖自动战斗调度器。

## 6. 宗门任务战斗

领取任务 → 指定地点挑战 → 公共 v6 战斗页 → 权威结算 → 返回任务地点领取奖励。

| 任务 | 对手 | 资源策略 |
| --- | --- | --- |
| 矿脉巡逻 | 配置化 v6 NPC | 挑战者现实 HP/MP，灵兽死亡扣寿命 |
| 每周演武 | 同门冻结构筑副本 | 满状态隔离，不影响双方现实资源 |
| 外宗悬赏 | 外宗冻结构筑副本 | 挑战者现实消耗，目标角色不受影响 |
| 长老试炼 | 配置化 v6 NPC | 挑战者现实 HP/MP，灵兽死亡扣寿命 |

领取时锁定 NPC 模板／等级／种子／内容版本，或目标角色 v6 构筑及合格首发灵兽。目标没有有效 v6 构筑则排除，无候选明确提示，不回退旧投影。挑战者每次开战冻结当前构筑，失败后可调整再战。

四类共用薄任务 Host，通过配置指定对手和资源规则，复用 v6 合法换宠与公共指令。首版无捕捉、战斗药品、新增灵兽经验或独立掉落，任务收益继续走既有领奖流程。

胜利完成目标；战败、逃跑、百回合平局不完成。同一任务最多一场活动战斗，未过期可重试，不新增挑战额度。已开始的战斗允许在任务过期后完成并正常结算；过期后不能新开或重试，已完成任务领奖沿用原规则。任务过期清理不得删除活动战斗依赖的任务事实。

战斗及待结算期间阻止转宗、放弃任务和构筑修改；页面离开不放弃战斗。现实资源模式自然恢复及互斥沿用已有 v6 权威规则，不重新引入 v5 伤势。

## 7. 结算与迁移

Redis 保存会话及终局事实。使用稳定 battleId 幂等，在同一 PostgreSQL 事务内提交需要的人物资源、灵兽寿命、任务目标更新和统一回放归档；成功后释放会话互斥，失败可重试同一终局。复用现有归档及结算凭据能力，不另建平行任务系统，也不把 Redis 单次锁当成持久幂等凭据。

奖励仍由既有领奖事务发放，战斗终局不再发一份。回放只授权任务执行者，对手快照来源角色不自动获得权限。

停机时只处理携带旧战斗快照的未完成任务：先输出数量、状态、额度占用和补偿核对清单，定向撤销并恢复实际占用额度，撤销与额度恢复需要幂等。已完成待领奖及非战斗任务保留。具体 SQL 必须在核对既有额度结构后编写，不转换旧 combatant 为 v6，不删除历史资产。预发布／生产维护操作另行执行，本阶段设计落档不代表已执行数据处理。

## 8. 验收清单

- 10E-1：五类页面验证 3 秒后单次提交、人物及灵兽选招、请求不重叠、取消后不再提交、刷新／离页恢复手动、终局停止与不跨场自动。
- 五宗门两流派及灵兽策略：纯逻辑测试覆盖合法选择、治疗／复活条件、固定排序、禁用动作和相同输入确定性。
- 接管竞态：取消不撤回已发请求、手动指令保留、擂台已收令不撤回、重复请求、旧 revision／回合拒绝、到期同时取消。
- 多人：仅本人控制、队友手动／自动混合、全员托管、收令超时、断线兜底、4v4 带宠与观战只读。
- 恢复：刷新恢复手动、离页停止提交、请求失败停止自动、服务端重复请求不重复行动、终局结算失败可重试。无需验收后台持续托管或托管调度索引。
- 10E-2：四类任务胜利领奖、战败、逃跑、平局、资源隔离与消耗、目标冻结、重试、任务过期和互斥。
- 任务结算及迁移：重复终局、事务失败恢复、回放权限、旧任务额度恢复幂等、保留待领奖任务。
- 执行相关 shared 纯逻辑测试、lint、build，按 `docs/testing.md` 完成本地浏览器验收；不新增 server/react-app 单元测试或一次性测试脚本。
- 宗门任务战斗路径不再执行 v5；突破试炼等其他旧依赖单独记录，不能标记全仓退役完成。

### 9.5 10E-2 实施与运行记录（2026-09-08）
