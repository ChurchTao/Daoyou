# combat-v6 召唤兽系统设计

> 状态：首版方向基线（Canonical）  
> 确认日期：2026-09-02  
> 适用范围：combat-v6 召唤兽持久领域、捕捉、培养、编组与战斗投影  
> 主设计稿：[`combat-v6 梦幻式战斗体系设计稿与迁移路线图`](./combat-v6-mhxy-redesign-roadmap.md)

本文锁定 combat-v6 首版召唤兽系统的领域边界和产品规则。召唤兽采用梦幻式个体生成、固定出生技能格、随机打书、独立五维成长和单宠在场规则，不复用人物属性、功法、宗门、经脉、道装或修炼实例。

具体物种、资质区间、技能内容、捕捉概率、经验曲线和恢复道具数值属于后续版本化内容；不得因此改变本文的个体、技能格、编组、寿命和投影边界。

---

## 1. 已确认的首版决策

1. 召唤兽是完全独立于人物 build 的持久领域。
2. 召唤兽使用体质、力量、法力、耐力、敏捷五维，不复用人物六维。
3. 召唤兽使用攻击、防御、体力、法力、速度五资质，不设置闪避资质。
4. 数值等级上限为 180；对外以妖类境界为主要表达，境界由数值等级确定性映射。
5. 每升一级五维各自然增加 1 点，并获得 5 点自由属性点。
6. 捕捉完成时实际生成几个技能，该个体的技能格上限就是几个，后续不能增加。
7. 打书完全采用随机覆盖，不允许指定覆盖、固印、锁定或保底。
8. 每名玩家最多携带 6 只召唤兽，场上同时最多存在 1 只自己的召唤兽。
9. 首版不开放召唤兽修炼，也不继承主人的人物修炼。
10. 首版实现寿命；召唤兽每次战斗死亡在有效结算时扣除 50 点寿命。
11. 寿命不因普通参战、胜利、逃跑或主动召回而减少。
12. 寿命低于 50 时禁止出战；寿命归零只进入“寿尽”状态，不删除个体。
13. 法宝首版不实现，仅保留未来独立系统方向，不预埋数据库字段或 combat-v6 分支。

## 2. 领域边界

召唤兽个体由以下事实组成：

```text
物种模板
+ 个体成长
+ 五项个体资质
+ 数值等级与妖类境界映射
+ 五维自然属性与自由加点
+ 出生技能与固定技能格
+ 当前寿命与寿命上限
= 可投影的召唤兽个体
```

首版不设置品质、稀有度、星级或系统权威评分。个体价值由玩家根据物种、资质、成长、技能格、技能组合和加点自行判断。

召唤兽不得读取或装配：

- 人物六维和人物自由加点。
- 人物修炼等级。
- 人物功法实例和槽位。
- 宗门心法、主动技能和经脉方案。
- 人物道装和未来法宝。
- battle-v5 或 creation-v2 战斗投影。

人物功法与召唤兽兽诀可以使用相似的内容编译思想，但必须拥有不同的持久实例类型、注册表和投影入口。

## 3. 物种模板与个体生成

物种模板定义可生成范围，不直接代表玩家拥有的个体：

```ts
interface SummonedBeastSpecies {
  id: string;
  name: string;
  carryLevel: number;
  growthRange: readonly [number, number];
  aptitudeRanges: {
    attack: readonly [number, number];
    defense: readonly [number, number];
    health: readonly [number, number];
    mana: readonly [number, number];
    speed: readonly [number, number];
  };
  innateSkillPool: readonly string[];
  requiredSkillIds?: readonly string[];
  minGeneratedSkillCount: number;
  maxGeneratedSkillCount: number;
}
```

捕捉成功后，服务端使用确定性随机源一次性生成：

- 个体成长。
- 五项资质。
- 出生技能数量。
- 出生技能组合。
- 初始寿命与寿命上限。

生成结果必须保存为个体事实，之后不能因物种模板或内容版本变化而重新掷骰。捕捉结果需要记录生成版本；相同种子、模板版本和输入应能重放出相同结果。

技能数量先在物种允许范围内生成，再从出生技能池中生成实际技能。必带技能的占位和抽取顺序必须由内容规则明确，不能由界面临时补齐。

```text
skillSlotCapacity = capturedSkills.length
```

因此：

- 捕捉到 0 技能的个体技能格上限为 0，首版不能打书。
- 捕捉到 2 技能的个体终身最多保留 2 个技能。
- 捕捉到 5 技能的个体终身最多保留 5 个技能。
- 升级、境界变化、改名、加点和寿命恢复均不能增加技能格。

## 4. 五维、五资质与成长

### 4.1 五维

| 五维 | 主要战斗职责 |
| --- | --- |
| 体质 `constitution` | 最大气血、少量生存面板 |
| 力量 `strength` | 物理攻击 |
| 法力 `magic` | 最大法力、法术攻击、少量法术防御 |
| 耐力 `endurance` | 物理防御、法术防御 |
| 敏捷 `agility` | 行动速度及后续允许的命中/闪避贡献 |

### 4.2 五资质

| 资质 | 主要影响 |
| --- | --- |
| 攻击资质 `attack` | 力量到物理攻击的转化效率 |
| 防御资质 `defense` | 耐力到物理防御的转化效率 |
| 体力资质 `health` | 体质到最大气血的转化效率 |
| 法力资质 `mana` | 法力到最大法力、法术攻击的转化效率 |
| 速度资质 `speed` | 敏捷到速度的转化效率 |

首版不设置闪避资质。命中和闪避如需进入召唤兽面板，应由敏捷、技能和状态产生。

### 4.3 成长

成长是个体的全局转化因子，资质决定对应面板的专项效率。正式公式进入数值阶段后版本化，概念结构为：

```text
资质倍率 = 个体资质 / 对应物种标准资质
属性贡献 = 属性点 × 个体成长 × 资质倍率 × 面板系数
```

物种标准资质、面板常数、取整方式和上下限必须由召唤兽投影版本统一定义，不直接复制人物面板公式，也不能使用前端计算结果作为战斗权威输入。

## 5. 等级、属性点与妖类境界

召唤兽保存精确数值等级，范围为 `0～180`。数值等级用于经验、属性成长、技能公式和内容条件；妖类境界是由等级确定性推导的世界观展示，不是第二套养成进度。

```ts
interface SummonedBeastProgression {
  level: number;
  exp: number;
}

function getSummonedBeastRealm(level: number): SummonedBeastRealm;
```

升级规则：

- 每升一级，体质、力量、法力、耐力和敏捷各自然增加 1 点。
- 每升一级获得 5 点自由属性点。
- 自然属性与自由加点分别保存或可审计推导，洗点只重置自由加点。
- 妖类境界变化不额外赠送属性，避免同一次升级重复成长。
- 达到境界门槛后直接更新展示，不需要材料、概率、突破任务或手动点击。

第一版妖类境界文案草案如下；名称和区间属于可配置内容，正式投放前可统一调整，但不得改变 `level` 是唯一计算等级的事实：

| 数值等级 | 妖类境界草案 |
| ---: | --- |
| 0～19 | 启灵 |
| 20～39 | 通慧 |
| 40～59 | 化妖 |
| 60～79 | 凝丹 |
| 80～99 | 妖婴 |
| 100～119 | 化形 |
| 120～139 | 妖王 |
| 140～159 | 妖皇 |
| 160～180 | 妖圣 |

## 6. 兽诀与随机打书

召唤兽技能实例与人物功法实例隔离：

```ts
interface SummonedBeastSkillInstance {
  skillId: string;
}
```

兽诀可以声明被动技能或少量主动法术：

- 被动兽诀编译为 combat-v6 `passives`。
- 主动法术编译为 combat-v6 `skills`。
- 普攻由召唤兽通用规则提供，不占技能格。
- 首版不设置技能熟练度、独立技能等级或 AI 生成技能。

### 6.1 打书流程

1. 校验召唤兽属于玩家、技能格上限大于 0、兽诀可使用且不在战斗锁定中。
2. 消耗操作使用服务端确定性随机源，在全部现有技能格中等概率选择一个格位。
3. 新技能覆盖该格位原技能。
4. 保存覆盖结果、随机种子/证明、内容版本和个体修订号。
5. 结果不可撤销，不返还被覆盖技能或兽诀。

首版禁止：

- 玩家指定被覆盖技能。
- 固印、锁定、保护格。
- 连续失败保底。
- 通过打书增加技能格。
- 在同一次请求失败后重复扣除兽诀。

打书必须通过持久事务和个体修订号防止并发重复消费。随机结果由服务端产生，客户端只能播放结果。

### 6.2 普通与高级同系技能

普通与高级同系技能可以同时占用两个技能格；投影进入战斗时只启用高级版本，普通版本保留在个体技能列表中但不重复生效。

该规则避免随机打书因为冲突清理而意外缩减固定技能格数量。内容注册表必须显式声明同系关系，不能通过技能名称字符串推断。

## 7. 携带、编组与战斗规则

玩家最多携带 6 只召唤兽，其中一只可设置为首发：

```ts
interface SummonedBeastLineup {
  ownerCultivatorId: string;
  carriedBeastIds: string[]; // 最多 6 个且不得重复
  leadBeastId?: string;      // 必须属于 carriedBeastIds
  revision: number;
}
```

编组必须与召唤兽个体分开持久化，不在个体上保存首发或替补位置。

战斗规则：

- 每个玩家场上同时最多存在 1 只自己的召唤兽。
- 战斗开始时，满足出战条件的首发召唤兽随人物进入场上。
- 召唤或更换召唤兽消耗人物本回合行动。
- 新召唤兽从下一回合开始提交行动，不能在换入回合额外行动。
- 被收回的召唤兽保留当前 HP、MP 和本场死亡事实。
- 被收回时清除“仅在场时存在”的临时状态；允许跨上下场保留的状态必须由状态定义显式声明。
- 被收回的召唤兽不参与速度队列、状态 tick、光环和胜负判断。
- 本场已经死亡的召唤兽不能再次召唤。
- 人物倒地后不能提交召唤或换宠指令。
- 板凳召唤兽不能阻止所属队伍被判定战败。

现有 combat-v6 已具备人物召唤、自动收回同主人场上宠、板凳和死亡不可再召等基础。正式接入时仍需补齐并测试状态暂停/清除、新宠行动时机和战后结果回写。

## 8. 寿命

召唤兽个体保存：

```ts
interface SummonedBeastLifespan {
  current: number;
  maximum: number;
}
```

首版规则：

- 普通参战、存活、胜利、逃跑和主动召回不消耗寿命。
- 召唤兽在一场有效战斗中死亡，战后结算扣除 50 点寿命。
- 同一只召唤兽在同一场战斗最多结算一次死亡寿命损失。
- 战斗回滚、作废、调试或不写回的模拟战不得扣除寿命。
- 当前寿命低于 50 时，不能设置为首发，也不能在战斗中召唤。
- 寿命归零后进入“寿尽”状态，但不删除、不放生、不清空技能和培养数据。
- 寿命恢复不得超过该个体的寿命上限。

战斗引擎只输出结构化死亡事实，不直接修改数据库寿命。Host 在权威战斗结算事务中按唯一战斗记录幂等扣除，避免重试导致重复扣寿命。

首版必须提供至少一个确定性的寿命恢复出口，避免高价值个体永久锁死。恢复物品属于召唤兽领域，不映射旧丹药；其名称、产出和恢复数值在内容阶段确定。

---

## 9. 召唤兽修炼

首版不开放召唤兽修炼：

- 不提供攻击、法术、防御或抗法修炼入口。
- 不读取或复制主人的人物修炼等级。
- combat-v6 兼容字段统一投影为 0。
- 首版召唤兽公式和平衡以零修炼为基线。

未来若开放，必须建立独立持久模型、资源和投影版本，不得回写人物炼体五轨或复用人物修炼实例。

## 10. 持久模型草案

```ts
interface SummonedBeast {
  id: string;
  ownerCultivatorId: string;
  speciesId: string;
  name: string;

  level: number;
  exp: number;
  growth: number;

  aptitudes: {
    attack: number;
    defense: number;
    health: number;
    mana: number;
    speed: number;
  };

  allocatedAttributes: {
    constitution: number;
    strength: number;
    magic: number;
    endurance: number;
    agility: number;
  };
  unallocatedPoints: number;

  skillSlotCapacity: number;
  skills: SummonedBeastSkillInstance[];

  currentLifespan: number;
  maxLifespan: number;

  generationVersion: string;
  revision: number;
}
```

持久模型只保存长期事实。最终物攻、法攻、防御、气血、法力、速度、技能运行时定义和 combat-v6 单位快照由版本化投影重建，不直接保存到召唤兽记录。

需要由校验器保证：

- `skills.length === skillSlotCapacity`，首版不存在后天新增空格。
- 技能 ID 唯一性和注册表有效性。
- 等级、经验、成长、资质、属性点和寿命均为有限非负数。
- 已分配点、未分配点与等级可获得总点数一致。
- 所有者变更、编组修改和打书都使用修订号并发保护。

## 11. 首版范围

首版包含：

- 召唤兽物种模板与捕捉个体生成。
- 独立五维、五资质、成长和属性加点。
- `0～180` 数值等级与妖类境界展示映射。
- 固定出生技能格和随机覆盖打书。
- 普通/高级兽诀、被动与少量主动法术投影。
- 最多携带 6 只、首发 1 只、场上 1 只。
- 召唤、召回、换宠、死亡和板凳规则。
- 寿命、死亡扣除 50、低寿命禁战和最小恢复出口。

首版不包含：

- 召唤兽修炼。
- 炼妖、合宠和繁殖。
- 还童、洗资质和洗成长。
- 内丹。
- 召唤兽装备。
- 忠诚度。
- 进阶造型。
- 召唤兽交易市场。
- 固印、锁技能和打书保底。
- 法宝。

## 12. 法宝的未来方向

法宝是未来独立于六部位道装、人物功法和召唤兽的构筑系统。首版只记录方向：

- 可以拥有独立装配位。
- 可以区分主动法宝和被动法宝。
- 可以使用灵气、战意、次数或回合冷却。
- 最终仍通过版本化投影输出 combat-v6 支持的主动技能、被动、状态或面板贡献。

当前不创建法宝持久表、不向角色或装备模型预埋法宝字段，也不在 combat-v6 core 增加无实际消费者的法宝专属分支。正式启动法宝设计时另建独立设计稿并提升对应内容/投影版本。

## 13. 实现顺序与验收

建议实施顺序：

1. 定义物种模板、召唤兽个体、编组和版本字段。
2. 实现捕捉生成、五维成长、自由加点和妖类境界映射。
3. 实现兽诀注册表、固定技能格和事务化随机打书。
4. 实现召唤兽到 combat-v6 单位、主动技能和被动的投影。
5. 补齐召唤、换宠、板凳状态和行动时机规则。
6. 实现战后死亡事实、幂等寿命扣除和寿命恢复出口。
7. 接入捕捉、培养、编组和战斗界面。

最低验收条件：

- 捕捉结果在相同种子与版本下可重放。
- 个体技能格在任意培养路径中都不会增长。
- 打书只能随机覆盖一个既有格位，失败重试不会重复扣道具。
- 普通/高级同系同时存在时只启用高级效果。
- 每个玩家最多携带 6 只，任何时点场上最多 1 只。
- 被收回的召唤兽不继续 tick 状态或提供光环。
- 新换入召唤兽不能在当回合额外行动。
- 死亡事实每场只扣一次 50 寿命，结算重试不会重复扣除。
- 寿命低于 50 的召唤兽无法首发或中途召唤，寿命归零不丢失个体。
- 召唤兽投影不读取人物修炼、人物六维或其他人物 build。
