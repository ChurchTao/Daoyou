# v6 战斗页面

## 范围与隔离

练功房和野外探索使用独立的 `CombatV6Layout` 与 `components/feature/combat-v6`。v5 战斗页面继续使用原布局。ESLint 限制新版页面导入旧战斗组件、布局、状态、协议与引擎；通用 UI 和全局主题令牌可共享。

阵容支持双方各 4 个人物及每人 1 个召唤物。人物与召唤物通过 `ownerId` 配对，缺席位置留空，状态行固定高度。这里只提供多人阵容的展示能力；真实多人控制、召唤兽持久化及出战入口仍由后续宿主能力接入。

## 信息与操作

- 桌面为我方、中央文字战报、敌方；窄屏为敌方、战报、我方、指令栏。
- 阵容展示 HP、HP 上层护盾、MP 和紧凑状态；具体数值、战意、战斗属性与状态时长通过点击名字打开弹窗。
- HP 使用 `--color-resource-hp`，MP 使用 `--color-resource-mp`，护盾使用 `--color-resource-shield-soft`，继承 v5 的全局颜色。
- 只展示当前可操作单位的指令。选行动后点击合法目标即提交；自动选目标的技能直接提交。详情按钮在选目标期间仍可使用。
- 当前练功房、野怪宿主只要求玩家人物指令，提交成功后自动请求结算；未来宿主切换 `commandOptions.unitId` 即可复用人物、召唤兽依次操作的展示。宿主接入时仍须调整路由提交流程，收齐指令后才 resolve。

## 逐行动播报

服务端通过引擎的可选行动观察回调采集快照，裁剪为公开单位展示字段，再生成差量。resolve 成功保存后返回临时 `playback`，不会持久化展示帧，也不向前端发送引擎内部状态。顶层 `units` 始终是最新完整状态。

`playback.format` 固定为 `delta-v1`，`fromEventSeq` 标记基准事件游标。每帧包含 `afterEventSeq`、`round`、`updates`；更新按单位 ID 携带 `set` 中的新绝对值，数组整体替换，空数组清空。可选字段移除使用 `unset`，新单位使用 `added`，离场移除使用 `removed`；需要插入或重排时携带 `order`。没有单位变化的行动仍保留空更新帧。

客户端每秒应用一个差量帧，同时开放对应战报，未变化单位保持对象引用。消费的帧从队列释放；不保留展开后的逐帧完整快照。播放期间禁止下令，结束后才显示下一回合指令或最终结果。没有整回合跳过按钮；“查看新战报”仅滚动到已经播出的内容。

`useCombatV6Session` 统一接收响应、推进帧和恢复；最新会话与可见状态分开保存。会话按 revision 合并，重复事件忽略，同版本元数据刷新不打断播放。提交指令产生的 `commandAccepted` 只推进游标，不是行动帧。缺少基准、事件不连续或单位缺失时停止播放并重新读取完整会话，恢复失败可手动重试。整页刷新恢复最新状态与历史战报，不重播旧回合。提交成功但 resolve 失败时可继续执行已提交指令。

已知会话刷新使用事件游标。普通回合只有提交、resolve 两次顺序请求；野怪探索和关闭定向刷新区域，结算等待期间只轮询会话，请求完成后再调度下一次，结算完成刷新区域及角色资源。读取支持取消与过期结果隔离，野怪结算完成前不可结束会话。

## React 实现约定

阵容、单位行、战报、指令和详情各自负责展示职责。指令选择带会话 revision 和操作单位身份，身份不匹配时直接派生为空，保留战报滚动和弹窗生命周期。Effect 用于网络生命周期、播放计时、DOM 滚动和原生弹窗，不用零延迟定时器复制派生状态。

战报仅对新增事件格式化；推进游标不会重新格式化历史。单位名称及主人关系建立索引，单位行和完成的行动条目通过稳定数据引用与 `memo` 跳过无关更新。活动会话不使用通用 TTL 缓存，不新增全局状态库。样式遵循仓库 Prettier/ESLint，通用 React 优化规则不等于套用 Next.js/RSC API。

## 发布

指令栏采用攻击、神通、器诀、防御、保护（存在合法目标时）、逃跑一级入口。神通和器诀复用通用 `InkDetailDrawer`，选中后收起并沿用原目标选择流程。技能名后的独立 `?` 支持鼠标悬停、触屏点击和键盘激活；不可用技能仍可预览效果与消耗。抽屉状态随会话 revision 和操作单位身份重置，不通过 Effect 同步选择状态。

`display.skillDetails` 提供 v6 技能分类及定性效果摘要；器诀分类以 v6 器诀注册 ID 为准，说明从效果定义生成，不引用 v5 文案或序列化原始公式。此摘要不表示伤害预测或完整触发条件，准确消耗和可用性继续读取 `commandOptions`。

此次直接替换旧的全量 `playback.frames[].units` 格式，不保留双协议，也不需要数据迁移。前后端必须同步发布；已经打开的旧页面需要刷新。顶层会话 API 版本及 Redis、回放归档结构不变，临时播放格式由 `playback.format` 标识。

## 验证

纯共享测试覆盖 16 单位行动观察、伤害状态一致性、观察前后战报与 RNG 相等；差量测试覆盖逐帧重建、零值、数组清空、回合末状态到期、群攻、护盾、复起、单位增减/插入及游标缺失。未新增 React 或服务端单元测试。

使用 `bun run scripts/combat-v6-presentation-benchmark.ts` 重现四种真实引擎场景。下表为示例完整 resolve 响应的 JSON 字节数和本地 gzip 字节数，包含最终单位、指令选项、事件及显示字典；不含 HTTP 头。线上是否压缩及实际网络耗时需另外观测。

| 场景          | 原 JSON → 差量 JSON | 原 gzip → 差量 gzip |
| ------------- | ------------------: | ------------------: |
| 1v3 普攻      |      10,294 → 4,296 |       1,048 → 1,002 |
| 16 单位普攻   |    100,300 → 14,794 |       2,822 → 1,726 |
| 16 单位群攻   |    127,748 → 46,098 |       5,769 → 4,488 |
| 16 单位多状态 |    205,574 → 90,601 |       7,639 → 5,926 |

16 单位普攻的行动帧从 86,803 降至 1,277 字节（降低 98.5%）；基准脚本守卫最低 80% 降幅。预热 10 次、采样 100 次的采集耗时中位数约 0.02～0.34ms/回合，计入公开字段投影与差量生成，不含战斗计算、引擎观察快照克隆和网络。

临时 HTTP 验证页使用真实引擎及生产组件/控制 Hook，检查逐行动显示、恢复执行、缺失游标重取、同版本增量刷新和详情；1024px/360px 阵容血条对齐，360px 战斗主体无横向溢出，HP/MP 颜色不变。React Profiler 的一次已有战报播放更新样本为 actualDuration 1.2ms、baseDuration 8.6ms，仅用于确认缓存生效，不代表线上 SLA。在已有 96 个行动条目的回合中，17 帧产生 17 次播放提交，战报格式化批次数维持不变。

2026-09-05 在已登录的 localhost:5173 完成真实野怪战斗、胜利及资源结算回归。发现并修复公共 `useResource` 将操作函数与 snapshot 一起重新创建的问题：结算 Effect 调用 reload 后，snapshot 更新又改变 reload 引用，从而形成刷新循环。reload/retry/invalidate/setData 现在只随资源 key 改变引用。结算后观察窗口没有新增 API 请求。区域锁覆盖整个战斗生命周期，因此有会话时仅按 `session.settlement` 判断是否轮询，不能以区域锁代替结算状态。
