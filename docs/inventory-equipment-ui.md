# 储物袋与道装栏

储物袋桌面采用左侧六槽道装与淡墨人物、右侧五列四十格物品布局；移动端上下排列。延续 GameSceneFrame、InkButton 与 Tailwind 4，不增加独立 CSS、角色评分或属性总览。

装备栏与袋中物品共用 ItemSlot 浮层，桌面 hover／键盘聚焦和移动端点击均可预览。袋中候选道装可展开与已穿戴道装的属性比较。空槽筛选该部位；搜索、分类不改变真实袋内位置，也不隐藏已穿戴道装栏。穿脱按钮复用现有装备编译器验证完整候选装配，保留轻灵的全套等级影响；名称仍按原始穿戴等级配色。最终写入仍由原 API 校验。

容量：穿戴道装使用独立 equipped 位置，不占随身四十格；穿戴释放原格，卸下需要一个空格，替换时旧道装回到新道装原格。储藏室显示物品条目总数，分页读取；读取袋与储藏室时并行。随身物品搜索、分类不发请求。写入期间防重复提交，写入后重新读取权威物品与穿戴状态；未完成读取时禁止使用旧道装状态操作。所有操作反馈使用 Toast。

## 全场景共享储物袋（2026-09-11）

- 随身物品统一使用 `useInventoryBag`，由现有 `resourceStore` 按角色隔离缓存、合并读取与接收资源事件；不在场景中另存完整背包副本，不新增平行 Context 状态。
- 主背包、悟道室、坊市、回收、灵田、炼丹、铸造、灵兽兽诀、邮件附件、拍卖寄售、聊天展示、宗门交付、秘境材料交付与休整均使用 `InventoryItems`。公共组件统一五列、四十格、间距与真实 `slotIndex`；传入完整物品数组，只对操作候选做资格判断。
- 不可用物品保留原位和详情；可选提示及操作由场景提供。主动搜索／分类保留真实位置，不从缓存删掉不匹配物品。储藏室分页、商品货架、旧宝库和铸造图录仍保持各自用途，不混为随身背包。
- 读取失败或刷新期间禁止依赖旧库存提交，刷新入口仍可用于恢复。邮件／拍卖／展示的所选物品依据共享快照校验版本；邮件附件失效后明确提示，并禁止静默改成无附件发送。宗门交付核对所选版本，秘境交付处理物品消失与数量变化。
- 铸造读取接口只返回人物等级、灵石和灵气，背包由公共资源读取。背包存取、整理、移动、拆分、兽诀学习均在事务内提交资源变更；`mutateInventory` 在事务提交后发布通知。移动到原格也返回统一 mutation 响应。

本轮验证：纯本地 `127.0.0.1:5174`，本地道友2。坊市、回收、灵田、炼丹药柜、铸造、拍卖、邮件、聊天展示、灵兽九类场景与主背包逐格比较，12 件物品的名称、数量、位置和 28 个空格一致。360px 灵兽抽屉为五列，物品区宽 328px，页面无横向溢出；拍卖不合资格物品仍可预览并解释原因。

## 穿戴道装独立存放（2026-09-15）

道装穿戴后进入 `inventory_items.location = equipped`，`slotIndex = null`，通过原 `cultivator_equipment_slots` 保留装配关系。统一背包资源的 `items` 仅含随身格位，`equippedItems` 单独返回最多六件穿戴道装；`used/total` 不含已穿戴道装。其他场景的公共物品栏继续消费 `items`。

穿戴释放原格位；替换时旧道装回到新道装腾出的格位，满背包也可换装；卸下使用第一个空格，满背包返回明确错误且整笔事务回滚。完整装配编译保留原境界与器蕴约束，库存位置在属性刷新前写入同一事务。0047 迁移将已有穿戴道装移出背包，保留实例及属性并增加物品修订号。

本地道友1实测：29/40 穿戴后变 28/40，装备只在装备栏出现；40/40 时替换成功，旧装备返回腾出的格位；满背包卸下提示「背包已满，请先腾出一格再卸下」，装备不变；腾空后卸下成功。360px 重复穿脱与层级正常，无横向溢出。临时12件容量样本通过 dev API 准备及清理，原29格／156件物资恢复，53条储藏室记录不变，最终恢复无穿戴状态。未消费原物资，允许库存实例修订号及资源事件正常更新。

验证：相关共享库存、背包契约与资源失效测试27项通过；lint、完整build（含类型检查）、新增／修改共享与服务文件Prettier及diff检查通过。本地已应用0047迁移，其他环境尚未应用；上线需配套部署服务与客户端并执行迁移。未实测六部位同时穿戴、轻灵连锁卸下限制或战斗占用，相关既有编译与锁检查保留。
