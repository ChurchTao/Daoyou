# 跨服角色转移 v2

## 管理员启用

每台服务器使用稳定且全网唯一的 `TRANSFER_SERVER_ID`（仅字母、数字、点、下划线、连字符），以及独立的 Ed25519 签名私钥和至少 2048 位的 RSA 解密私钥。私钥只放在服务器环境变量中；推荐生成 3072 位 RSA 密钥。

```bash
openssl genpkey -algorithm ED25519 -out transfer-signing.pem
openssl genpkey -algorithm RSA -pkeyopt rsa_keygen_bits:3072 -out transfer-encryption.pem
openssl pkey -in transfer-signing.pem -pubout -out transfer-signing.pub.pem
base64 < transfer-signing.pem | tr -d '\n'
base64 < transfer-encryption.pem | tr -d '\n'
```

将两个 base64 结果分别设置为 `TRANSFER_SIGNING_PRIVATE_KEY_B64`、`TRANSFER_ENCRYPTION_PRIVATE_KEY_B64`，与 `TRANSFER_SERVER_ID` 一起配置。勿将私钥或完整环境文件提交到仓库。本服的服务器 ID 和 Ed25519 签名公钥可在 `/admin/transfers` 的「本服签名身份」中查看并复制；`openssl pkey -pubout` 得到的 `transfer-signing.pub.pem` 与页面展示的是同一把公钥。目标服维护者核对后，在该页添加来源服务器 ID 和签名公钥。白名单只登记签名公钥，解密公钥随玩家凭证传递。白名单只属于目标服，默认不信任其他服。停用白名单会阻止新申请和待审申请通过。

部署时应用 `drizzle/0066_strange_the_hood.sql` 所属的常规业务迁移。每台服必须自行保留私钥备份；未结案的存档和回执依赖当时的私钥。轮换签名密钥前先结案待审申请和待处理转出，轮换解密密钥前先结案待审存档。使用 HTTPS，限制管理员账号访问。目标服结案后清除存储的加密存档正文，保留摘要、哈希和审核记录；备份中的历史正文仍需妥善保管。

## 玩家流程

1. 在目标服注册正式账号并登录 `/transfer`，申请一次性凭证。凭证有效期一小时，限制**发起导出**的时间。
2. 在原服使用该凭证导出角色并下载存档。导出后原角色冻结，且暂不可在该账号创建新角色；已导出的存档仍可在凭证过期后提交。原界系统频道随即记一笔飞升离界传闻。
3. 在目标服上传存档。服务器核验来源白名单、签名、目标账号和申请 ID、内容规则后进入待审状态。
4. 管理员在 `/admin/transfers` 查看摘要，决定通过或驳回。通过时在同一数据库事务内创建角色和资产，目标界系统频道记一笔降临此界传闻。玩家也可主动撤销待审申请。
5. 目标服玩家复制已签名的审核回执，回到原服的 `/transfer` 应用。通过回执会将原角色标记为已转出；驳回或主动撤销回执会解冻原角色，原界再记一笔折返传闻。若已导出但未提交，先在目标服提交，再撤销申请取得回执。

目标服的目标账号须没有活跃角色。一个导入申请只接受一个存档；同一来源角色只能成功转入一次。目标服与原服不需要互通 API，玩家负责传递凭证、存档和回执。

## 数据边界

跨界飞升以“撕裂虚空”为主题：转出是离开原界，转入是降临目标界。虚空会损伤角色自身修为，使原宗门六本心法分别降低 10 级，最低保留 1 级。境界、肉身、灵根命格、个人功法与槽位、宗门经脉进度仍按存档保留。宗门身份在目标服重新建立，贡献、累计贡献、职位和弟子阶位清零；声望清零。灵石最多携带 1500 万。天地灵气等短期资源重新初始化。

物品只取穿戴道装和随身背包前 8 格；`material.v1` 不携带。符箓每格最多 10 张，其余可堆叠物品每格最多 30 件，超出数量截断。只携带灵兽袋前 3 只，不携带仓库、邮件附件、拍卖行挂单或其他外部资产。目标服只接受 v2 凭证和存档，并在校验时拒绝超过 3 只灵兽的存档；预览和实际落库使用相同的心法损伤规则。活跃战斗、副本、挂单、未领取邮件附件、未结算红包会阻止导出。旧服特有或目标服不兼容的功法、宗门、物品、灵兽会被拒绝，不作静默替换。目标服保留已领取故事记录，避免重复领取对应奖励；灵田新手奖励不会重复领取。

存档以来源服 Ed25519 签名，并使用目标服 RSA-OAEP-256 与 AES-256-GCM 加密。目标服审核回执也由目标服签名。加密保护存档内容，签名证明来源服；它们不能证明来源服的游戏数据没有被其维护者改动。管理员需要根据预览决定是否接收高境界、罕见装备和灵兽。跨服差异大时应先停用白名单，再协调内容版本。
