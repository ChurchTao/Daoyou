# 永久通天塔（combat-v6）

通天塔保留角色的最高通关层数，失败不降层。与每周重置的蜃楼幻境分开，入口位于全局玩法导航。

## 玩法与数值

- 每 20 层对应一个境界，炼气至渡劫共 180 层。181 层起复用渡劫圆满守关配置，每 10 层提高敌人属性 5%，倍率上限为 5；当前技术层数上限为 100,000。
- 每层仅首通发放灵石，首领层附加奖励；每 20 层发放中聚灵符，每 50 层发放归元洗髓符，重合层数同时发放。
- 人物及出战灵兽满状态入场，采用 V6 自动指令策略推演，结果使用新版回放组件播放。不会把模拟战斗的 HP/MP 或灵兽状态写回日常角色。
- 战斗使用当前角色的宗门、道装、功法与灵兽构筑；需先加入已支持的宗门并选择新版流派。
- 九个境界分别排名：最高层降序、到达该层时间升序、角色 ID 升序。每周结算时按角色当时境界归榜，前 100 名沿用现有声望档位，通过邮件发放；榜位和最高层不清零。
- 首通奖励沿用贡献服原始规则，尚未针对 V6 的经济与养成节奏完成平衡。官方蜃楼敌人基准从金丹开始，炼气、筑基暂按人物等级比例折算金丹基准；这部分需要维护者评审。

## 实现边界

- `src/shared/lib/infiniteTower`：层数、奖励和 V6 敌人适配；敌人轮换采用固定日期配置，避免周切换改变永久关卡。随机种子按角色及层数确定。
- `InfiniteTowerApplicationService`：角色 Redis 锁、数据库事务、玩家资源事件与请求幂等回执。进度更新要求数据库当前层数恰好等于请求层数减一，奖励与进度一起提交。
- `infiniteTower/service`：服务端读取拥有的角色构筑，校验活动占用，推演并结算；客户端不提交敌人属性、战斗结果或奖励。待挑战 ID 使用独立的 Redis 命名空间和一小时 TTL。
- 符箓发放到新版统一背包，满格按现有规则进入储藏室。成功后通知背包和货币资源刷新。
- 结算回执保存本次回放，重试同一战局返回原结果。旧回执重试只清理对应战局，不删除后来创建的挑战。
- 周榜复用 `rank-rewards` 作业和每角色每周邮件幂等键，不增加调度器或改变官方调度时间。
- 本贡献为一次性自动推演模式，没有增加交互式实时战局、观战或公开战绩分享，也不恢复 V5 引擎。

## 安装与迁移

基于 `codex/combat-v6` 的 `cac2e95c`。发布前按项目部署流程备份数据库，并使用目标环境配置执行 `bunx drizzle-kit migrate`。

`0054_infinite_tower.sql` 仅新增 `wanjiedaoyou_infinite_tower_progress`、角色外键和排行榜索引；包含对应快照和迁移日志。没有重置现有角色、装备、宗门或蜃楼进度。

如果目标数据库之前已手工安装同名定制表，需先由维护者比对结构和迁移记录，不能直接重复创建。回退应用不要求删表；保留表即可保留永久进度。
