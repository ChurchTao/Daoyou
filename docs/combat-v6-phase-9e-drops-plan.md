# Phase 9E：通用掉落底座与野外接入

> 2026-09-07：实现及核心本地链路验证完成。未完成项单独列于文末。

## 已确认边界

- 掉落底座与任何业务系统无关，只处理配置与抽取；业务决定触发时机，奖励适配器决定如何发放。
- 野外胜利按场次抽取一次，与野怪数量、实际击杀数量无关；其他终局不掉落。
- 等级范围、槽位和概率由场景配置决定，不根据人物或野怪等级内置换算规则；概率不对外展示。
- 首轮材料 30%、图纸 8%、成品道装 1%、兽诀 3%，各组独立。兽诀内部普通四种各 24%、高级 4%。材料为矿石 40%、辅助 25%、妖兽 25%、天材地宝 10%。
- 青溪首版图纸、成品池配置为 10 级六槽位等权；固定材料为四种凡品。调整场景范围修改配置，不修改底座算法。配置中的装备奖励可引用 10～180 级各槽位。
- 成品沿用 v3 基础生成、固定已鉴定、无材料增益；背包不足的战斗奖励进入新储藏室。
- 不新增发奖凭据表、保底、后台、热更新、概率页面、灵石掉落或其他业务接入；战斗药品继续延期。

## 模块职责

| 模块 | 职责 |
| --- | --- |
| `src/shared/drops` | 独立配置校验、概率／权重／数量抽取，输出不透明奖励 ID |
| `src/shared/rewards/wild.ts` | 野外池与物品奖励解析，固定物品引用及随机装备生成适配 |
| `CombatV6WildSessionService` | 每场胜利触发、开战冻结池、原生哈希创建独立随机流、冻结终局物品事实 |
| `CombatV6ConditionProjector` / `InventoryService` | 沿用既有结算幂等、事务和容量规则发放 |

新池配置在开始战斗时复制进 Redis 运行态；升级部署或配置改变不影响已开场战斗。每组使用独立随机流，装备个体 ID 和生成种子也独立派生，不消费引擎 RNG。终局结果写入现有结算事实，重试发放读取已冻结事实，不再次抽取。历史配置引用的物品定义和生成版本需保持可解析。

## 库存 stack_key

- 角色持有路径仍是原统一库存；新增可空 `stack_key` 和 `(cultivator_id, location, definition_id, stack_key)` 非唯一索引。
- 固定物品键为 `definition.v1:<definitionId>`，材料展示事实来自稳定定义；独立装备键为空。
- 旧转换材料继续用 `material.v1` 保存完整实例事实。按名称、类型、品质、元素、描述顺序，以 UTF-8 字节长度前缀编码，再通过服务端 `node:crypto` SHA-256 得到 `material.v1:<hash>`。
- 前端只读取键，不计算哈希；共享纯逻辑只规范化事实并比较键。没有新增哈希依赖。描述仍区分旧材料；旧事实型与新固定材料不按同名合并。
- 迁移 `0041_inventory_stack_key.sql` 回填现有新库存行，不改变数量、格位或原始事实，不主动整理合并。旧宝库未全量迁移。
- 入库、转移、整理均复用键比较；储藏室通过索引寻找相关未满堆叠，不扫描所有材料事实。
