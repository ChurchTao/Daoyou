# combat-v6 手游数值基线治理计划

## 1. 治理目标与边界

以《梦幻西游》手游为主要参照，先建立可验证的伤害、人物五维、召唤灵五维和装备数值基线，再演变道友的宗门、功法与技能。成功标准不是“公式看起来像梦幻”，而是：同一版本、同一输入和同一战斗条件下，基线模型能解释参照样本；道友的每一项偏离都有明确原因、数值预算和回归证据。

本计划完成现状审计、资料分级、实施顺序和验收设计，尚未认定任何待核验公式为官方真值，也不代表数值实现或存档迁移已经完成。代码审计基于 2026-09-11 工作区；其中包含其他任务的未提交改动。后续实施前重新核对入口和版本。

基准产品明确为**回合制《梦幻西游》手游**，不混用电脑版、网页版、三维版、私服、特殊比赛服数据。`mhxy-combat-copy` 仅用于追溯现有实现来源，不能继续担任目标公式或正确性依据。手游的确切客户端版本、维护日期和服型在 G0 锁定；“当前手游”不能作为可复现的版本标识。

执行顺序：

```text
G0 来源与版本、等级坐标、完整数值清单
 → G1 伤害与结算基线
 → G2 人物五维及点数预算
 → G3 召唤灵五维、资质与成长
 → G4 装备、宝石及其他面板来源
 → G5 基线闭环、场景和存档迁移演练
 → G6 道友技能与特色数值微调
 → G7 统一发布与持续治理
```

G2 与 G3 同属属性层，均须先于技能平衡完成。各阶段可独立开发和验证，但不将“新伤害公式 + 旧人物/宠物/装备尺度”的中间状态单独发布给玩家。

治理期间暂停新增无依据的基础系数和用于掩盖底层问题的补偿倍率；正常功能开发可以继续，但新增数值必须进入本计划的来源与偏离记录。

## 2. 当前实现审计

### 2.1 伤害结算

实际规则为 `daoyouRulesetV6 → V5 → V4 → V3`，法术使用包含 `coeff` 的 `magicStrikeV3`。不能把文件中保留的旧 `magicStrike` 或历史导出 `baseDamage` 当作当前全部规则。见 [规则入口](../src/shared/engine/combat-v6/rules-daoyou/index.ts)、[公式](../src/shared/engine/combat-v6/rules-daoyou/formulas.ts)。

| 领域 | 当前实际行为 | 治理要求 |
| --- | --- | --- |
| 物理基础 | 破防时 `1.3 × (攻击−防御)`；防御达到攻击 90% 后为 `0.13 × 攻击`，至少 1 | 重新核验手游普通攻击、技能攻击与保底分段，不能默认继承电脑版简化值 |
| 修炼（物理示式） | `(基础值 × 技能倍率 + 附加值) × (1+0.02Δ) + 5Δ`；有效差夹在 ±20 | 验证手游修炼轨道、等级上限、正负差、百分比与固定值、结算位置 |
| 法术 | `(法攻−法防+师门项+power) × coeff × 分灵` 后套修炼 | 拆分人物法术、宠物单法/群法、特殊法术；确认技能等级项和倍率作用位置 |
| 暴击与狂暴 | 物法暴击共用 ×2；物理狂暴先将攻击乘 1.5，可叠加 | 分别核验人物与宠物、物暴与法暴；定义与被动技能的关系 |
| 随机波动 | 物理 0.9～1.1、法术 0.95～1.05；`rng.range` 连续取样 | 验证范围、分布、是否离散档位；只核对上下限不够 |
| 命中 | 物理 `clamp(0.2,1,0.5+(hit−dodge)/200)`；法术默认必中特判 | 核验手游是否需要常驻 hit/dodge 面板，以及普通攻击与技能攻击差异 |
| 固伤 | fixed/judge 公式直接取 power；真正 fixedHit 不套修炼、暴击、波动和普通状态受伤倍率 | 不能以“固伤”名称推定所有具体技能相同；逐项核验技能表达式、减免和护盾 |
| 后处理 | 暴击 → 波动 → 防御指令 → 状态受伤倍率 → OnHitCalc → 分流/护盾 → HP | 明确增伤、防御、护盾、保护、反伤、溅射、持续伤害的顺序与取整位置 |

公式至少有“攻击面板、忽视防御、技能系数、伤害结果系数、固定结果加成”五种语义，不应继续混用一个 `coeff` 或 `power` 表达所有效果。例如 `A×c−D` 与 `(A−D)×c` 在高防御下行为不同，不能通过调一个倍率互相替代。

`core/damage.ts` 当前对保护、固定公式族和伤害种类也有独立处理。审计需覆盖“原始目标/保护者的属性取值”以及“formula=fixed、kind=spell”这类组合，不能只替换公式函数而认为整个结算已对齐。这里列为验证项，不在本计划直接改行为。

### 2.2 人物：六维与点数预算都不是手游基线

当前 [人物裸身面板](../src/shared/engine/combat-v6/projection/character-panel-v1.ts)：

```text
物攻 = floor(40 + 力道×3.5)
法攻 = floor(40 + 灵力×3.5)
物防 = floor(10 + 体魄×1.75)
法防 = floor(10 + 神识×1.75)
气血 = floor(400 + 气血属性×20 + 体魄×3)
法力 = floor(200 + 灵力×4 + 神识×10)
速度 = floor(身法)
命中 = floor(80 + 身法)，闪避 = floor(身法)
治疗 = floor(气血属性×0.25 + 神识)
封印命中 = floor(灵力×0.5)，封印抵抗 = floor(神识×0.5)
物暴/法暴基础概率均为 5%
```

存储键为 `vitality/strength/spirit/endurance/speed/willpower`，人物仍有六维；召唤灵已经是五维，但使用另一套公式。当前增加 10 点力量产生 35 物攻，增加 10 点气血属性产生 200 最大气血。这与已找到的手游历史资料所述 10 物攻、80 气血明显不同，但资料尚不能代替目标版本的正式验收。[^1][^4]

更根本的是**每级可用点数也不同**：[境界成长](../src/shared/config/realmProgression.ts) 每维初始 10，小阶段每维自然 +2、自由点 +10，跨大境界每维自然 +4、自由点 +20；[人物战斗等级](../src/shared/engine/combat-v6/projection/character-level.ts) 却按 `(境界阶段序号+1)×5` 映射。仅把 3.5 改成 1 会降低面板，却没有复刻手游同等级的属性预算。

必须一起核对：出生属性、自然成长、自由点、额外永久点、重置规则、境界奖励、等级映射。禁止用装备或技能去补偿点数预算的错误。

### 2.3 召唤灵：现有资质和成长的作用方式需重建

[宠物投影](../src/shared/engine/combat-v6/beasts/projection.ts) 对五维先生成 `10 + 等级 + 已分配点`，再使用统一函数：

```text
贡献 = floor(属性值 × 成长 × 对应资质 / 1000 × 系数)
```

当前气血系数 8、法力 3、物攻/法攻 2、物防 1.5、速度 1.5；法防把耐力与半数魔力相加后乘防御资质和成长。见 [成长配置](../src/shared/engine/combat-v6/beasts/data/progression.json)。

这意味着现有系统中每增加一点力量的物攻收益同时依赖攻资和成长。手游历史资料候选式则把“等级×资质项”和“加点×成长项”分开，结构上就不同。[^2] 不能只替换系数 2。

其他影响项：

- 自由点总数校验为 `level×5`，五维自然底数均为 10；没有独立出生五维分布事实。
- 五种资质当前共用 900～1100 的生成范围，偏好资质另加 100；成长 0.95～1.05。物种只选择偏好和职业，并非每物种、每资质独立范围。[物种生成配置](../src/shared/engine/combat-v6/beasts/data/species.json)
- `BeastSchema` 对成长、资质的通用数值边界较宽；需补充与物种、来源、目标版本一致的有效范围。[个体模型](../src/shared/engine/combat-v6/beasts/schema.ts)
- 投影从 `DEFAULT_ATTRS` 开始，没有从主人修炼映射宠物修炼；手游宠修/人物修炼关系须独立核验，不能静默套用主人修炼。
- 可携带、可出战等级受角色等级约束。新的等级坐标必须同步检查捕获、升级、首发、替换和野外投影。

### 2.4 装备：部位语义、区间和生成分布均需对齐

当前 [器胚配置](../src/shared/engine/combat-v6/equipment/data/equipment-base.json) 为“等级×系数”并均匀抽整数；六部位都可抽 0～2 条六维附加值，概率 50%/40%/10%，单条范围为等级×0.08～0.14，偏好属性权重 2。它们均是现有自定义规则，不是已验证的手游概率。

| 60 级部位 | 当前器胚范围 | 可访问的手游历史表例（普通打造） | 状态 |
| --- | --- | --- | --- |
| 武器 | 物攻 33～51、法攻 15～27、命中 24～42 | 物伤 350～450、法伤 78～100、治疗 90～162 | 量级与第三属性语义均不同 |
| 头部 | 物防 7～10、法力 120～180 | 物防 52～67、法力 350～450 | 量级不同 |
| 衣服 | 物防 15～21、法防 15～21 | 气血 280～360、物防 87～112 | 部位属性不同 |
| 项链 | 法攻 15～27、法防 15～21 | 法伤 95～123、法防 52～67 | 量级不同 |
| 鞋子 | 速度 18～30、闪避 15～24、物防 3～6 | 表中为法防、速度，速度 40～72 | 部位属性不同 |

右列来自 2015 年第三方原文及图片，不是当前官方目标表；只用于证明现有尺度需要系统重建。[^3] 图片受遮挡的格子没有补猜，也不据此写入装备定义。

还有三个联动点：

1. [现有强化铸造](../src/shared/engine/combat-v6/equipment/forging.ts) 是概率二次抽样取较高值，仍在原区间内；这不等于手游“普通打造/强化打造不同区间”。不能只改名称。
2. 现有阵纹为单条 `formationInscription`，含物法攻每级 +6、防御 +4、气血 +80 等自定义值。需核验手游宝石类型、收益、允许部位、孔数、等级上限，再决定阵纹如何承接。
3. [装备校验](../src/shared/engine/combat-v6/equipment/compiler.ts) 使用当前模板计算合法范围；直接改模板会使已存旧装备在读取时变成非法。生成器版本本身不等于完整的旧区间解释能力。

### 2.5 隐藏在其他层的数值来源

当前完整入口 [projectCharacterToCombatV6](../src/shared/engine/combat-v6/projection/project-character.ts) 经个人功法装配、道装、炼体、可选宗门共同形成面板。个人功法既可加基础属性，也可追加面板；门派心法和经脉也有面板与事件钩子。只核对裸身与装备会漏算它们。

| 必审来源 | 当前入口 | 必须交付的核对结果 |
| --- | --- | --- |
| 炼体四修炼与生命根基 | `projection/body-cultivation-v6.ts`、`shared/lib/bodyCultivation/benefits.ts` | 手游修炼映射、等级限制、气血与治疗额外预算；明确“裸身气血”是否包含功法/装备五维 |
| 个人功法 | `projection/compose-character-manuals.ts`、`manuals/compiler.ts` | 五维、面板、百分比与钩子分账，不重复放大 |
| 门派心法 | `content/data/methods.json`、`content/compiler.ts` | 永久面板增益先于主动技能平衡对齐；不能把门派固有面板全部塞进技能 power |
| 经脉、器蕴、器诀、兽诀 | `content/data/*paths.json`、`equipment/special-*`、`beasts/skill-compiler.ts` | 属性加成、结果加成、忽防、连击、追击、暴击的语义与叠加顺序 |
| PVE 对手 | `encounter/compiler.ts`、`wild`、`tower`、`dungeon`、`sect`、`breakthrough` | 训练现有 60/120/180 档及其他 NPC/BOSS 跟随新尺度重建，禁止只重算玩家 |
| 自动战斗 | `shared/combat-v6/auto*.ts` | 输入观测、治疗阈值、技能选择对新数值的敏感性；比较时固定策略 |
| 展示与结算 | 人物面板、装备比较、灵兽面板、技能详情、Condition、回放 | 同一构筑同一语义；显示值、运行时值与资源上限一致 |

`realmProgression.ts` 还保留境界伤害/效果压制函数，但此次搜索只发现定义和测试，未发现当前 v6 伤害调用。不能把“文件里存在”写成“战斗中生效”，也不在本轮顺手清理。

## 3. 证据治理：官方事实、实测模型和自定义值分开

### 3.1 来源等级

| 等级 | 定义 | 可支持的结论 |
| --- | --- | --- |
| A | 对应版本的官方规则、更新公告、游戏内说明，原文已核验 | 只确认原文明确说明的机制或数值；不推导未披露的隐藏公式 |
| B | 有完整输入、条件和原始输出的独立实测，可复核 | 已验证条件内的经验模型；仍不称为官方公布公式 |
| C | 攻略/转载/工具推导，缺少完整原始样本或存在精度疑问 | 候选公式和调查线索，不能直接成为生产真值 |
| D | 项目当前实现、设计稿、参考复刻仓库 | 现状或道友自定义值，不用于证明梦幻正确性 |
| U | 原文不可访问、仅搜索摘要、版本不明、来源冲突 | 待核验，不得自动晋级 |

“发布在官网”与“官方公开规则”分开判断：官网上的玩家攻略仍可能是经验推导。多个转载站复制同一篇内容不算多个独立证据。搜索引擎 AI 汇总不进入公式证据库。

每项记录最少包含：`ruleId`、产品/服型/客户端版本、适用人物或宠物、场景、公式与变量单位、执行顺序、取整、上下限、来源标题/作者/日期/URL、核验状态、样本引用、冲突说明、采用或偏离决定。记录随代码评审一起更新，不搭建新的数值管理平台。

### 3.2 已发现的候选与冲突

| 规则 | 已见资料 | 当前判定与动作 |
| --- | --- | --- |
| 人物力量 | 2015 年正文：1 力量→1 物伤、0.6 法防、0.2 速度 [^1] | C；可用于准备候选矩阵，待目标版本确认 |
| 人物体质/魔力/敏捷 | 1 体质→8 HP、0.4 法防、0.2 速度；1 魔力→5 MP、1 法伤、1 法防；1 敏捷→1.5 速度 [^1] | C；需要出生常数和自然成长后才能算完整面板 |
| 人物耐力 | 封测文章正文为 2.4 物防、0.2 法防、0.2 速度 [^1]；2017 官网文章搜索摘要为 2.2 物防、0.2 法防、0.2 速度 [^4] | 冲突；不能按发布时间直接认定更正，更不能平均取 2.3 |
| 物理随机 | 2016 实测文章称 95%～105%、11 档 [^5]；当前引擎为 90%～110%连续值 | C/历史实测线索；复核原始样本、目标版本和取整再定 |
| 普攻系数 | 搜索结果同时出现“×1.2”和“攻击−防御、并非×1.2” [^6] | U；当前 ×1.3 无手游依据，1/1.2/1.3 均不能直接拍板 |
| 宠物属性 | 历史正文采用“等级×资质项 + 五维×成长项” [^2] | C；结构可调查，常数待核验 |
| 宠物法防/精度 | [^2] 公式写有 `力量属性点+成长*0.48`，表内物攻系数、速度差值又与正文不一致 | 原样登记冲突，禁止默默改成自己认为正确的式子 |
| 装备普通/强化 | 历史 60 级武器物伤 350～450 / 385～495 [^3] | C；独立区间明确可见，是否适用于目标版本仍待确认 |
| 修炼固定 +5、差值 ±20、暴击统一 ×2 | 当前 D 级实现 | 缺少合格手游证据，列入 G1 的必决项 |

当前没有一套经过完整原文核验且覆盖目标版本的 A 级伤害/人物/宠物/装备基线。以上数字只能支撑审计和试验设计，不能作为本轮“已对齐官方”的声明。

### 3.3 怎样解决冲突

先排除产品与版本混淆，再检查是否混入装备、宝石、修炼、门派被动、变身、阵法、内丹、坐骑、经脉等条件。然后将不同候选模型在同一批样本上比较，选择能被独立样本支持的模型，不以“攻略流传最广”表决。

对官方未公开项，采用可复核的 B 级经验模型是允许的，但必须标为“手游实测基线”，记录适用范围和残差。尚无法区分的模型保持 U 状态；不得用下游技能倍率把差异拟合掉。

## 4. 目标数值结构

### 4.1 统一五维语义

建议人物与召唤灵共享五维概念：体质、魔力、力量、耐力、敏捷；保留修仙展示名称时必须提供明确映射。人物与宠物共享概念，不共享面板转换系数。

| 概念 | 当前人物字段 | 当前宠物字段 | 建议处置 |
| --- | --- | --- | --- |
| 体质 | vitality | constitution | 对齐语义与预算 |
| 魔力 | spirit | magic | 对齐语义，不与“法术伤害面板”混称 |
| 力量 | strength | strength | 对齐语义与预算 |
| 耐力 | endurance | endurance | 按目标版本核验交叉收益 |
| 敏捷 | speed | agility | 基础敏捷与派生速度区分，是否改存储键由 G2 决定 |
| 第六维 | willpower | 无 | 退出基础战斗五维，不再通过隐藏第六维保留旧法防预算 |

推荐最终持久领域收敛为五维，而非长期保留“六维存储 + 临时五维投影”双重权威。神识若保留为叙事或后续独立养成，须另列非五维设计，不能在基线阶段继续暗加法防、治疗或封抗。

这是拟实施的领域迁移；现有 `AGENTS.md` 与技能中的“永久六维”约束在 G2 同步更新。本轮不提前更改它们，不先删数据库列。

### 4.2 基础面板是矩阵，不是几条孤立公式

人物目标表达为：

```text
裸身面板 = 对应等级/版本的基础项 + 五维收益矩阵 × 总五维
总五维 = 初始点 + 自然成长 + 已分配点 + 允许的永久额外点
```

再按已验证顺序加入装备五维、装备白字、宝石、门派永久面板和其他允许来源。总五维是否已经包含自然点必须明确；不能同时在“等级基础项”和“总五维”里重复加入同一笔自然成长。

人物五维矩阵须记录完整七项基础输出：HP、MP、物伤、法伤、物防、法防、速度。命中/闪避、治疗、封印、暴击属于另行核验的派生或特殊属性，不能为填满现有字段继续沿用没有来源的常数。

召唤灵每项面板单独定义等级项、资质项、成长项和五维交叉项。候选结构可写成：

```text
宠物面板[j] = 等级/资质函数[j](L, Q)
             + 五维/成长函数[j](五维, G)
             + 已明确的其他来源[j]
```

只有来源支持时才采用这个分解；不强迫所有面板套同一通用乘积。出生点、洗练、资质成长上限、宠修是独立事实，不能用“提高全体宠物 coeff”代偿。

### 4.3 等级坐标先锁定

G0/G2 必须输出“道友境界阶段 → 基线战斗等级 → 人物点数 → 心法等级上限 → 装备档位 → 宠物等级/携带上限 → 修炼上限”完整表。

推荐先在手游有可核验资料的等级范围内建立基线，以 60/69、80/89、100/109 附近作为取样候选点，再按选定版本调整。这里是采样建议，不宣称所有档位都是同一种官方分组。

道友现有 5～180 等级不能直接视为手游 5～180。超过可靠参考覆盖范围的成长先标为“扩展待定”；不能外推一条直线后写成官方数值。选择压缩映射或后续自定义扩展时，须一并评估心法、装备、宠物、NPC 和资源成本。

### 4.4 参考基线与道友特色分层

保留纯参考输入和样本用于验证，线上仍只有一条当前公式与投影权威；不新增多游戏、多版本动态规则平台。只有确实存在不同结算语义时才增加公式族，不给每个宗门复制整套公式。

基线样本明确关闭未覆盖的道友功法、五行反应、额外资源和器蕴。能找到手游对应物的机制按对应规则核验；没有对应物的先隔离为特色预算。校准完成后逐项重新加入，记录相对基线的增量。

“关闭特色”是基线验证条件，不是本轮删除游戏内容或线上清空玩家资产。

## 5. 分阶段实施与验收

### G0：证据台账与基准冻结

**输出：** 一份带状态的规则/来源台账、一个锁定的手游版本说明、现有数值来源清单、等级坐标草案、独立样本格式。

任务：

1. 优先补齐官方系统规则、维护公告、游戏内属性说明和装备打造预览；原文不可核验的条目标记 U。
2. 将伤害、五维、资质/成长、装备、宝石、修炼、门派永久属性逐项编号；每个值都有来源或“道友自定义”标识。
3. 对已发现冲突建立候选列表，保留原式与上下文；记录来源版本是否一致。
4. 明确哪些手游系统包含在首个基线：基础面板、普通/技能伤害、必要修炼与门派固有属性；法宝、器灵、坐骑、内丹等未纳入项要从参照样本中剥离，不能拿满配实战面板对裸模型。
5. 冻结旧实现样本，用于迁移差异分析；旧样本不是官方正确性黄金值。

**退出门槛：** 关键规则没有“来源不明却已确定”的数值；G1～G4 每个必需项都有 A/B 依据或明确的补证任务。某域的关键系数仍 U 时，该域不能进入生产切换；其他已具备证据的域可以继续独立研究和实现。

### G1：伤害公式和结算顺序

**输出：** 伤害规格、冲突裁定、参考样本、纯共享逻辑测试及当前规则实现。

覆盖：人物/宠物普通攻击、物理技能、单体/群体法术、固伤、持续伤害、治疗与护盾交互；修炼正负差、忽防、防御指令、物法暴击、保护、连击/反击/反伤、随机与取整。

先以外部给定的面板作为输入，避免人物或装备投影误差污染伤害验证。只实现用于对照的最小参考技能；道友五宗门倍率最终调整留到 G6。

必须比较 `A×c−D`、`(A−D)×c`、附加值位于修炼前后等候选；若官方技能语义要求不同，分别表达，不用统一放大最终 damage 凑样本。

**退出门槛：** 确定性样本逐项符合已确认的精确值/取整区间；随机样本的范围和分布符合证据，且能区分主要候选模型。不能仅以平均伤害接近作为通过。

### G2：人物五维与成长预算

**输出：** 五维领域与收益矩阵、等级点数表、六转五迁移规格、完整人物投影与展示改造。

任务：

1. 先核验出生常数、每级自然点和自由点，再确定矩阵；保留小数精度直到规范指定的取整阶段。
2. 角色创建、突破、分配、洗点、丹药和永久奖励共用同一预算权威，禁止每个服务各算一份。
3. 明确处理 willpower：拆分原自然点、玩家分配点和来源可识别的额外点；推荐按新总预算重新分配，保留可审计的旧事实，避免把整列直接加给魔力导致双重自然成长。
4. 同步 Zod/DTO、数据库读写、人物面板、加点 UI、功法/装备五维引用、技能表达式、测试夹具和项目约束。
5. 出生属性不是零基人物加点；面板特性不是可再次分配的基础点；迁移不得混淆。

**退出门槛：** 五种方向的逐点收益、混合加点、升级预算均通过独立样本；新建、突破、洗点、换装后预算守恒；人物详情、战斗入口、装备预览给出一致面板。

### G3：召唤灵五维、资质与成长

**输出：** 七项面板公式、物种资质/成长范围、出生与升级预算、个体迁移规格、宠修口径。

任务：

1. 分别固定等级/资质/成长/五维，仅改变其中一项，核对各项边际收益。
2. 宠物速度公式独立验证，不继承电脑版“只乘速度资质”的结论，也不直接继承当前统一乘积。
3. 将每物种、每资质及成长范围区分；普通、变异、神兽等若未来包含须独立建档，首期可只覆盖普通召唤灵，不为尚未计划的品类铺实现。
4. 记录出生五维、自然成长和可分配点；是否需要出生随机分布必须由手游事实和产品范围决定。
5. 兽诀改变面板还是伤害结果逐一分类；先验证无技能个体，再验证技能叠加。
6. 校准新生/捕获/升级/洗点/召唤投影，明确宠修来源；不让玩家宠物与野外同物种共享了名称却使用不明倍率。

**退出门槛：** 攻宠、法宠、血耐宠、敏宠在多等级/资质/成长下均能解释独立样本；个体预算守恒，升级前后可追溯，物种合法性检查覆盖生成和读取。

### G4：装备与其余面板来源

**输出：** 按等级×部位×打造类型的区间表、属性槽规则、宝石映射、概率声明、生成/校验同源规则、旧物品迁移规格。

任务：

1. 武器、头部、衣服、项链、腰带、鞋子分别核验；先对齐属性种类，再对齐数值上下限。
2. 普通/强化、专属、熔炼、宝石、器灵、临时符等分开；不能把加工后的展示值抄成初始白字区间。首期未纳入的加工层明确排除。
3. 核验五维附加的可出现部位、单加/双加、负属性、总和限制和互斥条件；不默认六个部位均可双加。
4. 区间和分布分开：官方区间已知不代表均匀分布、双加概率或特技概率已知。未知概率标为“道友暂定分布”，不能写“官方掉率”。
5. 阵纹/宝石按收益、部位、孔数、等级上限校准；门派永久面板和生命根基在同一预算账中核对。治疗强度不能仅靠当前人物神识公式承担。
6. 生成器、附加材料效果、实例解析、比较展示、掉落、铸造、交易、邮件等物品生产与读取口径一致。

**退出门槛：** 目标范围内每个装备档位/部位有来源；上下界和非法组合均有确定性校验；同一物品生成后可加载、穿脱、比较、转移，不会因新模板拒绝旧实例。

### G5：参考闭环与迁移演练

**输出：** 人物/宠物/装备组合样本、完整回合结果对照、NPC 重标定表、迁移报告与发布清单。

先组合一个可解释的参照构筑：等级、五维、装备、宝石、门派永久属性、修炼均可独立还原。每项面板输出来源分解，再进入 G1 公式。确认没有“面板少了 20%，技能多乘 25%”之类互相抵消。

比较同等级同投入的攻、法、血耐、辅助、速度方案；分别看人物对人物、人物对宠物、宠物对人物和宠物对宠物。PVE 单独查看普通遭遇与精英/BOSS，不把玩家公式强行宣称为官方怪物生成公式。

训练、野外、秘境、塔、宗门任务、突破、竞技场与排名都接同一新规则/投影。NPC 从新基线角色原型和明确场景预算生成或配置；仍需手工配置的 BOSS 必须标出倍率和目的。

**退出门槛：** 参考组合闭环通过，所有正式入口使用同一已锁定数值基线；迁移的异常存档有明确处置，无静默丢字段、重置资产或半完成状态。

### G6：最后调整道友技能和特色

**输出：** 每个技能的参照机制、偏离说明、修改前后预算、可复现交互样本。

调整顺序为：普通攻击标尺 → 单体技能 → 群体技能 → 多段/追击 → 固伤 → 治疗/护盾 → 控制 → 经脉/功法/五行反应组合。伤害公式族与技能数值分开评审。

每个技能同时记录：目标数、主副目标差异、段数、命中/暴击资格、基础系数、等级项、忽防、施法资源、气血门槛、休息回合、冷却、失败风险、附带控制/治疗，以及持续时间。不能只比较一回合总伤。

以“造成相当于多少次普通攻击的收益、为此占用多少行动、付出多少资源、承受多少风险”为主要比较口径。首轮保留参照基线能解释的倍率，仅对特色增量进行小步调整；调整幅度由样本和预算决定，不预先规定统一增减 10%。

**退出门槛：** 每个改动说明解决哪个已观察问题；同一批固定输入和策略可复现前后差异；优势来自明确机制/代价，不是遗漏减伤、重复加成或面板来源不对称。

### G7：统一发布与后续变更制度

**输出：** 同步的规则/投影/内容/生成器版本、迁移执行与恢复方案、验收记录、偏离登记。

在 G5 完成基线闭环、G6 完成特色校准后统一切换。后续任何基础公式改动都需要重新验证下游矩阵；任何技能微调都不得反向偷偷改变基础面板。

## 6. 样本与测试方法

### 6.1 三类样本分开保存

1. **当前实现样本：** 记录旧版本资产和面板，用于回归、迁移及差异解释；不证明官方正确性。
2. **外部参考样本：** 官方明确数值或可复核的游戏实测；包含完整输入、输出、版本和来源，用于决定期望值。
3. **道友特色样本：** 基线加一个可识别的特色因素，记录增量与代价，用于平衡与防止漂移。

所有纯确定性样本与测试留在 `src/shared`，沿用 Vitest；不新增独立 smoke/e2e/seed/benchmark 脚本，不把数据库或第三方服务写进单测。新测试路径只按已实现域建立，不预先搭建空框架。

### 6.2 最小验证矩阵

| 层 | 必要变化维度 | 核对输出 |
| --- | --- | --- |
| 伤害 | 相同修炼、正差、负差；低防、接近破防、高防；普通/技能；人物/宠物 | 基础伤害、保底、忽防作用、修炼与固定项位置、取整 |
| 随机/暴击 | 非暴击与暴击分组；多个种子；有/无防御与状态 | 支持集、分布、暴击倍率、顺序，不仅平均数 |
| 人物 | 每维分别 +1/+10；纯加与混加；多个等级；有/无门派与装备 | 收益矩阵、基础常数、点数守恒、来源分解 |
| 宠物 | 固定其他项，仅变 L/Q/G/单维；不同物种、加点与技能 | 资质和成长的独立边际、交叉项、取整、预算 |
| 装备 | 各部位/档位的最小、最大、非法值；普通/强化；附加属性组合 | 生成范围、合法性、叠加位置、实例可读取性 |
| 闭环 | 等级档、装备投入、修炼、职业、宠物角色、目标防御 | 完整面板与伤害链，持续输出、治疗覆盖、击杀回合 |

独立实测不要只保存最终平均伤害：记录每次命中值、是否暴击、双方属性、技能等级、目标数、增减益和随机条件。对未公开常数用一组样本拟合，另一组不同输入作留出验证，防止过拟合。

精确公开值按原规则精确匹配；只有已确认显示取整时才允许对应的整数误差区间，不能统一放宽 5%。随机模型按候选差异和实测方差决定样本量，记录置信区间、残差与停止条件；样本无法区分模型时继续标记不确定，不默认现有实现正确。

### 6.3 完整战斗指标

只看胜率不足以定位数值错误。至少报告：面板来源占比、每行动伤害/治疗、目标气血损失比例、击杀所需行动、爆发与持续输出、MP/HP 消耗、保护/护盾吸收、控制占用、先手概率，以及人物/宠物贡献。

固定阵容、策略和种子后比较版本；不要同时改自动策略和技能再归因于倍率。竞技场不是要求全部职业恰好 50% 胜率；对等投入和有意克制应分别解释。回合数、胜率和预算容差在参考样本可用后锁定，不能从当前失衡结果反推目标。

## 7. 存档与运行时治理

实施遵循 [战斗数据领域归属](combat-domain-ownership.md) 和 [测试规范](testing.md)。本计划不恢复旧 build/profile 父表，不让装备、功法、宠物依赖宗门归属，也不持久化运行时战斗投影。

### 7.1 六维转五维

只读盘点角色自然底数、已分配点、未分配点、额外永久奖励以及引用 willpower 的装备/功法/表达式。来源不可拆分的存档单列异常，不能假定全是自由点。优先制定一次性重新分配方案，用新等级总预算确定可用点，再明确额外永久奖励的承接方式。

需在 G2/G5 形成可审阅的迁移映射与影响统计，才执行写迁移。不得默认清空角色，也不把旧 willpower 数值直接全部退款而重复发放自然点。是否免费重置、如何折算不可追溯投入是迁移前的产品决策。

### 7.2 已生成装备与宠物

建议先保留旧实例 ID、归属、装配关系和原始数值快照，再一次性迁移到新合法模型。装备可研究按旧区间位置映射新区间，以保留相对品质；但这属于资产转换建议，不是官方概率，更不保证价格或战斗价值不变。单一值区间、被强化重抽的值、属性种类变化、取消的槽位都需单独处理。

宠物保留身份、技能与培养记录，成长/资质可研究按原区间位置映射，但不同资质的权重改变会影响价值；需逐类报告。缺少出生点事实时不能伪造“原本出生分配”，应明确记录迁移生成的新事实及确定性规则。

生成器、schema、内容修订与存档解释同时切换。是否保留短期迁移读取工具由实际需要决定；线上不长期双写或维持两套不明语义的资产。只回滚代码不足以恢复已转换资产，恢复方案必须包含原始事实备份和迁移后新增写入的处理边界。

### 7.3 进行中的战斗、资源与回放

- 发布前停止新开战并排空活动会话及结算 outbox，或明确终止/补偿策略；不能用新公式继续恢复旧数值的中途战斗。
- 若确有旧会话继续运行需求，必须能按快照锁定对应规则、内容和 RNG；一个文本版本戳不等于已经具备旧版本执行器。优先排空，避免为一次切换扩建长期多版本运行平台。
- 历史回放继续使用开战快照和已记录事件，不用新公式重算旧战报；已有排名和赛季比较需重建或标注版本边界。
- HP/MP 上限变化时明确保留绝对值、比例或统一恢复哪一种；不得意外把存活角色变成 0 HP，或通过反复迁移免费恢复资源。Condition、秘境连续战、伤势、治疗上限共同检查。
- 部署单元包含代码、静态内容和持久模型；清理/失效对应展示缓存与快照。读写遵循角色锁、事务和现有各域 revision。

## 9. 持续防漂移制度

每次数值变更必须回答六件事：依据是什么、改的是哪一层、修复什么现象、影响哪些角色/装备/宠物、独立样本如何变化、是否影响旧存档。缺少其中关键项不合并数值改动。

规则与数据继续放在已有共享域配置/纯函数，按需收敛常量；无需建立大而全的通用平衡引擎。参考公式与道友偏离记录分开保存；新的偏离只写增量和理由，不覆盖原参考证据。

CI 后续增加与本治理直接相关的 lint、构建和共享测试质量门槛；目前不能依赖仅构建推镜像的流程证明数值正确。公式/矩阵测试证明规则，外部样本证明参考对齐，组合测试证明系统闭环，三者不能互相替代。

所有影响伤害、五维转换、点数预算、装备范围的改动，触发 G5 代表构筑复验。技能微调只扩大到受影响的组合；出现新的跨层误差再扩大覆盖，不以盲目重复全量测试替代定位。
