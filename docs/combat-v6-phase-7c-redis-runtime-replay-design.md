# combat-v6 Phase 7C：Redis权威运行时与回放归档

## 目标

Phase 7C 将练功房从进程内会话迁移到 Redis。可继续推进的战局只存在 Redis，创建后最多存活两小时；PostgreSQL 只归档规则正常结束的自包含 v6 回放。

## 元信息与解耦

训练战斗使用 `combat_v6_battle_metadata_v1`：来源为 `training-room`，战斗类型为 `training`，并携带服务端签发的业务幂等键、遭遇 ID 和档位。客户端不能提供元信息。终局统一发布 `combat.v6.battle.finished`，战斗层不读取任务 ID、不判断任务完成、不发奖励，也不回写人物 condition。

事件 ID 用于消息投递消费幂等；元信息幂等键用于来源业务关联。未来任务、地牢或活动通过增加新的元信息判别成员接入，而不是修改战斗内核。

## 生命周期

- 运行快照保存投影输入、战局、RNG、指令、回合和事件，服务重启后可恢复。
- 指令提交和回合推进使用 Redis revision CAS；失败计算不会污染权威状态。
- 同一角色最多一场 v6 战斗，截止时间固定为创建后两小时，访问不续期。
- 正常终局保留到玩家显式结束或截止时间；过期、放弃和宗门失效均发布终局事件，但不归档回放。
- 不可变终局 Outbox 与运行态分离，最多保留24小时。JetStream 只发送 battle ID；终局详情保留至 TTL，回放载荷在归档消费者确认后删除。

## 回放

v6 回放独立于 battle-v5，包含元信息、版本、seed、初始单位、技能和状态定义、逐回合锁定指令、完整事件、最终状态与结果。完整载荷保留在 Redis，独立 WorkQueue 只发送 battle ID；归档消费者按 ID 读取后幂等写入 `wanjiedaoyou_combat_v6_replay_archives`。

本阶段只提供本人按 battle ID 读取回放的 API，不提供列表、分享或播放器。

## 后续边界

Phase 7D 才引入普通 PVE、Condition 消费者和任务中心消费者。正常结算允许战后 HP/MP 高于入场值，只按真实最大值夹取；任务完成判断始终由任务系统独立消费终局事件完成。
