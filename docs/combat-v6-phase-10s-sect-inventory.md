2026-09-10 用户确认实施，主体实现与重点本地运行验收完成。未覆盖的维护实际应用、故障与跨期矩阵见末节。

## 确认边界

- 材料、丹药、道装交付只消耗 bag；storage 与历史宝库须先取出。材料可选多个符合条件的堆叠，一次交齐。
- 道装交付要求一件指定新版部位、达到指定装备等级、未装备的道装；无品质、完美词条、特技、特效或附灵门槛。
- 需求按领取时角色境界阶段对应的 V6 等级，在正式开放的产出档位中向下取档，最低10级。现有青溪掉落仅10级，因此当前委托也封顶10级；不把已定义但尚未开放产出的高阶图纸视为可获取。复用青溪掉落等级配置，未来内容开放后同步变化。道装难度为≤40级简单、≤80级普通、≤120级困难、其余精英，沿用原奖励框架。
- 保留材料、丹药真实品质及其他条件，保留领取权限、次数、周期、贡献价格与限购。交付沿用当前立即结算奖励语义。
- 兑换已有新版定义的商品直接入 bag、溢出 storage；不支持的商品拒绝兑换，不回退旧表。扣贡献、限购与入库同事务。
- 交付复用完整公共物品栏；桌面左要求及选择、右五列40格背包，窄屏抽屉。
- 校验持有者、位置、revision、数量、装备与任务状态；沿用持久幂等。新库存不发布旧列表增删事件。

## 维护期

## 实现说明

- 新交付要求使用 equipment 与新版六部位；原任务 ID artifact_delivery、权限键和完成次数沿用，避免改变任务记账身份。其运行执行器与要求均已改名为 equipment，无旧法宝执行分支。历史交付快照中的 artifact 只作存档展示。
- 删除旧交付分页协议和旧物品选择器；背包最多40格，候选按真实物品事实判断。普通材料与固定掉落材料均通过 materialFactsOf 读取，丹药使用 spec，装备使用 V6 实例及装配表。
- 交付在现有玩家命令事务中通过 saveInventoryPlan 扣物，材料多堆任一失败整笔回滚。沿用现有任务完成与立即领奖语义，三类交付均校验 revision。
- 商店复用新奖励物品事实转换，但不创建邮件，直接 grantInventory；不支持新版定义的商品拒绝兑换。采矿任务材料奖励也停止写旧材料表。
- 交付和兑换保留失败请求的幂等键；成功后才清除。新版库存不再发布旧库存列表 upsert/remove，交付响应提供新版物品剩余数量；兑换响应提供 bag/storage 实际去向。
- 未改表结构、未增加运行时迁移框架。所有代码编辑使用内置 apply_patch，未使用 Python 改写文件。

## 维护操作

在选定环境、停机并备份后执行。环境文件需显式指定，以下仅以本地为例：

```bash
bun --env-file=env/local.env scripts/retire-sect-artifact-deliveries.ts --dry-run
bun --env-file=env/local.env scripts/retire-sect-artifact-deliveries.ts --apply <已核对的记录UUID> ...
```

应用前保留盘点输出；工具只处理指定 ID 且仍带旧 artifact 要求的记录。active 改为 abandoned，非 abandoned 记录计数因而释放；其他状态不变。移除全部旧法宝要求并更新执行器名，奖励快照和交付历史不变。重复执行不会再命中已处理记录。全部处理后再次无参数盘点，应为0，再启动新版。旧拍卖货单仍由用户用旧版本下架返还，不在此工具内处理。

本轮仅在本地执行 dry-run，结果0条；没有执行 --apply，也没有操作预发布或生产。
