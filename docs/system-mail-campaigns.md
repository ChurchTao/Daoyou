# 系统邮件按条件投递

后台发布一次邮件元信息；玩家进入游戏、在线心跳或打开邮箱时，通过事务消息与 NATS JetStream 检查投递资格。发布不扫描全服、不预创建个人邮件，也不提供 dry-run 或预估人数。

## 数据与边界

- `wanjiedaoyou_system_mail_campaigns` 保存正文、`RewardSelection[]` 冻结事实、条件、开始／结束时间、发布状态、发布时间、管理员及草稿修订号。客户端请求 ID 作为创建主键，创建指纹保护重复提交。
- `wanjiedaoyou_mails.system_mail_campaign_id` 可空；与 `cultivator_id` 的唯一索引实现每次发布、每个角色最多一封。没有额外投递表。历史邮件及其他直接发信入口保持空值。
- 活动邮件也是投递凭证，退出旧邮件定时物理清理；即便已领取、活动结束，也保留记录以承受延迟消息／人工重放。不要单独删除凭证后仍允许重放。
- 邮件发布表不提供删除、恢复或修改已发布内容的接口；修改内容通过复制为新邮件完成，复制属于新的奖励机会。
- 奖励继续通过现有物品协议、`MailService`、附件领取与资源提交路径。每次投递生成独立道装实例 ID，其余属性不重掷。投递不会直接把附件放入背包。

## 条件语义

条件之间 AND，指定赞助级别内部 OR。支持指定角色、角色创建时间区间、仅发布前创建的角色、含小境界的境界上下限、历史最高赞助级别（最低级别或指定集合）。不检查最近活跃时间，不将历史最高赞助级别解释为当前订阅。

后台输入／展示北京时间，接口使用带时区的 ISO 时间，新的时间列使用 `timestamptz`。投递与角色创建区间均为左闭右开；境界上下限均包含。无赞助档案的角色不匹配赞助限制。

事件保存服务端读取的角色创建时间、大小境界、历史最高赞助级别及检查时间。消费者以该快照判定，当前角色还必须有效。仅候选投递窗口覆盖检查时刻、且当时已发布的邮件参与判定。因此结束前检查、结束后消费仍能投递；发布前旧消息不会触发新邮件。后续达标可再次检查，不记录永久不匹配状态。

## 触发、事务与可靠性

- 进入游戏／切换角色后的实时连接与打开邮箱：按角色跨实例限频 15 秒。
- 持续在线心跳：距最近可靠入队至少 5 分钟检查一次。
- Redis 短租约合并多标签页并发；只有数据库事务提交后推进检查时间。失败会释放租约，后续活跃事件可重试；进程中断租约最多保留 30 秒。
- PostgreSQL 事务消息保存完整 `cultivator.mail-audience.observed` 快照。发布器收到 NATS PubAck 后标记发布，沿用 outbox relay、重试和死信处理。
- `system-mail-projector-v1` 复用消费幂等事务。候选按有效期筛选、按 ID 每页 100 条处理，不加载全服角色。
- 消费事务共享锁定有效角色和候选发布记录；停用对发布记录执行更新。停用提交后不会再开始新的投递；已经成功投递的个人邮件不撤回。
- 插入个人邮件使用数据库唯一约束与 `ON CONFLICT DO NOTHING`。仅插入成功时，同一事务创建 `mail.created`。消费记录、邮件和通知事件一起提交；提交后 ACK。
- 玩家邮箱订阅现有 `player-state.events` 中的 `mail.created` 通知并刷新列表，重连 ready 时补读，接收异步到达的邮件。并发列表读取取消旧请求，避免新邮件被旧响应覆盖。没有新增物品或实时通信协议。

## 后台接口与操作

所有接口都经过 `requireAdmin`，JSON／查询参数经 Zod 校验。

| 接口 | 行为 |
| --- | --- |
| `GET /api/admin/system-mails` | 标题搜索、每页 20 条、实际投递数（来自 mails） |
| `GET /api/admin/system-mails/:id` | 内容、条件、奖励快照与投递数 |
| `POST /api/admin/system-mails` | 幂等创建草稿 |
| `PUT /api/admin/system-mails/:id` | 按修订号修改草稿 |
| `POST /api/admin/system-mails/:id/publish` | 核对修订号后发布；拒绝已过投递结束时间的草稿 |
| `POST /api/admin/system-mails/:id/stop` | 停止后续投递；保留已投递邮件 |

旧 `/api/admin/broadcast/game-mail` 路由、收件人解析与批量循环已删除。旧 `ADMIN_BROADCAST_BATCH_SIZE` 配置不再使用。后台页面 URL 保持 `/admin/broadcast/game-mail`，导航名称为“系统邮件”。

页面以列表为首页；新建／编辑按“内容与奖励 → 条件与时间 → 核对发布”在弹窗内完成。奖励使用现有物品格和预览；允许保存草稿、复制为新邮件、查看详情和停用。发布成功意味着元信息生效，不代表所有角色已收到。

## 部署

先执行业务迁移 [0055_system_mail_campaigns.sql](../drizzle/0055_system_mail_campaigns.sql)，再部署新应用。应用启动自动注册新 durable consumer。迁移只新增发布表、mails 可空外键和唯一索引，不回填或重发历史邮件。

本地命令：

```bash
bun --env-file=env/local.env node_modules/drizzle-kit/bin.cjs migrate
```

本次只在 `env/local.env` 对应的本地数据库应用，未操作预发布或生产。
