# Phase 10Q：邮件附件与赠送接入新版物品栏

状态：2026-09-10 主体实施与重点本地运行验收完成；未全量覆盖项见文末。

## 开发边界

- 邮件支持带版本的新版物品附件，领取优先进入 bag，满包进入 storage。
- 玩家赠送只从 bag 选择并扣除；每封信保留一个物品堆叠，可调整数量。
- 首批支持新版材料、种子、丹药／灵果、图纸、玉简、兽诀、未装备道装；遵守已有绑定与禁止转移规则。
- 已装备道装、召唤兽个体、旧版战斗产物不直接赠送。历史可转换物品需通过已有宝库协议取出后使用新版赠送通道。
- 逐个检查新产生的系统奖励邮件，已有新版物品定义的附件改用新版协议；不改变奖励数量、生成规则、好友条件或传音符成本。
- 保留历史邮件读取、领取、已读与一键领取，解除赠送对旧拍卖物品读取和校验的依赖。
- 不迁移拍卖，不新增收费交易、批量历史转换、补偿、删表、独立托管表或调度器。

## 附件与结算方案

复用现有邮件表和领取流程，通过附件显式版本区分，不按邮件日期推断。

| 附件 | 领取去向 |
| --- | --- |
| 新版物品附件 | 新版库存，优先 bag，满包 storage |
| 旧格式物品附件 | 沿用原发放路径，进入洞府宝库；不在领取时转换 |
| 灵石、修为等资源 | 现有资源结算 |

客户端只提交物品引用、revision、数量与发送信息。服务端读取并校验归属、bag 位置、数量、版本、可赠送条件，保存完整可信物品事实。道装属性、种子生长事实、丹药效果原样携带，不重新生成；公开响应继续隐藏种子内部生长事实。

发送在同一事务中扣物、扣除原发送成本、创建邮件；领取在同一事务中发放附件并标记领取。复用现有玩家命令锁与持久幂等，覆盖发送重试、领取重试，以及单封领取与一键领取并发。混合新旧附件按各自协议结算，整次事务保持一致性。

## 页面方案

- PC 写信左侧为收件人、正文、一个附件格和发送操作，右侧为五列40格完整公共物品栏。
- 保留所有物品和原格位，不过滤不可赠送物品；允许查看详情，选择时提示限制。
- 附件格显示投入物与数量，支持调整数量和移出，不再铺设重复物品清单。
- 移动端点击附件格打开公共物品栏抽屉。
- 收信详情复用统一物品格；领取结果明确显示随身物品、储藏室或洞府宝库。

## 验收标准

| 场景 | 通过条件 |
| --- | --- |
| 双角色闭环 | 两个真实本地角色赠送、收信、领取成功，发送数量正确减少，接收事实一致 |
| 范围 | 首批可赠送类型正常；已有绑定限制、已装备物品、召唤兽个体及旧战斗产物不可绕过 |
| 库存 | 满包进入 storage；同事实合堆、不同事实分离 |
| 服务端校验 | 过期版本、数量不足、越权与 storage 物品拒绝且无错误扣除 |
| 幂等并发 | 重复发送、重复领取、单封与一键领取竞争不重复扣除或发放 |
| 历史兼容 | 历史附件仍走旧表，新版附件进入新版库存，混合附件正确结算 |
| 原子性 | 发送失败不损失物品或传音符，领取失败不错误标记已领取 |
| 隐私 | 客户端不能伪造物品事实，接口不泄露隐藏生长事实 |
| UI | 桌面与窄屏完成选择、改数量、移出、发送和领取；完整公共物品栏保持一致 |

实施时运行 lint、类型检查／构建及适用共享纯规则测试；服务端、数据库和页面使用代码检查与本地浏览器运行验收，不新增对应单元测试或一次性脚本。优先复用本地测试账号及现有 dev 能力，按实际运行结果记录未覆盖项。10P 与前序阶段的未验收项继续保留。


## 实施结果

- 邮件新增 `inventory_v1` 附件，使用现有物品定义与完整实例事实，发送协议仅接收物品 ID、revision、数量和请求 ID。客户端不能提交物品属性或效果。
- 玩家发送改为新背包扣除，删除邮件对 AuctionService、旧物品表扣除和旧装配结算的依赖。发送成本仍是一张随身空白传音符；附件与成本、邮件创建同事务。持久幂等防止重试重复发送。
- 新赠送不继承旧拍卖“玄品起赠”门槛，按确认范围开放；符箓作为发送成本使用，不在本阶段赠送消耗品范围内。当前新版模型没有独立通用绑定字段，本次未新增绑定体系。
- 新版附件领取复用 grantInventory，单封与一键领取均在原事务中发放并标记领取。历史附件继续旧资源结算，不修改存量邮件。
- 新奖励生产通过 sendNewRewardMail 转换已有新版定义的材料、种子和消耗品；历练、任务、创角、排名、兑换码、后台广播与反馈奖励调用点已接入。拍卖成交／退回继续原邮件协议，历史旧造物没有重新生成或转换。
- 新种子附件公开响应仅展示名称、品质、描述及线索，隐藏 seedSpec；道装和灵果领取保留原属性与效果。
- 写信拆出 MailComposer，桌面左表单与附件格、右五列40格完整公共背包，窄屏抽屉；支持选择、数量修改、移出及重选。新附件详情复用 ItemSlot；历史附件保留摘要并标明洞府宝库。领取与一键领取反馈实际去向。
- 本地 dev 发放新增 mail 类型，可显式准备历史协议或通过正式新奖励生产入口创建样本，继续受纯本地环境限制；没有 schema 迁移或新表。

验收时修正独立附件格缺少显式宽度，以及空背包格被误标选中的问题。为满包检查临时转入的三件旧存放物品已转回 storage，原账号与默认浏览器视口已恢复。开发 watch 重启后的页面已重新加载确认正常。

本地测试留下的真实变更：local1 共向 local2 发出9封附件邮件，消耗9张传音符；local2 向 local1 发出1封附件邮件，消耗1张传音符。赠送物品、已领邮件和新建本地好友关系保留；local2 增加混合样本中的1灵石。dev 共准备13张传音符（local1余3张）、兽诀与玉简各1，以及两封奖励样本；没有重置其他角色数据。local1最终背包37格，满包产物仍在storage。测试数据均未触及预发布或生产。
