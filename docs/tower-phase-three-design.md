# 蜃楼幻境第三阶段：节奏定标与运行可靠性

日期：2026-09-19。状态：核心实现及自动化回归完成，体验验收限制见第 8 节。按用户最新确认，以正常中期养成、装备与普通宠物定标；跨周从简，不做昂贵的少数故障恢复。

## 1. 目标和范围

第三阶段交付可以进入开放验收的现有玩法：正常构筑有合理节奏，周组合都有应对方式，跨周与失败重试不重复发奖、不丢已提交事实、不遗留错误占用。

保持 20 层、5/15 精英、10/20 首领、九次简单祝福、每战满状态、正常角色构筑、公共战斗组件、战前机制预览。玩法未发布，继续硬切，不增加旧解释器。

继续使用每周一条策略配置、每角色一条本周领奖记录；Redis 保存活动挑战与冻结单场快照，复用已有回放归档与资源事务。不新增爬塔历史表、奖励流水表、全角色副本或完整 NPC 周存储。

本阶段不扩大机制范围，不添加商店、事件、路线分支、复活、召唤、双首领、封印多敌、编辑后台或塔专属 AUTO。不以新增词条数量作为完成标准。现有池检验通过后再单独安排内容扩充。

## 3. 数值与策略方案

### 定标构筑

沿用真实投影和装备/灵兽生成，建立金丹至渡劫七档参考构筑。按物理、法术、控制/辅助路线覆盖，另检查现有不同流派中技能目标数、固定伤害、技能等级成长明显不同的代表。不能将三个已测流派代表所有宗门流派。

每档先冻结中期正常养成样本，再构造初期下沿与圆满上沿；核对自然属性、可分配点、装备获取等级、功法上限、修炼与灵兽合法性。禁止把金丹面板统一乘倍率伪装成高境界构筑。样本与测试共用，记录生成种子及配置来源，不引入运行时战力追涨。

### 难度定位（已确认）

- 中期正常养成、合理分配的构筑，使用普通可得装备与普通宠物，采用应对机制的打法，应具备通关当前合法周组合的能力。无宠仅作诊断，不要求通关；不要求每个种子获胜。
- 初期/养成不足允许止步关键层；圆满/养成较完整应获得清晰成长优势。不追求不同宗门、境界或每周组合完全等难。
- AUTO 是便利与诊断基线，不要求全部构筑自动通关。若问题属于公共 AUTO 的通用选招缺陷，记录最小复现，单独评估共享影响，不在塔里硬编码宗门补丁。

普通 2–3、精英 4–5、首领 6–8 回合继续作为中期样本诊断起点，不设置强制回合上限或固定胜率承诺。统计成功/失败分别的回合分布、连续通关率、人物/灵兽死亡、承伤和最长控制窗口，不能用总均值掩盖失败。

先定位机制和行动经济，再调整周期、阵容份额与生命/输出预算，最后检查防御和速度。所有敌人调整进入现有配置；不修改角色正常数据或公共伤害公式来为塔兜底。重点检查控制能否形成实际可用窗口、辅助是否值得处理、固定伤害是否拖时，以及九次祝福后的末段成长。

### 覆盖方法

分层控制组合数量，不把全部维度做无界笛卡尔积：

1. 结构：所有合法候选在 5/10/15/20 层及七境界编译，验证预览、技能周期、关系、份额和资源；铺垫对应关键层。
2. 战斗：中期代表构筑、有宠/无宠、多固定种子覆盖所有关键层候选；比较直接主敌、先辅助、控制辅助及针对重击等合法应对。
3. 极端：对离群组合加初期下沿、圆满上沿、输出集中/防御集中/均衡祝福。祝福必须由实际候选逐次选出，不能凭空授予理想九层。
4. 连续：选覆盖主套路和阵容差异的代表周，完整推进 1–20 层，失败终止，下一场重新满状态；与逐层独立样本分开统计。
5. UI：正常构筑完成至少一趟完整流程，记录实际游玩、战斗播放和操作时间；不把工具等待与代码检查耗时计为正常体验。

不先拍脑袋设 90%/95% 等验收胜率。冻结样本后提供失败种子与应对方式，确认无稳定无解组合；数值门槛若需产品决策，再根据该轮数据提出。

## 4. 周轮转、结算与存储边界

### 周切换（已确认从简）

北京时间周一 00:00 切周。新周配置沿用首次请求发布、唯一周键、条件写入和重读结果，不新增定时任务。新周首页展示新周强敌与机缘；旧战仍明确属于旧周。

| 旧挑战状态 | 建议行为 |
| --- | --- |
| 未开战/选择祝福 | 到点结束，不再开旧周下一层 |
| 战斗进行中 | 到点失效、解除占用，不接受后续指令，不补发该层奖励 |
| 已终局但结算失败 | 快照保留期间沿用现有幂等结算，不允许新周入场覆盖其领奖行 |
| 已结算未关闭战斗页 | 旧战到点失效；已提交奖励保留，刷新返回幻境，不再重复发奖 |

没有跨周续战宽限。Redis 仍保留至周结束后 24 小时用于现有重试，这是存储保留期。失效的未终局战斗丢弃临时战中进度，角色保留已持久化资源，不额外补偿。接受快照到期/丢失后的未结算进度丢失，不做无限保留或灾难恢复系统。

只有旧战结算收口后，进入新周才覆盖该角色唯一领奖行。不能为了允许旧周晚领奖而增加第二条领奖记录。小阶段变化继续使用同一大境界档；大境界变化按现有规则结束旧挑战并重新入境，周领取事实不重置。

### 幂等和故障矩阵

- 双标签页同时开始/选祝福/开战/提交/结束：runId、revision、角色锁仍是权威；过期请求返回冲突，不能覆盖新进度。
- 多请求/多实例发布本周：最终只有一行，所有调用者返回最终持久化结果；当前周不能因刷新重抽。
- 开战快照保存后、恢复资源提交前后中断：重试继续同一战斗，不在战中反复补满。
- 战斗终局快照已存、SQL 未提交：重试同一终局及冻结奖励；SQL 失败资产/claim/归档一起回滚。
- SQL 已提交、Redis 确认失败：依据既有归档凭据和领奖行恢复状态，不再恢复气血、不再发资产、不重复推进楼层。
- 榜单更新失败：保留现有日志，不回滚奖励；用户接受偶发漏记，不新增补写字段或后台任务。
- 切周前后叠加上述失败：旧周结算不能写入新周 claim，领奖周不能回退。

不新建通用事务协调器、任务队列或奖励补偿平台。跨存储错误的处理优先沿用现有锁、SQL 事务、归档事实和 Redis 快照；补写只针对已证实的缺口。

## 5. 配置与发布

保持现有有限组合池、显式 behaviorId 和按策略编译。完整技能仍在仓库内容中，周记录不复制。

配置作者检查应覆盖引用、互斥、行为适配、层号映射、铺垫/普通层覆盖及无可选周组合等问题；实际缺少哪些检查以实施时审查为准，不再增加一套平行 Schema 或规则语言。

连续周检查保留近三周软避重，补候选分布和缺失历史诊断；不为提高新鲜感放开已禁止的组合。若证明存在内容长期无法抽到，优先修规则/评分，不另造抽取系统。

未发布期间必要内容更新按当前硬切方式更新标识。正式开放后不允许同版本周中改技能/参数；版本化长期运营与历史兼容另行设计，本阶段不预建。部署前确认所有实例使用相同配置。

## 6. 开发顺序与交付

1. **固定验收基线。** 冻结各境界参考构筑、难度定位、跨周状态规则；列出已测与未测范围。
2. **收口运行边界。** 统一到期与占用规则，沿用终局结算重试，不改变存储模型，不增加榜单补偿系统。
3. **逐档定标。** 先解决金丹已知离群，再校准元婴至渡劫；形成配置修改与前后对照，补全周/候选覆盖。
4. **真实流程验收。** 正常构筑浏览器通关、双会话竞争、本地服务中断恢复、窄屏及预览一致性；恢复测试准备数据，保留玩法奖励和记录。

共享确定性逻辑用 `src/shared` 测试。数据库、路由、Redis 和 UI 只用代码审查、lint/build 及本地浏览器/实际服务验证，不添加模拟单测、一次性 E2E 或跑分脚本。

周边界规则可提取接受显式时间的纯函数用于测试，真实服务验证不修改宿主系统时钟。优先使用已有本地验证能力；若跨周场景确需新增入口，只允许受现有纯本地保护的最小测试准备能力，不把“指定当前周/任意快进”开放给正常 API。精确故障窗口未能复现时如实标记，不把读代码记为实测通过。

完成要求：全部现有合法组合有验证记录；七境界完成正常构筑实战检查；已知节奏问题有结论；实际重复操作/故障/跨周矩阵有结果；旧战不会覆盖新周事实或永久占用；SQL 仍一周一条配置、一角色一条领奖行。可复现缺陷未收口时不宣布正式开放验收通过。

本阶段不包含生产部署，也不顺手修改无关炼体文案测试。全量测试若仍存在既有失败，单独记录。

## 7. 已确认事项

用户已确认：

1. 正常中期养成、正常可得装备与普通宠物，合理手动可以通关；无宠及 AUTO 不承诺全通。
2. 跨周从简，到点结束未终局旧战；终局沿用现有结算重试，接受低概率进度丢失和榜单漏记，不为其新增复杂机制。

其余按既有决策与最小改动原则处理，无需确认新表、状态隔离或战斗 UI 改造。

## 8. 实施与验证记录

- 内容升级为 `combat-v6-tower-v7`、快照 `tower-v6-v7`，Redis 使用 `configured-v7`；schema 仍为 3，不增加表或迁移，保留 SQL 领奖事实。
- `lifecycle.ts` 统一读取与占用判断：到点丢弃非终局旧战；终局待结算保持占用，沿用现有重试。读取只做投影，不进行未持锁写入。周界前已受理请求可能完成该轮，不新增跨周协调器。
- 配置检查补齐普通/铺垫层互斥、16 个非关键层完整覆盖、合法层号、后段关键层及阵容职责引用。
- 参考构筑使用真实境界预算、普通装备生成和同等级普通岩甲豕；开放装备最高 90 级，化神以上不虚构更高装备。五宗门各选一条代表路线，不代表全部流派。幽都纠正为勾魂阎罗，旧样本实际误选物理路线，历史统计不作为当前控制路线证据。
- 七境界 × 五宗门 × 44 个关键层候选 × 三种子，共 4,620 场，4,617 胜；每个候选均有获胜样本，无首回合人物死亡。金丹九劫的灵障沉稳物理首领在 10/20 层各一败，天衍同组合 20 层一败；不承诺每种子必胜。
- 三个代表周、七境界、五宗门、三种子，共 315 次连续挑战全部完成 20 层；祝福逐节点从真实候选选择，失败会立即停止。单趟总回合 51–235，这不是浏览器游玩时长。
- 初期/圆满与防御优先祝福补充 210 场末层检查，全部获胜。该批只覆盖一个代表周，不能推导所有初期构筑必过。
- 测试中的手动策略优先辅助；九劫优先法术，面对单体物理敌人择机封印。公共 AUTO、技能公式及玩家数据不变。无相仍用公共选招，部分高境界法系多敌候选需 30–43 回合；可以通关，但节奏偏慢，后续需真实手动体验确认，不据此全面削弱敌人。
- 周界纯函数覆盖零点前后、非终局失效、终局待结算及已结算释放；周生成补遗漏历史及跨年确定性检查。
