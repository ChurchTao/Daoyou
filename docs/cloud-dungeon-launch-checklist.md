## 1. 模型与环境配置

- [ ] 确定高级模型组的 DeepSeek 模型：DeepSeek 接口拒绝 `deepseek-v4.1-flash-1017`，可用的有 `deepseek-flash`、`deepseek-v4-flash`、`deepseek-v4-pro`。确定后更新预发布与生产环境的 `LLM_ADVANCED_PROVIDER`，并同步 `env/example.env`（当前仍写着被拒绝的型号）。
- [ ] 后台生成没有玩家身份，高级组只取权重最高的一条路由（同权时按名称排序取第一个）。生产环境的 `LLM_ADVANCED_PROVIDER` 要让适合剧本生成的模型权重最高：2026-11-04 本地 prd 预热中，同权时取到 `glm-5.3`，大纲全部超时；随后使用 `alibaba/qwen3.8-flash`、思考预算 4,096 的手动完整生成已成功。注意权重也会改变玩家侧高级场景按用户分流的比例。
- [ ] 预发布、生产环境都配置 `LLM_ADVANCED_PROVIDER`；未配置时高级场景会退回基础模型组，案卷一致性明显下降。
- [ ] 结构化输出的稳定性：本地开发中基础模型组（qwen）曾间歇返回 “This response_format type is unavailable now”，导致后台生成批量失败。上线前确认所选模型对结构化输出的支持与配额，必要时为基础组配置多条路由。
- [ ] 高级模型的大纲耗时：2026-11-04 起剧本生成开启思考，大纲一次约 5 分钟。单步时限已放宽到 15 分钟，传输层等待也已对长时限请求取消（Node 内置 fetch 默认只等响应头 300 秒）。上线前用目标环境的高级模型测一次完整生成的耗时与成功率；若经过反向代理或网关，确认其读超时不短于 15 分钟。
- [ ] 后台模型任务开关：`BACKGROUND_LLM_JOBS` 缺省只在 `NODE_ENV=production` 运行。确认生产镜像的 `NODE_ENV` 为 production；如从本地用 `env/staging.env` 预热，要在该文件里显式设为 `on`，预热完删除。
- [ ] 用目标环境的密钥实际调用一次 `dungeon-case`、`dungeon-case-text`、`dungeon-case-review`、`dungeon-npc`、`dungeon-settlement` 五个场景，确认模型可用、结构化输出正常。

## 3. 剧本库预热

- [ ] 上线前在目标环境把每个库存位预热到至少 2 本。当前 31 个节点、5 种案型共 69 个库存位（遗府疑案 13、遗珍寻踪 15、破禁试炼 17、异变溯源 16、立场抉择 8），预热目标约 138 本。
  - 清扫任务已会自动把不足 2 本的库存位排队补货，但全服待生成上限为 5、每个实例同一时间只生成 1 本、每本约 60–90 秒，单实例全部补满需要一个多小时。需提前启动并留出时间。
  - 预热后逐个库存位核对数量（`wanjiedaoyou_dungeon_scenarios` 按 `map_node_id, template_id` 统计 `status = 'active'`），并抽查各节点若干本的质量。
- [ ] 节点调整后不再配置的库存位（如原先配在祭坛、裂渊上的遗珍寻踪）里已生成的剧本仍是 active，只是不会被选中；上线前可按需停用，避免统计口径混淆。
- [ ] 阶段 6（计分与叙事）不改生成，阶段 7（结构变体）会升级生成版本并整批重生成剧本：预热应安排在阶段 7 完成之后，避免预热两次。
- [ ] 评估预热与日常补货的模型费用：2026-11-04 起整条生成链路走高级模型并开启思考（每本：大纲 1 次 + 正文 3 次 + 审校 1–2 次 + 入库审校 1 次）。本地实测 kimi-k3 大纲一次约 1 万输出 token，其中思考约 8 千，费用与耗时都明显高于不开思考；按 138 本预热与日常补货估算总费用，必要时改用更便宜的思考模型。
- [ ] 生成并发：队列按地图节点划分，节点间并发，生产环境每 5 分钟的清扫会给所有不足 2 本的库存位排预热任务，首次上线约 31 路高级模型调用同时进行（每个实例）。确认供应商的并发与限速配额；同进程的 AI 并发上限为 64（`AI_MAX_CONCURRENT_REQUESTS`），与玩家交谈、结算共用，预热期间留意交谈是否出现“AI 服务繁忙”。
- [ ] 用目标环境的高级模型确认思考开关生效（日志 usage 中有 `reasoningTokens`），且该模型不因 `enable_thinking` / `thinking` 参数拒绝请求。
- [ ] 保底案卷覆盖：每个模板至少有一份与其绑定节点场景相符的保底案卷（已保证不会交给不相符的节点）。没有保底的节点冷启动生成失败时会拒绝开局、请玩家稍后再来，因此库存预热是这些节点能否开局的前提。
