# 云游探秘解谜版：上线前清单

开发阶段暂不处理、但上线前必须逐项确认的事项。开发中发现新的上线事项时追加到对应分类，完成后勾选并注明日期与验证方式。玩法开发路线见 [cloud-dungeon-roadmap.md](cloud-dungeon-roadmap.md)，设计与实施记录见 [cloud-dungeon-mystery-redesign.md](cloud-dungeon-mystery-redesign.md)。

## 1. 模型与环境配置

- [ ] 确定高级模型组的 DeepSeek 模型：DeepSeek 接口拒绝 `deepseek-v4.1-flash-1017`，可用的有 `deepseek-flash`、`deepseek-v4-flash`、`deepseek-v4-pro`。确定后更新预发布与生产环境的 `LLM_ADVANCED_PROVIDER`，并同步 `env/example.env`（当前仍写着被拒绝的型号）。
- [ ] 预发布、生产环境都配置 `LLM_ADVANCED_PROVIDER`；未配置时高级场景会退回基础模型组，案卷一致性明显下降。
- [ ] 用目标环境的密钥实际调用一次 `dungeon-case`、`dungeon-case-text`、`dungeon-case-review`、`dungeon-npc`、`dungeon-settlement` 五个场景，确认模型可用、结构化输出正常。

## 2. 数据库与部署

- [ ] 执行迁移 `drizzle/0071_dungeon_scenario_library.sql`（剧本库、游玩记录、生成任务三张表）。
- [ ] 部署切换期间旧版服务与新版服务不要同时消费同一个后台命令流：旧服务不认识 `dungeon-scenario.generate`，唤醒可能落空，任务要等新服务 5 分钟一次的兜底清扫才处理。确认部署顺序或接受短暂延迟。
- [ ] 确认 `*/5 * * * *` 的剧本清扫任务在生产调度中生效。
- [ ] 版本升级（`MYSTERY_GENERATOR_VERSION`）会在清扫时整批停用旧剧本，上线时库中只剩当前版本；如在上线后再次升级，需评估全量重新生成的成本与首局等待。

## 3. 剧本库预热

- [ ] 上线前在目标环境把每个库存位预热到至少 2 本。当前 31 个节点共 41 个库存位，预热目标约 82 本。
  - 清扫任务已会自动把不足 2 本的库存位排队补货，但全服待生成上限为 5、每个实例同一时间只生成 1 本、每本约 60–90 秒，单实例全部补满需要一个多小时。需提前启动并留出时间。
  - 预热后逐个库存位核对数量（`wanjiedaoyou_dungeon_scenarios` 按 `map_node_id, template_id` 统计 `status = 'active'`），并抽查各节点若干本的质量。
- [ ] 评估预热与日常补货的模型费用（每本：大纲 1 次高级模型 + 正文 3 次基础模型 + 审校 1–2 次高级模型 + 入库审校 1 次高级模型）。
- [ ] 保底案卷覆盖：每个模板至少有一份与其绑定节点场景相符的保底案卷（已保证不会交给不相符的节点）。没有保底的节点冷启动生成失败时会拒绝开局、请玩家稍后再来，因此库存预热是这些节点能否开局的前提。

## 4. 旧版副本数据

- [ ] 统计目标环境中尚未结束的旧版回合制副本（`dungeon_runs` 中非 FINISHED 且运行态没有 `mystery` 的记录）。
- [ ] 在页面上验证旧版副本的“结束探索”：能正常结算、收益照发、记录归档。本地开发时未实测（唯一的旧版副本属于其他测试）。
- [ ] 决定是否在上线时统一结算这些旧副本，或保留让玩家自行结束。

## 5. 未完成的验收

开发期间没有在页面上覆盖、上线前需补测的路径：

- [ ] 战胜结尾对决（擒下真凶 / 夺宝者）与战胜守卫：测试角色太弱，目前只有单元测试覆盖。需要一个足够强的测试角色。
- [ ] 移动端窄屏：调查界面、交谈与出示抽屉、结案面板、迎战页、结算页。
- [ ] `RECOVERABLE_ERROR`：结算失败后的“重试结算”“安全撤退”“放弃副本”。
- [ ] 已结案的本再次遇到（重温）的开局提示。
- [ ] 冷启动：库中没有剧本时首位玩家开局的等待与超时（前端开局超时 200 秒）。

## 6. 平衡与数值

- [ ] 结尾对决（首领强度）与守卫（精英强度）对各境界角色的胜率；落败后残血进入下一局是否可接受。
- [ ] 评分档位与奖励：S/A/B/C 的分布是否合理，探索收益（关键线索掉落）与通关奖励的比例。
- [ ] 行动力预算（遗府疑案 30、遗珍寻踪 38）与事件发生回合在实际游玩中的松紧。

## 7. 内容安全与质量

- [ ] 玩家自由对话的输入过滤（`textFilter`）与越狱防护在生产模型上复测。
- [ ] 抽查生成案卷中的已知问题：选项说法带“伪”“假”等字眼、结局叙事夹带英文或写入未发生的调查动作、房间描写提到会离场的人物。

## 8. 运营与观测（可上线后补，但需决定）

- [ ] 剧本库管理：查看、下架、手动补货的后台入口。
- [ ] 玩家对剧本的评分与反馈，接入自动下架规则（当前规则：游玩满 20 次且完成率低于 20% 或均分低于 30 时下架）。
- [ ] 模型费用与生成成功率看板：按场景统计调用次数、耗时、失败与回退保底的比例。
