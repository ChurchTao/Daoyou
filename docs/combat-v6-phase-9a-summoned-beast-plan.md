# Phase 9A：持久召唤兽与双操作闭环实施计划

> 2026-09-06：代码已实现，本地基本链路已验证；完整多人及故障验收尚未完成，具体结果见文末。依据：[总路线图](./combat-v6-mhxy-redesign-roadmap.md)、[召唤兽设计基线](./combat-v6-summoned-beast-system-design.md)。

## 目标与范围

让玩家真正拥有并控制召唤兽，完成真实 4v4、每人一宠、共 16 个在场单位的战斗闭环。接入野怪、练功房和擂台，沿用现有 v6 页面、v5 配色、差量播放、只读观战及统一回放归档。

本阶段包含正式个体、独立编组、一次性新手领取、首发、顺序下令、召回换宠、寿命结算和确定性恢复出口。个体从第一天保存成长、资质、等级、自由属性事实、固定技能格与生成版本；不另建临时模型。

不包含捕捉入口、经验获取与升级加点操作、兽诀获取与打书入口、交易、合宠、装备、召唤兽修炼、阵法、药品战斗指令、法宝或全仓 v5 清理。基础投影所需的最小技能内容属于本阶段。

## 已确认规则

| 事项 | 规则 |
| --- | --- |
| 个体与编组 | 独立持久化；最多携带六只，首发一只，同主人场上最多一只 |
| 获取 | 一次性新手领取，生成正式个体；本地验证走相同入口 |
| 属性 | 独立五维、五资质、成长；不继承人物构筑与修炼 |
| HP/MP | 每场满状态入场；本场收回保留，战后不持久化当前值 |
| 提交 | 先人物后宠物，可返回修改，最终整组提交；单单位直接提交 |
| 倒地 | 人物仍提交允许的操作，可以指挥存活宠物；不能预选召唤／换宠 |
| 超时／离线 | 为人物与可行动宠物分别补普攻，不自动换宠 |
| 换宠 | 消耗人物行动；旧宠指令按实际速度顺序和在场状态决定是否执行；新宠下一回合行动 |
| 板凳 | 不行动、不 tick、不提供光环、不阻止战败；清除仅在场临时状态 |
| 死亡 | 本场死亡宠物不可再次召唤；有效 PvE 每宠每场最多扣 50 寿命 |
| 无损玩法 | 擂台、练功房不扣寿命 |
| 寿命 | 低于 50 禁止首发／召唤；归零保留个体；提供确定性恢复出口 |
| 观战与归档 | 公共比例视图，不公开私有构筑；沿用统一战斗归档，宠物不是历史授权角色 |

## 实施顺序

### 1. 核对既有能力并锁定最小内容

核对引擎召唤、收回、死亡事实、控制权、运行态恢复以及三个 Host 的现状，识别缺口后修改；不重建已有可复用能力。

整理首批物种、初始等级、成长与资质区间、投影公式和取整方式、出生技能、初始寿命、新手领取规则及恢复方式。复用已有青灵狐、岩甲猪、疾风狼物种身份，持久个体重新按版本化规则生成，不能复制野怪最终面板。本次采用的内容默认值见文末；这些数值属于实施默认值，并非用户逐项确认的平衡结论。

验收：领域输入、投影输出及每项规则有明确归属，没有 v5 投影依赖，内容默认值没有藏在页面中。

### 2. 纯领域模型与投影

实现正式个体、编组校验、确定性生成、等级属性推导和兽诀投影；人物与宠物使用独立实例及注册表。明确同系普通／高级技能同时存在时只启用高级效果。

验收：纯共享测试覆盖相同种子生成一致、点数守恒、固定技能格、独立修炼、寿命边界、六只携带与唯一首发；投影不修改个体事实。

### 3. 持久化与管理入口

新增个体与编组持久结构，使用现有 Drizzle/repository/事务方式。新手领取防止并发重复发放；编组及恢复操作校验归属、修订号和战斗占用。战斗开始冻结携带个体与投影，禁止战中修改这些个体影响权威战斗。

实现列表、详情、携带、首发及寿命恢复的最小 UI；不显示尚未开放的养成功能按钮。恢复不能超过寿命上限，不通过测试专用 API 绕过正常规则。

验收：迁移可审查，正常用户入口完成领取和编组；重复请求不多发个体或多扣资源。远程环境不执行测试写入。

### 4. 引擎与 Host 控制链路

补齐主人与宠物控制关系、召回换宠时序、板凳状态处理和结构化死亡事实。整组指令由服务端验证，不能操作他人的宠物或为尚未获得行动资格的新宠提交指令。

擂台按参与玩家收齐合法整组指令，倒地人物不跳过；超时／离线补默认操作。PvE 保持既有提交后 resolve 的依赖顺序。HTTP 提交，WebSocket 推送回合状态和结果，HTTP 恢复基准与缺口，客户端逐行动播放。

验收：共享测试覆盖换宠前后速度顺序、新宠行动时机、死亡不可重召、退场停止 tick／光环、胜负判定和恢复确定性。

### 5. 顺序操作与公开播放

指令栏先人物后宠物，返回修改不得遗留错误目标或旧宠操作。复用一级分类、二级抽屉与技能 tooltip；阵容稳定对齐，详情展示具体属性。无宠物或当前无宠物操作时省略宠物步骤。

差量正确表达宠物上下场、HP/MP、状态与回合；观战保持公共信息边界。归档冻结必要展示资料，旧录像不依赖当前物种表重算；历史列表继续只读元数据，不解包回放。

验收：桌面与 360px 视口、连续点击、返回修改、播放期间刷新、断线恢复、观众中途加入和回放逐行动同步。

### 6. 战后寿命与完整验收

有效 PvE 结算事务按战斗和宠物身份幂等处理死亡寿命，不依赖终态 HP 推断是否曾死亡。擂台与练功房不写回寿命。结算失败重试不重复扣除，作废战斗不扣除。

验收：真实 4v4 每人一宠完成连续收令、超时普攻、倒地复活、换宠、终局、观战与回放；PvE 验证死亡扣除、恢复及低寿命禁战，擂台验证无损结算。未实际验证的故障和容量场景逐项记录。

## 验证与发布边界

- 仅在 `src/shared` 添加纯确定性测试，不新增前端、服务端、数据库或第三方模拟单元测试，不新增一次性 seed／smoke／E2E 脚本。
- 浏览器验证遵循 `docs/testing.md`，使用纯本地环境和项目测试账号规范。
- 代码修改使用内置编辑工具；React 遵循指定最佳实践，格式使用仓库配置；不引入全局状态库或全站整改。
- 执行适用的共享测试、`bun run lint`、`bun run build`、触及文件 Prettier 检查与 `git diff --check`，记录真实结果和未验证项。
- Phase 8 的 4v4 观战负载、多实例、慢连接及故障矩阵保持独立待验收，不将 9A 功能完成等同于生产容量通过。
- 不加功能开关或 v5 回退链路；正式上线仍采用停机维护硬切。迁移、部署与全仓 v5 退役不因本计划自动完成。

## 实施记录（2026-09-06）

- `src/shared/engine/combat-v6/beasts` 保存正式个体模型、确定性生成、独立面板与技能投影；同系普通／高级连击只启用高级效果。
- 迁移 `0038_v6_summoned_beasts.sql` 新增个体表及编组表；领取、编组、休养通过人物锁和事务保护。战斗开始冻结携带个体，战中禁止修改。
- `/game/beasts` 提供一次性领取、详情、携带、首发和休养；复用场景壳、抽屉和 tooltip。
- 野外、练功房、擂台统一人物／宠物整组指令；召回和换宠按权威行动顺序更新差量帧。己方宠物可查看具体属性，其他玩家及观众只获得公开比例，不公开未出场备用宠物。
- 有效野外结束或逃跑结算，依据 `unitDead` 事实在既有结算凭据事务中去重扣寿命；技术作废不扣，擂台及练功房不扣。

### 本次内容默认值

每名角色一次性三选一：青灵狐（灵火）、岩甲猪（岩甲护身）、疾风狼（疾风袭）。初始 10 级，50 点按物种方向预分配，一个固定出生技能格，寿命 1000。资质基础区间 900～1100，专长资质额外 100；成长 0.950～1.050。9A 休养免费恢复至寿命上限，9B 再设计资源消耗。所有默认值由共享领域模块定义，页面不独立计算战斗面板。

### 协议与发布

- PvE 提交改为 `{ expectedRevision, commands: [{ unitId, command }] }`；擂台为 `{ round, requestId, commands }`。服务端一次验证并保存完整控制组，不保留旧单指令协议。
- `command` 增加 `summon`／`recall`；会话通过 `controlledCommandOptions` 返回人物与当前宠物的选择。先选人物只是客户端草稿，宠物选择完成才发送一次 HTTP 请求。
- 本阶段版本戳使用 `COMBAT_V6_PHASE_9A_*_VERSIONS`，包含 `daoyou_rules_v7` 及各玩法的召唤兽内容／编译器版本。归档保留冻结的单位与技能展示资料。
- 发布需停机、完成迁移并硬切前后端，旧页面必须刷新；旧活动会话不作为兼容目标。迁移仅已在纯本地 PostgreSQL 应用，未执行远程迁移或部署。
