# 临时宗门迁移工具

入口：`/admin/sect-migration`。工具只调用已有认证、角色锁、事务、背包和资源接口；不修改游戏启动、全局中间件、定时任务、修炼或丹药。未发布的 `0044` 在删除旧表前自动保留迁移来源；实际转化与补偿只在本工具执行，迁移结束可以整组删除工具。

## 停机与执行

停机由部署侧负责。先备份数据库、完成旧版清账，停止游戏实例、消息消费者与外部定时任务。先执行包含来源保留步骤的正常数据库升级，再使用含迁移页面的前端，临时把 API 进程入口换为本分支的：

```bash
bun --env-file=你的环境文件 src/server/routes/api/admin/sect-migration/serve.ts
```

此入口沿用原来的 `HOST`、`PORT`、认证及管理员配置，只服务登录、验证码、管理员会话和迁移接口，不执行 `src/index.ts`，不会启动游戏消费者或定时任务。需要可运行 Bun 的源码维护环境；无需修改正式启动配置或构建链。前端仍使用包含迁移页面的正常 SPA，API 域名及反向代理保持原有配置。

1. 停机后执行项目正常数据库迁移。`0044` 的第一步会锁定旧宗门来源表，将每个 active 成员的身份、心法等级、双流派层数、当前流派和原节点配置保存到同库 `app_settings` 的 `sect-migration:v1:pending:<membershipId>`，并保存 `sect-migration:v1:manifest` 清单。不依赖新版服务或提前点击后台按钮。
2. 来源保留与后续旧表删除、清空、结构升级处于 Drizzle 的同一事务，任一步失败都回滚。若发现已有 `sect-migration:v1:` 记录，直接中止，须核查记录来源，不覆盖、不自动删除。没有 active 成员时仍保存空清单。
3. 启动上述临时管理服务，打开迁移页面，勾选已停机，查看目标等级、经脉深度、退款与异常，点击“迁移下一批”，每批最多 20 人。工具检测到旧数据库时不会允许执行新版写入。
4. 每位玩家迁移成功后，在同一个事务内删除其 pending 记录；失败保留原记录。进度、退款、道具发放、资源事件及迁移凭证一起提交，重复执行不重复退款。
5. 刷新核对到所有成员均通过，下载凭证留档，关闭临时 API 服务，恢复正常游戏入口。核对依赖当前余额/进度，应在开服前完成。

勾选停机仅记录管理员的操作前提，不声称检查或停止了其他进程。已有新版培养数据的成员禁止覆盖。已经执行过未含保留步骤的旧 `0044` 的数据库，不会因修改文件自动重跑；缺失来源只能从升级前备份找回旧记录，不能强行重跑 `0044`；工具不会用新版测试进度推断旧资产。

## 迁移与补偿

### 命令行执行

停机期间也可直接运行同目录的 `cli.ts`，无需启动 API 或浏览器。脚本与管理后台共用逐人迁移函数，保留战斗占用检查、事务、退款、凭证及成功后删除来源的逻辑。脚本在操作者明确确认停机时跳过 Redis 角色互斥锁和角色状态串行锁，最多同时处理 16 人，各自使用独立事务，每 20 人输出进度；后台仍按原方式加锁并串行执行。来源行锁、归属校验及防重复发放检查保持。战斗占用检查复用当前事务，避免并发时额外申请数据库连接。全量预检在开始执行时完成，避免每批重复全量扫描，报告统一批量读取感悟果数量。失败或阻塞的来源保留，重新运行只处理仍可迁移的成员。

```bash
# 默认只预检，不写数据库
bun --env-file=env/staging.env src/server/routes/api/admin/sect-migration/cli.ts --dry-run

# ADMIN_USER_ID 替换为环境配置中已有管理员的用户 UUID；凭证路径必须不存在
DB_MAX_CONNECTIONS=32 bun --env-file=env/staging.env src/server/routes/api/admin/sect-migration/cli.ts \
  --apply --maintenance --operator-id "$ADMIN_USER_ID" \
  --audit /绝对路径/sect-migration-audit.json
```

执行前关闭后台页面的迁移操作。`--maintenance` 表示操作者确认已经停机，不会自动停止服务。脚本不启动定时任务或消费者。死亡角色、归属异常、已有新版进度等仍按后台规则阻塞，不自动清除来源。凭证文件包含完整最终报告和逐人凭证，权限为 `0600`；存在阻塞或失败时退出码为 2，执行异常为 1，全部核对通过才返回 0。中断后已提交的凭证保留在数据库，可以重跑续作。

### 继承规则

- 五个宗门的固定映射在 `src/shared/sect-migration/mapping.json`。六本心法按槽位继承等级，不匹配名字或技能效果。未知 ID、越界、分支超过主心法等情况阻止该成员迁移，不静默裁剪。
- 旧六层经脉包含 `ultimate`。新版共享深度取双流派最大值，第 7 层不赠送；节点清空让玩家重选。旧当前流派按固定映射继承，未选择流派的成员保留待选择状态。
- 另一流派的投入按旧标准累计返还：第 n 层修为 `5000 × 4^(n-1)`，灵石为修为的 5 倍，感悟每层 100。退款公式冻结。
- 修为、灵石直接返还，超过既有余额上限时整笔失败；大额灵石在同一事务内分段调用现有接口，不被单次增量上限截断。
- **感悟改发宗门感悟果**，50 点补偿对应 1 颗，每颗增加 50 点感悟（每层补偿 2 颗，最多 12 颗）。它是已有 `consumable.v1` 的完整灵果实例，复用灵果服用逻辑，感悟已满时拒绝消耗。超出 200 上限的部分按现有规则不保留；玄品适用于当前所有境界。没有新增物品定义、专属使用入口或对主流程的例外规则。删除工具后依然可用。
- 道具自动堆叠，背包不足时按现有规则进入新版仓库。核对包括道具数量增量与退款前后余额。

## 删除工具

迁移完成且凭证已下载后：

- 删除 `src/server/routes/api/admin/sect-migration/`、`src/react-app/routes/admin/sect-migration/`、`src/shared/sect-migration/`。
- 删除 `src/shared/contracts/sectMigration.ts` 和本文档。
- 移除 `src/server/routes/api/admin/index.ts` 的对应 import/route，以及 `src/react-app/router.tsx`、`src/react-app/routes/admin/_config/nav.ts` 的页面入口。

除此之外没有需要恢复的主流程改动，也没有新增数据库表、字段或迁移编号。已执行的 `0044` 作为迁移历史保留，不随工具删除或回退；它只依赖当时的旧表和 `app_settings`，不依赖工具代码。`app_settings` 中的迁移凭证可作为审计记录保留；如需清理，先归档再仅清理 `sect-migration:v1:` 前缀。玩家的新宗门进度、资源和补偿道具均不依赖这些凭证或工具代码。
