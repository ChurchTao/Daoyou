# Phase 10F：突破试炼战斗迁移 V6

> 2026-09-09：Mac 解锁后已完成六种试炼真实运行与主要异常分支验收，修复三项运行问题；难度平衡及部分恢复边界仍待专项验收，不标记整阶段全部通过。所有试炼使用正常 V6 普通战斗，不设置人物或灵兽单独参战的特殊规则。
> 上位设计：[总路线图](./combat-v6-mhxy-redesign-roadmap.md)。前序阶段未验收项继续保留，本计划不将其标记为通过。

## 1. 范围

迁移现有六种突破试炼的战斗入口、对手生成、会话、操作页面、结算及回放。保留任务领取条件、前置目标、丹药准备和最终突破规则；胜利只完成对应试炼目标，不直接提升境界。

| 试炼 | V6 对手方案 |
| --- | --- |
| 心魔劫 | 当前人物 V6 构筑镜像，保留清心状态对难度的影响 |
| 化神之扰 | 配置化天劫投影 |
| 法则试锋 | 配置化法则残影 |
| 雷劫淬体 | 配置化劫雷化身 |
| 大执念劫 | 当前人物 V6 构筑镜像，带明确的难度修正 |
| 天劫前奏 | 配置化天道劫影 |

不重做突破任务体系，不新增试炼、战斗药品、经验、掉落或养成系统。后台模拟器迁移和全仓 V5 删除另行安排。

## 2. 普通战斗与托管

人物及合格灵兽遵循公共 V6 参战、召唤和换宠规则，不增加试炼专属禁用逻辑。复用公共操作页，默认手动，一级「自动／取消自动」按钮控制人物和在场灵兽。

客户端在可下令且播放完成后等待 3 秒，单次提交 AUTO；服务端仅选招并执行当前回合。刷新、离页、新场次回到手动，终局不自动重试或突破。自动策略沿用公共规则，不新增自动召唤、换宠或后台调度。

## 3. 对手与资源

每次开战冻结玩家构筑和对手；同场恢复不得重新生成。战败、逃跑、百回合平局不完成目标，结算后可以调整构筑再挑战，新挑战按当时构筑重新生成，不新增次数限制。

心魔使用原生 V6 人物投影，其余试炼使用 V6 NPC 配置，不调用旧敌人生成器或让 AI 决定数值。旧版属性倍率不直接照搬，按 V6 公式配置和验收；具体数值属于实施时的内容配置，不扩展为新难度系统。

人物继承现实 HP/MP，终局结算实际消耗，灵兽死亡寿命及现实资源互斥遵循已有普通战斗规则。不新增失败惩罚、人物／灵兽经验或战斗掉落。

## 4. 会话与结算

复用 V6 单人战斗能力，提供开战、恢复、回合提交及终局结算。任务记录保存必要的会话关联和结算凭据，不新增通用任务框架或独立调度系统。

同一任务最多一场活动战斗。活动及待结算期间禁止构筑修改、其他互斥战斗和最终突破；离页不放弃战斗。终局资源变化、试炼目标更新和统一战绩归档使用同一数据库事务及稳定战斗标识保证幂等，失败后重试同一终局，不重复扣资源或推进任务。

保留已完成的旧试炼目标。新挑战硬切 V6，不转换旧战斗快照，不新增回滚开关。本阶段仅移除本次入口不再需要的旧引用，不代表其他 V5 依赖已退役。

## 5. 实施顺序

1. 核对任务推进、最终突破和互斥入口；实现六种原生 V6 对手及配置，验证纯投影逻辑。
2. 接入可恢复会话、事务结算和公共战斗页面，移除突破挑战旧执行及播放路径。
3. 完成真实本地运行验收，记录每项证据与未覆盖项，同步路线图状态。

## 6. 验收标准

- 六种试炼均可进入 V6 页面，手动／自动操作正常，生成可播放的统一战绩。
- 人物与合格灵兽正常参战，合法召唤／换宠及灵兽死亡寿命结算正确，无试炼专属参战限制。
- 胜利只推进对应目标；最终突破仍检查全部既有条件，未完成其他条件不能绕过。
- 战败、逃跑、百回合平局不推进目标，资源消耗正确，结算后可重试。
- 清心状态对心魔难度的影响正确；同场恢复对手不变，重新挑战使用新构筑。
- 刷新、离页返回、服务重启可恢复同场；自动默认关闭，不产生后台回合。
- 重复提交、旧 revision、响应丢失后重试不重复执行；数据库事务失败及终局确认失败后可恢复同一结算。
- 活动及待结算期间禁止改构筑、另开互斥战斗和提前突破；任务列表在结算后及时刷新。
- 已完成旧试炼目标保留；新挑战不经过 V5 执行器和旧播放器。
- 运行相关 shared 纯逻辑测试、lint、类型检查和 build；遵循 [测试规范](./testing.md) 完成本地浏览器及受影响页面布局检查。不增加 server/react-app 单元测试、一次性验收或故障注入脚本。

## 7. 当前状态

### 7.1 已实施

- 原 TaskService 一次性 V5 挑战执行改为前置检查与独立胜利目标更新；六种对手采用原生 V6 投影／NPC 配置。首轮 NPC HP 系数依次为 2、2.2、2.4、2.6，攻击系数依次为 1.1、1.15、1.2、1.25，等级取当前人物 V6 等级；清心心魔为等构筑，未清心心魔和大执念镜像的 HP 及双攻提高 10%。这些数值尚未通过真实配装的难度验收。
- 新增 BreakthroughHost 和 CombatV6BreakthroughService，继承公共 PvE 回合、人物与灵兽指令、合法换宠和百回合上限。版本为 combat-v6-breakthrough-v1，未修改普通战斗规则。
- 保留 POST /api/tasks/:id/challenge 入口，返回 V6 会话；恢复、回合提交、resolve 和 AUTO 位于 /api/combat-v6/breakthrough/tasks/:taskId/sessions。新页面提供开始试炼、手动／自动、恢复、重试结算及失败后的主动重新挑战，不在刷新时自动开新场。
- Redis 保存活动快照和终局事实，无活动 TTL；任务 metadata.breakthroughBattle 保存权威占用及 settled 凭据。按 revision CAS 更新战局，先保存终局再提交数据库事务；资源、灵兽死亡寿命、目标和统一回放同事务提交，成功后终局 Redis TTL 为一天。不新增数据库表或迁移。
- 任务、库存、构筑、灵兽、练功房、野外、擂台及既有受保护业务入口纳入突破活动互斥，现实资源自然恢复暂停；最终突破在前置检查前也校验战斗互斥。终局页面刷新任务和资源缓存。
- 新增回放来源 breakthrough 和战绩列表标签。旧突破战斗执行及播放器引用移除，全仓其他 V5 引用保留。
- 按用户授权扩展纯本地 dev 修为、感悟、清心／护脉及指定秘境目标准备能力，不能提交战斗完成目标；范围及恢复说明见 [测试规范](./testing.md)。
