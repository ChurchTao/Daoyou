# Phase 10Y：秘境自主选物与异常恢复收尾

2026-09-11 用户确认实施；实现及重点本地验收完成。候选为 `codex/combat-v6` / `caa308de` 上本阶段工作区变更，尚未发布。

## 开发边界

- 用户补充替代10X自动选材决定：秘境材料类成本通过公共InventoryItems选择具体bag物品和数量后提交。不预选、不自动替换；取消不扣费、不生成下一轮。灵石等非物品成本随最终提交一起结算。
- 多个要求分别选物，支持跨堆叠。同一堆叠跨要求共享可用数量；服务端核对所有者、位置、类型、名称、最低品质、数量和revision，任何不符整次拒绝。
- 选物随原行动存入已有pendingAction与费用账本；重试沿用原选择，不改用其他材料。
- 网络中断、空响应和解析失败先读取权威状态。读取失败保留最近画面、阻止旧状态操作并提供重新读取，不自动重发写请求、不无限轮询。
- 状态读取区分无活动、处理中、读取失败，并支持按本人runId恢复已完成结算；恢复操作只允许服务端当前明确提供的动作。
- 补齐材料和战前占用边界，发现问题作局部修复。不新增表、不改奖励、难度、地图、战斗药品、蜃楼或多人玩法。

## 验收

### 实施记录

- `DungeonMaterialSubmission` 复用公共 `InventoryItems`／`ItemSlot`，按要求选择堆叠与数量，不预选任何物品。桌面并列需求与物品栏，360px单列滚动；不符合当前要求的物品不会被选入。
- `materialSelections` 随actionId写入已有pendingAction和costLedger；纯领域函数只扣具体提交物品，预检与实际事务共用规则。提交引用失效整次拒绝，重试不改用别的物品。
- 继续、退出与恢复请求携带runId、round、status和pendingActionId，服务端在既有角色锁内比较。恢复操作必须在RECOVERABLE_ERROR且属于明确允许的动作；最终结算重试／再次退出沿用原结算及未提交成本。
- 秘境前端统一处理写请求失败：只做一次权威状态核实，不自动重发写请求；读取失败保留最近已知页面、禁用旧操作、提供重新读取。首次读取失败不展示新探索入口。锁冲突429／409提示仍在处理中。
- 状态读取使用同一角色锁，避免生成中读到旧轮次后误允许新行动。仅按本人runId读取已完成记录；浏览器sessionStorage只记角色对应的最近runId，结算确认后清除，不存库存或权威进度。
- Bun入口原先沿用默认10秒空闲超时，而秘境生成已有超过10秒的记录；仅六个秘境生成／结算POST请求设置240秒上限，与已有命令锁时长一致。前端90秒未确认时进入状态核实，不扩大其他接口超时。此项修正已知的超时配置不匹配，不将10X那次空响应的具体来源断言为已重现定位。
