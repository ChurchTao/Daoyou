# 召唤兽物种与通用生成底座定稿

2026-09-12。用户已确认十五种物种、资质成长区间、核心技能、出生候选及概率。本次将这些事实写入策划配置，并接通已有初始领取和捕捉个体生成；新增野外遭遇编排和金柳露洗炼玩法是后续接入，不属于本次功能。

## 数据权威与版本

- `src/shared/engine/combat-v6/beasts/data/species.json` 是物种权威：格式2、内容修订5。
- `species.schema.json` 由 `BeastSpeciesPackShape` 生成，提供编辑提示；`loadBeastPacks` 负责结构与跨技能引用校验。
- 图标、名称、描述、开放境界、携带等级、初始伙伴资格、五项资质、成长及出生技能概率都在JSON中。没有固定定位或物种加点偏好。
- 讨论中的“结丹”对应游戏已有“金丹”键；炼气／筑基／金丹／元婴／化神初期分别为5／25／45／65／85级。
- 原三个物种ID和资质成长范围保留。新增十二种独立物种记录，不依赖先注册野外敌人。旧ID中的`combat.wild.species`命名空间为兼容保留，不再意味着必须已经出现在野外。

## 生成接口与随机契约

`trait-generator.ts` 导出 `rollBeastTraits(species, seed): BeastTraits`。传入的是已通过内容包校验的物种定义，返回只含：

```ts
{
  aptitudes: { attack, defense, health, mana, speed },
  growth,
  skills,
}
```

该函数没有数据库、主人、UUID、等级、库存和属性加点依赖，也不修改输入配置。物种与seed相同时输出一致；不同seed允许生成相同个体，不承诺唯一性。

算法使用已有SeededRng：

1. 数值流直接使用seed，按攻击、防御、体力、法力、速度抽取整数闭区间，再抽取成长千分整数并除1000。保留旧三个物种数值流的顺序。
2. 额外数量流使用`seed ^ 0x5bd1e995`，按配置权重累计区间抽签。
3. 技能选择流使用`seed ^ 0x27d4eb2d`，从候选数组中等权取出并移除，直到满足数量。

这三个流使技能池／概率变化不扰动资质成长，数值范围变化不扰动技能。不同数值项仍按固定顺序使用数值流，不为技能多的个体降低资质，也不为高成长保底更多技能。配置数组顺序也是确定性输入，重排候选或概率行可能改变同种子的技能结果。

`generator.ts` 负责将抽取结果组装为正式个体。初始领取使用配置等级，捕捉使用传入等级；新个体的全部可分配点数置于`unallocatedPoints`，不按物种代替玩家加点。持久化输入仍经BeastSchema校验。

## 配置修改示例

```json
"birthSkills": {
  "core": ["beast.combo", "beast.sneak-attack"],
  "candidates": ["beast.agility", "beast.perception", "beast.counter"],
  "extraCountWeights": [
    { "count": 0, "weight": 70 },
    { "count": 1, "weight": 30 }
  ]
}
```

修改候选技能、概率、资质或成长不需要改抽取代码；修改结构则同步Zod与JSON Schema。权重为正整数且合计100，数量不得重复。校验同时检查未知／重复技能、核心候选重叠、高低级同族混入、抽取数量超过候选池、出生格数越界、区间倒置及境界等级映射。改变配置后提升内容修订，再运行定向测试与构建。

## 存量与追溯

新个体标记`summoned_beast_v2`，保存`generationContentRevision`和`generationSeed`。版本标记用于识别算法与配置，不代表仅凭种子就能在任意未来配置下重建；复现还需对应版本的配置，可从Git取得。

旧`summoned_beast_v1`和`summoned_beast_capture_v1`继续解析，内容修订字段对旧个体可缺省。已有技能格、技能、资质、成长、寿命与加点均不重置，也不要求存量落入新范围。仓储以完整individual JSON保存，因此无需数据库字段迁移。兽诀仍能覆盖核心技能。

| --- | --- | --- |

| 金柳露洗炼 | 可调用同一函数重抽生物事实 | 道具扣除、等级与加点重置规则、寿命处理、技能格更新、事务、重试幂等；本次没有新增道具或洗炼API |

洗炼不能直接覆盖整个正式个体，也不能让客户端指定最终seed或抽取结果；哪些字段允许重置由后续已确认的洗炼规则决定。战斗中的野怪抽取应使用遭遇入口分配的确定性seed，不使用时间或全局随机数。
