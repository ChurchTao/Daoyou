# 战斗常驻状态

擂台切磋、练功房和天骄榜以满状态入场，战斗损耗仅存在于单场快照。其余战斗从人物和灵兽的常驻状态装配，在常规终局提交气血和法力。人物常驻气血最低结算到 1。灵兽仅在实际出战后写回，发生阵亡时每场扣一次寿命并回满。技术中止与活动强制到期保留入场前的常驻状态。

人物继续使用 `cultivators.condition`。灵兽当前值位于 `cultivator_beasts.individual.vitals`，历史个体缺省值等于当前面板上限。修改上限时按修改前的当前绝对值裁切。拍卖及传送随同一灵兽个体保存血蓝。回合快照、历史评级和战报可持有当时的战斗事实。古魔周进度和秘境运行记录只承载玩法进度。

灵兽休养仅回复气血和法力。单只按物种最低携带境界计价，袋内批量休养按需要恢复的个体计费。补给入口和灵兽袋共用同一个接口与校验。寿命低于出战门槛的限制沿用现行规则。

## 停机切换

1. 按现有维护流程阻止新请求。用旧版本收尾已产生的终局，核对 Redis 终局队列、待处理奖励及 NATS 终局消息已结清。重点检查已结束但尚未写回的野外、结伴讨伐、古魔、秘境、试炼和百晓战。备份数据库和受影响 Redis 键，并记录已完成的场次和账本。
2. 停止旧 API、活动调度器和消费者。在受影响环境应用 `0086_unified_battle_vitals.sql`。迁移解除旧古魔场次与角色占用，保留个人通关、奖励进度、手牌和榜单。旧进行中秘境战局终止，已入账的战果保留。处于探索、补给和待迎战的秘境仍可读取进度。宗门任务和破境清理未结算战斗指针，百晓清理旧挑战指针。
3. 在目标 Redis 用 SCAN 核对并清理旧战局键 `combat:v6:*`、`tower:v6:configured-v8:run:*`、`dungeon:active:*`、`dungeon:battle-result:*`、`baixiao:duel:*`。此步骤须在旧终局结清后执行。保留已经归档的战报、蜃楼榜、天骄榜、周常进度、登录会话及其他缓存。擂台房间持有的旧战局引用继续由现有房间占用对账释放。
4. 配套启动新 API 和 SPA，检查健康、登录、常驻状态读取、休养扣费和首场新战局。检查终局重试没有重复扣寿或扣费。需要回滚时，保持维护入口，恢复配套旧版本及切换前数据。删除的列和旧战局键须从备份恢复。
