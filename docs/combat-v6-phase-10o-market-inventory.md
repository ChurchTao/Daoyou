## 开发边界

- 不迁移灵田其余消耗／收获、玩家交易、邮件赠送，不新增道装等商品，不处理历史补偿或删表。历史未鉴定材料继续走原鉴定路径。

## 实施与事务边界

- 新版购买契约位于 `src/shared/contracts/market.ts`：单件与批量统一为1–40个唯一 listingId，每项数量固定为1；提交 requestId 和确认金额，拒绝未知字段、客户端价格／商品事实。服务端重新计算价格，确认金额仅用于防止陈旧价格成交。
- `MarketInventoryDelivery` 复用 `grantInventory` 和既有 `material.v1` 事实，普通坊市与黑市共用；不会先写旧表再转换。
- 普通坊市扣款、整批入库和逐商品成交凭据同一 SQL 事务完成。复用已有玩家命令凭据表，不新增表、迁移、调度器或交易框架。
- 请求凭据处理响应丢失／重复提交；逐商品凭据阻止更换请求编号或改变批次组合再次购买。角色锁加账号购买锁保持跨角色的个人额度语义；查询按账号读取凭据。
- Redis 已购集合继续读取，并在事务后尽力更新；保留历史购买和删除旧角色后的账号标记语义。数据库凭据覆盖事务已经提交但 Redis 标记失败的窗口，重试也会补写 Redis。凭据沿用两天清理期限，长于最长两小时货架周期。
- 黑市复用已有会话锁、角色锁和成交幂等机制；只改变真实材料的发放出口。历史会话揭晓没有新 location 字段时不虚构去向。
- 新版材料不再推送旧 `inventory.materials` 条目；该事件仅用于仍写宝库的种子。交易响应更新灵石，坊市重新读取完整背包。
