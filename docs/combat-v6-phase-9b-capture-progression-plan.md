# Phase 9B：正式获取与基础成长实施计划

> 2026-09-06：已按确认边界实现，基础本地流程通过，完整验收仍有未验证项（见第 6 节）。依据：[总路线图](./combat-v6-mhxy-redesign-roadmap.md)、[召唤兽设计基线](./combat-v6-summoned-beast-system-design.md)、[9A 实施记录](./combat-v6-phase-9a-summoned-beast-plan.md)。

## 1. 目标与原则

完成“野外捕捉 → 持有编组 → 出战成长 → 自由加点 → 寿命恢复”的基础循环。继续复用 v6 战斗 UI、人物后宠物整组指令、权威事件、差量播放和统一归档。

捕捉尽量按一次普通施法处理，复用现有行动顺序、目标转向和 MP 支付机制。不为捕捉另建调度器、补偿流程或独立战斗状态机；只有捕获个体入库等持久副作用由 Host 和既有结算事务负责。

下列规则与数值已落实到代码；数值属于初版内容，尚未进行高等级平衡验证。

## 2. 已确认规则

### 捕捉

- 仅野外可捕捉单位开放；人物一级指令增加“捕捉”，占用本次人物行动，宠物仍正常下令。擂台和练功房不开放捕捉。
- 捕捉消耗人物 MP，随目标物种携带等级线性增加。不消耗灵石或捕捉道具，不增加熟练度、保底与补偿。
- 到行动执行时选择合法目标。原目标死亡或离场后，按现有目标选择顺序转向其他可捕捉目标；只能转向人物达到携带门槛的野生单位。
- 有合法目标且 MP 足够才施法扣费，概率失败同样消耗 MP。无合法目标或 MP 不足则不执行、不扣费，不额外寻找“更便宜”的目标。
- 首次下令时可校验目标和 MP，但不能替代执行时校验。超时／离线仍为普攻，不自动捕捉。
- 捕捉成功使目标退出战斗，明确区分捕获与死亡；宠物攻击原目标时沿用现有攻击转向规则。捕获单位不提供击杀奖励。
- 捕获个体战后入库，本场不能召唤。正常胜利、战败、逃跑均保留成功捕获成果；技术作废不发放。最后一名敌人被捕捉后按无敌方在场的正常胜负判定结束，不新增终局模式。
- 个体战斗等级沿用野怪等级，成长、资质、出生技能及固定技能格一次性独立生成，不复制野怪最终面板，不因重试重新掷骰。

### 两种等级与出战限制

- **携带等级**：物种的准入门槛。人物未达到时不能捕捉或出战。
- **战斗等级**：个体的实际成长等级。超过人物当前 v6 战斗等级时，允许持有，但不能首发、召唤或继续培养。
- 人物达到物种携带门槛时，可以捕获战斗等级高于自己的野怪；捕获后受上述限制。
- 培养等级上限为 `min(人物当前 v6 战斗等级, 180)`。到达上限不继续积累经验，多余经验不储存；人物等级不另建换算体系。
- 限制须在战斗入口与召唤候选生成时执行，不能只靠管理页按钮。无法出战的已有个体保持原始事实，不降级、不删除、不自动替换首发。

### 经验与加点

- 仅有效野外胜利产出宠物经验，擂台、练功房、战败及逃跑不产出。
- 仅终局在场且存活的己方已有灵兽获得完整宠物经验，不平均分配、不回溯上一只宠物。死亡、已召回和本场新捕获的个体均无资格；无符合条件个体时不发放。
- 灵兽当前只有存活、死亡，不增加人物式倒地。魂生等特殊兽诀在本阶段未纳入；后续已接入，见[技能迁移记录](combat-v6-beast-classic-skills.md)，现名以[文案定稿](combat-v6-beast-skill-copy.md)为准。
- 自动升级，每级五维各自然增加 1，并获得 5 点自由属性。妖类境界随等级推导，不增加突破机制。
- 捕获时已有的 `等级 × 5` 自由点按物种方向预分配；后续升级所得点数由玩家手动分配。
- 加点在战外批量编辑、预览、一次确认保存；不支持洗点、撤销或自动加点方案。战斗等级高于人物时也不允许分配已有点数；等于人物等级时可分配合法已有点数。
- 9A 个体原有成长、资质、技能格和加点全部保留，不重新生成。

### 管理与恢复

- 持有上限 24，只携带最多 6，单主人场上最多 1。本场已捕获待入库的个体也占持有名额，满额不能捕捉。
- 新捕获个体进入持有列表，不自动加入携带编组或替换首发。
- 放生无收益、不可恢复，确认前展示个体身份与信息；首发需先取消，放生同步移出携带编组。战斗及结算占用期间禁止管理变更。
- 9A 免费休养改为消耗灵石恢复寿命，确认前展示恢复量和费用；继续复用既有灵石资源写入路径。不增加饲料、配方或道具系统。
- 每场满 HP/MP 入场的规则不变，不引入战外补血补蓝。死亡每宠每场扣 50 寿命、低于 50 禁止出战等规则继续沿用。

## 3. 数值内容表（已确认并实现）

### 首批物种

仅开放现有青溪灵草坡三种物种，野怪等级继续为 5～15；不新增地图、稀有品种或品质评级。

| 物种   | 携带等级 | 捕捉 MP | 预分配方向 | 专长资质 | 必带出生技能 |
| ------ | -------: | ------: | ---------- | -------- | ------------ |
| 青灵狐 |        5 |      15 | 法力       | 法力     | 灵火         |
| 岩甲猪 |        5 |      15 | 体质       | 体力     | 岩甲护身     |
| 疾风狼 |        5 |      15 | 力量       | 攻击     | 疾风爪       |

三种均为启蒙物种，暂设相同门槛；未来高门槛物种仍使用相同线性 MP 公式。不得在未增加地图内容时改动现有野怪等级分布。

| 参数 | 推荐值 | 说明 |
| --- | --- | --- |
| 捕捉消耗 | `10 + 物种携带等级` MP | 门槛 5 / 20 / 60 时分别为 15 / 30 / 70 MP；后两项仅公式示例 |
| 捕捉概率 | `clamp(0.35 + 0.40 × (1 - 当前HP / 最大HP) + 0.01 × (人物等级 - 目标战斗等级), 0.10, 0.85)` | 同级满血 35%，半血 55%，10% 血量 71%；高 10 级目标降低 10 个百分点 |
| 个体成长 | 0.950～1.050，步长 0.001，均匀抽取 | 沿用 9A 区间 |
| 普通资质 | 900～1100，整数均匀抽取 | 专长资质额外 +100，沿用 9A |
| 初始／最大寿命 | 1000 / 1000 | 不增加随机寿命差异 |
| 出生技能格 | 1 格 80%，2 格 20% | 先确定数量，再生成组合；不扩大到 0 格或更多格 |
| 技能组合 | 必带物种主动技能；第 2 格固定为普通连击 | 复用已存在的普通连击定义，不投放高级连击；不加新技能池抽取层 |

出生格数建议用于提供最小个体差异，捕获后永久固定；9A 已领宠物仍保持原有 1 格。如果后续调整生成表，只影响新个体，旧事实保留。

### 经验与休养

| 参数 | 推荐值 | 示例／约束 |
| --- | --- | --- |
| 升级所需经验 | 当前等级 `L` 升至 `L+1`：`100 + 20 × L` | 5→6 为 200；10→11 为 300；15→16 为 400 |
| 胜利宠物经验 | 每名实际击败野怪贡献 `10 × 野怪战斗等级`，合计发给唯一合资格宠物 | 击败 10 级野怪获得 100；捕获单位贡献 0 |
| 等级衰减 | 9B 暂不增加 | 当前只有 5～15 级野怪，线性升级成本已降低高等级收益；新增高等级区域前重新评估 |
| 休养 | 一次恢复全部缺失寿命；每恢复 10 点消耗 1 灵石，费用向上取整 | 缺 50 点花 5 灵石；缺 1000 点花 100 灵石 |
| 满寿命／余额不足 | 不发起恢复／拒绝且不扣资源 | 不提供部分恢复滑杆或欠费恢复 |

示例：同等级 10 级宠物从 0 经验开始，胜利击败三只 10 级野怪即可升一级，前提是人物培养上限允许；若唯一敌人被捕获，正常结束但没有击杀经验。以上为初版可审查参数，不代表经过线上经济或高等级平衡验证。

## 4. 代码落点与实施顺序

### 第一步：共享规则与捕捉行动

- 在现有 `beasts` 领域模块增加物种携带门槛、捕获生成、经验升级、加点和休养价格等纯函数；沿用个体 `level`、`exp`、已分配／未分配点数字段。
- 当前经验校验上限为 100000，实施时按实际公式与“当前级内经验”语义核对，不盲目扩大字段。新生成版本应与旧个体生成版本并存识别，不重写旧个体来源。
- 捕捉接入现有行动、目标筛选和费用路径；core 仅执行中立规则／事件，物种表与持久化不能进入 core。
- 捕获结果在权威运行态中冻结，恢复不得再次抽取。捕获事件、目标退场和 MP 变化进入差量帧与回放。

验收：转向、MP 不足、失败扣费、目标退场、固定种子生成、技能格和点数守恒等纯共享测试通过；规则不依赖浏览器或数据库。

### 第二步：获取与持久结算

- 沿用当前野外 Host、运行态存储与有效结算凭据，持久化捕获个体、宠物经验、寿命及既有战斗奖励。
- 在原有事务边界内保证原子提交与重试幂等；每个捕获结果有稳定身份，重复恢复或结算不得重复入库／加经验／扣寿命。不另建按玩法区分的宠物结算表。
- 终局一次确定经验接收者，结算时不读取玩家后来修改的首发来替换接收者。经验上限由服务端权威人物等级约束。
- 捕获不计击杀；复核既有奖励汇总，不从“敌方不在场”反推全部被击败。
- 容量计算包含本场待入库捕获；继续复用人物锁及战斗占用限制，避免另建名额预订服务。

验收：实际本地捕捉、终局、恢复与重复结算不重复发放；正常逃跑／战败保留捕获、技术作废不发放。不得用数据库模拟单元测试代替运行验收。

### 第三步：管理与战斗 UI

- 捕捉沿用一级指令与阵容目标交互，返回修改、宠物步骤及整组提交方式不变；提供 MP 成本和不可捕捉原因。
- 灵兽详情分别标明携带门槛与个体战斗等级；加点在编辑时展示点数与面板变化，服务端重新校验输入。
- 增加放生与付费休养确认，保留现有详情抽屉／tooltip，不建立第二套通用组件或全局状态库。
- 人物、宠物等级限制贯穿编组、首次进入与战中召唤；禁止在页面重新计算另一套权威等级或成长面板。

验收：桌面／360px、返回修改、连续点击、战中管理阻止、容量已满与余额不足等行为正确，血条保持对齐。

### 第四步：验收与发布说明

- 完整循环：捕捉 → 结算入库 → 编组 → 胜利经验 → 自动升级 → 加点 → 下一场投影 → 死亡寿命 → 灵石休养。
- 验证最后在场且存活、末回合换宠、死亡、召回、上限丢弃经验和超等级捕获后的出战限制。
- 接续 9A 未验收的真实 4v4、带宠观战、PvE 死亡与结算重试、多备用宠换宠；多实例、慢连接等故障矩阵单独记录，不默认通过。
- 仅在 `src/shared` 增加纯确定性测试；浏览器按 `docs/testing.md` 使用本地账号，不添加一次性 seed／smoke／E2E 脚本，不向远程环境写测试数据。
- 执行 focused tests、适用的全量共享测试、`bun run lint`、`bun run build`、触及文件 Prettier 与 `git diff --check`。
- 维护期硬切协议与内容版本；是否需要数据库迁移由最终持久字段差异决定，不预先新增表。永久个体事实保留，归档继续冻结展示资料，列表不解包回放。无 v5 回退和功能开关。

## 5. 不包含

兽诀获取／打书、洗点、洗资质／成长、捕捉道具、稀有度、保底、宠物交易、合宠、装备、修炼、经验道具、离线训练、新地图、全仓 v5 退役。未来兽诀可能增加的死亡后特殊状态不提前实现。

## 6. 实施与验收记录

### 代码与发布

- `beasts/progression.ts` 集中实现捕获生成、捕捉技能、升级、加点、终局经验和休养价格；core 沿用技能执行路径处理费用、转向、成功退场与失败事件。
- 野外 Host 冻结捕获结果和终局经验，既有结算凭据与事务统一写入个体、成长和寿命。个体使用稳定 ID，不另建捕捉结算表。
- 管理服务沿用人物锁、战斗占用和 revision 校验；付费休养复用灵石资源事务。管理页增加预览加点、放生及费用确认，战斗页新增一级捕捉指令。
- 实时事件和公共回放剔除个体生成种子；捕捉失败保留独立行动失败事件，成功保留目标退场。归档继续冻结当场面板。
- 无数据库迁移，沿用已有个体 JSONB。启用 9B 规则与投影／野外内容版本；维护期清理旧活动战斗并刷新页面，硬切新协议，无双版本运行或功能开关。旧个体保留原始成长、资质、技能与加点。本轮未部署。

### 自动检查

全量共享测试 211 文件、1967 项通过；v6／契约定向测试 30 文件、236 项通过。最终事件脱敏变更后相关测试 5 文件、37 项通过。lint、客户端／服务端／Worker 构建和触及文件格式检查通过；未新增前端、服务端或数据库单元测试。

纯共享测试覆盖捕捉转向、失败扣 MP、无目标／MP 不足、容量、等级门槛、固定生成、点数守恒、经验上限、终局存活资格、恢复 RNG 一致及公开事件脱敏。这些测试不替代数据库与浏览器故障验收。
