# 灵植 JSON 配置与策划编辑

灵植目录的唯一内容源为 `packages/game-content/src/spirit-field/data/garden.json`，编辑器 schema 为同目录 `garden.schema.json`。运行时读取并校验该 JSON，界面、灵种生成与生长规则使用同一份目录，不另维护 TypeScript 物种列表。

灵植目录为凡品到神品各四种，共 32 种。

## 编辑入口

| 字段 | 编辑含义 |
| --- | --- |
| `schemaVersion` | 目录结构版本，当前为 `1` |
| `offlineCapMs` / `collectionLimit` | 基础积蓄时间与保种数量上限；实际积蓄上限不小于当前一轮周期 |
| `productionByQuality` | 八品质的实际药材、灵果与天材地宝生产周期，单位毫秒 |
| `species[].id` | 存档身份；已使用的 ID 不更名、不删除 |
| `name` / `description` / `element` | 成株名称、设定与五行 |
| `quality` | 物种固有品质；每阶对应独立物种 |
| `growthForm` / `harvestPart` | 种子在库存展示的形态与采收部位 |
| `portrait.atlas` / `portrait.index` | 图谱文件名和列号 `0–3` |
| `matureMs` | 播种至可付费成株的实际等待时间，单位毫秒 |
| `branchMs` / `evolveMs` | 从实际付费成株／定向后开始的分段等待基准，按原种品质倍率缩放 |
| `baseOutput` | 未定向时的产物名称、类别、说明；周期统一从品阶表读取 |
| `branches.abundance` / `branches.essence` | 繁茂与结实／凝珍的长期产物 |

新灵种名称始终由 `成株名称 + 的种子` 派生，例如“紫猴花的种子”，不另填种子名。品质本生物种不会因为蜕变换名或换物种；蜕变提高之后产物的品质一档，生产周期随产物品质调整。

成株等待直接使用 `matureMs`，凡品至神品为 5 分钟／15 分钟／30 分钟／1 小时／2 小时／3 小时／4.5 小时／6 小时。`branchMs` 从付费成株起计，`evolveMs` 从付费定向起计，二者按原种品质倍率 `1 + 品质序号 × 0.25` 放大。阶段等待彼此接力，各段时长独立配置。时间到达只解锁操作，不自动改变形态或发放首次收成。生产周期直接从 `productionByQuality[实际产物品质]` 读取最终毫秒数，不再乘品质倍率。`herbCycleMs` 对应基础药材与繁茂，`fruitCycleMs` 对应灵果，`treasureCycleMs` 对应凝珍。基础每轮一份、繁茂两份，灵果与天材每轮一份；各物种输出只配置产物本身，不重复维护周期与数量。蜕变后使用升品后的同类周期，物种身份不变。所有周期必须在二十八天寿命内。当前周期均不超过七天，包含神品三天二十二小时药材、十二小时灵果、五天十二小时天材，一茬可多轮收获。配置调整需重新构建并重启 API／刷新 Web，不支持运行中热更新。

种子与产物均沿用正常物品价格；种子基价在 `materials/config.ts`，成株／定向／蜕变灵气、固定成功率、三次尝试上限、二十四小时冷却及蜕变灵石比例在 `spirit-field/config.ts`。调平衡时核对整茬首熟、定向前收成、剩余寿命与种子成本，通过 `productionByQuality` 调整产量节奏。详见 [灵田收益预算](spirit-field.md#收益预算)。

坊市灵种品质使用 `spirit-field/config.ts` 的 `SPIRIT_GARDEN_MARKET_SEED_QUALITY_WEIGHTS`，在货架品阶范围内归一化；当前天层神品实际概率为 2%，常层和珍层分布不变。清畦返同株原种品质种子的概率为 `SPIRIT_GARDEN_CLEAR_SEED_CHANCE = 0.25`。灵兽遗种从全部 32 个物种等权抽取，八阶各四种，因此品质各占 12.5%。调整目录数量时需同步核对这一分布。

新种使用 `seedSpec.version = 2`，只保存物种身份、品质、名称与展示字段；成长时间、生产周期和培养规则读取当前目录，不再复制旧三阶段时间、产量范围或隐藏习性。目录选种器位于 API 的 `spirit-field/application/SpiritGardenSeedGenerator.ts`，只做随机选种，不调用 AI。通用材料 AI 的类型、随机池和提示词描述均排除种子。

库存播种只识别当前物种与其固定原种品质对应的种子身份，不按名称或五行猜测旧种。旧种经 [材料转化](seed-migration.md) 按同品质等数量随机换新，不能重新生成旧种作为奖励。已发布旧在田作物的迁移属于独立存档处理。

## 灵果复合效果

灵果产物使用 `kind: "spirit_fruit"`，在 `fruitEffects` 中列出 1–3 个不重复效果。每个效果只写 `family` 与 `share`，不允许直接填写状态操作或任意药效数值。

```json
"fruitEffects": [
  { "family": "healing", "share": 0.6 },
  { "family": "mana", "share": 0.4 }
]
```

`share` 必须为正数且合计为 `1`。上述组合将原同品灵果的恢复气血效果分配 60%，恢复法力效果分配 40%，共享一份预算。不会叠加两份完整灵果药效。单效果 `share: 1` 与旧灵果数值一致，仍沿用弱于同品丹药的基线；整数效果向下取整，每个配置效果必须能产生有效药效。

| `family`                    | 实际作用                         |
| --------------------------- | -------------------------------- |
| `cultivation`               | 下次闭关修为加成                 |
| `healing` / `mana`          | 战外恢复气血／法力               |
| `detox`                     | 降低丹毒                         |
| `insight`                   | 增加感悟                         |
| `breakthrough`              | 突破增益状态                     |
| `tempering` / `marrow_wash` | 推进气血炼体／洗髓               |
| `longevity`                 | 增加寿元，仍受寿元上限约束       |
| `beast_cultivation`         | 喂养灵兽增加修为，只允许单独配置 |

多效果由既有药效协议执行，保留境界、修炼等级、寿元和服用目标限制。`hybrid` 是生成复合果时的协议分类，不作为 JSON 中可填的效果族。旧存档待领单效果保留原用途与数量，不会随新配置被改写。

## 阶段立绘

每阶一张 `botanical-garden-*.webp`，四列对应同阶四株，四行依次为幼苗、成株、蕴灵、蜕变。神品只使用前三行。只有付费成株、付费定向和成功蜕变才切换对应阶段；蜕变失败保留蕴灵形态。素材位于 `apps/web/public/assets/spirit-garden/`。同一株固定根部落点，阶段差异使用花、果、分杈和剪影表达。图录取成株行，田块、详情和保种阁取实际阶段。空白与图格间隙使用透明 alpha。

立绘采用写意国画水墨，参考万界道友稀有灵兽的宽笔、飞白与局部彩墨。画面按纸色、深色底和手机田块尺寸验收。

## 修改后验证

1. 按 JSON Schema 编辑配置，核对稳定 ID、品阶、效果份额和图谱位置。
2. 执行内容与灵田规则的聚焦纯测试，检查全目录药效预算和存档兼容，再执行类型检查与构建。
3. 在本地页面按品质查看四种植物，检查 360px 和桌面图录、立绘、种子名与真实产物预览。

改变已存在物种的生产周期或存档身份，可能影响已存生产进度，需同时设计兼容规则；不能直接靠删除校验跳过损坏存档。完整物种清单见 [32 种灵植目录](spirit-garden-catalog.md)。
