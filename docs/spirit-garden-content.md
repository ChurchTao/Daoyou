# 灵植 JSON 配置与策划编辑

灵植目录的唯一内容源为 `packages/game-content/src/spirit-field/data/garden.json`，编辑器 schema 为同目录 `garden.schema.json`。运行时读取并校验该 JSON，界面、灵种生成与生长规则使用同一份目录，不另维护 TypeScript 物种列表。

灵植目录为凡品到神品各四种，共 32 种。

## 编辑入口

| 字段 | 编辑含义 |
| --- | --- |
| `schemaVersion` | 目录结构版本，当前为 `1` |
| `offlineCapMs` / `collectionLimit` | 积蓄生产时间上限与保种数量上限 |
| `species[].id` | 存档身份；已使用的 ID 不更名、不删除 |
| `name` / `description` / `element` | 成株名称、设定与五行 |
| `quality` | 物种固有品质；每阶对应独立物种 |
| `growthForm` / `harvestPart` | 种子在库存展示的形态与采收部位 |
| `portrait.atlas` / `portrait.index` | 图谱文件名和列号 `0–3` |
| `matureMs` / `branchMs` / `evolveMs` | 成株、定向、蜕变的基础在田成长时间，单位毫秒 |
| `baseOutput` | 未定向时的产物、数量、基础周期与说明 |
| `branches.abundance` / `branches.essence` | 繁茂与结实／凝珍的长期产物 |

新灵种名称始终由 `成株名称 + 的种子` 派生，例如“紫猴花的种子”，不另填种子名。品质本生物种不会因为蜕变换名或换物种；蜕变只提高之后产物的品质一档。

时间仍按原种品质倍率 `1 + 品质序号 × 0.25` 放大，序号从凡品 `0` 到神品 `7`。例如 JSON 中 4 小时基础生产周期，对灵品实际为 5 小时。配置调整需重新构建并重启 API／刷新 Web，不支持运行中热更新。

## 灵果复合效果

灵果产物使用 `kind: "spirit_fruit"`，在 `fruitEffects` 中列出 1–3 个不重复效果。每个效果只写 `family` 与 `share`，不允许直接填写状态操作或任意药效数值。

```json
"fruitEffects": [
  { "family": "healing", "share": 0.6 },
  { "family": "mana", "share": 0.4 }
]
```

`share` 必须为正数且合计为 `1`。上述组合将原同品灵果的恢复气血效果分配 60%，恢复法力效果分配 40%，共享一份预算。不会叠加两份完整灵果药效。单效果 `share: 1` 与旧灵果数值一致，仍沿用弱于同品丹药的基线；整数效果向下取整，每个配置效果必须能产生有效药效。

| `family`                    | 实际作用                         |
| --------------------------- | -------------------------------- |
| `cultivation`               | 下次闭关修为加成                 |
| `healing` / `mana`          | 战外恢复气血／法力               |
| `detox`                     | 降低丹毒                         |
| `insight`                   | 增加感悟                         |
| `breakthrough`              | 突破增益状态                     |
| `tempering` / `marrow_wash` | 推进气血炼体／洗髓               |
| `longevity`                 | 增加寿元，仍受寿元上限约束       |
| `beast_cultivation`         | 喂养灵兽增加修为，只允许单独配置 |

多效果由既有药效协议执行，保留境界、修炼等级、寿元和服用目标限制。`hybrid` 是生成复合果时的协议分类，不作为 JSON 中可填的效果族。旧存档待领单效果保留原用途与数量，不会随新配置被改写。

## 阶段立绘

每阶一张 `botanical-garden-*.webp`，四列对应同阶四株，四行依次为幼苗、成株、蕴灵、蜕变。神品只使用前三行。素材位于 `apps/web/public/assets/spirit-garden/`。同一株固定根部落点，阶段差异使用花、果、分杈和剪影表达。图录取成株行，田块、详情和保种阁取实际阶段。空白与图格间隙使用透明 alpha。

立绘采用写意国画水墨，参考万界道友稀有灵兽的宽笔、飞白与局部彩墨。画面按纸色、深色底和手机田块尺寸验收。

## 修改后验证

1. 按 JSON Schema 编辑配置，核对稳定 ID、品阶、效果份额和图谱位置。
2. 执行内容与灵田规则的聚焦纯测试，检查全目录药效预算和存档兼容，再执行类型检查与构建。
3. 在本地页面按品质查看四种植物，检查 360px 和桌面图录、立绘、种子名与真实产物预览。

改变已存在物种的生产周期或存档身份，可能影响已存生产进度，需同时设计兼容规则；不能直接靠删除校验跳过损坏存档。完整物种清单见 [32 种灵植目录](spirit-garden-catalog.md)。
