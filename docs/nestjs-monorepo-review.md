# NestJS 与 monorepo 迁移复核

日期：2026-10-05。审查版本：`48d9e33b`，迁移前对照：`c0b267df`；结合迁移提交 `0de7fd73` 和后续修复、主动下线提交区分回归与有意变更。

## 结论

属性分配问题确由迁移丢失请求投影引入，已在 `48d9e33b` 修复，并通过真实本地提交验证。本轮未确认新的未修复迁移回归。这个结论覆盖下面列出的静态审查与有限运行验证，不代表全部玩法、并发结算或生产环境已经验收。

近期属性分配和战斗身份字段问题有共同原因：迁移后的适配器传递了更宽的运行时对象，而 TypeScript 的结构类型仍允许它赋给较窄参数。领域实现没有变化、类型检查通过，并不能证明适配器传入的实际对象相同。

## 已确认问题及修复状态

### 属性分配把协议版本号当成点数（已修复）

- `packages/contracts/src/characterAttributes.ts` 的请求保留 `attribute_model_version: 2`。
- 迁移前 `src/server/routes/api/cultivator/profile.router.ts` 在提交前只选取六维属性；迁移后的 `apps/api/src/cultivator/profile.service.ts` 直接传递完整请求。
- `apps/api/src/cultivator/application/CultivatorProfileApplicationService.ts` 原用 `Object.values(delta)` 求和，因此申请 25 点会算成 27 点；余额不足时失败，余额足够时多扣 2 点。预览只算六项，产生预览与提交不一致。
- 当前实现显式相加六项，不再让版本号参与数值计算。
- 本轮实际提交 `{ attribute_model_version: 2, vitality: 100 }`：返回 200，体魄 70 → 170，剩余点数 100 → 0，气血上限 996 → 1820，与预览一致。随后通过正式本地 dev 调整接口恢复六属性、剩余点数和准备性气血／法力；再次读取确认体魄 70、剩余 100、气血上限 996。资源版本按正常命令递增，没有回滚事件历史。

### 活跃角色身份污染严格对象（此前已修复，本轮复核）

`ActiveCultivatorRef` 实际带 `status: 'active'`。此前 `...actor` 写入严格战斗运行时／事件对象导致解析报错，`ec98f4ad` 已在破境、排行榜、野外与狩猎相关路径改为显式身份字段。本轮继续检查剩余身份展开与请求转发，未找到新的确认遗漏；普通函数参数上的展开不能直接判定为错误，需要跟踪到最终构造／解析边界。

### 转世后的角色回算（此前已修复，本轮复核）

`dd96d909` 已让事务中的角色资源回算只读取 active 角色，避免已转世角色继续触发回算失败。本轮检查角色资源刷新、提交与失效通知的调用链；未实际再次转世测试角色。
