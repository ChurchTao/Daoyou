# V6 野外寻觅

玩家从常用地图进入已开放野外节点，点击「寻觅灵兽」，看到本次随机编组的物种、等级及成年／幼崽标记，然后选择「继续寻觅」替换当前遭遇，或「开战捕捉」进入既有 V6 战斗。没有区域移动和分支追踪，捕获仍通过战斗指令完成。

## 当前规则与配置

- 每次成功寻觅消耗 **2 点天地灵气**，开战不额外收费。刷新、重连不会重新寻觅；继续寻觅前明确提示会离开当前这组灵兽。
- 当前仅开放青溪灵草坡，成年等级 5–15，青灵狐、岩甲猪、疾风狼随机组成 1–3 只编组。
- 每只灵兽暂定 5% 概率为 0 级幼崽；移除旧每日 20 次上限，以灵气消耗约束寻觅。两项属于本次实施默认值，可继续调优。
- 成年五维额外点数先均衡分配，再在均值 ±30% 的整数边界内转移，总量不变。幼崽无额外加点。资质、成长、出生技能沿用灵兽内容包。
- 区域配置：`src/shared/engine/combat-v6/wild/data/wild.json`；统一费用：`src/shared/config/qiSystem.ts`；掉落：`src/shared/rewards/data/wild.json`。

## 权威数据与恢复

1. `POST /api/combat-v6/wild/explorations` 接收节点与请求 UUID。角色锁与数据库事务内校验战斗占用、境界、构筑和寻觅间隔，生成完整个体，扣除灵气并保存遭遇。费用、结果、幂等请求和资源事件共同提交；失败整体回滚。
2. `wanjiedaoyou_wild_searches` 每个角色保留一个当前遭遇。前端只接收公开的物种和等级，不能提交资质、技能或其他个体事实；再次寻觅替换原结果。刷新从数据库恢复，不扣费。
3. `POST /api/combat-v6/wild/sessions` 只接收当前 `encounterId`。服务端检查角色归属与当前结果，读取当前人物构筑和恢复后的资源，使用已保存灵兽的面板、主动技能和被动创建战局；战局 ID 与遭遇 ID 一致。
4. 开战先在 PostgreSQL 保存准备快照，再发布 Redis 权威战局与请求回执。发布前中断可重试：重新读取人物状态，保留灵兽、战斗 ID 与原有到期时间。重复已接收的开战请求返回原战局，不扣费、不重抽；过期或已结束的遭遇不能重新开战。
5. 捕捉成功从战局冻结的个体直接复制结算，沿用既有 NATS 结算及角色资源提交链路入库，捕获时不调用随机生成器。

页面的短暂寻觅反馈使用统一加载组件，结果淡入尊重系统减少动态效果设置。灵气余额走既有资源 store；请求失败时保留幂等键，明确的客户端拒绝才重新生成键，并重新读取当前遭遇以恢复已提交结果。

## 迁移与版本

- `drizzle/0050_wild_searches.sql` 仅新增遭遇保存表与角色外键，无旧资产迁移。
- 新战局使用 `daoyou_wild_seeking_content_v2` / `wild_individual_v3`。旧活动野外战局缺少完整个体，恢复时按既有 technical-abort 路径结算已记录的资源和捕获事实，不将旧战局补抽为新个体。上线应先结束旧活动野外战局。
- 本轮迁移已应用专用本地数据库；其他环境发布前仍需执行项目迁移流程。
