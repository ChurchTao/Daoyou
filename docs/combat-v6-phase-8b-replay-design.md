# Phase 8B：新版战绩与逐行动回放

> 2026-09-06：实现已接入；共享测试、静态检查与本地迁移通过。浏览器因 Mac 锁屏未完成本轮交互验收，不标记整阶段验收完成。

## 范围与硬切

- `/game/battle/history` 仅显示当前角色关联的 v6 练功房、野怪和擂台归档，按来源筛选，每页 10 条。
- `/game/battle/:id` 使用独立 v6 播放器。战斗结束页提供单场回放入口，详情单独加载。
- 旧 `/api/battle-records/*`（包括列表、单场、分享创建和公开读取）统一返回 410；旧公开分享页只提示已停止查看。数据库旧记录保留，不清表，不读取旧记录作为 fallback。
- 首版仅本人视角，不开放观战、分享、切换他人视角、视频导出、统计分析或召唤兽养成。

## 列表绝不读取完整回放

继续使用统一 `wanjiedaoyou_combat_v6_replay_archives` 与 `wanjiedaoyou_combat_v6_replay_participants`，不按玩法拆表。

归档时在主表写入 `round_count`、`sides`（冻结的双方名称数组）、`playable`；关联表保存 `side`。胜负以归档胜方和当前角色阵营转换为本人结果。

`GET /api/combat-v6/replays?page=1&source=arena-sparring`：

- 通过当前活跃角色授权，只 JOIN 该角色的参与记录。
- 显式 SELECT battle ID、来源、结束时间、回合数、双方名称、结果、可播放标记和阵营；不 SELECT `replay`，不使用 `replay->...` JSON 表达式，不调用详情 repository，不查询每场人物资料。
- 按结束时间和 battle ID 倒序，读取 11 条确定下一页，不执行全量计数；响应仅返回 10 条元数据。
- 前端筛选与页码存于 URL；切换筛选、页码、角色或卸载取消过期请求。列表不预取详情，不解包录像，不导入播放器。

迁移 `0037_v6_replay_history_metadata.sql` 对既有 v6 归档执行一次元数据提取并补齐参与方。这是维护期的数据迁移，不是列表请求路径。应用仅在本地数据库完成，未执行远程迁移。

## 历史展示来源

新归档使用 `combat_v6_replay_v2`，在既有初始构筑、种子、指令、事件与终态之外保存：

- `timeline.initialUnits`、`initialRound`、`fromEventSeq`：开场展示基准。
- `timeline.frames`：每行动、回合末的绝对值差量。状态/护盾/资源数组整体替换，单位增减及顺序显式表达。
- `timeline.finalUnits`：冻结终态展示，供完整性校验，不使用最新版属性计算重建历史终态。
- `display`：归档时冻结的技能名称、描述和状态名称。

PvE Host 与擂台在权威行动观察回调中采集单位展示差量，回合末补帧；和对应运行态在同一次持久提交中保存。没有第二次结算，不消耗额外 RNG，不从战报反推气血。恢复运行态会保留历史差量；缺失开场基准的旧运行态继续产生静态 v1 归档，不伪造前半场状态。

读取单场时先校验格式和归属；在服务端逐帧应用原始展示差量，再投影为本人精确数据／其他单位比例血条，重新计算可下发差量。私有事件过滤后重新编号，帧游标同步映射。不能直接下发原始归档或原始差量给客户端。重建终态必须与冻结终态一致。

## 播放器与版本边界

- 复用 `CombatV6Roster`、`CombatV6Log`、`CombatV6Details` 及既有 v5 资源配色；替换底部指令栏为回放控制，不建立 WebSocket、不提交战斗操作。
- 默认暂停，点击播放后 1 秒推进一个行动；支持暂停、上一/下一行动、重置到开场、回合跳转、0.5/1/2/4 倍速。回合、单位和战报游标一起更新；终局表现到时间线结束后才出现。
- 战报进入播放器时整理一次，播放只推进可见游标。名称索引包含初始、终态和新增单位。
- 按需每 32 帧保存检查点，最多保留 16 个（包含开场）；未变化单位结构共享。回退从最近检查点重建，不维护全部完整行动快照或反向差量。
- v1 既有 v6 记录仅展示战报及最终状态，并明确缺少动态数据。未知格式或损坏差量拒绝读取，不能调用当前引擎重新执行旧录像。
- 引擎版本记录规则来源，回放格式版本管理读取方式。以后升级必须保留已发布展示格式的明确读取语义。
