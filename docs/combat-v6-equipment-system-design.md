# combat-v6 道装系统设计

> 状态：装备领域方向基线（Canonical）  
> 建立日期：2026-09-02  
> 上位设计：[`combat-v6 梦幻式战斗体系设计稿与迁移路线图`](./combat-v6-mhxy-redesign-roadmap.md)  
> 适用范围：combat-v6 人物装备、生成、装配与战斗投影

本文定义 combat-v6 的全新装备系统。它采用梦幻式六部位、白字、附加属性、被动特效和主动特技结构，同时使用修仙世界观表达。

本系统从领域模型、生成规则、持久化事实到战斗投影均完全独立，不读取、转换或复用其他装备系统的数据和运行时产物。

---

## 1. 已确认的硬约束

1. 新系统正式名称为“道装”。
2. 道装使用六部位：法兵、法冠、法衣、灵佩、腰封、云履。
3. 不存在品质、稀有度、颜色等级或由系统给出的权威装备档次。
4. 玩家只根据实际白字、附灵属性、器蕴、器诀、灵纹和淬炼结果判断价值。
5. 不保存或展示综合战力分、装备评分、S/A/B 档、极品标签等替代品质的结论。
6. 同器阶装备可以出现明显不同的实际价值；优质组合本身就是稀缺性。
7. 道装不使用境界衰减。器阶和御使等级负责纵向换代。
8. 道装不能提供攻法、防御、法术、抗法四项修炼等级。
9. 道装不能修改角色持久六维；附灵六维只在入场投影中生效。
10. 所有战斗效果必须编译为 combat-v6 的面板贡献、被动、器诀或单位标签。
11. 道装实例不保存 `SkillDef`、最终面板或其他可由版本化注册表重建的运行时对象。
12. “法宝”保留给未来独立的法宝系统，不作为六部位道装的名称。

### 1.1 “没有品质”的精确定义

以下字段和概念不得进入道装领域：

```text
quality
rarity
tierColor
itemGrade
powerScore
equipmentRating
极品 / 稀有 / 史诗 / 传说等系统判定标签
```

`equipmentLevel`（器阶）不是品质。它只表示数值基准和穿戴等级。

生成概率也不是品质。器蕴或器诀可以很少出现，但道装实例只记录“有什么”，不会因为出现了稀有结果而被系统追加一个品质分类。

## 2. 世界观术语

| 机制概念 | 游戏内名称 | 说明 |
| --- | --- | --- |
| Equipment system | 道装 | 六部位人物装备总称 |
| Equipment level | 器阶 | 装备数值等级，建议 10～180 |
| Required level | 御使等级 | 人物战斗等级达到后方可装备 |
| Base stats | 器胚属性 | 由部位和器阶决定的白字 |
| Bonus attributes | 附灵属性 | 随机的投影期六维加成 |
| Passive special effect | 器蕴 | 装备自带常驻被动 |
| Active special skill | 器诀 | 消耗战意主动施放的装备技能 |
| Enhancement | 淬炼 | 提升器胚白字的独立成长层 |
| Gem | 灵纹 | 提供定向固定属性的镶嵌物 |
| Reforge | 重铸 | 重置附灵结果 |
| Affix lock | 锁灵 | 重铸时保留指定附灵 |
| Crafting | 炼器 | 生成全新道装 |
| Identification | 鉴器 | 揭示道装实际生成结果 |
| Rage resource | 战意 | 使用器诀的战斗资源 |

代码使用稳定、无叙事歧义的英文领域名；中文名称属于展示词典，不应散落在计算逻辑中。

## 3. 六部位

```ts
type DaoEquipmentSlot =
  | 'weapon'
  | 'head'
  | 'armor'
  | 'necklace'
  | 'belt'
  | 'footwear';
```

| 枚举 | 中文槽位 | 可用外观 | 器胚定位 |
| --- | --- | --- | --- |
| `weapon` | 法兵 | 剑、刀、枪、杖、扇、幡、珠、琴 | 伤害、法伤、命中 |
| `head` | 法冠 | 冠、簪、盔、巾、莲冠 | 防御、法力 |
| `armor` | 法衣 | 道袍、灵甲、羽衣、战铠 | 防御、法防 |
| `necklace` | 灵佩 | 玉佩、璎珞、灵珠、护符 | 法防、法伤 |
| `belt` | 腰封 | 道带、玉带、兽纹腰封 | 气血、防御 |
| `footwear` | 云履 | 云靴、道履、战靴、踏风履 | 速度、闪避、防御 |

外观类型不改变槽位规则。剑宗的飞剑、鬼道的魂幡和音修的古琴都属于 `weapon`，不会产生宗门专属装备枚举。

每个角色同一时间只能在每个槽位装备一件道装。

## 4. 道装实例的组成

一件道装由以下事实组成：

```text
身份
├─ 实例 ID
├─ 模板 ID
├─ 名称与外观形态
├─ 部位
├─ 器阶与御使等级
└─ 生成版本

战斗事实
├─ 器胚属性
├─ 附灵属性
├─ 器蕴 ID
├─ 器诀 ID
├─ 淬炼状态
└─ 灵纹状态
```

没有任何额外品质层对这些数值进行统一乘算。道装价值完全由上述事实组合形成。

### 4.1 建议实例契约

```ts
interface DaoEquipmentInstanceV1 {
  schemaVersion: 1;
  id: string;
  templateId: string;
  name: string;
  slot: DaoEquipmentSlot;

  equipmentLevel: number;
  requiredLevel: number;

  baseStats: DaoEquipmentPanelRoll[];
  attributeBonuses: DaoEquipmentAttributeRoll[];

  essenceIds: string[];
  artId?: string;

  tempering: {
    level: number;
  };
  inscription?: {
    inscriptionId: string;
    level: number;
  };

  appraisalState: 'unappraised' | 'appraised';
  generatorVersion: string;
  createdAt: string;
}
```

这个结构刻意没有：

- `quality`
- `rarity`
- `score`
- `battleProjection`
- `SkillDef`
- v5 modifier 或能力配置

物品归属、交易、绑定和来源记录属于持久化/经济外围事实，不进入纯战斗投影契约。

## 5. 器阶与自然换代

建议器阶：

```text
10、20、30……180
```

基本规则：

```text
人物战斗等级 >= requiredLevel
```

默认情况下 `requiredLevel = equipmentLevel`。器蕴可以显式降低御使等级，但不能改变道装的器阶和白字基准。

低器阶道装不会因为角色成长而衰减。它的实际数值保持不变，只会自然落后于高器阶道装。这样装备比较、交易定价、回放和战斗投影都没有隐藏倍率。

同器阶的生成区间由版本化模板唯一决定。修改区间必须提升 `generatorVersion`；已生成实例保留实际数值，不随新模板漂移。

## 6. 器胚属性

器胚属性是部位固定拥有的面板白字，每个数值在器阶对应区间内独立生成。

### 6.1 部位白名单

| 部位 | 主器胚属性 | 次器胚属性 |
| --- | --- | --- |
| 法兵 | `physicalAtk` | `magicAtk`、`hit` |
| 法冠 | `physicalDef` | `maxMp` |
| 法衣 | `physicalDef` | `magicDef` |
| 灵佩 | `magicDef` | `magicAtk` |
| 腰封 | `maxHp` | `physicalDef` |
| 云履 | `speed` | `dodge`、`physicalDef` |

第一版所有器胚属性均使用固定点数。比例类效果进入器蕴，不进入普通白字，避免面板出现难以比较的混合乘区。

### 6.2 生成原则

- 每个部位的核心器胚字段固定，不随机缺失。
- 实际数值在当前器阶的合法区间内生成。
- 各字段分别生成，不使用单一总分在字段间反推。
- 不因为器蕴、器诀或附灵优秀而压低白字作为“预算补偿”。
- 不因为白字优秀而降低器蕴、器诀概率。

优秀白字、优秀附灵和优秀特殊效果可以同时出现。这种组合稀缺性就是装备价值的来源。

## 7. 附灵属性

附灵只允许提供六项角色基础属性的投影期加成：

```ts
type DaoEquipmentAttributeName =
  | 'vitality'
  | 'strength'
  | 'spirit'
  | 'endurance'
  | 'speed'
  | 'willpower';
```

对应显示：体魄、力道、灵力、根骨、身法、神识。

### 7.1 生效方式

```text
角色持久六维
+ 六件道装附灵六维
= 本场有效六维
→ 计算基础战斗面板
→ 叠加道装器胚与其他系统贡献
```

附灵不会写回 `Cultivator.attributes`。卸下道装后，重新投影即可移除其影响。

### 7.2 生成规则

第一版建议：

- 每件道装生成 0～2 条附灵。
- 同一属性在同件道装上最多出现一次。
- 暂不加入负属性换取更高正属性。
- 附灵数量和数值分别生成。
- 不存在“达到某品质才有两条附灵”的门槛。
- 不同玩法来源使用同一器阶生成法则；高难玩法通过增加掉落机会，而不是使用隐藏的高品质版本。

部位可以设置生成倾向，但不完全锁死属性：

| 部位 | 倾向属性 |
| --- | --- |
| 法兵 | 力道、灵力、神识 |
| 法冠 | 体魄、神识、灵力 |
| 法衣 | 体魄、根骨、力道 |
| 灵佩 | 灵力、神识、体魄 |
| 腰封 | 体魄、根骨、身法 |
| 云履 | 身法、神识、根骨 |

倾向只影响生成权重，不能制造宗门专属装备。

## 8. 器蕴

器蕴是道装自带的常驻被动特效。实例只保存器蕴 ID，实际定义由 `contentVersion` 对应的 v6 内容注册表提供。

```ts
interface DaoEquipmentEssenceDef {
  id: string;
  name: string;
  allowedSlots?: DaoEquipmentSlot[];
  conflicts?: string[];
  stackPolicy: 'unique' | 'highest' | 'stack';
  passiveId?: string;
  innate?: DaoEquipmentInnateContribution;
  panel?: CombatV6PanelContribution[];
}
```

### 8.1 第一批建议方向

| 器蕴 | 作用方向 |
| --- | --- |
| 轻灵 | 降低御使等级要求 |
| 藏锋 | 提升物理会心 |
| 凝神 | 提升法术会心 |
| 定魂 | 提升封禁抵抗 |
| 破禁 | 提升封禁命中 |
| 不屈 | 通用致命保护 |
| 激昂 | 受到伤害时额外获得战意 |
| 归元 | 降低器诀战意消耗 |
| 纳灵 | 满足条件时恢复法力 |
| 再生 | 回合结束恢复少量气血 |

第一版每件道装最多一个器蕴。待冲突和叠加规则稳定后，再决定是否允许少量双器蕴组合。

### 8.2 边界

- 强器蕴通过低生成概率形成稀缺性，不附加稀有度标签。
- 同名 `unique` 器蕴装备多件只生效一次。
- 器蕴不得直接修改四项修炼等级。
- 器蕴不得按宗门 ID 或经脉节点 ID 分支。
- 单个装备特例必须抽象为可复用被动、条件或状态原语。

---

## 9. 器诀与战意

器诀是道装授予的主动特殊技能。每件道装最多携带一个器诀，实例只保存器诀 ID：

```ts
interface DaoEquipmentArtDef {
  id: string;
  name: string;
  rageCost: number;
  skillId: string;
  allowedSlots?: DaoEquipmentSlot[];
}
```

所有已装备器诀都可以在战斗中使用；快捷栏只是 UI 偏好，不是能力限制。

### 9.1 战意资源

游戏内称“战意”，代码使用独立的 `rage` 资源：

```ts
interface CombatV6RageState {
  rage: number;
  maxRage: number;
}
```

当前 `furyRate` 表示物理狂暴概率，不是器诀资源。实现战意前应消除命名歧义，推荐将其改名为 `physicalFuryRate`。

### 9.2 器诀内容方向

- 单体或群体治疗。
- 解除封禁、驱散负面状态。
- 复活。
- 群体攻防增益。
- 驱散敌方增益。
- 单体爆发或特殊伤害。
- 战术性保护、减伤或速度调整。

器诀不属于宗门，不使用宗门心法等级。其强度来自器诀定义、人物面板和战意成本。

## 10. 淬炼、灵纹与重铸

这三种成长必须彼此独立，避免一次操作重置整件装备价值。

### 10.1 淬炼

- 只提升器胚白字。
- 不放大附灵六维。
- 不修改器蕴或器诀。
- 淬炼等级受到器阶上限约束。
- 淬炼增量由固定表计算，不存浮动公式结果。

### 10.2 灵纹

- 提供部位白名单内的固定面板属性。
- 不生成被动和主动技能。
- 第一版每件道装最多镶嵌一种灵纹。
- 灵纹可升级，但升级不会改变灵纹属性类型。

建议方向：

| 部位 | 灵纹方向 |
| --- | --- |
| 法兵 | 伤害、法伤、命中 |
| 法冠 | 防御、法力 |
| 法衣 | 防御、法防 |
| 灵佩 | 法防、法伤 |
| 腰封 | 气血、速度 |
| 云履 | 速度、闪避 |

### 10.3 重铸与锁灵

- 只重置附灵数量、属性种类和数值。
- 不改变器阶、器胚、淬炼和灵纹。
- 默认不改变器蕴与器诀。
- 可锁定一条附灵后重铸其余内容，消耗随锁灵数量增加。
- 器蕴和器诀若开放重铸，必须使用完全独立的稀缺资源和操作入口。

## 11. 鉴器

鉴器是推荐保留的梦幻式获得体验，但它不影响战斗结构。

推荐规则：

1. 道装生成时，服务端已经确定全部实际结果和 `generatorVersion`。
2. 未鉴定状态只隐藏白字之外的结果，不能装备、重铸或交易为已知属性物品。
3. 鉴器只揭示既有结果，不在点击时重新随机。
4. 鉴器失败、客户端重试或网络重放不能改变结果。

若第一版暂不实现鉴器，可以统一生成 `appraisalState: 'appraised'`；契约仍保留状态位，后续无需重构实例结构。

## 12. 确定性生成

道装生成器是独立的纯领域模块，不调用战斗 Session，也不依赖其他物品生成体系。

```ts
interface GenerateDaoEquipmentInput {
  seed: number;
  templateId: string;
  equipmentLevel: number;
  generatorVersion: string;
}
```

建议生成顺序：

```text
校验模板与器阶
→ 生成各项器胚白字
→ 生成附灵条数
→ 生成附灵属性与数值
→ 独立判定器蕴
→ 独立判定器诀
→ 生成名称/外观变体
→ 校验完整实例
→ 固化实际事实
```

同一 seed、模板、器阶和生成版本必须得到相同结果。

### 12.1 不使用总预算纠偏

生成器不应在最后计算“总战力过高”并削弱其中某项。否则玩家观察到的各项概率会被隐藏相关性破坏。

合法组合由以下规则控制：

- 各字段独立合法区间。
- 器蕴/器诀显式冲突表。
- 每件装备的数量上限。
- 部位白名单。
- 生成版本固定概率表。

系统允许真正意义上的极品组合出现，但不替玩家贴“极品”标签。

## 13. 战斗投影

```ts
interface DaoEquipmentProjectionV6 {
  baseAttributeBonuses: Partial<Attributes>;
  panel: CombatV6PanelContribution[];
  passiveIds: string[];
  grantedSkillIds: string[];
  unitTags: string[];
  diagnostics: CombatV6ProjectionDiagnostic[];
}
```

投影顺序：

```text
校验六槽装配
→ 校验器阶、御使等级和鉴器状态
→ 汇总附灵六维
→ 由有效六维计算角色基础面板
→ 汇总器胚、淬炼和灵纹贡献
→ 解析器蕴冲突与叠加策略
→ 授予器诀
→ 输出诊断
```

道装投影器不创建 `BattleSession`，也不写入角色永久属性。

### 13.1 面板白名单

道装可以直接贡献：

```text
physicalAtk
physicalDef
magicAtk
magicDef
maxHp
maxMp
healPower
speed
hit
dodge
critRate
spellCritRate
physicalFuryRate（完成字段更名后）
sealHit
sealResist
```

道装禁止直接贡献：

```text
level
skillLevels
attackCultivate
defenseCultivate
spellCultivate
resistSpellCultivate
```

```text
├─ content/equipment/         # 器蕴、器诀、模板与灵纹表
```

推荐注册表：


## 15. 展示与玩家估值

系统只展示可验证事实：

- 器阶和御使等级。
- 每一项器胚实际值。
- 每一条附灵实际值。
- 器蕴和器诀的完整规则文本。
- 淬炼和灵纹的实际贡献。
- 与当前已装备道装的逐项面板差异。

系统不展示：

- 装备品质。
- 稀有度颜色。
- 综合评分。
- “推荐替换”结论。
- “适合某宗门”的系统标签。
- 用隐藏权重计算的价值排序。

允许背包按器阶、部位、获得时间和具体属性筛选；市场允许玩家按实际字段设条件。默认排序不应伪装成价值判断。

道装名称和边框可以表达部位、元素意象或来源风格，但不能通过固定颜色暗示一个不存在的品质体系。

## 16. 校验规则

实例校验至少包括：

- `slot` 属于六部位枚举。
- 器阶和御使等级属于允许区间。
- 器胚字段符合部位白名单。
- 所有数值为有限数并处于对应生成版本区间。
- 附灵只使用六维且同件不重复。
- 器蕴数量不超过版本上限，引用存在且无冲突。
- 器诀最多一个，引用存在且允许该部位出现。
- 淬炼等级不超过器阶上限。
- 灵纹符合部位白名单。
- 未鉴定道装不能进入战斗投影。
- 实例不包含品质、评分或运行时战斗对象。

所有校验均应返回结构化诊断，而不是依赖展示层猜测失败原因。

## 18. 测试与质量门禁

纯领域测试位于 `src/shared`，至少覆盖：

- 同 seed、模板、器阶和版本生成完全相同的实例。
- 所有部位只生成白名单器胚。
- 附灵只使用六维且不写回角色持久属性。
- 无品质、稀有度和评分字段进入实例。
- 装卸道装只改变 v6 投影结果。
- 器蕴冲突与叠加规则确定性。
- 器诀引用和战意成本完整性。
- 淬炼只改变器胚贡献。
- 重铸不改变被锁定事实。
- 未鉴定实例不能进入战斗。
- 内容表不存在悬空 ID。

还必须通过架构测试保证道装领域不导入其他装备、物品生成或战斗运行时实现。

## 19. 尚待数值设计确认

以下属于平衡表问题，不影响本设计的结构实施：

- 10～180 各器阶、各部位的器胚区间。
- 附灵条数概率和每器阶数值区间。
- 六部位的附灵倾向权重。
- 第一批器蕴列表、概率和叠加策略。
- 淬炼上限、提升曲线和消耗。
- 灵纹种类、等级曲线和合成消耗。
- 战意上限、获取公式和第一批器诀成本。
- 是否在第一版开放鉴器，或先统一为已鉴定状态。

这些数值必须通过版本化配置管理，不得写入 combat-v6 core。
