# combat-v6 角色六维与战斗面板设计

> 状态：角色基础投影方向基线（Canonical）
> 建立日期：2026-09-02
> 上位设计：[`combat-v6 梦幻式战斗体系设计稿与迁移路线图`](./combat-v6-mhxy-redesign-roadmap.md)
> 适用范围：combat-v6 人物永久六维、有效六维、裸身面板与入场面板编译

本文定义角色现有六维如何进入 combat-v6，并锁定第一版正式面板公式 `character_panel_v1`。

现有角色的自然成长、自由加点和洗点成果全部保留；battle-v5 的 `AttributeSet`、六阶段 modifier 和战斗投影不进入 v6 生产链路。公式即使采用与旧面板相近的起始数量级，也必须由 combat-v6 独立实现、测试和版本化。

---

## 1. 已确认的硬约束

1. `Cultivator.attributes` 继续只保存体魄、力道、灵力、根骨、身法、神识六项永久基础属性。
2. 现有境界自然成长、自由属性点、属性分配和洗点规则完整保留。
3. 最终战斗面板是可重建的运行时投影，不写回角色六维或数据库派生字段。
4. combat-v6 不调用 battle-v5 的属性计算器，也不读取旧装备、功法、宗门和炼体 modifier。
5. 道装附灵提供的六维只形成投影期有效六维，不改变永久六维。
6. 首版种族、灵根和命格完全不进入 combat-v6 投影，不生成面板、技能、被动、状态、单位标签或条件；境界压制不参与本面板公式。
7. 人物 `level` 和 `skillLevels` 不参与裸身面板推导，避免与六维自然成长重复计入成长。
8. `hit`、`dodge`、`sealHit`、`sealResist` 都是面板点数，不是 0～1 概率。
9. 四项修炼是独立等级字段，不由六维生成，也不提前改写物攻、物防、法攻和法防。
10. 六维不直接提供物理暴击、法术暴击或物理狂暴增量。
11. 相同角色事实、build 快照和 `projectionVersion` 必须产生完全相同的入场面板。

## 2. 保留的角色成长

角色永久六维继续使用现有成长规则：

```text
初始六维每项 = 10

每次小境界突破：
  六维每项自然成长 +2
  自由属性点 +10

每次大境界突破：
  六维每项自然成长 +4
  自由属性点 +20
```

每个完整大境界累计：

```text
六维每项自然成长 +10
自由属性点 +50
```

当前境界阶段的单项自然属性为：

```text
natural = 10 + realmIndex × 10 + stageIndex × 2
```

洗点只移除玩家分配部分，将六维恢复到当前境界自然值，并返还所有已分配点。combat-v6 不另建第二套人物加点数据。

## 3. 永久六维与有效六维

### 3.1 永久六维

```text
永久六维
= 境界自然属性
+ 玩家自由加点
```

永久六维是角色持久真相。任何战斗投影、装备装卸、功法替换和状态变化都不得修改它。

### 3.2 有效六维

```text
有效六维
= 永久六维
+ 当前道装附灵六维
```

首版只有道装附灵进入六维派生之前。道装器胚、灵纹、淬炼、器蕴，修炼、功法、宗门心法和经脉默认输出最终面板贡献或被动，不伪装成永久六维。

未来若允许其他来源修改有效六维，必须新增明确的 `effectiveAttribute` 贡献类型、固定编译顺序并提升 `projectionVersion`，不能把它混入普通最终面板加法。

## 4. 六维职责

| 六维 | 主职责 | 次职责 | 不负责 |
| --- | --- | --- | --- |
| 体魄 `vitality` | 最大气血 | 少量治疗强度 | 法术防御、暴击 |
| 力道 `strength` | 物理攻击 | 无 | 命中、速度、物理暴击 |
| 灵力 `spirit` | 法术攻击 | 最大法力、封禁命中 | 治疗强度、法术暴击 |
| 根骨 `endurance` | 物理防御 | 少量最大气血 | 法术防御、封禁抵抗 |
| 身法 `speed` | 行动速度 | 命中、闪避 | 暴击、封禁命中 |
| 神识 `willpower` | 法术防御 | 最大法力、治疗强度、封禁抵抗 | 法术攻击、封禁命中 |

力道不再额外增加命中，避免纯力道构筑同时取得最高伤害和稳定命中。灵力与神识分别承担封禁进攻和防守，使控制构筑仍存在属性取舍。

## 5. `character_panel_v1` 裸身公式

设有效六维为：

```text
V = vitality
S = strength
P = spirit
E = endurance
A = speed
W = willpower
```

第一版正式公式：

```text
physicalAtk = floor(40 + S × 3.5)
magicAtk    = floor(40 + P × 3.5)

physicalDef = floor(10 + E × 1.75)
magicDef    = floor(10 + W × 1.75)

maxHp       = floor(400 + V × 20 + E × 3)
maxMp       = floor(200 + P × 4 + W × 10)

speed       = floor(A)

hit         = floor(80 + A)
dodge       = floor(A)

healPower   = floor(V × 0.25 + W)

sealHit     = floor(P × 0.5)
sealResist  = floor(W × 0.5)

critRate          = 0.05
spellCritRate     = 0.05
physicalFuryRate  = 0
```

所有输入必须为有限非负数。投影结果统一向下取整；概率字段由入场校验夹到规则允许范围。四项修炼、当前 `hp/mp` 和战意等资源不属于上述裸身公式。

### 5.1 初始角色样例

六维均为 10、没有任何 build 时：

| 面板 | 数值 | 面板 | 数值 |
| --- | ---: | --- | ---: |
| 物理攻击 | 75 | 法术攻击 | 75 |
| 物理防御 | 27 | 法术防御 | 27 |
| 最大气血 | 630 | 最大法力 | 340 |
| 速度 | 10 | 治疗强度 | 12 |
| 命中 | 90 | 闪避 | 10 |
| 封禁命中 | 5 | 封禁抵抗 | 5 |
| 物理暴击率 | 5% | 法术暴击率 | 5% |
| 物理狂暴率 | 0% |  |  |

该样例应成为角色投影的第一组黄金测试。

## 6. 点数面板的概率语义

### 6.1 物理命中与闪避

Daoyou v6 规则使用：

```text
physicalHitChance
= clamp(20%, 100%, 50% + (source.hit - target.dodge) / 200)
```

相同六维的初始角色之间：

```text
50% + (90 - 10) / 200 = 90%
```

由于同等自然成长会同时增加双方身法，标准同水平对局的基础物理命中率维持在 90%。攻击方和目标身法每相差 10 点，会使命中率约变化 5 个百分点；道装的直接命中、闪避贡献也使用相同点数单位。

法术伤害首版继续必中。封禁类状态走独立封禁公式，不复用物理命中。

### 6.2 封禁命中与抵抗

封禁成功率继续由规则层组合：

```text
封禁基础成功率
+ 技能等级与目标人物等级差
+ 法术修炼与目标抗法修炼差
+ (sealHit - sealResist) / 200
```

`sealHit/sealResist` 是调整点数。二者每相差 10 点，最终封禁率约变化 5 个百分点。六维相同且不存在其他 build 时，灵力与神识贡献互相抵消，封禁率仍由技能底率、等级差和修炼差决定。

## 7. 治疗、暴击与物理狂暴

### 7.1 治疗强度

`healPower` 是加到治疗技能 `power` 上的固定面板，不是百分比治疗增幅：

```text
基础治疗量 = skillPower + healPower
```

神识是治疗强度的主要六维来源，体魄仅提供少量贡献。这样治疗构筑不必堆叠法术攻击，也不会把灵力同时变成法伤、封禁和治疗的全能属性。

未来的百分比治疗增减应由明确的 `healDealt/healTaken` 被动或状态表达，不能把百分比直接写入 `healPower`。

### 7.2 暴击

人物裸身物理暴击率和法术暴击率均为 5%。六维不直接增加暴击，后续增量来自道装、功法、宗门、经脉和战斗状态。

首版不恢复 v5 的个体暴击抵抗、暴击伤害增幅和暴击伤害减免。若未来确有内容需求，必须先扩展通用 v6 规则，而不是在角色投影中隐式抵扣。

### 7.3 物理狂暴字段

现有 core 的 `furyRate` 实际含义是物理狂暴概率：触发后先放大物理攻击，再进入物理防御公式。正式领域字段统一命名为：

```text
physicalFuryRate
```

实现迁移期间若 core 尚未完成字段更名，只允许在最终边界做一次 `physicalFuryRate -> furyRate` 适配。不得在新配置、持久模型和 UI 中继续使用含义不明的 `furyRate`，也不得与未来器诀使用的战意资源混用。

## 8. 人物等级、技能等级与修炼

### 8.1 人物等级

兼容期人物战斗等级继续按 36 个境界阶段映射为 5～180：

```text
level = (getRealmStageRank(realm, realmStage) + 1) × 5
```

`level` 用于封禁等级差、逃跑、技能开放和内容条件，不参与 `character_panel_v1`，因为境界已经通过六维自然成长影响面板。

### 8.2 技能等级

```text
宗门主动技能等级 = 所属宗门心法等级
```

没有正式技能等级来源的开发期技能可以暂用人物等级，但必须输出投影诊断。功法被动一般不使用人物技能等级；确有需要时由功法内容定义提供显式等级。

### 8.3 四修炼

```text
attackCultivate
defenseCultivate
spellCultivate
resistSpellCultivate
```

四项修炼直接读取新修炼系统等级，在伤害和封禁公式中计算修炼差。它们不修改有效六维，也不提前折算为攻防面板。

生命根基在裸身公式之后增加 `maxHp/healPower`：每级增加 `character_panel_v1` 裸身气血 0.5%，每两级增加 1 点固定治疗强度。只放大裸身气血，不放大道装和其他 build 的固定气血。

## 9. 入场面板编译顺序

```text
境界自然六维
+ 玩家自由加点
= 永久六维

永久六维
+ 道装附灵六维
= 有效六维

有效六维
→ character_panel_v1 裸身面板
→ 道装器胚、灵纹、淬炼直接面板
→ 四修炼字段与生命根基贡献
→ 功法被动与允许的面板贡献
→ 宗门心法面板与主动技能等级
→ 经脉 patch、被动与面板贡献
→ 长期状态修正
→ 当前资源策略
→ 校验并封装 LineupUnit
```

所有来源先由投影层归并，combat-v6 core 只接收最终 `Attrs`、技能、状态、被动和单位标签，不知道这些结果来自哪个 build。

战斗开始后的状态加减只改变当前战斗面板，不反向修改战前投影、有效六维或角色持久数据。

## 10. 持久化与版本契约

允许持久化：

- 角色永久六维和未分配属性点。
- 当前道装实例与装配关系。
- 修炼、功法、宗门心法、经脉等各领域的长期事实。
- `projectionVersion` 和用于复盘的已编译入场快照。

禁止持久化为角色权威数据：

- 有效六维。
- 裸身派生面板。
- build 汇总后的最终战斗面板。
- battle-v5 `AttributeSet` 或 modifier。
- 可由内容注册表和版本重新编译的运行时对象。

正式版本标识：

```text
projectionVersion = character_panel_v1
```

以后修改任一系数、六维职责、取整顺序、贡献阶段或等级参与方式，都必须发布新的 projection version。旧战斗记录继续使用其保存的版本戳和入场快照解释，不静默套用新公式。

## 11. 实现验收条件

1. 只读取角色身份、境界、六维和资源策略即可生成可开战的裸角色。
2. 投影生产代码不导入 battle-v5 或 creation-v2。
3. 装卸道装只改变有效六维和最终面板，不改变永久六维。
4. 洗点后重新投影得到新面板，数据库中不存在需要同步维护的派生字段。
5. 六维全 10 的黄金样例与本文一致。
6. 同六维角色的基础物理命中率为 90%，同灵力/神识时封禁点数差为 0。
7. `level` 变化不会在六维不变时额外改变裸身攻防血蓝。
8. 四修炼只进入独立字段和规则公式，不污染六维或裸身攻防。
9. 所有非有限数、负面板、未知贡献和版本缺失在开战前产生诊断；错误阻止开战。
10. 相同输入快照和版本产生字节级稳定的最终面板与战斗事件。
