# 管理后台新版物品接入

天骄宝阁、宗门宝库、游戏邮件和兑换码统一复用新版物品栏的 `ItemGrant`、物品定义注册表和实例事实校验。管理后台不再维护一份独立物品协议。

## 配置与交互

- 四个入口共用 `RewardItemPicker`，使用现有 `InventoryGrid`、`ItemSlot` 和物品预览；可搜索、分类、翻页、预览后选择。
- 注册表提供图纸、传承灵印、灵兽培养道具、功法玉简和阵纹；材料库提供 V1 材料及有效灵种。
- 道装、丹药、灵果、符箓通过当前领域生成器生成，预览确认后保存完整事实。消耗品直接写入新版库存奖励，不再创建旧版消耗品库条目。
- 两个玩家商店同步复用物品栏格子与预览，保留价格、每周限购、购买和资源刷新流程。
- 游戏邮件及兑换码保留灵石、声望奖励；邮件预览展示收件人数、收件人示例和奖励摘要。
- 原道具库改为材料库，删除旧法宝／消耗品编辑与选择入口。保留材料及灵种生成和每日生成设置；不支持的旧材料只显示弃用状态。

## 保存与发放

商店的 `item_snapshot` 保存不含数量的 `ItemGrant`，数量继续使用既有列。邮件和兑换码保存既有 `inventory_v1` 附件快照。每次购买、每位邮件收件人和每次兑换分别生成新的道装实例 ID，其他已确定属性与技能保持不变。

发放继续经过现有事务、库存、邮件领取和资源更新流程。历史邮件及兑换码保留原附件协议；旧附件解析只服务于历史读取和领取，不再用于新配置。

## 发布与迁移

发布本次应用代码前，需要执行业务迁移 [0054_admin_inventory_rewards.sql](../drizzle/0054_admin_inventory_rewards.sql)，并避免旧版本在迁移后继续配置商品。迁移不删除历史表或购买记录。

1. 为两类商店增加物品快照；旧材料库来源改为可空，移除来源唯一索引，支持同一物品配置多条商品。
2. 对能够无损转换的普通 V1 材料回填快照，保留商品 ID、价格、数量与购买历史，包括旧功法典籍／神通秘术材料分类。
3. 其余旧商品（包括旧法宝、旧消耗品及未回填的灵种）下架。管理员从“重新配置”选择新版道具后再上架，不自动猜测替代品。
4. 旧法宝／消耗品材料库条目归档，历史奖励快照保留。

本轮仅对 `env/local.env` 对应的本地数据库执行迁移。使用明确加载环境的命令：

```bash
bun --env-file=env/local.env node_modules/drizzle-kit/bin.cjs migrate
```

## 后台交互重构（2026-09-23）

本轮保持已有发放协议与服务端接口，重整五个页面的任务流程。

| 页面 | 首页 | 操作流程 |
| --- | --- | --- |
| 材料库 | 搜索、分类、发布状态与物品格列表 | 新增／编辑打开独立窗口；批量生成与每日设置分别打开，生成时只展示当前所选类型的参数 |
| 天骄宝阁、宗门宝库 | 商品列表显示物品格、价格、限购和上架状态 | 新增／编辑打开窗口，选择道具后配置商品；保存后关闭并刷新列表 |
| 兑换码 | 搜索、状态、有效期与领取名额 | 奖励详情按需打开；新建按“奖励与邮件 → 领取设置 → 核对创建”，成功页保留可复制的兑换码 |
| 游戏邮件 | 选择指定角色、筛选人群或全部活跃角色 | “收件人 → 内容与奖励 → 确认发送”；预览实际人数与附件后发送，完成页与编辑页分离 |

道具选择器按真实物品分类显示，所有候选均使用 `ItemSlot`。丹药、灵果、符箓和道装的生成参数进入独立步骤；生成后回到候选物品格，通过与其他类型相同的预览操作选择。材料按具体种类向服务器查询，避免先分页再排除灵种造成空页。

奖励编辑区以物品格展示已选道具，在预览中调整数量或移除；货币保留各自数量输入。后台使用局部原生模态窗口管理焦点与滚动，Esc 只关闭当前层；校验错误在当前窗口内显示。移动端导航默认折叠，编辑窗口正文滚动、操作区固定可见。
