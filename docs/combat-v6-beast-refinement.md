# 归元灵露洗炼

2026-09-12，按用户确认方案实现。入口为灵兽详情「学习兽诀」旁的「洗炼」，复用兽诀抽屉、背包选择、确认弹窗和操作后刷新流程。首版只通过本地dev接口发放，无新增掉落或商店购买渠道。

## 规则与配置

策划配置：`src/shared/engine/combat-v6/beasts/data/refinement.json`，配套JSON Schema和`refinement-config.ts`校验。配置维护名称、图标、颜色、描述、适用境界、单次消耗、叠加上限、归零等级经验和寿命恢复开关。

两档灵露共用 `origin-dew` 瓶形图标，通过 `color` 区分：归元灵露为 `jade`（青碧），上品归元灵露为 `gold`（金色）。储物袋格子与物品详情的图标、名称同步使用该配色，颜色不影响洗炼概率。

| 定义ID | 名称 | 适用物种 |
| --- | --- | --- |
| `beast.refinement.origin-dew` | 归元灵露 | 炼气、筑基、金丹 |
| `beast.refinement.superior-origin-dew` | 上品归元灵露 | 全部游戏境界；元婴及以上必须使用 |

每次消耗一瓶。判断依据为物种携带境界，与灵兽当前等级无关；主人仍须达到物种携带境界。上品不提高任何概率，与普通使用同一`rollBeastTraits`函数、同一物种出生配置；低阶物种在相同seed下两种药露结果完全一致。

洗炼将等级、经验、已分配点和待分配点归零；资质、成长、全部技能与格数重新生成。核心出生必带，原有兽诀技能不保留、不返还。技能格可以增加或减少，始终等于新技能数量。0级灵兽可以重复洗炼，重新升级正常获得属性点。

当前寿命恢复至原有上限，寿命上限数值不变。保留个体ID、主人、名字、物种；不修改携带编组或首发。更新生成seed、算法版本、物种内容修订与个体revision。旧版本灵兽仅在主动洗炼时进入当前物种生成规则。

## 服务端与界面

`POST /api/combat-v6/inventory`新增`action: refine`，与兽诀学习共用现有认证、角色归属、战斗占用检查、角色锁、数据库事务与资源事件。提交物品ID／revision、灵兽ID／revision；不接受客户端随机seed或结果。

道具必须在背包且数量足够，灵兽必须属于当前角色且revision匹配。药露扣除与个体写入同时提交，失败整体回滚。成功后物品和灵兽revision递增；重复旧请求因版本失效被拒绝，不会再次扣费或重抽。响应丢失时刷新灵兽与背包核对，不提供旧结果择优保留。

界面确认明确提示等级加点归零、全部技能重置、格数可能减少、兽诀不返还、寿命恢复及不可撤销。成功提示技能格变化并刷新灵兽详情。药露作为固定库存物品注册，复用背包堆叠、储藏和已有物品分类；没有新增产出配置。
