# Phase 10P：灵田与新版物品栏闭环

状态：2026-09-10 主体实施与重点本地运行验收完成。尚未逐项覆盖的异常场景见文末，不标记为全量验收完成。

## 目标与边界

打通坊市购种 → 播种培育 → 收获 → 炼丹／炼器／回收或食用的新版库存链路。保留现有种植玩法、生成规则、成长阶段与时长、培育方式与成本、亲和判断、产量品质、AI 判断和命名机制。

- 坊市购种和灵田初始种子领取进入新版物品栏。
- 播种与道具培育仅使用 bag，不直接读取或消耗 storage、洞府宝库。
- 收获普通材料、灵果进入新版物品栏，优先 bag 合堆／空格，满包进入 storage，并反馈实际去向。
- 历史种子通过既有宝库取出协议显式取出；历史材料、丹药沿用既有取出通道。
- 保留历史已种作物和进度，不要求重新播种，不重算或替换已有种植快照。
- 不做批量搬迁、补偿、删表、邮件或玩家交易迁移，不新增自动种植、批量收获及其他种植玩法。

## 推荐实现

### 物品事实

种子建立独立新版物品定义，复用现有 seedSpec、生长快照和指纹校验，支持公共物品格展示。名称相同而生长事实不同的种子不得错误合堆。坊市、初始领取、宝库取出使用同一事实转换入口，替换当前坊市仅供展示的 market.seed 分支。

不扩展普通材料类型以容纳种子。普通收获材料使用 material.v1；灵果使用 consumable.v1，保留“灵果”类型与 spirit_fruit spec，通过既有消耗品流程按原效果食用，不改称丹药。

历史种子只有具备有效生长事实时才能取出用于种植；缺失或无效事实保持原记录并明确提示，不随机补生成。取出沿用已有协议的容量与事务语义，不为灵田建立第二套转换渠道。

### 消耗与结算

播种消耗一份选中种子，培育按原规则消耗选中的材料或丹药。服务端校验物品归属、bag 位置、类型、数量与版本；不接受客户端提交的生长规则、价格、效果或产量作为权威事实。

灵石、灵气、法力等非道具成本沿用现有资源服务。道具扣除与田块推进同事务；收获发放与田块重置同事务。复用玩家命令幂等和库存写入能力，不新增调度器或平行事务框架。保留已有 AI 准备与最终结算校验边界，重复提交不得重复扣除或发放。

收获反馈包含物品、数量与去向，成功后更新田块和公共背包。客户端计时只用于显示，阶段与可操作状态以服务端为准。

### 页面交互

- PC 左侧田块与当前作物操作，右侧五列40格完整公共物品栏，保持原格位，不过滤无关道具。
- 空田选择种子；待培育田块先选择培育方式，再从公共物品栏选择对应道具。适用性由交互提示表达。
- 左侧投入格展示选中道具、本次消耗数量和确认操作，替换资源下拉列表，不重复铺设材料清单。
- 成熟田块就地收获。切换田块或培育方式清除不再适用的选择，提交中禁止切换操作上下文。
- 移动端使用公共物品栏抽屉。已有的成长历史和线索保留可访问入口，不扩成首屏规则说明。

## 实施顺序

1. 新版种子定义、展示与宝库取出，检查普通材料、灵果协议复用；验证事实校验与合堆隔离。
2. 迁移初始领取、坊市种子入库、灵田播种／培育／收获，检查归属、位置、资源成本和事务幂等。
3. 改造灵田公共物品栏交互，检查桌面与移动端田块切换、选择清理、提示与状态恢复。
4. 本地运行验收完整闭环，更新路线图及已验收／未验收清单。

以上作为同一阶段交付，避免出现种子已经改为新版入库而灵田仍不能播种的中间状态。

## 验收标准

| 场景 | 通过条件 |
| --- | --- |
| 购种与初始领取 | 新种子进入新版库存，可直接从 bag 播种，不新增对应旧材料记录 |
| 历史种子 | 显式取出后可播种；无效事实拒绝取出且旧数量不变 |
| 已种作物 | 改版前作物快照、进度与历史保留，可继续培育和收获 |
| 培育 | 材料、丹药只扣选中的 bag 道具；数量不足、错类、移入 storage、过期版本或越权均拒绝且不推进田块 |
| 非道具培育 | 灵石、灵气、法力等按原规则扣除，不因库存迁移改变成本 |
| 收获 | 材料可直接投入炼丹／炼器并回收；灵果可从新版物品栏食用且效果与原规则一致 |
| 库存容量 | 同事实正确合堆、不同事实不混堆；满包产出进入 storage，不因 bag 满而丢失收获 |
| 幂等与并发 | 重复及并发播种／培育／收获不重复扣除或发放，不出现已扣物未推进或重置后未发货 |
| UI | PC及窄屏公共物品栏保持完整视图；切换田块不会沿用错误投入；刷新恢复正确状态 |

纯规则测试仅放 src/shared；服务、数据库与页面采用代码审查和本地浏览器运行验收，不新增一次性验收脚本。实施后运行 lint、build 与受影响共享测试，按影响范围决定是否全量测试。运行准备复用本地测试账号及现有 dev 接口，若无法覆盖成熟作物等场景，再补最小必要的本地验收能力；不改变正式成长时长。

## 实施结果

- 新增 seed.v1，共用种子事实校验入口；按完整规范化 seedSpec 计算合堆身份，服务端使用 SHA256 库存键。公共查询只返回名称、品质、描述与线索，不公开隐藏生长事实。
- 初始领取、坊市购买、宝库显式取出统一进入新版库存；播种和道具培育按归属、bag 位置、类型、数量与 revision 校验并扣除。种子支持背包／储藏室往返存取。
- 收获使用既有 material.v1／consumable.v1 发放。沿用玩家命令锁、事务与持久幂等，培育提交时复查原田块状态，已完成请求重放跳过 AI 准备。
- 灵田页面改为六田块、当前操作与公共物品栏；桌面五列40格，移动端抽屉。投入格替代资源下拉框；线索、历史、成长倒计时继续可访问。
- 仅本地 dev 增加当前生长阶段结束与有效旧种子样本发放，用于复用正式流程验收；没有改变正式时长、产出规则或数据表。
