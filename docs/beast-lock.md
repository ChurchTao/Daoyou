# 灵兽锁定

灵兽袋与仓库的灵兽详情在「管理」中提供「锁定／解锁」，点击直接生效，无二次确认。锁定后，名册显示 🔒 图标，详情显示 🔒 已锁定；融合选择器、拍卖寄售和游商回收入口禁止选择该灵兽。管理中的放生操作也会禁用。

服务端在融合、拍卖寄售、游商回收与放生的现有事务内检查锁定状态，拒绝直接请求。出战、携带、存取、改名和培养仍按原有条件执行。

## 数据与接口

- `SummonedBeast.isLocked` 存入现有 `cultivator_beasts.individual` JSONB。历史记录缺省表示未锁定，无需数据库迁移；原有培养和结算通过完整个体解析及字段保留继续传递此状态。
- `POST /api/combat-v6/beasts/lock` 接收 `{ beastId, expectedRevision, isLocked }`，只允许当前活跃角色操作自己的灵兽，返回更新后的完整灵兽管理视图。
- 复用角色 Redis 变更锁、角色行锁、战斗占用限制及数据库事务。状态变化时灵兽 revision 加一，旧 revision 请求拒绝；目标状态与现状相同时不增加 revision。
- 前后端需配套更新，禁止仅通过前端禁用按钮提供保护。

## 验收（2026-10-23）

- 先补融合任一材料锁定、寄售锁定的纯规则回归用例，确认原实现失败后再实现保护。覆盖解锁恢复资格及缺省字段的存量灵兽。
- 本地 `127.0.0.1:5174`，复用本地道友1；Playwright 检查 1280×900 和 360×800。灵兽袋、仓库的确认锁定、刷新保留状态、取消解锁及确认解锁正常；锁定时放生禁用，喂养和仓库取出仍可用。窄屏无横向溢出。
- 使用真实完整请求验证锁定后的融合、寄售、游商回收、放生均返回409；旧 revision 和非本人灵兽返回409，非法布尔值返回400。后续读取与只读数据库查询确认锁定和 revision 已提交，未移除灵兽。
- 融合选择器及拍卖寄售弹窗中的锁定灵兽不可选，显示解锁提示；从锁定灵兽打开融合页时不预选该灵兽。最终页面无框架错误遮罩，新加载的拍卖页无控制台错误或警告。
- 测试灵兽恢复为未锁定，保留正常递增的 revision。未实际消耗已有灵兽验证解锁后的融合、寄售、回收或放生成功，也未独立覆盖战斗占用、真实触屏及跨标签页并发操作。
- 执行 `pnpm run lint`、`pnpm run typecheck`、`pnpm run build`、`pnpm run test packages/game-rules/src/beasts` 与 `git diff --check`。构建保留既有大包提示；验收中的预期400／409请求会出现在浏览器控制台，开发服务器重启时曾出现临时连接失败。
