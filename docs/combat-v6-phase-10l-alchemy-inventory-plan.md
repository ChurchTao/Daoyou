# Phase 10L：旧造物生产退役与炼丹物品栏接入

状态：2026-09-09 业务代码已实施，主要链路运行验收通过；历史旧战斗产物邮件及部分消耗品专属流程仍保留运行验收缺口，详见文末。

## 已确认边界

- 炼丹只使用新版随身物品栏 `bag` 的材料，不直接使用 `storage` 或旧材料表。旧材料库降级为洞府宝库，取出后才能炼制。
- 炼丹玩法、生成规则、提示词语义、成本、剂量、概率、品质、产量、丹方、药效、限制和副作用保持不变。迁移与旧造物引擎耦合的必要代码，使炼丹独立，不重新设计生成引擎。
- 新炼制的丹药直接进入新版物品栏。旧丹药、消耗品数据与表结构保留并降级为洞府宝库，通过统一协议取出到新版物品栏。
- 旧功法、神通、装备的生产代码全面下线；历史数据和表结构不删除。补偿、转换旧战斗产物的方案由用户后续另行设计。
- 历史邮件中的旧造物继续按原链路领取到旧表，即洞府宝库。保留为此所需的最小发放代码，不将邮件领取视为新生产，也不增加邮件到新版物品栏的另一套转换。
- 炼丹布局复刻新版炼器的结构和交互，重新生成炼丹炉图片。保留原炼丹模式和步骤，不照搬炼器的配方规则或固定材料格数。

## 实施后的代码事实

- 新版材料协议支持草药；炼丹按完整材料事实合并随身拆堆，仍保留原一至六味、每味最多 99 份的规则。炼器继续拒绝草药。
- 新增 consumable.v1，完整保存原 spec、品质、描述、提示词和评分；按完整事实堆叠，支持详情、存取和使用。材料与消耗品持久化堆叠键使用摘要，避免长药效事实超过数据库字段长度。
- 炼丹从 bag 读取、验证成员版本并事务扣料，直接发放新版丹药。旧生产成本中炼丹部分迁为独立纯逻辑，原生成与药效执行规则保留。
- 洞府宝库共用取出接口，支持 material / consumable；旧数量、所有权、容量与扣除均在事务内验证。旧消耗品不能直接使用。
- 旧生产编排、专属材料分析、生成器、敌人旧造物生成链、提示词及页面已删除；历史产品协议、发放、持久化与 rehydrate 保留。
- 按用户追加确认，创角和新手任务停止新增旧装备、功法及神通；保留其他奖励和新版创角构筑。后台道具库旧装备创建、更新和预览也已关闭。

## 推荐实现

### 单一数据通道

新炼丹：bag 材料 → 原炼丹规则 → 新版消耗品事实 → 新版物品栏。

历史物品：旧表（洞府宝库）→ 用户主动取出 → 同一新版物品协议 → bag。

历史邮件：原附件领取 → 原旧表（洞府宝库）。本阶段不增加旧功法、神通、装备到新版战斗物品的自动转换。

宝库取出在一个事务内校验所有权与旧数量、转换事实、检查容量、扣除旧数量并写入新版物品栏。失败不得丢失旧物品，也不得形成重复资产。不执行批量搬迁；旧表仅按实际取出数量扣减。

### 炼丹独立

先保留现有规则的固定输入验证，再迁移炼丹实际需要的代码；共享材料约束只抽取真正被现行玩法复用的部分。生成链路仍使用现有 AI 客户端、服务端校验和确定性资源结算。

选材、丹方分析、适配预览和自动配料均采用 bag 同一来源。相同材料拆成多堆不能改变种类计数或生成效果；不能仅凭同名合并药性不同的材料。服务端重新核验实际堆叠、版本与数量，不能信任客户端药性事实。

产物使用现有 `consumables.spec` 的药效语义作为协议依据。迁移时保留炼丹生成的品质、外观、剂量及批次差异，只有完整事实一致的物品可以堆叠；不通过回写旧表来中转新产物。

容量处理推荐沿用新版物品栏已有的入包／溢出储藏室规则，实际结算后明确显示去向；宝库主动取出仍要求 bag 有足够容量。此项为实现建议，实施前结合现有物品栏规则核实，不增加自动丢弃、自动出售或邮件补发。

### 消耗品使用

新版物品栏提供详情和使用操作，复用现有药效、限制与事务机制；旧表物品先取出再使用，避免旧、新两套主动使用入口长期并存。

盘点符箓及其他消耗品的专属调用方，按相同事实协议接入，保留原效果和使用条件。库存迁移不扩展为战斗中用药功能。

### 页面与素材

- 复用新版炼器的设施入口、桌面炉阵与物品栏双栏布局、移动端材料抽屉、开炉确认及结果交互。
- 保留即兴炼丹、丹方炼丹、剂量调整、推演及结果信息，材料格数量遵循原炼丹上限。
- 新炼丹炉采用独立透明背景素材，风格与现有炼器炉协调；不修改炼器炉素材。已生成素材位于 `public/assets/alchemy/xuanfire-furnace.png`，已接入页面。
- 数字沿用 Tailwind `font-mono`，不添加全局数字字体变量。

### 旧生产清理

下线旧预览、生成、重新生成、待处理确认及替换入口，清除其专属服务、提示词与孤立消费者。邮件中已有产物的领取发放继续可用；先核查实际调用方再删除，不假定邮件外一定没有历史记录。

本阶段不删除历史表、不实现旧战斗产物补偿、不重做市场和排行榜、不整体删除 battle-v5。仍有现行消费者的历史读取代码保留并记录。

## 验收标准

1. 固定材料事实与输入下，迁移前后的纯炼丹规则结果一致；生成提示词、模型参数、校验及产物处理语义不变。
2. 即兴和丹方炼丹均完成真实选材、预览、炼制、产物入栏及使用。炼丹不读取或扣除旧材料表、storage 材料。
3. 拆堆不改变材料种类及效果，异质材料不错误合并；陈旧版本、数量不足、跨角色和并发消耗被正确拒绝。
4. 原料扣除、产物发放及资源结算遵循现有幂等和失败语义；容量不足不会丢失资产，产物实际去向有反馈。
5. 旧材料、丹药及其他消耗品可从宝库按协议取出；重复或失败取出不重复生成物品、不损失旧数量，药效事实保持一致。
6. 新版丹药详情、堆叠、拆分、存取和使用可用；适用限制、副作用及现实资源刷新保持原行为。
7. 历史邮件领取旧功法、神通、装备仍只进入旧表，不触发生成或自动转换；旧生产接口不能扣费、调用生成模型或创建新产物。
8. 桌面与移动端验收新版炉阵、材料选择、剂量修改、模式切换、确认、生成中状态和结果。
9. lint、共享测试、前后端构建及 diff 检查通过，历史表 schema 不删除；10I～10K 的未验收项继续保留。

## 实施顺序

1. 物品协议与统一宝库取出：验证材料和消耗品事实保持、堆叠及容量规则。
2. 炼丹规则迁移及 bag 输入／新版产物输出：验证两种炼丹模式与结算。
3. 新版消耗品使用和旧生产退役：验证药效及邮件历史发放。
4. 新炼丹页面与素材：完成桌面、移动端及跨链路运行验收。
