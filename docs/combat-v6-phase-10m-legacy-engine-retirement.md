# Phase 10M：历史造物读取解耦与 V5 引擎退役

2026-09-09 用户确认实施。代码退役已完成，静态检查和本地基础运行检查通过；真实旧物详情与历史附件领取缺少样本，尚未运行验收。

## 开发边界

- 保留旧装备、神通、功法的数据、表结构及基础查看。显示已存名称、品质、说明和属性；缺失事实显示“未记录”，不根据词缀 ID 重建战斗能力。
- 旧装备、神通、功法榜单整体退役；天骄榜、财富榜、丹药榜保留。丹药榜数据源迁移另行讨论。
- 历史邮件继续沿原资源发放事务写旧表，不增加转换或旧产物生产通道。
- 不删除历史表，不实施补偿、数据迁移、战斗药品或新模拟器；炼丹玩法、生成规则及新版物品栏不在本阶段改造。
- 保留仍使用旧物的历史经济通道，包括邮件转移、市场、回收、宗门提交；本阶段没有重设计这些玩法。

## 实施结果

- 删除 battle-v5、creation-v2 全目录及其专属测试、旧模拟调用、战后消费者、condition 战斗桥接和旧法宝境界缩放。
- 历史读取改用 src/shared/legacy/products.ts 的存档工具。未知词缀和额外存档字段原样保留，附件入库移除 battleProjection，不再 rehydrate、编译能力或重新评分。
- 旧装配读取保留既有记录用于历史展示，移除运行投影。旧表 JSON 列使用不透明归档类型；schema 与迁移目录没有修改。
- 神通、功法页面共用历史列表，保留分页和详情，移除启用、遗忘操作；宝库法宝列表仅保留详情。
- 移除旧战斗投影展示组件与消费者，历史详情直接展示已有属性和词缀说明。
- 两个旧装配入口及两个直接删除入口返回 410；对应命令、物品栏装配处理器和失去调用方的仓储写入方法已删除。
- 三类旧产物榜单 API 返回 410，界面移除对应标签。

## 未验收项与后续约束

- 本地只读查询确认 creation_products 没有历史产物，邮件表没有旧战斗产物附件。因此真实旧物详情、跨账号已有物品权限、旧法宝附件领取与重复领取未做运行验收。没有伪造旧产物补样。
- 现有 MailAttachment 只支持 artifact 这一类旧战斗产物，不支持 skill / gongfa；本阶段没有扩展这两条发放通道。既有领取的玩家锁、幂等键、事务发放及 isClaimed 条件更新已静态核查。
- 未重新执行五种战斗模式完整对局、市场／回收／宗门提交全流程，以及炼丹真实消耗；共享引擎回归通过不代替这些运行验收。
- 10I～10L 既有未验收项继续按原记录保留。历史表仍等待用户约定的后续版本删除，不在本次发布中 DROP。
- 没有新增服务端／前端单元测试或一次性验收脚本，没有迁移数据库或部署。既有 eslint.config.js 用户改动保持不动。
