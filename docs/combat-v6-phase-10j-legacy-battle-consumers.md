# Phase 10J：旧战斗展示与分享消费者退役

2026-09-09 用户确认实施。主体代码和重点运行验收完成；未执行场景见文末，不视为全量战斗回归收口。

## 开发边界与实现

- 洞府近期战绩调用现有 `/api/combat-v6/replays?page=1`，取最近三场。与完整战绩页共享 `CombatV6HistoryList` 和来源标签，直接进入现有 V6 回放页。保留加载、空态、错误重试及角色切换清理，不新增接口或持久模型。
- 世界、宗门聊天创建契约只允许文字和道具。旧客户端提交 `battle_showcase` 时在冷却和持久化之前返回 HTTP 410“旧版战报分享已停用”。历史消息仍可读取内嵌摘要，取消回放链接并展示停用提示；不查询旧战绩表。
- 删除旧战报分享弹窗、V3/V5 播放组件、宗门 `sect.outcome.battle` 渲染器。当前宗门挑战的 `sect.outcome.battle-started` 与 V6 页面保持原链路。
- 删除 V3 战绩仓储、旧 BattleStateCoordinator、旧服务器模拟转导、旧战斗投影入口及 ConditionService 专属旧战斗准备／结算方法；移除 V3 retention 清理。
- 删除独占旧回放／训练草稿测试及旧 UI 架构扫描；保留共享 V5 引擎测试，模拟器测试直接引用共享纯逻辑。
- 三张弃用历史表只保留 schema／历史类型。本版不改表结构、不执行 DROP；部署后下一版本按 [历史表删除计划](./combat-v6-legacy-table-retirement.md) 删除。
- 不实现 V6 公共分享或新模拟器，不扩大为全仓 battle-v5／creation-v2 退役，也不宣称 10I 的补充验收已完成。

## 验收标准

1. 首页最近三场与 V6 历史列表同源、顺序一致，能播放对应 V6 回放。
2. 两个聊天入口明确拒绝旧分享，拒绝发生在冷却与写入之前；文字和道具契约保留。
3. 历史分享只显示嵌入内容与停用说明，没有旧链接或旧表查询。
4. 删除的组件、仓储和协调器不再有源码引用；弃用三表无运行时读写或自动清理。
5. lint、共享测试、前后端构建通过；未取得真实样本的场景明确区分静态检查与运行验收。
