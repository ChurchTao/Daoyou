# Phase 10N：NPC 回收与新版丹药榜

2026-09-10 完成主体实施、静态检查和重点本地运行验收。

## 已确认边界

- PC 左侧为回收掌柜对话，右侧为完整 40 格公共物品栏；选物、多选、调整份数、报价和确认成交形成单一路径。
- 固定 NPC 台词，服务端确定性报价，不接 LLM、自由输入或议价系统。
- 只回收 bag 中的材料、丹药。旧材料、丹药先从宝库取出；storage 中的物品先取回 bag。图纸、兽诀、功法玉简、新版道装不临时套价。
- 复用原低阶材料价格、高阶材料估价及丹药回收规则；历史法宝回收保留为折叠入口，沿用原交易服务。
- 丹药榜统计新版 bag + storage 中的现存丹药；同一角色、完整事实相同的丹药合并一条，数量不放大评分，完全消耗或回收后退榜。保留原品质门槛（玄品起）、评分字段与前 100 条限制。
- 不迁移购买、黑市鉴定、种植、玩家交易、邮件赠送，不删除历史表，不实施旧装备补偿。

## 实施方案

- /api/market/recycle：preview 只接受最多 40 个不同格位的 ID、revision、出售数量；不接受客户端价格。按真实 bag 记录估价，将完整所选快照与报价存入有时限的 Redis 记录。
- confirm 只提交 quoteId。沿用玩家锁、SQL 角色锁和现有幂等凭据，在一个事务内核对所有物品、扣除数量、增加灵石。重复请求返回原成交结果；任意物品位置、版本、数量或事实变化均拒绝旧报价。达到数据库灵石存储上限时整笔失败，不截断款项。
- 部分出售保留原格位并增加 revision，全部出售释放格子，不自动整理其他物品。
- 选物期间只更新当前报价，不逐点击追加聊天；成交后保留本页最近五条成交反馈。报价细项显示单价、数量和合计，高阶评语可展开。
- PC 默认展开报价；移动尺寸默认折叠明细，底部成交栏沿用壳层 --game-bottom-offset，避让世界聊天和底部导航。
- 公共 InventoryItems 统一在容器宽度达到 480px 时使用 8 列，确保桌面回收侧栏可以紧凑展示 8×5 格；窄容器仍使用原 4／5 列规则，所有调用处共用相同规则。
- 旧材料、丹药的读取／预览／确认回收消费者删除；旧 /api/market/sell 对这两类返回 410，旧会话也不能继续成交。旧法宝分支保持原路。
- 丹药榜直接按新版库存的角色与完整 JSONB 事实分组，数量求和。榜单身份和同分排序使用角色与事实摘要，不使用堆叠记录 ID，避免拆堆改变榜单身份或同分顺序。详情复用新版 ConsumableDetails。
