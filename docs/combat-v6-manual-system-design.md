# combat-v6 境界功法系统

> 2026-09-10：经用户确认，替代 Phase 5A／9F 的本篇、真解和覆盖散功方案。无旧数据迁移或兼容。
> 上位设计：[改造路线图](./combat-v6-mhxy-redesign-roadmap.md)。

## 玩法规则

- 炼气、筑基、金丹、元婴各开放一位，总共四位；更高境界不增加位置。
- 功法有固定境界归属，只能在对应位置激活。效果类型不按境界硬限制，由内容设计体现方向差异。
- 每个位置可以学习多本，每本独立保存层数和已解锁上限，同时只激活一本。
- 学习消耗一本同名玉简，从第一层开始。空位自动激活；已有激活功法时，新学功法保存在收藏中。
- 免费切换，无冷却，不丢失培养进度。沿用现有战斗／结算占用保护，战斗结束后才能操作，下一场生效。
- 默认九层，三层、六层消耗一本同名玉简突破瓶颈，只解锁后续层数，不直接升级。三本玉简加八次修炼完成一本功法。
- 升层消耗当前可用修为与道心感悟；修为继续用于境界提升，不能透支或导致境界倒退。功法满层不是角色突破条件。
- 未达到功法对应境界时，可持有和交易玉简，不能学习或培养。
- 未激活功法允许培养。第一版只有六维固定属性加成，稀有功法可同时提供两项效果，两项从一层同时生效。

## 策划数据包

入口：`src/shared/engine/combat-v6/manuals/data/manual-pack.json`。

同目录 JSON Schema 提供编辑器提示；`pack.ts` 使用 Zod 严格校验结构和跨字段规则。构建加载即校验，不做在线热更新、不支持任意公式或脚本。

| 字段 | 含义 |
| --- | --- |
| version | 数据包格式版本 |
| progressions | 共用培养规则，以 ID 引用 |
| maxLevel / bottlenecks | 满层与瓶颈层数，瓶颈递增且小于满层 |
| costsByRealm | 各功法归属境界的逐层成本数组；第一项为一升二，必须覆盖所有后续层 |
| id | 稳定功法 ID，同时派生玉简和被动 ID |
| realm | 功法位归属 |
| rarity | common／rare，显示用，不强制效果数量 |
| effects | 一至两项不重复的六维属性；valuePerLevel 为每层固定加成 |
| dropWeight | 现有野外玉简组内相对权重，与稀有度独立配置 |

当前十六本：每境界三本常见单属性、一本珍稀双属性。炼气／筑基每项每层 +1，金丹／元婴每项每层 +2。四本珍稀全部九层提供六维合计 108 点，是初始调参基线，不代表长期平衡结论。

默认修为逐层费用：炼气 20、筑基 100、金丹 500、元婴 2000，分别乘以当前层数；道心感悟二至九层分别消耗 2 至 9。全本共消耗基础修为费用的 36 倍与 44 感悟。成本按功法归属境界计算，不因角色升境变化。

野外既有玉简组总掉落率保持 3%，常见权重 100、珍稀权重 5；现有池暂覆盖全部十六本，每本珍稀的相对掉率为常见的 1/20。玉简沿用统一库存、堆叠和拍卖交易。暂不新增获取渠道。

修改内容无需修改 TypeScript；新增效果机制才扩展编译器。Schema 结构源为 ManualPackShape，结构变更后通过 Zod toJSONSchema 更新同目录 schema；重复 ID、重复属性、缺失引用和不完整成本表由运行时细化校验拒绝。

## 实现边界

- 已学进度保存在功法状态的 learned JSONB；激活位置沿用独立槽位表，不创建多套构筑。
- 纯 changeManual 与 previewManualAction 产生确定性状态和费用计划。服务端负责身份、玉简归属、版本、战斗占用及资源事实。
- 角色锁、数据库事务与版本比较覆盖扣费、玉简消费、功法进度、激活位置和资源事件；任一步失败整体回滚。
- 每本激活功法编译一个被动标识和一至两项六维贡献。贡献在装备／宗门／炼体面板计算前加入临时属性，派生值遵循现有 v6 公式，不写入永久六维。
- 被动身份用于记录来源与层数；属性修正由人物编译器应用一次，不再在战斗开始时重复增加。
- 公开构筑只显示激活功法与层数，不暴露未激活收藏或培养记录。
- 需要应用迁移 `0043_manual-level-progression.sql`；没有旧功法数据兼容。历史 5A／9F 文档保留为阶段记录，不再作为当前规则。
