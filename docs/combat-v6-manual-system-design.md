## 玩法规则

- 炼气、筑基、金丹、元婴各开放一位，总共四位；更高境界不增加位置。
- 功法有固定境界归属，只能在对应位置激活。效果类型不按境界硬限制，由内容设计体现方向差异。
- 每个位置最多学习六种功法，每本独立保存层数和已解锁上限，同时只激活一本。暂不支持遗忘或替换；学满后不能继续学习新的功法，同名玉简突破不占额外名额。
- 学习消耗一本同名玉简，从第一层开始。空位自动激活；已有激活功法时，新学功法保存在收藏中。
- 免费切换，无冷却，不丢失培养进度。沿用现有战斗／结算占用保护，战斗结束后才能操作，下一场生效。
- 默认九层，三层、六层分别消耗两本、三本同名玉简突破瓶颈，只解锁后续层数，不直接升级。六本玉简加八次修炼完成一本功法。
- 升层消耗当前可用修为与道心感悟；修为继续用于境界提升，不能透支或导致境界倒退。功法满层不是角色突破条件。
- 未达到功法对应境界时，可持有和交易玉简，不能学习或培养。
- 未激活功法允许培养。每本提供一项六维属性与一个机制，从一层同时生效，九层内均逐层增强。

## 策划数据包

入口：`src/shared/engine/combat-v6/manuals/data/manual-pack.json`。

同目录 JSON Schema 提供编辑器提示；`pack.ts` 使用 Zod 严格校验结构和跨字段规则。构建加载即校验，不做在线热更新、不支持任意公式或脚本。

| 字段 | 含义 |
| --- | --- |
| version | 数据包格式版本 |
| progressions | 共用培养规则，以 ID 引用 |
| maxLevel / bottlenecks | 满层与瓶颈层数，瓶颈递增且小于满层 |
| costsByRealm | 各功法归属境界的逐层成本数组；第一项为一升二，必须覆盖所有后续层 |
| id | 稳定功法 ID，同时派生玉简和被动 ID |
| realm | 功法位归属 |
| effects | 一项六维属性；valueAt1 为一层初始加成，valuePerLevel 为后续每升一层的增量 |
| mechanism | 机制类型、单条件、适用伤害种类（如需要）、valueAt1 / valueAt9；九层线性插值 |

当前 24 本，每境界六本。炼气／筑基／金丹／元婴一层分别 +12／18／24／36，后续每层分别 +2／2／4／4，四本激活功法全部九层提供六维合计 186 点。机制包括条件增伤、减伤、治疗／护盾增强、闪避、封印抵抗和回合末恢复，详见首版计划。数值是首轮调参基线，尚非长期平衡结论。

修为逐层费用：炼气 40、筑基 200、金丹 1000、元婴 4000，分别乘以当前层数 L（1～8）；感悟费用分别为 2／3／4／5 × (L + 1)。单本九层累计修为分别 1,440／7,200／36,000／144,000，累计感悟分别 88／132／176／220。最高单次感悟消耗为 45，当前储存上限为 200。成本按功法归属境界计算，不因角色升境变化；旧已完成升级不追溯补扣。

野外既有玉简组总掉落率保持 3%，24 本玉简以 fixed 条目显式配置，初始各权重 100。功法包不再存稀有度或产出权重，产出包独立决定供应。玉简沿用统一库存、堆叠和拍卖交易；暂不新增渠道。

修改内容无需修改 TypeScript；新增效果机制才扩展编译器。Schema 结构源为 ManualPackShape，结构变更后通过 Zod toJSONSchema 更新同目录 schema；重复 ID、重复属性、缺失引用和不完整成本表由运行时细化校验拒绝。

## 实现边界

- 已学进度保存在功法状态的 learned JSONB；激活位置沿用独立槽位表，不创建多套构筑。
- 纯 changeManual 与 previewManualAction 产生确定性状态和费用计划。服务端负责身份、玉简归属、版本、战斗占用及资源事实。
- 每境界六种上限由共享状态校验与学习规则同时检查，服务端在扣减玉简前执行，不只依赖前端隐藏学习入口。
- 角色锁、数据库事务与版本比较覆盖扣费、玉简消费、功法进度、激活位置和资源事件；任一步失败整体回滚。
- 每本激活功法编译一个随层数编译的机制被动和一项六维贡献。贡献在装备／宗门／炼体面板计算前加入临时属性，派生值遵循现有 v6 公式，不写入永久六维。
- 被动负责单条件机制结算并记录来源与层数；属性修正由人物编译器应用一次，不再在战斗开始时重复增加。
- 公开构筑只显示激活功法与层数，不暴露未激活收藏或培养记录。
- 需要应用迁移 `0049_manual_first_release.sql`：清空旧已学进度、槽位、库存玉简、拍卖与邮件／兑换码中的玉简附件；不映射、不退款、不留旧定义兼容。冻结历史战斗归档保留，自包含快照不作为可用功法资产。切换环境应先停止旧版本写入并排空活动战局，再执行迁移与部署。历史 5A／9F 文档保留为阶段记录，不再作为当前规则。

## 功法页面（2026-09-21）

- 桌面左侧以盘坐墨像和四个境界功法位展示当前配置；点击功法位选择境界。右侧直接展开该境界已学书目，点击书目仅预览，只有「改修此法」提交激活。选中底色与「修」印记分别表示预览、生效，不再提供轮播、箭头或滑动切换。
- 桌面详情原位展示，低于 1024px 时使用紧凑功法位概览和单层详情抽屉；移动端不展示大幅立绘。空功法位进入公共储物袋选玉简，未开放境界保留低强调的锁定位。
- 详情聚焦本层与下一层的属性、机制变化。条件与数值分层，精确作用范围、释义、圆满效果和境界进度折叠展示。备选可展开与同境界当前所修的属性增减及机制比较，不合成战力分数。
- 九层节点按三层分段，以填墨、当前层强调、瓶颈锁和圆满印记表达进度。三／六层突破分别消耗 2／3 本玉简，只开放后续层数；九层隐藏培养操作。未生效的已学功法也可独立参悟。
- 培养区就是操作确认层：显示下一层收益、消耗、扣除后余额或资源缺口，点击明确命名的操作按钮直接提交，不再追加通用确认弹窗。提交期间防重复，完成后重新读取服务端权威状态，并在原位反馈。
- 学习新功法继续复用 InventoryItems／ItemSlot 选中具体玉简，回到功法详情预览第一层收益后扣 1 本。突破自动从背包找到一叠数量足够的同名玉简，仍按库存 id／revision 校验，不实现跨堆叠扣减；背包读取失败或刷新期间禁用扣玉简。首本学习自动激活，其余学习保留原配置。
- 未满六种时显示学习入口；学满后隐藏入口，仍可培养或改修。数值、服务端事务和战斗编译规则不变。美术素材沿用 [功法墨像素材记录](./combat-v6-manual-portrait-assets.md)。
