# 坊市材料堆叠

普通坊市的草药、矿石、妖兽材料、辅助材料和天材地宝按品阶增加每个货品的整叠数量。

| 品阶 | 每叠数量（含上下限） |
| --- | --- |
| 凡品 | 20–30 |
| 灵品 | 10–15 |
| 玄品 | 5–8 |
| 真品 | 2–3 |
| 地品 | 1–2 |
| 天品、仙品、神品 | 1 |

数量在生成新货架时等概率抽取，写入同一周期的共享 Redis 缓存。重新进入页面、切换角色或再次读取不会重新抽取。灵种、功法典籍、神通秘术、御灵集道具、道装和暗巷黑市保持原有单件规则。

- 配置：`packages/game-content/src/market.ts` 的 `MARKET_MATERIAL_STACK_RANGES`。
- 生成规则：`packages/game-rules/src/market/material-stock.ts`。
- 原有单价乘以数量后形成整叠售价；命格折扣应用于该总价。格子下面、物品预览、选购合计和服务端扣款都使用同一整叠售价。
- 购买请求中的 `quantity: 1` 表示购买这个货品一次，叠内数量只能由服务端决定，不支持拆叠购买。每个账号对本周期的同一货品仍限购一次。
- 实际按货架数量入库，返回的 `deliveries.quantity` 是实际购买数量。购买成功后库存显示为 0；重复请求幂等返回，使用新请求再次购买已购货品被拒绝。
- 保留已有货架的 ID、价格和限购记录；部署前缓存的单件货品继续按原数量出售，到下一批刷新才应用新数量。不清缓存或重置购买额度。

纯规则测试覆盖各品阶数量上下限、区间内波动、材料类型边界、整叠价格和无效价格。实际购买、余额、入库数量及刷新后的限购状态通过本地页面与真实 API 验证。

## 本地验收（2026-11-10）

- `local1` 从页面选购聚元尘 14 份、黄铜母 26 份，确认合计与实际扣款均为 7704 灵石，余额 218562 → 210858。聚元尘新增 14 份至储藏室；黄铜母与原有堆叠合并，由 1 → 27 份。只读数据库与后续材料、货币 API 读取均一致，满包未丢失物品。
- 同一请求重放返回 `state.replayed=true`，没有重复扣款或入库；不同请求再次买同一货品返回 409。再次读取和切换货架后数量、价格不重新抽取，已购货品库存为 0。
- 修改确认总价返回 409，伪造叠内购买数量返回 400，失效货品 ID 返回 409，均未扣款。
- 独立浏览器上下文中的 `local4` 余额 6195，购买 6482 灵石的聚元尘返回灵石不足，余额不变；购买黄铜母 26 份扣除 1222 灵石，余额 4973，全部进入储物袋。
- 桌面与 360px 页面检查数量角标、整叠售价、选购合计与物品预览，无横向溢出；功法典籍、神通秘术仍为 1 件。两名账号的同一货品分别独立限购。
- 未发放临时物资或直接写数据库；保留正式本地购买的材料及交易记录。未实测背包堆叠恰好跨越 999 上限的分流场景，沿用既有库存规则；回执提示统一按实际总件数报告，不把整叠数量误报为全部进入首个位置。
