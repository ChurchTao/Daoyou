# 云游探秘解谜版：开发路线图

解谜版的核心链路（剧本库、案卷生成、调查、对话、守卫、事件、静思、结案对决、结算）已经可玩，全部 31 个卫星节点也已切到新玩法。阶段 0–3、5 已完成；上线前还有阶段 6–9（推理公平与叙事一致、结构变体、美术与表现、上线前回归），按顺序推进，每个阶段内按小步提交。

- 设计与实施记录：[cloud-dungeon-mystery-redesign.md](cloud-dungeon-mystery-redesign.md)
- 上线前清单：[cloud-dungeon-launch-checklist.md](cloud-dungeon-launch-checklist.md)（开发中发现的上线事项一律记到那里，不在这里展开）

## 推进方式

每一小步都走同一套流程：

1. 动手前写清本步的设计与默认取舍，涉及玩法规则或界面结构的先确认。
2. 规则放在 `game-rules`，配纯函数单元测试；骨架变动跑 300 个种子的结构、可解性与最坏情况校验。
3. 涉及生成的，用真实模型生成样本抽查一致性。
4. 涉及界面的，按 `daoyou-game-ui` 规范实现，并在浏览器中实测，包括窄屏。
5. 在设计文档第 17 节记录实施结果、验证情况与已知不足，然后提交。

## 阶段 0：稳固（小改动）

先修掉已知会伤害体验的问题，避免后续阶段在错误的基础上叠加。

| 步骤 | 内容 | 验收 |
| --- | --- | --- |
| 0.1 | 生成失败时不再把场景不符的保底案卷交给玩家：保底案卷只用于其绑定节点；其他节点生成失败时重试一次，仍失败则开局报错、不扣灵气，并为该库存位排队补货 | 剑宗遗址生成失败时不会出现沉船案 |
| 0.2 | 生成质量的已知小问题：结案选项带“伪”“假”等字眼时改写或重试；结局叙事过滤英文取值 | 抽查若干份无此类问题 |
| 0.3 | 精英遭遇战的随从命名：守卫战的随从改为与守卫同源的名称，或守卫战只出守卫本身 | 迎战页不再出现“秘境精锐” |

## 阶段 1：场景设定重构与剧本适配

目标：给生成器足够具体的素材，让每个节点生成的剧本有地域特色；同时定下每个节点适合哪些案型，作为阶段 3 的依据。

### 1.1 场景配置结构

现有 `dungeon_config.scenario` 只有一句 `setting`。扩充为结构化设定（字段为初拟，实施时定稿）：

| 字段 | 内容 | 用途 |
| --- | --- | --- |
| `setting` | 一段总述：此地是什么、给人什么感觉 | 大纲阶段的总基调 |
| `places` | 6–10 个此地典型的场所（如“剑冢”“藏经阁残基”“试剑坪”） | 房间命名与描写的素材，避免千篇一律的“偏殿”“密室” |
| `inhabitants` | 可能在此出现的人物身份（如“剑宗遗脉”“拾荒散修”“守殿残魂”） | 人物设定的素材，人物身份贴合地域 |
| `history` | 1–3 条此地的往事钩子 | 真相与动机的来源，让案子扎根于此地 |
| `objects` | 此地特有的器物与痕迹 | 物件、线索、物品的素材 |
| `factions` | 相关势力（已有字段，目前全空） | 立场类剧本与人物来历 |
| `forbidden` | 禁写内容（已有字段，目前全空） | 避免与世界观冲突 |

- 结构放在 `game-domain/world/map.ts`，内容校验放在 `game-content` 的测试里。
- 生成器的大纲与正文阶段使用新字段；只给与本段有关的字段，控制提示长度。

## 阶段 2：体验与界面

目标：把“读一大段文字再点按钮”改为“看得见的案情”，玩家不必靠记忆管理线索、人物和地形。

| 步骤 | 内容 | 要点 |
| --- | --- | --- |
| 2.1 | 交互方案设计 | 按 `daoyou-game-ui` 定身份层、任务层、导航层；以窄屏为先出线框，确认后再实现 |
| 2.2 | 案情板 | 合并现在的笔记与结案面板。页签：线索、人物、地点。线索按来源（地点、人物）分组，新获得的标记未读。玩家可把线索钉到结案问题上，结案时直接对照所钉证据作答。不展示线索与问题的真实对应，避免泄题 |
| 2.3 | 小地图 | 已知房间的连线示意图，标出已到访、上锁、守卫、有人在场、发生过异动；点击房间前往 |
| 2.4 | 人物卡 | 头像（按人物身份类别准备一套通用水墨像，遵循 `daoyou-ink-portraits` 规范）、称谓与关系、状态标记（已取得信任、谎言被戳穿、已离场）、最近对话。交谈与出示从卡片发起；出示时优先列出与此人有关地点、人物的证据 |
| 2.5 | 行动反馈 | 每个动作标出行动力消耗；“异动”预兆以横幅提示，持续到事件发生或被阻止；获得线索时有明确的提示 |
| 2.6 | 等待体验 | 实时生成开局时展示进度与过场（先展示已确定的地点与人物数量）；结局叙事生成期间先展示评分明细 |
| 2.7 | 窄屏与整体验收 | 全流程在手机宽度下走一遍；回归结算、迎战、对话 |

## 阶段 3：剧本类型扩充

目标：按 1.2 的矩阵补齐案型，每个节点至少 2 种自然适配的剧本，撤掉牵强配对。新增顺序按覆盖节点数从多到少：

### 3.1 破禁试炼（unlock）

- 前提：前辈留下的禁制、试炼或机关，要闯过并取得其中之物。人物少，以环境推理为主。
- 结案（开启）问题：几道机关各自的解法、开启顺序、取得之物该如何处置。
- 新机制：机关组件（需按顺序或组合操作的物件），错误操作会触发反噬（扣气血或行动力）或封死一条路线；守卫与事件沿用。
- 适配 17 个节点。

### 3.2 异变溯源（anomaly，新原型）

- 前提：此地出了异常（灵脉枯竭、妖兽暴动、封印松动、阵法失控），要查明成因并止住它。
- 结案问题：异变的根源、是谁或什么引起、该如何平息。
- 新机制：异变随回合加剧（与事件系统结合，逐步封锁地点或加强遭遇战）；平息方式选对后，结尾对决改为与异变之源交手。
- 适配 16 个节点。

### 3.3 立场抉择（allegiance）

- 前提：两方或三方对立，各执一词；玩家需查清各方真实意图，最终选择支持哪一方。
- 结案问题：各方真实意图，以及最终选择支持谁。没有唯一正确答案，评分看判断是否有证据支撑。
- 新机制：结局分支，不同选择带来不同的结局叙事与奖励倾向；结尾对决的对手取决于选择。
- 适配 8 个节点。

### 3.4 每种新案型的交付内容

- `game-rules` 骨架构造器与单元测试（含 300 种子校验）；
- 剧本模板 JSON、生成器的案型描述与提示词片段；
- 至少一份与绑定节点场景相符的手写保底案卷；
- 新机制的规则、投影与界面；
- 真实生成抽查与浏览器实测。

### 3.5 节点切换与回归

- 按定稿矩阵更新全部节点的 `templates`，撤掉牵强配对；
- 生成版本升级、预热数量写入上线清单；
- 全案型回归：每种案型至少完整玩一局。

阶段 0–3 已全部完成：稳固、场景设定重构、界面（小地图、案情板、人物卡、异动横幅）、四种新案型（破禁试炼、异变溯源、立场抉择，以及此前的遗珍寻踪）与节点切换。全部 31 个节点按矩阵配置，每个节点 2–3 种自然适配的案型，没有牵强配对；每种案型各有一份绑定节点的保底案卷。实施细节见设计文档第 17 节。

原计划为可选项，阶段 5 完成后的梳理确认需要做，已并入阶段 7。

## 阶段 5：沉浸式界面

目标：阶段 2 的界面信息齐全，但铺得太满，像网页而不像游戏。本阶段让正文成为唯一焦点，地图、线索、人物按需查看；系统文案说大白话；机关、异动、守卫、对决各有专属场景。不改玩法规则与服务端。设计见设计文档第 24 节。

| 步骤 | 内容                                                             |
| ---- | ---------------------------------------------------------------- |
| 5.1  | 文案分层：入口与动作改为直白文案，加确认框、新手引导和临界提醒   |
| 5.2  | 正文舞台：正文流、可点的字与就地菜单、行动力香、轻反馈、窄屏底栏 |
| 5.3  | 屏宽适配：宽屏三栏常驻但压低存在感，中屏侧板                     |
| 5.4  | 机关场景与守卫对峙卡                                             |
| 5.5  | 异动表现：预兆、暗场转场、各效果落点、墨色侵蚀与镇物             |
| 5.6  | 推理场景、立场卷轴、现形转场；五种案型在手机与宽屏全流程回归     |

### 进度（2026-11-03）

阶段 5 已全部完成：系统文案改为直白说法；调查主屏改为正文舞台（正文里的字可点、就地菜单）；按屏宽分三档布局；机关、守卫、异动、推理、抉择与结尾对决各有专属场景或表现。五种案型各完整走了一局（手机与宽屏都有），实施细节见设计文档第 17 节。

## 阶段 6：推理公平与叙事一致

目标：答对必须靠证据，叙事不与局面矛盾。这是上线前必须完成的一阶段。来自阶段 5 回归中的实测：0 条线索直接作答也能拿满真相分和效率分；打败守卫后房间描写仍写守卫站在门口；局面不变时连点提示，十次给出同一句、每次扣行动力。

| 步骤 | 内容 | 要点 |
| --- | --- | --- |
| 6.1 | 证据计分 | 每道计分题按“答对 + 是否掌握支撑它的关键线索”（线索的 `supports`）计分：答对且掌握至少一条支撑线索得满分，答对但一条都没有只得部分分（默认 40%）。效率分改为乘以“证据率”（已掌握的支撑线索占比），不再单纯奖励少花行动力。抉择题不受影响。结算页逐题注明“有据”或“无据”。 |
| 6.2 | 证据计入线索分 | 玩家为某题选作证据、且确实支撑该题的线索算“证据得当”，占线索分的 20%；选错不扣分。让案情板上的“作为证据”从笔记变成玩法。（界面不用“钉”字，见设计文档第 25 节。） |
| 6.3 | 叙事随局面更新 | 重访或局面变化后不再原样重放首访描写：守卫被击败或化解、物件被毁、人物离场、房间被封时，由程序在房间描写后补一句当前状态；首访描写中提到已不在场的守卫时改用简述。不新增模型调用。 |
| 6.4 | 提示不原地重复 | 与上一条提示相同时不扣行动力，并说明“眼下没有新的头绪”；或在可能时给出更具体的一层提示（指向具体物件或人物）。 |
| 6.5 | 回归 | 五种案型各验证：盲答得分明显低于调查后作答；结算页的有据／无据标注；守卫、毁物、封房后的描写。规则改动配单元测试。 |

动手前在设计文档写清计分公式与默认值，确认后实施。

进度（2026-11-03）：阶段 6 已按默认值完成，实施与验证见设计文档第 17 节。

## 阶段 7：同类内的结构变体

目标：同一案型里推理的“形状”不再固定，打破“找出说谎者就知道答案”之类的套路。依赖阶段 6：证据规则不改，变体再多也能靠猜。

- 做法：每个案型的骨架构造器支持若干变体，按种子选取；变体改变说谎者的分配、真相成立的方式与线索指向，结案问题保持不变。模板声明允许的变体；大纲提示词告诉模型本局的变体及各身份的真实立场。每个变体都跑 300 个种子的结构、可解性与最坏情况校验。
- 第一批（每案型 1 个，专门打破最明显的套路）：

| 案型 | 变体 | 打破的套路 |
| --- | --- | --- |
| 遗府疑案 | 说谎者不是真凶，只在掩盖自己的私事；真凶说的是真话但有破绽 | 说谎的人就是凶手 |
| 遗珍寻踪 | 显眼处的遗珍早已被调包，真品在别处 | 最显眼的地方就是答案 |
| 破禁试炼 | 闯关者说的是真话，误导来自前人记错的一步 | 不信对手就对了 |
| 异变溯源 | 被当作祸首的妖物其实也是受害者，真祸首另有其人 | 揪出被冤枉的那一个就完事 |
| 立场抉择 | 中间人这次说的是真话，挑拨来自暗处的第三方 | 中间人一定在挑拨 |

- 第二批（视第一批的效果）：真凶有同谋、异变有主副两源、两条机关提示中有一条是伪造的等。
- 生成版本随之升级，库中剧本整批重生成（预热事项记入上线清单）。

进度（2026-11-03）：阶段 7 第一批五个变体已完成，实施与生成抽查见设计文档第 17 节。保底案卷经核实不需替换（遗府疑案骨架本无守卫）。

## 阶段 8：美术与表现

目标：在玩法完整的基础上补足质感。界面结构不变，只加表现层。

| 步骤 | 内容 | 要点 |
| --- | --- | --- |
| 8.1 | 打字机效果 | 本回合的新段落逐字显出（中文约 30–40 字／秒），点任意处立即显示全文；可在设置中关闭；“减少动态效果”下直接显示。正文里可点的字在显出后才可点。 |
| 8.2 | 人物立绘 | 按人物身份类别准备一套通用水墨立绘（如弟子、长老、散修、商人、仆役、器灵、残魂、妖物等，约 12–16 张），按 `daoyou-ink-portraits` 的笔墨基准与验收；在人物资料、交谈与守卫对峙卡中替换姓氏印章。案卷人物需要一个“身份类别”字段，由生成时从固定列表中选取。 |
| 8.3 | 结尾对手与异变化形 | 首领级对手按案型角色（真凶、夺宝者、守试者、异变化形、对立一方）各一张，用于现形转场与迎战页。 |
| 8.4 | 场景插画 | 先定规范：现有 `daoyou-map-art` 只管地图，`daoyou-ink-portraits` 不含场景山水，需要补一份场景插画的笔墨与构图规范（可新建技能）。按地貌类型（山门、洞府、遗迹、山林、水泽、荒漠、城镇等约 8–10 类）而非逐个节点出图，用作开场题签背景与案情板地点页的淡墨底图。 |
| 8.5 | 音效（可选） | 翻页、落印、机关转动、反噬、暗场的短音效与开关；默认关闭。是否做视 8.1–8.4 后的观感再定。 |

美术素材的生成与验收按对应技能执行；代码侧只负责注册、加载与显示位置。

进度（2026-11-03）：阶段 8 已完成（音效不做）。素材经本机 Codex 命令行调用内置 image_gen 生成，见设计文档第 17 节与 [cloud-dungeon-mystery-art.md](cloud-dungeon-mystery-art.md)。
