# combat-v6 Phase 7A：确定性遭遇编排与训练 Host

> 状态：已实现（2026-09-04）  
> 上位设计：[`combat-v6 梦幻式战斗体系设计稿与迁移路线图`](./combat-v6-mhxy-redesign-roadmap.md)

## 1. 目标

Phase 7A 是 combat-v6 第一个玩法消费纵切。它把 `character_build_v5`、独立训练 NPC、确定性策略和 `BattleSession` 编排成可逐回合驱动、查询和观察的共享纯逻辑 Host。

本阶段不接数据库、服务端会话、API、页面、奖励、战后回写、checkpoint 或持久录像。调试转录只服务测试、对拍和问题复现，不承担跨版本恢复契约。

## 2. 训练内容

训练 NPC 使用独立最终面板，不读取人物六维、宗门、道装、功法、修炼、battle-v5 或 creation-v2。首版固定提供60、120和180级三档显式面板，不随玩家动态缩放。

六类遭遇为：

1. 单体木桩。
2. 普通攻击陪练。
3. 三体木桩。
4. 低气血友方的治疗防护训练。
5. 由敌方正常施加控制、减益、DOT和伤势的净化训练。
6. 由敌方正常击倒友方的复活训练。

训练场景不直接注入运行时状态、护盾、伤势或倒地。训练友方虽使用人物的“倒地可复活”战斗种类，但仍属于独立 PVE 定义，不读取人物构筑。

## 3. Host 契约

遭遇编译顺序固定为：校验内容与档位、以 `full` 策略投影玩家、投影 NPC、校验阵容、合并技能和状态、创建带 Phase 7A 版本戳的战斗。

玩家位于 A 方且是唯一可由调用方提交指令的单位。其他单位由以下三种确定性策略驱动：始终防御、攻击稳定排序后的首个敌人、按回合索引循环技能。技能轮转不在 AI 层规避资源或封禁失败，仍交由 core 产生正式失败和兜底事件。

只读指令查询返回：

- 单位能否提交。
- 普攻与保护目标。
- 防御和逃跑可用性。
- 已拥有主动技能、基础目标数、目标模式、候选目标和预计失败原因。

查询不消费 RNG、不写事件、不替代执行裁定。玩家在锁定前可以覆盖指令；推进回合前必须已经为仍站立的玩家提交指令。

## 4. 版本与结果

```ts
{
  engineVersion: "combat-v6",
  rulesetVersion: "daoyou_rules_v5",
  contentVersion: "daoyou_training_encounter_content_v1",
  projectionVersion: "training_encounter_v1",
}
```

训练结果只解释为 `victory / defeat / draw / aborted`。玩家逃跑为 `aborted`，回合上限为 `draw`；任何结果都不生成奖励、失败成本或持久状态变化。

`combat_v6_encounter_host_v1` 调试转录保存初始编译单位、技能与状态定义、seed、版本戳、每回合锁定指令、事件和结束快照。它返回不可变副本，但不提供恢复接口。

## 5. 后续边界

Phase 7B 才接服务端权威内存会话、战斗 API 和最小训练房页面。Phase 7C 才进入普通任务 PVE，并逐玩法确定持久资源、奖励权威、失败成本和战后事务。正式 checkpoint、断线恢复、观战和长期录像继续属于 Phase 8。
