# V6 战绩页面

## 收录范围

战绩以当前角色在 `combat_replay_participants` 中的参战关系为准，查询已持久化的 `combat_replay_archives`，按结束时间、战斗 ID 倒序排列，每页 10 条。首页取同一列表的最近 3 条。

仅天骄榜（`ranking`）、擂台切磋（`arena-sparring`）保存长期可回放记录。

- 天骄榜挑战双方、擂台参战者均按各自角色视角查看同一战斗，包括被挑战的记录。
- 练功房和野外保留当场播放、终局结算与恢复，不再生成回放归档 outbox。
- 宗门挑战、破境试炼、秘境、蜃楼保留轻量结算凭据：继续使用归档表的来源／幂等键唯一约束，`replay` 为 NULL，不写参与者索引。宗门与蜃楼对归档行存在性的检查继续防止重复结算。
- 迁移 `0048_competitive_replay_retention.sql` 仅放宽 `replay` 非空约束，必须在新代码处理非竞技结算前应用。旧数据不删除、不改写；列表和详情查询均限制竞技来源，旧非竞技记录不再可见。
- 发布前积压的回放消息仍由原消费者确认，但非竞技消息只落轻量凭据，不再保存完整回放。
- 胜负和双方顺序由服务端按参与者阵营转换，前端不重新判定。
- `aborted` 展示为“中止”，不推断为落败或特定逃跑原因。
- 列表阵容来自开战快照；完整过程进入回放查看。
- 进行中的战局不属于战绩；竞技归档仍遵循原有事务和权限边界。
- 秘境整次探险路线与收获继续由探险札记负责；不混入旧 V5 战绩或他人公开分享回放。

## 展示与布局

- `/game/battle/history` 保持 `GameViewportLayout` 与 `battle-history` 场景注册，正文使用 `GameSceneFrame` 的 `lite` 宽度。
- 场景身份、HUD、聊天与全局导航各由现有壳组件负责，正文从玩法筛选直接进入记录。
- 记录依次展示结果与玩法、双方开战阵容、时间与回放操作；桌面阵容并列，窄屏上下排列。
- 胜利使用主题朱红色，其他结果使用墨色；保留文字结果，不仅依赖颜色区分。
- 日期、时间、回合数、页码使用默认 `font-mono`，日期精确到分钟。
- 首页使用同一组件的 `compact` 分支，只保留结果、玩法、对手、时间和回合数；整条记录仍可打开回放。
- 分类仅为全部、天骄榜、擂台切磋；筛选切换回到第一页，筛选和页码存入 URL。空列表、加载失败与重试沿用现有原语。
