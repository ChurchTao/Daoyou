# Phase 10A：秘境战斗与奖励链路切换 v6

> 2026-09-08：主体实现与本地主链路验收已完成，专项边界验收尚有待补项；已验证与未验证项见文末实施记录。

## 目标与边界

打通“探索 → v6 遭遇战 → 继续探索 → 最终结算”，所有现有秘境战斗入口硬切 v6。保留入口、地图、探索选择、AI 叙事及必要的恢复流程；共用少量按等级配置的普通、精英、首领模板，不为每张地图新增独有 Boss。

人物使用新版装备、道印、修炼、心法与经脉投影，支持持久灵兽及战斗内召唤／换宠。复用 v6 战斗页面、差量帧、逐行动播放、会话恢复及统一战绩归档。

不包含多人秘境、组队、阵法、战斗药品、新伤势系统、复杂 Boss 机制、旧奖励迁移或全仓 v5 删除。此前阶段未验收项继续独立追踪。

## 已确认玩法

1. 胜利后保留“继续探索／带着收获离开”的停顿，展示已确定的收获，不在展示或继续时再次抽奖。
2. 失败或成功逃跑结束本次秘境。保留此前已确定的探索收益及获胜战斗掉落；当前失败／逃跑战斗无奖励，无通关奖励。不额外扣款、掉落背包物品或追回累计收益。
3. 胜利后主动离开正常发放累计收益，无通关奖励。探索中的普通退出和异常恢复出口须明确映射到同一结算规则，不引入认输机制或重抽出口。
4. 首轮所有秘境遭遇不可捕捉。
5. 本次秘境产生的全部物品奖励，包括探索、搜刮和最终奖励，都通过通用掉落配置进入新版储物袋。旧奖励数据不迁移；满包沿用现有统一库存溢出处理。
6. AI 负责叙事与选择文案，不能决定物品、数量、品质及资源收益。收益由服务端配置确定；AI 评级仅用于展示，不决定经济收益，替换旧按评级保底材料数量的规则。
7. 人物经验、灵兽经验及物品等收益在秘境最终结算时统一发放。灵兽经验按每场终局在场且存活的灵兽分别记录，不能归给整次秘境结束时携带的灵兽。
8. 人物／灵兽按当前合法资源入场，HP、MP、寿命等战斗状态逐场结算，不在场次间自动回满。保留探索回血、回蓝入口，改用 v6 上限与校验；不再生成旧战斗伤势效果。
9. 从进入秘境至退出及结算完成，禁止换装备、改经脉、参悟道印、灵兽培养等构筑修改。战斗内合法召唤／换宠仍允许；现有其他构筑变更入口一并核对，避免绕过占用限制。
10. 停机维护硬切，旧秘境战斗不续跑、不兼容，不增加功能开关。维护前处理旧活动会话及未完成结算，不能静默丢弃已提交收益。

## 职责与数据流

探索系统决定遭遇触发和后续分支；战斗系统管理阵容、指令、回合和终局；掉落底座仅接受配置和随机源；秘境业务结算负责奖励归属、库存发放与任务进度。

探索触发遭遇后，由服务端确定模板并创建 v6 战斗，探索会话关联 battleId 并暂停推进。服务端消费终局、结算战斗状态并记录本场待发收益后，才能恢复探索或进入最终结算。客户端播放完成只影响展示，不触发权威奖励判定。

- 遭遇配置、抽奖输入及已确定结果按现有会话持久化边界保存；刷新、重试、进程恢复不能重新抽怪或抽奖。
- 复用现有会话、Redis 锁及事务／幂等结算能力，不新增消费凭据表或通用工作流框架。实施时核对已有持久化落点，必要字段限于本链路恢复所需。
- 战斗终局重复到达不得重复累计收益、扣寿命或更新任务。最终发放重试不得重复入包、发经验或货币。
- 跨系统结算尚未完成时保持恢复态，不开放下一场或解除秘境占用；数据库提交与 Redis 状态更新之间的失败须可从已提交事实恢复。
- 掉落底座不依赖秘境、角色或库存；core 不读取秘境剧情、奖励或数据库。
- 战绩使用统一元数据与参与角色关联表；列表不读取或解包回放数据包。

## 实施顺序

### 1. 梳理入口与确定性配置

核对 `DungeonApplicationService`、`dungeon/service_v2`、奖励工厂、探索资源操作、前端秘境状态及任务消费者。列出需要替换的旧投影、战斗执行、AI 奖励输入和所有收益出口。

建立最小遭遇模板和秘境掉落／资源收益配置，沿用现有通用定义目录与掉落底座；具体首轮数值由现有等级范围制定并在实施记录中列明，不新增复杂难度系统。

验证：各入口都能映射到服务端合法配置，未知或非法 AI 输入不能直接成为战斗或奖励参数。

### 2. 接入战斗与探索恢复

创建秘境 v6 编排入口，衔接已有运行态、角色资源权威与占用约束。前端使用共用战斗组件及播放控制器，恢复后回到对应探索阶段。

验证：连续两场遭遇、胜利停顿、主动离开、失败、逃跑、刷新及重复提交；未完成结算不能继续探索。人物构筑和灵兽正常进入战斗，旧战斗执行入口不再可用。

### 3. 接入收益累计和最终发放

替换全部秘境物品奖励出口，删除本链路 AI 奖励数值控制及评级保底逻辑。逐场记录灵兽经验资格和累计收益，最终统一发放；资源状态仍逐场落地。

验证：探索、搜刮、通关各收益来源；失败／退出收益边界；重复终局、结算重试、满包、灵兽死亡及换宠后的经验归属。任务事件不重复计数。

### 4. 硬切与清理

关闭秘境旧创建／执行链路，仅删除本次替换后无引用的代码。核对所有地图入口，更新协议、发布和恢复说明。全仓 v5、旧造物及其他玩法依赖继续后续分阶段处理。

验证：秘境生产链路不再使用旧战斗投影；发布说明列明旧活动会话处理、前后端同步发布及刷新要求。

## 实施记录（2026-09-08）

### 已实现

- 秘境复用 `dungeon_runs.battle_payload` 保存 v6 输入、运行态、事件、回合记录及 revision，数据库是恢复基准，不新增战斗表或消费凭据表。战斗写入沿用人物 Redis 锁、人物行锁和事务。
- 终局资源、灵兽寿命、本场待发收益和统一战绩归档在同一事务提交；最终库存、人物经验／灵石、各场灵兽经验和秘境归档按既有终局提交条件原子发放。
- 前端复用 v6 会话、差量帧与逐行动组件；关闭旧执行、查探和放弃 API（410），删除替换后失去引用的旧准备页面与 Hook。
- 秘境期间冻结构筑、暂停自然恢复；恢复丹药仅在无活动战斗的探索／休整阶段使用。存活灵兽继承 HP／MP；本次秘境已死亡灵兽不再加入后续遭遇。
- AI 仅决定叙事与选择文案，结算提示词不再设计额外材料。新物品奖励统一通过通用掉落底座进入储物袋，溢出沿用库存底座规则。既有探索选项的材料消耗仍沿用宝库资源操作，本阶段未迁移该旧消耗来源。

### 首轮配置

地图要求境界的初期映射为 v6 等级 L。普通／精英／首领分别为 1／2／1 名敌人；HP 为 `(100 + 20L) × 1／1.2／2.5`，攻击为 `(15 + 5L) × 1／1.1／1.3`。第 1—2 轮普通，第 3—4 轮精英，最后一轮首领。叙事敌名不影响数值。

| 来源     | 单次材料概率 | 人物经验 | 灵石 |
| -------- | ------------ | -------- | ---- |
| 探索轮次 | 30%          | 2L       | L    |
| 获胜战斗 | 60%          | 5L       | 2L   |
| 正常通关 | 100%         | 10L      | 5L   |

材料从现有四种青溪固定材料等权抽取，每次至多一件。概率仅为开发配置，不在玩家页面公开。每个来源使用持久化秘境种子和来源键生成独立随机流，不消耗战斗 RNG。
