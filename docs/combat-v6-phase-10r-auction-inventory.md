# Phase 10R：拍卖寄售与新版物品栏闭环

状态：2026-09-10 主体实施与重点本地运行验收完成；未覆盖项见文末。

## 已确认边界

- 新上架仅扣新版 bag；覆盖上架、浏览、购买、部分成交、主动下架、到期退回、公共与好友专属寄售。
- 保留每角色五个有效货单、48小时期限、按件一口价、阶梯税、单次交易总额上限、好友与专属交易符箓成本、同账号角色禁止交易规则。
- 有品质的材料、种子、丹药／灵果保留玄品起售及品质单价上限。用户补充确认：无旧式品质的道装、图纸、功法玉简与兽诀全部允许寄售，单价上限9,999,999灵石，不虚构品质。
- 用户在上线前停机维护，使用旧版本将所有旧有效货单下架返回。新版本不实现旧货单转换、撤单工具或双协议交易兼容。部署前应只读核对旧有效货单已清空。
- 历史邮件领取继续使用10Q既有协议；不转换历史附件、不删除历史货单或表。
- 不开发竞价、求购、批量上架、召唤兽交易、绑定体系、补偿或经济数值重平衡。

## 设计

复用现有货单表，在 itemSnapshot 保存显式版本和可信新版物品事实；上架从背包扣除，货单余量成为寄售期间数量权威，不新增托管表。客户端只提交引用、revision、数量、价格、交易对象与请求标识。

买家扣款、货单扣量、买家物品邮件及卖家税后灵石邮件同事务；主动下架和过期通过条件状态更新，仅返还剩余数量。物品邮件使用 inventory_v1，领取优先 bag、满包 storage。道装身份与属性、丹药效果、种子完整事实原样保留，对外隐藏种子内部生长事实。

沿用玩家命令锁与持久幂等；上架补充请求标识，购买重试保留同一请求标识，下架按货单身份幂等。数据库条件更新负责最终数量及状态约束。

寄售弹窗左表单与单附件格、右五列40格完整公共背包，窄屏抽屉。不可售物品可查看详情，选择时说明限制。浏览页继续现有筛选、精确搜索、排序、分页和高额确认，改用新版分类及统一物品详情。

## 验收

- 两个真实本地账号上架、部分购买、领取、剩余下架／到期返还。
- 支持类型事实不变；满包溢出；版本、数量、装备、归属、专属权限及同账号限制。
- 上架重放、争买、下架／过期与购买竞争不重复扣物、扣款或发邮件。
- 税费、卖家邮件和专属符箓成本正确。
- 桌面、窄屏格位、选择、数量、单价、成交与返还反馈。
- lint、build及适用共享纯规则测试；不新增服务端／页面／数据库测试或一次性验收脚本。

前序阶段未验收项继续保留。

## 实施结果

- AuctionService 已解除对旧材料表、旧消耗品表、creation_products、旧装备读取与装配事件的依赖；新上架唯一来源为 bag。未添加旧货单兼容分支或维护撤单工具。
- 货单复用现有字段，itemType 使用新版物品类别，itemSnapshot 为 `{ version: 'inventory_v1', item: ItemGrant }`；无品质品类的 itemQuality 为空，不新增表或数据库迁移。
- 购买、下架和到期退回统一发 inventory_v1 邮件；保持原交易数量、税费、时间、好友及同账号规则。完整事实只在服务端流转，公开列表不返回原始快照。
- 上架使用 requestId 和 revision，持久防重覆盖物品、数量、价格及交易对象；购买失败重试复用请求标识。复用标识修改内容返回409。下架仍按货单身份幂等。
- 寄售弹窗复用完整公共物品栏、物品预览与窄屏抽屉；浏览页保留搜索、分类、排序、分页、按数量购买与高额确认，替换旧物品展示组件。场景文案不再宣称支持竞价。
- 删除本次迁移后已无消费者的旧消耗品寄售开关和旧材料寄售适配函数。全程使用 apply_patch 修改文件，格式化只读取 formatter 输出后通过 apply_patch 应用。
