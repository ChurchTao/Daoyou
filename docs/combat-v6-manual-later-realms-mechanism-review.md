# 后续境界功法：实效与实现成本审查

> 2026-10-25更新：本文件保留实施前的成本审查与取舍依据。最终采用的被动合同、数值、获取及接入验收见[实施记录](combat-v6-manual-later-realms-implementation.md)；下文“尚未实施”“先验证”等描述是审查时点状态，不再作为当前开发清单。

> 2026-10-24。审查对象为[附加被动第二稿](combat-v6-manual-later-realms-design-draft.md)。仅审查及修订建议，不修改运行时代码。四境各六本、名称、出处、六维属性、九层培养与最终八位的决定全部保留。本文对被动的评审结论优先于第二稿的机制合同和搭配推荐。

## 1. 结论与判断标准

第二稿不能直接作为开发清单。24本中，7本需要重写核心效果或触发前提，10本需要明确／简化合同，4本可保留方向，3本的精细版本需要先验证收益再决定是否投入。技术上容易实现，不等于值得给玩家一个高阶功法位；有战术价值，也不等于值得为一本书新增完整结算流程。

判断分为三项：

- **实际收益**：当前已经有合格技能和对手，效果改善伤害、防护或解除现存威胁；不能仅改善当前不紧缺的资源。
- **触发与操作成本**：正常打法能自然触发，或玩家付出的防御／弱攻击回合能得到足够回报。不能把稀有前提、低概率、长间隔层层叠上后仍当常用选择。
- **实现与维护成本**：除效果本身，还包括投影、自动战斗、战报、确定性回放和边界验证。下文低／中／高为相对成本，不是开发人日承诺。

| 成本 | 本文口径 |
| --- | --- |
| 低 | 复用现成过滤、修正或效果，主要在功法内容模型和编译器接入 |
| 中 | 增加有限共享事实、状态分类或一个明确事件；可供数本书共用 |
| 高 | 新增结算时点、跨行动身份记忆、精确收支账或覆盖全部提前返回的生命周期；验证成本明显高于填内容 |

本文的实效是依据当前代码和用户反馈做的结构性判断，未测胜率、平均战斗回合或剩余法力分布。战斗回合上限不能当作典型战斗时长。

## 2. 决定设计去留的代码事实

### 2.1 缩冷却、节蓝与补蓝不适合承担本轮核心收益

按人物180级、宗门法门满级及七层经脉展开当前五宗十流派的可达配法，去重共73个可用宗门主动定义，其中16个在至少一种配法中存在冷却。这是所有配法并集，不是一个角色同时拥有的技能；其中还包含召唤／追击、复活／协同等不符合六道白名单的技能。口径依据[宗门注册表](../packages/game-content/src/sects/registry.ts)、[进度上限](../packages/game-content/src/sects/progression/progression.json)与[流派编译](../packages/game-rules/src/sects/compiler.ts)，不是线上技能使用率。

因此不能说游戏完全没有冷却，但六道原案的覆盖确实很窄：还要轮换技能、前招仍余至少两回合冷却、概率成功、每三回合才尝试一次。长达36或150回合的特殊技能减一回合，也不等于能在正常战斗中多用一次。不能为救这本书给现有技能普遍加冷却。

用户已经指出当前法力不紧缺。角色基础法力还随灵力、神识增长，见[面板投影](../packages/game-rules/src/combat/projection/character-panel-v1.ts)。道经要求放弃主力出手去普攻回蓝，机会成本更差；五藏节蓝即使常驻触发，也可能没有胜负收益。三本都应撤掉原收益，不以“以后也许有耗蓝压力”为本次设计依据。

### 2.2 九转目前没有原案要求的法术段数

当前可用直接法术主动主要来自天衍、九劫，其原生攻击均为对每个目标一段；第二稿还排除了法术连击复制。红尘断尘的三段是物理，天衍焚天和九劫六霄是多个目标各一段。**原生多段法术门槛目前无合格技能，九转原案应直接替换。** 不能将群攻人数算成同目标段数，也不能为功法临时重做宗门技能。

核对入口：[红尘技能](../packages/game-content/src/sects/data/lingxiao-combat.json)、[天衍技能](../packages/game-content/src/sects/data/tianyan-skills.json)、[九劫技能](../packages/game-content/src/sects/data/jiujie-combat.json)。

### 2.3 技能标签、实际伤害类别与持续伤害必须分开

- `spell`技能标签不等于法术伤害。幽都裂魂咒、无相破妄指存在普通固伤；幽都销魂蚀骨还存在直接比例伤害。实际分类由效果和公式决定，见[伤害效果分派](../packages/combat-core/src/effects.ts)。通用增伤若一律只认物理／法术，会遗漏完整流派。
- 当前宗门的魂毒、蚀骨魂毒、余火都是**有数值封顶的比例气血跳伤**，按`Fixed + Status`来源结算，不等于主动技能的`percentageDamage`标记。太阴、万毒若笼统排除“比例DOT”，会排掉当前主要对象。
- 修订建议明确覆盖这三类已有气血跳伤；不改扣蓝跳伤，不扩到直接比例攻击，不新增跳数、延时或绕盾规则。详见[魂毒定义](../packages/game-content/src/sects/data/youdu-combat.json)、[余火定义](../packages/game-content/src/sects/data/tianyan-foundation.json)、[DOT结算](../packages/combat-core/src/status.ts)。

### 2.4 自动战斗不能默认会为被动铺垫

[自动估分](../packages/game-rules/src/combat/auto-utility.ts)明确不推演被动连锁；防御只有极小基础生存分及低血修正，没有“本次防御换来下轮盾／折锋”的收益估计。当前策略也不能靠上次技能、目标或伤害类型主动规划轮换。

因此物法交替、换治疗目标、防御后再攻击等设计，必须另外计入自动战斗适配成本。能在手动演示触发，不代表挂机玩家实际用得到。新增估值应只读取玩家可见事实，不借用敌方隐藏面板或未公开指令。

### 2.5 护盾、净化有现实对象，但要控制范围

天衍已有主动自盾；五宗都有可驱散数值增益，红尘重创降疗、幽都滞魂／摄魂、天衍降速降攻降防、九劫裂甲等也可提供净化对象。太阳、吞天、辅助净化并非为未来虚构对象而设计。

不过，当前能轮换**人物友方主目标**的主动治疗主要是无相甘露愿、归元愿。天衍的部分治疗是攻击敌方后给低血队友的附带治疗，自盾也不能轮换队友；无相护生愿是减伤状态，不是护盾。九天的多重前提不应宣称普遍服务所有辅助。

同时，现成`Buff/Debuff`分类过宽，包含隐身、印记、追击准备等规则状态。普通数值增减益需明确分类／白名单，不能直接全部吞掉或净除。见[无相技能](../packages/game-content/src/sects/data/wuxiang-combat.json)及[驱散入口](../packages/combat-core/src/effects.ts)。

## 4. 七项建议替代：只改被动，不动名称与属性

以下是复审后的下一稿方向。仍需确定一／九层强度，但不再依赖缺失技能或不紧缺资源；不是已经上线的配置。

| 道经 | 增强本人宗门主动对**主目标**的直接伤害；普通固伤参与，直接比例伤害、DOT、派生伤害不参与；副目标不增强 | 稳定的聚焦攻击选项，不要求弱普攻换资源。允许24本里有少数简洁基准项，不给每本堆连锁 | 低：主目标／来源／比例排除已有 |

| 太皇经 | 提升本人主动直接物理攻击的狂暴概率，沿用现有物理狂暴公式和每段判定，不另加破守、穿透或追击 | 物理攻伐专精，面对正常攻击目标就能产生收益；当前已有狂暴结算，不依赖敌人先防御 | 低：已有物理狂暴率修正。按期望伤害与爆发分布定强度，不能把新增概率直接当最终增伤百分比 |
| 九转天功 | 本人直接法术攻击带**可净化普通数值减益**的目标时，忽视部分法防；不靠原生多段，不增加攻击次数 | 天衍已有减速、降攻、降防，九劫及队友也有配合对象；建立减益后压制，与太阳的耗盾不同。首击若尚未附上减益，不提前享受加成 | 中：现有法防穿透＋普通数值减益分类；分类与吞天／净化共用，不另做招式历史 |
| 九天十地经 | 每回合首次正常完成、以存活人物为主目标的宗门主动治疗后，若该目标有合格普通数值减益，则有概率净除一项；无合格状态不尝试，不净化封印／DOT | 顺着原有治疗行为附带解减益；同一伤员可以持续救，不为触发被迫换人。明确是无相等主目标治疗流派专精 | 中：识别正常完成的治疗主动和主目标＋状态分类；可先用有限支持技能清单，取消精确有效治疗量／溢疗／净新增盾条件，不宣称覆盖攻击附带治疗 |
| 六道轮回天功 | 增强本人宗门主动群攻对**非主目标**的直接伤害；普通固伤参与，直接比例伤害、DOT和派生伤害排除 | 强化群攻铺压，与道经的主目标专精有明确作用面差别。红尘群攻、幽都普通固伤群攻、天衍与九劫群法都有现存对象；只剩主目标时无收益 | 低：副目标过滤和伤害修正已有，无CD、历史技能或额外行动需求 |

五藏与杀戮同属炼虚位，本来就不能同时激活；不需要为此另建护盾互斥系统。它们与其他境界及宗门护盾继续按现行规则共存，但要核对八位总预算。

道经、六道的直接增伤应通过已有`OnHitCalc`上下文过滤直接比例伤害；当前普通modifier求值没有透传该标记，不能仅写`excludePercentageDamage`就认为生效。梵圣使用的伤后钩子同样缺此标记，须补通用透传。西皇、九天也没有现成的“治疗标签”可直接筛，需有限技能清单或规则层分类；主目标死亡／倒地／失效时不补盾、不净化，也不改投另一名队友。

这些替代不以“每本通用”为目标。太阴仍服务DOT流派，九天仍服务主目标治疗，太阳仍专门破盾。合格的专精应在对应打法中明显有效，不能只是所有玩家都偶尔触发一点。

## 5. 十项明确／简化合同的落点

1. **炼神**：保留解除封印后的短期抗封。取消单次消费能省掉新的封印尝试生命周期；解除原因和合格封印仍需可靠识别，不能误称纯配置。下一稿还需明确自然到期与友方解除的支持范围。
2. **西皇**：从“有效过量治疗转盾”改为“正常完成特定主目标治疗后附固定小盾”，满血治疗也允许按设计得盾；因此不再需要区分真实溢疗、重伤浪费、禁疗浪费。必须支付并实际完成治疗技能，受术者仍存活合法，不能因未报ActionFailed就无条件生盾。仅支持明确治疗主动，不把攻击附带治疗误认成给敌人上盾。
3. **恒宇**：聚焦记忆只由实际发动的攻击和主动改变打法更新；强制休息／被控跳过不清空。攻击同一主目标的后续出手只获一档穿透，未命中照常算该次攻击，不叠层。目标身份与多段冻结依然有中等以上成本，不能承诺零改核。
4. **百脉**：防御完成后生盾保留。补成功防御的通用事实和自动防御收益估值；验证人物防御时灵兽仍可输出，不以“玩家放弃全部输出”计算机会成本。
5. **万毒**、6. **太阴**：共享已有气血DOT适用范围及修正顺序。先用现行比例与封顶计算原始跳伤，太阴对其结果只增幅一次，万毒再作受方减免；不能只增封顶前比例而在常见封顶区完全无收益，也不能同时对比例、封顶、结果分别加成。增幅后仍为有限封顶数值，不改跳数、扣蓝或绕盾，排除直接比例攻击。
7. **杀戮**：每回合首个使主目标实际掉血的合格攻击行动结束时，按该行动的合格主目标实际掉血总额生盾，并受最大气血上限约束。接受中等的通用实伤汇总成本，避免系统偏袒单段招；不含吸收盾、击杀溢出、直接比例、DOT或派生伤害。现有`impactDamageByTarget`含盾吸收，不能直接当实际掉血总额。整次仍只一面盾、一个共享额度，不让多段／物法钩子各领一次。
8. **古神**：建议优先在已有直接伤害计算阶段做大段防护，不严格追求扣盾后的气血削峰；阈值、可减免范围与护盾顺序需重写并明确告知。这是效果语义调整，不是原合同的等价低成本实现；若该版本无法提供清楚的重击专防，就暂缓，不偷换为全程常驻减伤。
9. **金刚**：复用百脉的成功防御事实。已有“防御→下轮实际攻击→敌方下一次伤害行动减弱”前置，不再另加每两回合一次；采用现有伤害行动后消费状态的语义，保留准备和折锋的短期到期。自动评估必须计入这条收益，否则应视为手动专用、未完成自动适配。
10. **不灭天功**：改回合开始检查，避开受控也要执行的行动前窗口；有一项敌方合格普通数值减益／气血DOT即可尝试。每回合轮首至多尝试一次，不沿用三回合间隔，九层提高概率；不解封印、不处理自施代价和规则标记。

状态分类投资有复用价值：九转识别减益、九天净除减益、吞天移除增益、不灭天功自净可以共用。首期采用明确的内容分类／支持清单即可，不建设允许任意脚本的效果系统。

## 6. 三项精细版本先验证，不直接判鸡肋

| 功法 | 值得保留的体验 | 先解决的问题 |
| --- | --- | --- |
| 原始真解 | 对重复强招形成识破，逼敌人换招或换攻击者 | 单敌单招识别在主流战局中的有效承伤占比；若经常被群攻或不同敌人刷新，记忆成本不值得。需冻结整次行动，不能同招后段自行视为第二次施法 |
| 不灭经 | 盾与空窗带来修复，区别于低血常驻回血 | 全来源气血减少是否值得单独记录；优先用有限触发次数限制续航，而非另建精确恢复总额账。必须实测DOT、自损、气血费用下是否仍有足够窗口，以及与人物防御＋灵兽输出的拖战关系 |
| 无始经 | 自己行动前承受压力，天然适合慢速人物 | 统一行动窗口的通用价值是否足够；要覆盖受控、休息和无指令等提前返回。若只处理成功AfterAction，会产生受控时整回合保护，属于规则错误而非平衡细节 |

这三项不通过新增复活、额外行动、时间倒流或新资源补偿。先以现有内容验证可见收益；没有收益证据时，不因“大乘必须复杂”而锁定高成本合同。

## 7. 开发范围与验证安排

### 7.1 公共接入成本单独列项

- **八位接入**：境界／槽位类型、校验、内容、数据库范围、界面展示与旧进度兼容。它是本次扩境的固定成本，不计成每本机制各做一次。
- **功法编译能力**：有边界的被动类型、参数校验、共享频率／预算与短期状态投影。目前[功法投影](../packages/game-rules/src/combat/projection/compose-character-manuals.ts)没有合并功法自己的`statusDefs`；需要统一处理命名空间与冲突。
- **状态分类与DOT**：支持上文明确的现有状态，不让普通Buff/Debuff等于全部可吞／可净状态；不因新功法让DOT开始走盾。
- **自动战斗和可见反馈**：防御铺垫等确有决策变化的被动才加对应估值；显示准备、适应、折锋、识破等可见状态。不能假定被动接入后自动策略自然理解。
- **器诀子调用边界**：第二稿统一排除器诀调用的子招也有成本。现有子招拥有独立行动，排除`Art`标签只能排除器诀本体。实施前需统一决定哪些新效果允许子招、共享什么预算；不能为24本分别补一套父子身份，也不能把此成本漏掉。

### 7.2 建议顺序

1. **先做有效且便宜的内容**：道经、五藏、太阳、太皇、六道。先证明高阶书有实际收益，不为了“新”堆等待条件。
2. **再补可复用的能力**：DOT专精、普通数值状态分类、成功防御事实、少量物法记忆及必要的实伤汇总；支持太阴／万毒、吞天／净化、百脉／金刚、惊蛰、杀戮等。西皇／九天按简化的治疗技能支持范围实现，不先建设精确溢疗系统。
3. **最后决定精细结算**：原始、不灭经、无始，以及仍要保留原语义的古神。根据前两步发现的实际收益和共享能力复用情况决定，不先大规模改核。

这个顺序是技术拆分，不改变四境每境六本的目标，也不意味着用未定的空被动上线占位。正式开放某境前，该境六本应分别完成最终效果和验收。

### 7.3 实施时的实效验收

- 每本在已有合法流派／现有对手中有明确适用例，并列不适用例。特殊换修允许覆盖窄，但在目标场景应显著改善结果；不把未知出场率伪装成已测数据。
- 对比相同配置的未装配／一层／九层；关注实际增伤、耗盾、有效吸收、实际恢复、净化成功处理的威胁。只数触发次数不能证明强度，溢出恢复和到期未消耗护盾不能计作有效收益。
- 检查正常自动出手能否利用；需要防御准备的，比较整段行动的收益，计入人物放弃出手及灵兽仍然输出。不能靠手动刻意喂条件证明AUTO有效。
- 对首段、群攻、法连、器诀子调用、固伤／直接比例、DOT、重伤／禁疗和受控跳过做针对性规则验收；功法间共用额度，不让多钩子重复领取。
- 一／九层系数均未定，当前不能承诺每本都已“有强度”；实施时若低层长期撞上上限，或在主要配法没有有效收益，应继续改效果，而不是单纯抬高触发概率。
- 纯共享规则用所属包的确定性单元测试；自动行为与实际战斗按`docs/testing.md`的浏览器模拟验收，不另建一次性战斗脚本。这里只规定未来验收，本轮没有运行这些测试。
