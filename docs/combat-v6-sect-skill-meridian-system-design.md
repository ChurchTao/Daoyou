本文定义 combat-v6 的宗门战斗体系。现有宗门社会身份和玩家已经投入形成的心法等级、经脉深度平滑进入新版；旧宗门技能、`AbilityConfig`、通用成长倍率、四技能装配和 v5 运行时产物全部退出。

新版宗门可以拥有高度独特的战斗机制，但必须编译为 combat-v6 通用技能、状态、被动、资源、面板、标签和效果原语，不得在 core 中按宗门、流派、节点或技能 ID 写分支。

---

## 1. 已确认的硬约束

1. 每个宗门固定六本心法：一本主心法和五本分支心法。
2. 心法范围为 0～180 级；上限为 `min(180, 人物等级 + 10)`。
3. 分支心法不得超过主心法等级。
4. 每个宗门技能必须且只能归属一本心法，技能等级等于所属心法等级。
5. 取消 v5 `growthProfile` 对伤害、治疗、护盾和状态的通用百分比成长；每个技能显式读取技能等级。
6. 心法可以提供少量明确的 v6 面板成长，但不能提供四项人物修炼。
7. 所有已解锁宗门战斗技能均可使用，不再装配固定四个主动技能。
8. 快捷栏只保存 UI 排序偏好，不决定战斗能力。
9. 所有人使用统一普通攻击；宗门若要改变普攻，通过内容被动或技能覆盖实现。
10. 宗门特色机制必须保留，但不能形成宗门专用 core 分支。
11. 特殊战斗资源按机制需要决定，可不配置；首版每个宗门最多一种。
12. 每个宗门固定两个流派。
13. 每条流派固定七层经脉，每层固定三个互斥节点。
14. 每个流派只保存一套经脉方案，因此每宗门共保存两套方案。
15. 激活流派时自动使用该流派唯一的经脉方案，不存在同一流派下的多方案槽位。
16. 经脉方案只能在战斗外免费修改、重置和切换。
17. 旧六心法等级按槽位原值继承，不返还修为或灵石。
18. 旧经脉最高解锁深度与节点选择结构平滑迁移，不翻译旧节点战斗效果。
19. 旧四技能栏、旧技能效果和旧经脉运行时产物不进入 v6。
20. 宗门社会身份与宗门战斗进度必须保持领域分离。
21. 同一宗门的两条流派共享唯一一套基础技能；流派只能通过根基、经脉 patch 和少量授予技能改变构筑，不得拆成两套基础技能表。
22. 短期形态与特色资源必须编译为通用状态、资源、成功结算效果和被动；core 不识别形态名、资源 ID 或宗门 ID。
23. 治疗、防护、净化和复活宗门仍遵守共享基础技能原则，不为治疗流与输出流维护两套基础技能。

## 2. 领域结构

```text
宗门
├─ 社会身份
│  ├─ 宗门归属、职位与贡献
│  ├─ 任务、设施、商店与组织关系
│  └─ 入宗、离宗与转宗记录
└─ combat-v6 战斗传承
   ├─ 六本心法
   ├─ 宗门根基特性
   ├─ 宗门主动、被动和内部技能
   ├─ 可选特色战斗资源
   ├─ 两条流派
   └─ 每流派一套七层经脉
```

社会身份可以继续使用现有宗门组织领域。combat-v6 投影只能读取必要的战斗进度，不得导入 v5 宗门编译器或旧 `AbilityConfig`。

## 3. 六本心法

### 3.1 结构

每个宗门定义：

```ts
interface SectMethodDefV6 {
  id: string;
  slot: 1 | 2 | 3 | 4 | 5 | 6;
  name: string;
  description: string;
  isPrimary: boolean;
  panelRule?: SectMethodPanelRuleV6;
}
```

要求：

- 恰好六本且槽位 1～6 完整唯一。
- 恰好一本 `isPrimary: true`。
- 六本同时存在，不是需要装配的心法槽位。
- 主心法负责统摄宗门传承和核心技能上限。
- 五本分支心法由各宗门自行定义职责，不强制套用统一攻、防、速、控、疗模板。

### 3.2 等级规则

```text
methodLevelCap = min(180, characterLevel + 10)

primaryMethodLevel ≤ methodLevelCap
branchMethodLevel ≤ primaryMethodLevel
```

心法升级是确定性成长：消耗修为和灵石，必定成功。具体成本曲线属于后续平衡配置。

人物等级、心法等级和四项修炼是三个独立维度：

- 人物等级来自境界阶段映射。
- 心法等级决定宗门技能解锁与技能等级。
- 四修炼来自新版修炼系统并参与修炼差公式。

### 3.3 技能等级唯一来源

每个宗门技能声明 `sourceMethodId`：

```text
skillLevels[skillId] = methods[sourceMethodId]
```

经脉授予的技能也必须指定所属心法。缺失所属心法属于内容错误，不能无声回退到人物等级。

开发期临时技能若使用人物等级 fallback，必须产生投影诊断，正式内容发布前必须清零该诊断。

### 3.4 取消通用 `growthProfile`

旧宗门通过 `growthProfile` 统一放大某本心法所属技能的伤害、治疗、护盾和状态强度。combat-v6 不继承这层隐式倍率。

新版采用：

```text
心法等级
→ 技能等级
→ 技能自身的 schoolTerm / 等级表达式 / 显式里程碑
```

允许显式成长：

- 技能伤害、固定伤害和治疗公式。
- 护盾量。
- 技能目标数量。
- 攻击段数。
- 状态持续回合。
- 封禁底率或其他白名单规则参数。

禁止通过一条通用百分比同时放大整类技能效果。结构变化必须写在具体技能或经脉 patch 中。

### 3.5 心法面板贡献

一本心法最多提供一条明确的面板成长规则，例如：

```text
物理攻击、法术攻击
物理防御、法术防御
最大气血、最大法力
速度、命中、闪避
治疗强度、封禁命中、封禁抵抗
```

心法不能提供：

```text
attackCultivate
defenseCultivate
spellCultivate
resistSpellCultivate
永久六维
```

面板贡献进入 `CombatV6PanelContribution`，不修改角色数据库六维。

## 4. 宗门技能

### 4.1 技能类型

```ts
type SectSkillKindV6 = 'active' | 'passive' | 'internal';

interface SectSkillDefV6 {
  id: string;
  sectId: string;
  sourceMethodId: string;
  unlockMethodLevel: number;
  kind: SectSkillKindV6;
  definition: SkillDef;
}
```

| 类型 | 说明 |
| --- | --- |
| `active` | 玩家在行动阶段主动选择的宗门技能 |
| `passive` | 宗门根基、技能被动或经脉授予的常驻能力 |
| `internal` | 追击、反击、形态入场、反应结算等内部引用技能，不显示为指令 |

普通攻击由 combat-v6 通用规则提供，不属于任何一本宗门心法。宗门若要强化或改变普攻，通过被动、状态或单位技能覆盖实现。

### 4.2 解锁与使用

```text
宗门身份有效
+ 所属心法达到技能解锁等级
+ 当前流派/经脉没有 revoke
= 本场可用技能
```

所有已解锁主动技能进入战斗指令列表，不存在固定四技能装配限制。

快捷栏可以保存若干常用技能 ID，但它只是客户端或玩家偏好数据：

- 快捷栏外的已解锁技能仍然可用。
- 快捷栏缺失不阻止开战。
- 快捷栏不进入确定性战斗快照的能力校验。

### 4.3 技能数量建议

单个宗门首版建议提供：

- 6～9 个基础主动技能。
- 1 个宗门根基被动。
- 1～3 个内部或条件被动。
- 每条流派最多额外授予 1 个标志性主动技能。

一个成熟构筑通常拥有 8～12 个可主动选择的宗门技能。具体数量不是 schema 硬上限，但新增技能必须承担清晰战术职责。

### 4.4 冷却原则

常规宗门技能默认无冷却，通过以下方式限制连续施放：

- 法力或气血成本。
- 目标和气血条件。
- 宗门特色状态或资源。
- 施放后休息。
- 每场次数。
- 明确的特殊技能冷却。

冷却是终式、救命、强控制等技能的特殊规则，不是所有技能的默认组成。

非战斗宗门能力，例如传送、炼器、采集和组织功能，不进入 combat-v6 技能表。

## 5. 宗门特色机制

### 5.1 机制边界

每个宗门可以拥有独特的形态、反应、资源和循环，但只能产出：

```ts
interface SectMechanicProjectionV6 {
  resources: CombatResourceDef[];
  skills: SkillDef[];
  statuses: StatusDef[];
  passives: SkillDef[];
  panel: CombatV6PanelContribution[];
  unitTags: string[];
}
```

core 不认识宗门名称。若特色机制需要新的 core 原语，必须满足“可被多个无关内容复用、无法由现有原语组合”的条件。

### 5.2 无相禅宗：佛、魔、无相

保留三种形态：

| 形态 | 定位 |
| --- | --- |
| 佛相 | 防御、护盾、恢复、保护 |
| 魔相 | 输出、吸血、气血消耗、风险换收益 |
| 无相 | 条件进入的短期强化窗口，融合或升华佛魔能力 |

三种形态编译为互斥状态：

```text
Status.Sect.Wuxiang.Form.Buddha
Status.Sect.Wuxiang.Form.Demon
Status.Sect.Wuxiang.Form.Formless
```

切换形态必须先移除当前形态，再应用目标形态并触发入相效果。同一时刻只能存在一种形态。

无相不作为随时切换的常驻第三姿态，应具有积累条件、持续限制或退出代价，否则佛相与魔相的取舍会失效。

无相禅宗建议保留“心念”资源，用于表达行动积累、佛魔转换、提前入相和满资源进入无相的选择。

### 5.3 天衍圣地：五行生克反应

> combat-v6 Phase 6C 已按 [`combat-v6-tianyan-sect-design.md`](./combat-v6-tianyan-sect-design.md) 落地。法印是无使用权归属的普通 Debuff：队友可以协同触发，`sourceId` 只保留事件归因。

保留金、木、水、火、土法印与相生、相克反应。五行关系属于内容表：

```ts
interface ElementReactionDefV6 {
  existingMark: ElementId;
  incomingMark: ElementId;
  kind: 'generate' | 'overcome' | 'same';
  effects: EffectDef[];
}
```

内容编译器把反应表展开为状态检查、状态移除、状态施加和效果结算。core 只执行通用原语，不理解“五行”或“天衍圣地”。

衍数保留为0～3单场资源：反应获得，三才护阵消耗1点，两流派终式消耗3点；满值不自动释放。

### 5.4 幽都：固伤、削弱与伤势

幽都整体参考梦幻式阴曹地府，围绕：

```text
固定伤害
+ 群体削弱
+ 中毒/持续伤害
+ 伤势
+ 治疗压制
+ 倒地与还魂干预
```

两条流派分别侧重：

| 流派方向 | 定位 |
| --- | --- |
| 勾魂阎罗 | 固定伤害、幽毒、伤势、群体恢复和锢魂控制 |
| 六道魍魉 | 法术驱动的物理攻击、幽毒附着、必中群攻和物理爆发 |

固定伤害使用 v6 `fixed/judge` 公式族。削弱、毒和压疗使用通用状态与治疗系数。

伤势应成为可复用的通用战斗原语：

```text
recoverableHp = max(1, maxHp - wound)
```

- `maxHp` 保持角色真实最大气血，不因伤势重新计算。
- 普通治疗不能超过 `recoverableHp`。
- 特定技能可以增加或恢复 `wound`。
- 伤势只属于本场战斗快照和事件，不写回角色永久六维。

推荐新增通用效果 `addWound/removeWound`。该原语以后可以由宗门、药品、召唤兽和 NPC 共用，不得命名为幽都专属效果。

Phase 6A 不配置“魂火”或其他幽都专属战斗资源；如果后续出现明确的积累—消费闭环，必须通过新内容版本重新评审。

### 5.5 特殊资源规则

宗门特殊资源改为可选：

```ts
interface SectDefinitionV6 {
  combatResource?: CombatResourceDef;
}
```

首版每宗门最多一种。资源必须参与真实决策，不能只作为视觉计数器。

初步方向：

| 宗门 | 资源方向 |
| --- | --- |
| 无相禅宗 | 保留心念 |
| 天衍圣地 | 根据反应计数是否形成决策决定衍数去留 |
| 幽都 | 首版可移除魂火 |
| 红尘剑宗 | 连招与终式确有消费关系时保留剑意 |
| 九劫天宫 | 承劫—清算循环成立时保留劫数 |

## 6. 双流派

每个宗门固定两个流派：

```ts
interface SectPathDefV6 {
  id: string;
  sectId: string;
  name: string;
  description: string;
  foundationPassive?: string;
  layers: MeridianLayerDefV6[];
}
```

两条流派共享：

- 六心法等级。
- 宗门基础技能表。
- 宗门根基特性。
- 人物四修炼、道装和功法。

流派负责：

- 授予流派根基被动。
- 改变特色机制的使用方向。
- 通过经脉修改共享技能。
- 在必要时 grant/revoke 少量技能。
- 形成两个完整且互斥的战术构筑方向。

流派不能复制成两套互不相关的宗门，也不能要求重新升级六本心法。

## 7. 七层经脉

### 7.1 固定结构

每条流派固定：

```text
7 层
× 每层 3 个互斥节点
= 21 个节点
```

每个宗门共：

```text
2 条流派
× 21 个节点
= 42 个经脉节点
```

每一已解锁层必须选择 0～1 个节点；同层不能选择多个。未选择节点的方案仍可保存，但投影诊断应提示构筑未完成。

第一至第六层逐步改造核心循环。第七层是构筑终点，可以：

- 授予流派终式。
- 大幅修改核心技能。
- 改变资源循环。
- 授予强力条件被动。
- 改变特色机制的形态或反应结果。

不强制所有第七层节点都是主动大招。

### 7.2 每流派一套方案

```ts
interface SectMeridianLoadoutV6 {
  pathId: string;
  nodeIds: string[];
  revision: number;
}

interface SectCombatProgressV6 {
  activePathId: string;
  meridianLoadouts: [
    SectMeridianLoadoutV6,
    SectMeridianLoadoutV6,
  ];
}
```

两套方案与两条流派一一对应：

- 流派一保存一套节点选择。
- 流派二保存一套节点选择。
- `activePathId` 决定当前生效方案。
- 不提供同一流派下的第二、第三方案槽位。

战斗外切换流派、选择节点和重置节点全部免费。排队、匹配或战斗快照锁定后，本场继续使用锁定时的编译结果。

### 7.3 节点允许输出

经脉节点只能：

- patch 已有技能。
- grant / revoke 技能。
- 授予被动。
- 增加白名单面板贡献。
- 增加单位标签。

禁止：

- 任意脚本。
- 直接修改 BattleSession。
- 在 core 中按节点 ID 分支。
- 修改角色永久六维。
- 提供四项修炼等级。
- 修改其他宗门的技能。

### 7.4 patch 操作与冲突

允许的 patch 操作应显式化，例如：

```text
set
add
multiply
appendEffect
removeEffect
grant
revoke
```

编译顺序：

```text
宗门基础技能表
→ 心法等级与技能解锁
→ 当前流派根基被动
→ 第一至第七层节点按层级编译
→ grant / revoke
→ 合并技能 patch
→ 校验技能归属和等级
→ 生成最终技能、被动、面板、资源和标签
```

多个节点对同一字段执行不兼容的 `set` 时必须报错。禁止依赖对象遍历顺序或后写覆盖。

## 8. 持久化模型

推荐把社会身份与 v6 战斗进度概念拆开：

```ts
interface SectMembershipState {
  sectId: string;
  rank: string;
  contribution: number;
  // 社会玩法事实
}

interface SectCombatProgressV6 {
  version: 1;
  sectId: string;
  methods: Record<string, number>;
  meridianDepth: number;
  activePathId: string;
  meridianLoadouts: [
    SectMeridianLoadoutV6,
    SectMeridianLoadoutV6,
  ];
}
```

可以暂时共用数据库容器，但领域类型、编译器和版本必须分离。

只持久化：

- 六心法等级。
- 经脉解锁深度。
- 当前流派。
- 两条流派各自的节点选择。
- 乐观并发 revision。

不持久化：

- `SkillDef/StatusDef`。
- 最终技能等级表。
- 经脉 patch 结果。
- 最终宗门面板。
- 宗门特色机制的运行时状态。
- 固定四技能装配。

快捷栏属于 UI 偏好，不是 `SectCombatProgressV6` 的战斗权威字段。

## 9. 旧宗门平滑迁移

### 9.1 迁移目标

玩家不获得修为或灵石返还，也不需要重新从零升级。迁移通过保留等级、深度和选择结构承接原投入，同时停止所有旧战斗效果。

### 9.2 六心法等级

按槽位一对一继承：

```text
旧槽位 1 等级 → 新槽位 1 等级
……
旧槽位 6 等级 → 新槽位 6 等级
```

只继承等级，不继承：

- 旧心法通用成长倍率。
- 旧面板 modifier。
- 旧技能和技能等级投影。
- 旧心法描述的战斗语义。

迁移记录保存源心法 ID、目标心法 ID、槽位和等级，保证幂等。

### 9.3 经脉深度

现有两个流派最高六层。新版统一经脉深度取：

```text
newMeridianDepth
= max(旧流派一解锁层数, 旧流派二解锁层数)
```

新版两条流派均可以在该深度内配置节点。这样不会降低玩家已有的最高战斗深度，也不因旧系统曾在两个流派分别投入而直接把层数相加制造额外战力。

第七层是新版新增成长，迁移时默认未解锁。

### 9.4 流派与节点选择

```text
旧流派序号 → 新流派同序号
旧层级 1～6 → 新层级 1～6
旧节点在该层的位置 1/2/3 → 新节点同位置
```

这只是结构迁移，不是旧节点效果翻译器。旧节点 ID、被动、modifier 和技能 patch 不进入 v6。

无法识别稳定位置时，使用对应流派的推荐默认节点并输出迁移诊断。迁移后两条流派各拥有一套可直接使用的经脉方案。

### 9.5 四技能栏

旧四技能栏停止作为战斗能力真相。

如果旧技能 ID 与某个新技能存在明确的人工映射，可以把顺序转换为快捷栏偏好；无法对应的技能从快捷栏移除并使用新版推荐快捷栏补齐。所有已解锁技能仍然可从完整技能列表使用，因此不会损失战斗权限。

### 9.6 特殊资源与战斗状态

旧战斗中的剑意、心念、法印、魂火、劫数和形态状态不迁移。它们是单场运行时状态，新战斗按照新版宗门定义初始化。

### 9.7 v6 之后的转宗

未来 v6 宗门之间转宗时：

- 六心法等级按槽位 1～6 保留。
- 经脉深度保留。
- 目标宗门两套节点方案重新生成或清空选择。
- 宗门技能、根基特性和特色资源自动替换。
- 四项人物修炼、道装和功法不变化。

## 10. 宗门投影契约

```ts
interface SectCombatProjectionV6 {
  skills: SkillDef[];
  passives: SkillDef[];
  statusDefs: StatusDef[];
  skillLevels: Record<string, number>;
  skillOverrides: SkillDef[];
  resources: CombatResourceDef[];
  panel: CombatV6PanelContribution[];
  unitTags: string[];
  diagnostics: CombatV6ProjectionDiagnostic[];
}
```

宗门编译器不创建 BattleSession，只把持久事实和版本化内容编译为入场贡献。

入场前至少校验：

- 六心法槽位完整且恰好一本主心法。
- 心法等级符合人物上限和主从约束。
- 每个技能拥有存在的所属心法。
- 每个已解锁技能具有明确等级。
- 恰好两个流派和两套一一对应的经脉方案。
- 每条流派恰好七层、每层恰好三个节点。
- 同层最多选择一个节点。
- 节点符合经脉深度和心法要求。
- grant/revoke/patch 的技能全部存在。
- patch 冲突已经确定性解决。
- 特殊资源数量不超过一个。
- 所有内容 ID 在版本内唯一。

## 11. 内容交付顺序

一个宗门的推荐纵切顺序：

1. 锁定宗门特色机制的状态机或反应表。
2. 定义六心法职责、面板贡献和等级归属。
3. 完成共享基础技能表。
4. 完成第一条流派、七层二十一个节点。
5. 验证技能 patch、资源、状态和投影协议。
6. 完成第二条流派、七层二十一个节点。
7. 补齐迁移映射、推荐快捷栏和推荐节点位置。
8. 建立宗门黄金测试和对拍场景。

不接受把旧 `AbilityConfig` 临时挂到 v6 作为阶段性交付。第一条流派纵切完成前，可以缺少第二条流派内容，但类型和投影协议必须已经支持最终双流派结构。

## 12. 实现验收条件

1. combat-v6 core、rules 和投影代码中不存在宗门、流派、节点或技能 ID 特判。
2. 六心法等级能够独立生成所有宗门技能等级。
3. 取消四技能栏后，所有已解锁主动技能均可提交指令。
4. 通用普通攻击可以被宗门内容以稳定覆盖方式强化，但 core 行为不变。
5. 心法成长不再调用 v5 `growthProfile` 或六阶段 modifier。
6. 两条流派均为七层，每层恰好三个节点。
7. 两条流派各保存一套且仅一套经脉方案。
8. Phase 7B 初始化后暂不开放切换和重置；以后开放时，已锁定战斗快照不得受战外变更影响。
9. 无相强化窗口、天衍反应、九劫电芒协同均由内容表生成，幽都伤势使用通用原语。
10. 不需要特色资源的宗门可以用空资源配置正常开战。
11. Phase 7B 只迁移 active membership 的旧六心法等级；经脉深度、流派和节点从零开始。
12. 迁移过程中不返还修为或灵石，也不加载旧技能、旧节点、旧功法或旧装备效果。
13. 相同内容版本、角色进度和经脉方案产生完全相同的投影与事件流。
14. 五宗门完整构筑由 Phase 7B 权威装配器交给 Phase 7A Host，以 `full` 资源策略编排进版本化训练遭遇；宗门编译器自身仍不创建 BattleSession。
