# 旧灵种转化（临时）

玩家从洞府的「旧灵种转化」进入 `/game/seed-migration`。旧种子保留原名称和库存事实，不再按名称、五行或品阶兜底成新物种，也不能直接播种。当前百草志目录生成的种子使用 `seedSpec.version = 2`，固定身份为 `garden-seed:物种ID:原种品质`，并显式记录 `speciesId`。所有旧 v1 事实均按存量旧资产处理，即使显示名称或旧 ID 与当前目录相同，也不能直接播种。

## 转化规则

- 每粒旧灵种转化为一粒**同品质**新灵种，不消耗灵石或天地灵气。
- 每粒独立从该品质四个新物种中等概率抽取；允许重复，结果按物种合并。旧种的元素、习性、成长时间、收成偏好与旧名称不影响新物种。
- 一次可以转化同一来源的 1–999 粒；不足 999 粒可以全部转化，也可保留部分旧种。新种子不能再次参与转化。
- 支持旧 `materials` 宝库，以及统一库存 `inventory_items` 的随身和储藏室种子。宝库中的旧灵种不再直接取出，统一使用本入口。
- 旧宝库来源只依赖锁定记录的合法品质和数量，不要求修复旧 `seedSpec`。统一库存仍按真实种子事实校验；异常品质、数量或损坏的库存事实保留来源并提示核对，不默认降档或静默删除。
- 发放复用统一背包容量和堆叠规则，背包不足时交付至储藏室。所有新种使用现行目录的品质、名称和完整事实。

## 请求与资产提交

GET `/api/seed-migration` 返回当前角色可处理的宝库和统一库存旧种清单。POST `/api/seed-migration/exchange` 携带 `requestId`、来源、来源身份、转化数量与预期来源数量；统一库存还必须提供物品 `revision`。

转化使用现有角色锁和数据库事务。身份归属、数量和版本由服务端锁定记录核对；随机结果、原种消耗、新种发放与资源提交一次完成。任一检查或发放失败均回滚，不单独扣除来源。

原请求重放返回相同结果，不再次扣种或重新抽取。同一 `requestId` 改参数、陈旧数量、陈旧物品版本、他人来源和已被耗尽的来源均拒绝。玩家在网络结果未确认时沿用原请求重试。

## 其他资产载体

未领取旧邮件和拍卖托管资产不在本工具中直接读取或删除；先通过原有领取、成交或退回流程进入统一库存，再转化。旧资产的合法流转不代表允许重新生成或作为新奖励发放。旧种不可播种的规则同样作用于这些后续领取的资产。

新奖励、后台生成和市场上架只接受现行目录种；本地旧 `vault-seed` 发放也不接受旧快照。普通材料奖励的缺货兜底排除种子，避免旧种库条目变成未设计的掉落，或在副本、讨伐中被错误解析为普通材料。

## 发布数据处理

旧种材料库、关联商品和旧奖励配置由维护者在发布时手动盘点、清理，本仓库不提供自动删除迁移。玩家背包、储藏室、旧宝库、邮件和拍卖中的旧种保留供转化；不要因清理投放来源而删除玩家资产。

发布采用维护窗口，配套更新 API／SPA，核对旧市场缓存及旧种商品已停售。上线后检查转化清单、有效转化、原样重放、错误数量／版本及新种正式播种。旧在田数据的处理独立核对，不通过清库重置玩家灵田。
