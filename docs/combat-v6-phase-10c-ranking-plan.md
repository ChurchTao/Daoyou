# Phase 10C：天骄榜挑战切换 v6

> 2026-09-08：代码已实现，纯本地三账号完成主要真实链路验收。共享测试、Lint、构建通过；故障窗口与发布操作的未验证项见末节。

## 边界

仅迁移天骄榜挑战、次数、名次、页面及统一回放。保留每境界前 100 名、每日 10 次、跨境界切磋不改排名、空榜直接入榜不扣次数、未上榜挑战失败且榜未满时补入榜尾。平局按挑战未成功且消耗一次处理。保留既有周奖励，不新增奖励。赌斗、宗门任务、其他榜单、全站面板及全仓 v5 删除另行安排。

双方使用挑战开始时一致读取的 v6 构筑，独立满 HP/MP，每方一人物及合格首发灵兽；不自动换宠、逃跑或新增策略配置。调用 v6 ruleset 的自动决策，当前默认决策是普攻／无目标防御，并非新增智能施法 AI。达到引擎回合上限平局。不写回现实资源，不扣灵兽寿命、不发经验。被挑战者无需在线，活动战斗不阻止其构筑副本被挑战；挑战者必须无其他活动战斗。

## 协议与结算

- HTTP 提交带 UUID 的挑战请求；相同角色、请求 ID 与参数恢复同一结果，参数不同拒绝。客户端不因请求失败换 ID 重抽。
- 保存冻结输入与种子后预占发起日的一次额度（上海时区），可恢复运行态保留 48 小时。正常终局转为已用；明确无终局且无法继续的计算失败释放额度；网络或归档失败保留原结果供重试。
- 先保存终局，再以数据库事务写统一归档及原完成事件；最后在 Redis 原子确认最新榜单、修改名次、确认次数和保存结算摘要。并发榜单变化重读后重算，不以开战旧名次覆盖新榜。
- 获胜且目标仍在榜并高于挑战者时，沿用插入目标位置、后续顺移的既有规则。目标离榜不改排名，仍保留战果并扣次数。未成功且自己未在榜时，有空位补榜尾。
- Redis 保存榜单、日额度及短期恢复状态；不新增挑战凭据表，不承诺跨存储原子性。数据库成功而 Redis 未确认时重试幂等归档再结算；Redis 全丢失允许榜单与次数重置，不从回放重建。
- 短期状态过期或丢失时，新建前只查询归档 ID 是否存在；已有归档的旧请求拒绝重新计算／扣次，提示从战绩查看。新的挑战使用新 UUID，不解包回放来重建名次。
- 挑战结算期间占用挑战者，播放归档不占用。双方均成为统一回放参与者，旁人无权限。列表只读元数据，详情按需加载差量回放，客户端逐行动播放。

## 页面与维护

保留天骄榜入口及现有沉浸挑战路由，替换旧战斗组件，复用 v6 回放播放器。首次自动播放，播放结束后展示名次与剩余次数；刷新或失败后以原请求恢复。旧 v5 挑战接口返回 410，不增加功能开关。

上线停机后、开放新请求前，使用维护环境的 Redis SCAN 核对并定向删除 `golden_rank:list`、`golden_rank:list:*`、`golden_rank:daily_challenges:*`、`golden_rank:challenge_lock:*`。只清天骄榜旧排名、次数和旧挑战锁，不使用 FLUSHDB，不清财富榜、物品榜、幻境榜、数据库战绩或邮件。本轮不执行预发布／生产清理。

## 验收

共享纯测试覆盖构筑隔离、合格首发、确定性自动战斗与差量重建、名次规则、发起日边界。服务和页面采用真实本地双账号，检查胜负平局、资源不变、双方与第三方回放权限、同境界／跨境界、次数上限、重复与并发、刷新及归档失败重试。执行 lint、build、相关共享测试、触及文件 Prettier 与差异检查。

## 未验证项与发布边界

- 未在真实午夜执行跨日挑战；上海时区边界由共享纯测试覆盖。未制造本阶段 PostgreSQL 已提交但 Redis 结算确认失败的网络窗口、进程在自动计算中途退出或 Redis 全量丢失。代码通过固定输入／种子、幂等归档和 Redis 原子结算支持正常恢复，但这些实际故障不能据静态检查标记通过。
- 正常成长构筑的全境界难度与自动策略平衡、100 人满榜的真实并发压力未验收；满榜插入／失败规则有纯测试。未开展 React Profiler 定量测量。
- 排名变更消息采用现有事务消息链路，Redis 名次提交后尝试写入并按请求 ID 去重；消息写入失败不回滚排名，同请求重试可补写，不新增跨存储补偿表。
- 本轮未发布、未清理预发布／生产旧榜单、未提交 Git。10A、10B 的遗留验收不因此自动通过，赌斗及宗门任务仍使用旧链路。
