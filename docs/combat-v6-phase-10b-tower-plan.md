## 3. 玩法约定

### 独立资源与构筑

- 入场冻结人物构筑、携带灵兽及内容版本。人物和所有符合出战条件的携带灵兽初始化满 HP/MP；默认出战选择遵循已有规则。
- 后续场次继承局内 HP/MP。护盾、临时状态和战意按现有 v6 新战斗初始化规则处理，不将整份上一场单位状态直接带入下一场。
- 不写现实人物 HP/MP，不扣灵兽寿命，不发人物战斗经验或灵兽经验；里程碑明确配置的经济奖励另行结算。
- 灵兽死亡后本次挑战不可再次出战；普通恢复祝福不复活灵兽。结束后丢弃局内资源，下次挑战重新初始化。
- 挑战期间禁止修改构筑，允许战斗内合法召唤与换宠。休整页允许结束挑战，战斗中复用逃跑，不增加认输指令。
- 现实资源的正常恢复不作为幻境资源来源；不得因幻境结束用入场旧值覆盖期间的现实资源变化。

### 祝福

首轮保留既有名称、数量、叠加上限和选择节奏，不扩展复杂词条组合。

| 祝福 | v6 实现约定 |
| --- | --- |
| 体魄澎湃、力贯千钧、灵海翻涌、铁骨铮然、踏风行、明心定神 | 分别对应 vitality、strength、spirit、endurance、speed、willpower；每层 +8%，最多 5 层 |
| 大道均衡 | 六维各 +5%/层，最多 3 层 |
| 玉骨长生 | 最大 HP +10%/层，最多 5 层 |
| 气海扩容 | 最大 MP +12%/层，最多 5 层 |
| 吐纳回元 | 每场开始前恢复缺失 HP 的 10%/层，最多 3 层 |
| 周天流转 | 每场开始前恢复缺失 MP 的 15%/层，最多 3 层 |

首轮祝福作用于人物，灵兽沿用冻结构筑。六维增益使用同一份无祝福基准，同类百分比相加后重新投影，不在已增益结果上反复乘算；最大资源增益在派生上限后计算一次。核心引擎不识别幻境祝福 ID。

上限增加时保留当前资源比例，向下取整并裁剪至合法范围；只在祝福确认时转换一次。战前恢复在创建该场战斗时执行一次，刷新、重复开战请求不再次恢复。候选祝福由服务端生成并保存，刷新不重抽；已满层选项不再出现，无可选项时直接进入下一层准备状态。

### 敌人、周期与奖励

- 同周期、同境界组、同楼层、同内容版本使用相同敌人配置；不按玩家个人战力动态缩放。
- 使用 v6 普通、精英、首领模板和固定等级成长配置；不转换旧敌人，不使用 AI 决定属性、技能或奖励。
- 里程碑奖励通过通用掉落配置解析，物品立即进入统一库存，满包转储藏室；灵石、声望等非物品通过现有资源写路径直接发放。
- 首轮不增加普通层重复收益。保留既有里程碑声望 5/10/15/20；其他奖励按旧奖励实际组成整理为明确配置，实施时记录前后对照，不复制旧产物生成链路。
- Redis 周进度存在时，同角色、同周、同里程碑只领一次，不因正常重开或境界变化重新领取。失败、逃跑和主动结束不收回已发奖励。Redis 数据丢失后允许重新挑战；领取标记同时丢失时允许重新获得里程碑奖励，不另建数据库凭据追回这一限制。
- 周切换后允许已创建的单场战斗结束，成绩和奖励归原周期；结算后结束旧挑战，不再进入旧周期下一层。尚未开战的旧挑战直接结束。
- 旧活动挑战不续跑；停机维护时处理旧状态及未领取邮件，不能用删除旧 Redis 数据代替历史奖励处理。

## 4. 状态、协议与持久化

### 状态转换

`READY → WAITING_BATTLE → CHOOSING_BLESSING → READY`。

- 战败、成功逃跑、回合上限结束、主动离开、通关或周期到期进入 `FINISHED`，保存明确结束原因。
- 最后一层获胜直接结束；跨周结算不再要求选择祝福。
- 战斗终局先提交权威结算，客户端播完后展示祝福或结束页；客户端播放确认不是发奖的唯一触发条件。
- 所有推进请求校验角色归属、runId、battleId、revision 和当前状态，防止旧响应推动新挑战。

### 数据职责

- Redis 保存挑战状态，包括角色、周期、境界组、revision、冻结构筑、局内资源、祝福及候选、当前战斗 payload、最高通过层、结束原因及时间。复用角色锁与 revision 校验，保证正常运行时同角色仅一条活动挑战。
- Redis 按角色和周期保存已领里程碑、实际奖励摘要、最高成绩及首次到达时间，正常重开保留这些周进度。TTL 覆盖周期结束及跨周单场结算窗口，不因短期不操作提前清除周领取标记。
- 不新增挑战表、周进度表或消费凭据表。数据丢失时返回无活动挑战并允许重新开始，失效占用需一并解除；不从回放重建挑战、周进度或排行榜。
- 奖励物品、货币等仍写入现有数据库，单次奖励写入使用数据库事务。Redis 保留待结算奖励及固定随机输入，正常请求通过锁、状态和领取标记去重；数据库提交成功后再更新 Redis 已发标记与进度。
- Redis 与数据库不承诺跨存储原子提交。数据库已发奖但 Redis 标记未保存的故障窗口可能在重试后重复发奖，本阶段接受该边界，不引入分布式事务或持久补偿机制。数据库事务明确回滚时不标记已发，保留可重试状态。
- 周榜继续使用 Redis；数据丢失允许成绩重置，后续挑战产生新成绩。榜单更新失败不回滚已发奖励，也不通过重新发奖修复榜单。
- 统一回放表增加幻境来源，不建幻境回放专表。列表仅读元数据，详情按需加载包。
- 不恢复旧 Redis 挑战，不兼容旧帧协议，不增加功能开关。旧敌人表先停止读写；删除表及历史数据需单独列明维护步骤，不在业务切换中顺手清库。

### HTTP 与前端

复用 v6 会话控制器和公共战斗组件，HTTP 提交指令后再 resolve；恢复时读取完整基准与所需事件增量。单人玩法不新增 WebSocket。

幻境页面只负责入口、当前层、局内资源、祝福、周奖励和榜单。沿用 v5 配色及紧凑血条，所有显示值来自 v6 权威契约；详情沿用统一抽屉/tooltip。主战斗区域不复制一套组件。

React 遵循指定最佳实践及仓库格式，避免 Effect 同步派生状态、重复刷新与重叠轮询。活动挑战不进入通用 TTL 缓存。

## 5. 实施顺序与交付检查

1. **定义与 Redis 状态**：整理 v6 幻境契约、状态转换、资源规则、祝福投影、Redis 键与 TTL；验证锁、revision、丢失后重开及旧状态处理，不新增挑战记录的数据表迁移。
2. **单层 Host**：接入冻结构筑、敌人模板、指令、恢复、终局与统一归档；跑通真实登录单场胜负及刷新。
3. **连续挑战**：接入局内资源、祝福选择、灵兽死亡/换宠、主动结束与跨周规则；验证不回写现实资源和重复请求不重复恢复。
4. **奖励与榜单**：落地里程碑配置、直接入包、Redis 周领取去重及榜单更新；验证并发、满包、正常重开、事务回滚重试和数据丢失后的允许重开边界。
5. **页面硬切与清理**：接入公共 v6 UI，关闭旧幻境战斗、邮件奖励和敌人生成调用链，同步后台/定时任务；只删除确认无调用的幻境专属旧代码。

每一步先完成适用的验证再推进；不得以代码实现代替实际验收。具体文件拆分沿用仓库职责，不预先创造多层框架。

- 测试只用纯本地环境与既有账号，遵循 `docs/testing.md`；不新增前端/服务端/数据库单元测试或一次性故障脚本。

Phase 10A 尚未通过的服务进程中断、事务失败恢复等，在复用相关机制时补验并分别记录；其他既存未验证项保留原状态。本阶段完成不代表可删除整个 v5，也不代表完成生产维护验收。

## 7. 实施与验收记录（2026-09-08）

### 已实现

- `src/shared/engine/combat-v6/tower/host.ts` 提供独立 Host、可恢复快照、冻结构筑祝福投影、局内资源、死亡灵兽排除及集中敌人配置。普通层单敌、精英双敌、首领单敌双气血，NPC 首轮普攻；尚未做真实高等级难度调优。

- Redis 使用 `tower:v6:run:<角色>`、`tower:v6:week:<角色>:<周期>`、`tower:v6:leaderboard:<周期>:<境界>`，与旧挑战和成绩隔离；过期时间为周期结束后 24 小时。领取标记在正常重开时保留，不新增任何数据表或迁移。
