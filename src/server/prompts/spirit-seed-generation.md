## system

## 任务

根据一组已经确定品质、数量、元素限制与地域线索的“灵植种子骨架”，补全种子的身份、生态习性和潜在用途。输出将被结构化 schema 校验；不要解释规则，不要输出 schema 之外的字段。

这是一个以中国修仙小说为审美背景的虚构灵植生态任务。请使用读者熟悉的草木、菌类、藤本、根茎、山川气候、阴阳寒热与五行生克常识来建立因果。避免依赖任何特定作品、游戏名称或专有世界观。

## 灵植生态常识

- 种子只是未定形的生命载体，可以是籽、果核、芽核、根芽、菌孢或灵藕节；此时不能提前确定成熟产物名称。
- 金性常与坚壳、矿脉、收敛相应；木性偏生发与药性；水与冰偏湿润、寒地和蓄藏；火偏温热、向阳与活跃；土偏厚壤、根茎和稳定；风偏轻灵、藤蔓与传粉；雷偏骤发、破壳与强刺激。元素是倾向，不是绝对答案。
- 生境、形态、成长特征、培育偏好和潜在用途应互相支持。例如喜阴集露的菌孢不宜同时被写成酷爱烈日；石生根芽可以与矿砂、固壤或地脉形成关联。
- 高品质可以表现为年代久远、灵纹复杂、灵机内敛或生态条件苛刻；不要简单堆砌“神、帝、圣、至尊”等夸张词。

## 三阶段培育语义

萌芽阶段关注破壳与扎根：

- `seasonal_nurture` 顺时温养；`qi_sprout` 灵气催芽；`stone_soil` 灵石固壤；`sun_wake` 向阳醒种；`shade_dew` 荫棚集露；`ore_soil` 矿砂改土；`aux_formation` 辅材醒灵阵。

蕴灵阶段关注枝叶、根脉与本源：

- `rest_nurture` 静置养性；`intrinsic_infusion` 本命灌注；`qi_growth` 灵气催生；`herb_companion` 药材伴养；`monster_blood` 妖血沃根；`pill_nourish` 化丹培元；`tcdb_return` 天材返哺；`aux_gather` 辅阵聚灵。

成型阶段关注药性与形态归宿：

- `leaf_medicine` 凝叶成药；`flower_fruit` 开花结果；`return_treasure` 返源化宝；`natural_form` 顺势化形。

## 隐藏字段设计

- `preferredMethods` 应选 2～6 项，尽量覆盖两个以上阶段，并与生态设定形成清楚因果。
- `avoidedMethods` 最多 4 项，必须与 `preferredMethods` 互斥；没有充分理由时宁可少选。
- `preferredHabitats`、`avoidedHabitats` 与 `growthTraits` 应描述同一套生态逻辑，不要随机拼接。
- `useTags` 只是潜在药性方向，`outcomeBiases` 只是可能的成型倾向；两者都不是最终承诺。
- `creationTags` 只选择 schema 允许的既有语义值，并与元素、形态或用途相符。
- 若骨架指定元素，`element` 必须严格等于指定值；地域只作为生态线索，不能改写既定品质与数量。

## 玩家可见文案

- `seedName` 为 2～12 字，必须像尚可播种的种体，而不是成熟灵草、宝物或灵果。
- `seedDescription` 只描写可观察的外形、触感、气味和微弱灵机，不宣告成熟效果。
- `clueTexts` 写 2～3 条粗粒度观察：如遇晨光发暖、近水凝露、贴近矿砂轻颤、受强烈血气时蜷缩。线索可以帮助推测，但不能直接给出答案。
- 可见文案不得出现字段名、枚举值、评分、概率、内部规则，也不得直说“偏好某方法”“必定产出某物”或“服用后获得某效果”。
- 同一批种子应有不同的名称、生态组合和措辞，不能只替换元素字。

## 内部工作步骤

在生成每一项前，先在内部完成以下推理，不要把推理过程写入输出：

1. 从品质、指定元素和地域建立一个自洽的生境与生长形态。
2. 由生境和形态推导成长特征、喜好与忌避的培育方式。
3. 再推导潜在用途、成型倾向和造物语义标签。
4. 最后把隐藏设定改写成不泄底的外观描述与观察线索。
5. 自检所有枚举合法、字段互不矛盾、批次内名称不重复、可见文本没有泄露隐藏答案。

只返回结构化结果；不要输出分析、步骤、理由、Markdown 或额外说明。
