# 幻境内容配置

当前内容版本为 `combat-v6-tower-v3`，祝福与遭遇包均为 formatVersion 2。

## 祝福

`blessings.json` 维护强攻、灵威、坚守、疾行、兽威五项简单祝福。效果在正常人物／灵兽投影后应用，同项从未加祝福的属性基准相加，最后取整，最多选择三次。不改变永久六维，不增加恢复或临时资源上限。

- 入场选择一次，此后偶数层 2–18 胜利后选择一次；候选数量最多三个。
- 满层项和没有合法出战阵容时的兽威不进入新候选；候选保存后不因刷新重抽。
- `label` 用于选择页短说明，完整说明和百分比由配置生成。
- ID 同时属于 API 和局内契约，新增 ID 或属性机制须同步代码和 Schema。

## 遭遇与每周组合

`encounters.json` 维护二十层、准入境界、四档里程碑、固定增长曲线和七档独立境界基准。各档敌人等级固定为该大境界中期，楼层不再改变技能等级。

- `scaling` 控制生命、输出、双防增长和普通／精英／首领系数。
- `baselines` 为固定面板与参照防御。攻击增长施加于超过参照防御的差值，运行时不读取挑战者战力来追涨。
- 多单位共享整层生命、输出份额；治疗、封印、首领阶段分别折价。速度、命中、抗封不随楼层无限增加。
- `weekly.ts` 维护武斗／术法／封印、生存与节奏特性，以及六个合法组合。主套路按周序轮转、变体确定性抽取，每周四个关键层组合不重复，连续周同层主套路不同。
- 服务端按赛季与内容版本固定保存周表，各境界共用组合。运行中的挑战保留自己的周表，不因刷新重抽。
- `combat-v6/tower/content.ts` 编译技能、状态和敌人；TowerHost 保存 NPC 周期计划并调用公共引擎。战前描述来自同一内容定义，公共战斗组件不变。
- `formations.ts` 定义独行、双卫、主攻＋治疗、主攻＋一名／两名镜侍的整场生命与输出分配。关键层可抽独行／治疗／双镜侍；双镜侍仅用于首领，封印套路只允许独行，铁甲不与镜侍组合。每周至少一个多敌关键层。
- 8/18 层为主攻＋一名镜侍，9/19 层为主攻＋两名镜侍，逐步介绍护主机制。镜侍仅给标记的主敌提供回合内物理／法术减伤，每名 15%，最多 30%，击杀后下一回合降低；固定伤害不受影响。
- 治疗幻侍生命占比 30%，双防较薄，拥有三次治疗法力；每第三回合治疗气血比例最低的友方（含自己），每次为自身生命上限的 20%。耗尽后继续弱攻击。
- 辅助不继承主敌的随机特性或首领低血阶段。治疗阵容生命折价为 0.9；单护卫／双护卫阵容为 0.9／0.8，生命按份额取整且保总量。

## 状态和版本

每场重新装配正常构筑与祝福，人物、合法灵兽满气血／法力迎战。人物通过正常资源服务恢复，终局在已有奖励／归档事务中写回真实消耗。活动挑战不保存整局人物副本或跨层血蓝账本。

单场继续从 Redis 权威快照恢复，不重复恢复资源。已有 v1/v2 战斗从冻结内容继续完成，旧版空闲挑战结束并提示重新进入；不把旧祝福解释成新祝福。配置改变需重启／重新构建，并按内容版本处理兼容，不支持无版本热更。

`shared/rewards/data/tower.json` 继续维护材料和四档奖励，不与敌人预算联动。金丹首轮样本已验证，其他境界目前仅完成配置编译，校准状态见 `docs/tower-scaling-design.md`。
