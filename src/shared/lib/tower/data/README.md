# 幻境内容配置

`blessings.json` 维护十一种现有祝福的名称、效果标签、叠层上限、每层比例和推荐规则。描述与效果预览从参数生成，不另外填写百分比文案。

- attribute／allAttributes 在人物装配前增加六维比例；resourceMax 在装配后增加气血／法力上限；recovery 在下一场战斗入场时回复缺失资源。恢复战斗快照时不重复回复。
- blessings 数组保持当前累加和抽取的有序来源。相同属性贡献逐项相加，不逐项相乘；不要随意重排，浮点运算与相同哈希的顺序可能受影响。
- choices.count 为候选数量；forced 按顺序指定低气血／法力推荐，必须引用对应资源的回复祝福。满层祝福不再进入候选。
- 当前 ID 同时用于 API 与局内状态，身份集合仍是代码契约；新增 ID 或效果机制需要扩展类型与 Schema，已有比例、叠层和推荐参数直接编辑配置。

`encounters.json` 维护准入境界、难度步长、每层类型／境界阶段／里程碑与三类敌人模板。楼层连续排列，最后一层同时是通关层；C／B／A／S 里程碑各出现一次。

- 敌人数值按既有等级公式生成，hpBase／hpPerLevel、attackBase／attackPerLevel、floorGrowth 和模板 hpScale 分别控制成长，最终生命／攻击仍 Math.round。
- baseAttrs 保存完整基础属性。生成器覆盖 hp／maxHp、双攻、双防和速度；其余属性直接采用配置。上述被覆盖字段当前为0占位，用于保持原输出字段顺序，不作为另一份成长参数。
- `combat-v6/tower/content.ts` 生成敌人，Host 负责玩家／灵兽／敌人的战斗编排和已存资源恢复。版本与快照格式不变。
- `shared/rewards/data/tower.json` 单独维护材料有序权重与四档奖励数量／灵石系数／声望；楼层通过 milestone 档位引用奖励，不将奖励混进敌人实例。
- 修改包后重新构建／启动。正在进行的局内状态保留已保存的资源与祝福层数；新装配读取当前配置，旧战斗快照直接恢复。本轮没有实现热更新或存量迁移。
