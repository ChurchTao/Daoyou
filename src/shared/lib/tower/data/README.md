# 幻境内容配置

当前内容为 `combat-v6-tower-v7`，周策略 schema 3。存储与硬切规则见 [逐层策略存储](../../../../../docs/tower-strategy-storage.md)。

## 祝福

`blessings.json` 保存强攻、灵威、坚守、疾行、兽威五项效果，每项最多三次，正常人物／灵兽投影后从原始属性相加并取整，不改变永久六维或资源上限。

入场及通关 2/4/6/8/10/12/14/16 层后选择，共九次；18 层后不再选择。节点来自 `choices.afterFloors`。满层项和无合法灵兽时的兽威不进入候选；候选保存后刷新不重抽。

## 敌人与周编排

`encounters.json` 是当前境界基准、楼层增长、类型系数、准入及里程碑配置。攻击增长作用于超过参照防御的差值，不读取玩家战力追涨。敌人等级通过该层配置的境界阶段计算。

`engine/combat-v6/tower/data/enemies.json` 保存属性修正、词条兼容与行动周期；`mechanics.json`、`skills.ts` 保存既有机制参数和 V6 技能/状态；`generation.json` 保存候选、普通层、铺垫和后段周期引用。阵容份额在 `formations.ts`。

4/9/14/19 层铺垫关联下一关键层；14 层展示 15 层主周期，其他铺垫依配置介绍主敌或单个辅助。15/20 层通过已有技能的周期编排产生差异，无独立调息技能。辅助只携带自身显式词条。

发布器保存完整 20 层策略和明确 `behaviorId`，每周 SQL 一行；开战根据配置编译敌人，不持久化完整 NPC。周抽取保留确定性轮转、合法组合、同周不重复、至少一个多敌关键层和近三周软避重。

## 状态与奖励

每场使用正常构筑加祝福，人物与合法灵兽满气血／法力迎战；单场刷新读取冻结 Redis 快照，保留战中消耗。公共战斗 UI 不增加塔专属操作。预览由同一策略和技能定义生成。

奖励配置仍为 `shared/rewards/data/tower.json`，每角色一个 SQL 本周领奖记录，最多20层 claim。硬切挑战与榜单保留 SQL 领取事实；奖励、claim、正常资源写回及战斗凭据继续共事务。

配置需构建／重启，不支持同版本周中热更。七境界代表构筑校准与剩余体验限制见 [数值设计](../../../../../docs/tower-scaling-design.md)。
