# 道装基础数据包（G1）

策划编辑 `equipment-base.json`。`equipment-base.schema.json` 提供编辑器字段提示，`../pack.ts` 在加载时补充语义校验；任一错误都会停止加载，并报告文件、条目 ID（条目级错误）和字段路径。

## 可编辑内容

| 区块／字段 | 含义与约束 |
| --- | --- |
| `formatVersion` | 数据格式版本，当前固定为 1；不能用来表示数值调整 |
| `contentRevision` | 内容修订号，调整内容时递增；不参与随机种子，也不自动迁移旧装备 |
| `templates` | 六个标准部位各一条，保留现有 ID；图纸及产出入口通过部位构造标准 ID |
| `name` | 标准模板名称；V3 打造名称仍由 `forging/names.ts` 生成 |
| `baseStats` | 器胚属性及系数。上下界为 `floor(器阶 × 系数)`，在两端均包含的整数区间抽取；属性不可重复 |
| `favoredAttributes` | 六维中的偏好属性，可为空，不可重复 |
| `inscriptions` | 阵纹 ID、名称、面板属性、每级固定加成、允许部位；实际贡献为 `valuePerLevel × 阵纹等级` |
| `bonusCountProbabilities` | 按 **0 条、1 条、2 条**顺序填写概率，总和为 1；原值 `[0.5, 0.4, 0.1]` |
| `favoredWeight`／`normalWeight` | 偏好与其他六维的相对抽取权重，均须大于 0；原值 2／1，不是百分比 |
| `bonusValue` | 附灵上下界系数，原值 0.08／0.14；各自 `floor(器阶 × 系数)` 后至少为 1 |

例如，将 `bonusCountProbabilities` 改为 `[0.6, 0.3, 0.1]`，含义是无附灵 60%、一条 30%、两条 10%。此例只说明编辑方法，当前发布数据仍是 50%／40%／10%。

附灵按代码中的六维顺序加权、不放回抽取。器胚数组顺序会改变随机数与属性的对应关系，请勿仅为排版重排。ID、顺序、系数或概率变化均应作为内容变更评审，而非格式整理。

## 代码与发布边界

静态 JSON → `loadEquipmentBasePack` → `content.ts` 的现有定义／查询入口 → 生成器与编译器。生成、打造附灵重抽、实例校验共享 `daoEquipmentAttributeRange`；器胚三条路径共享模板系数。

配置通过重新构建、部署／重启生效；不支持线上热更新。Schema 从 `EquipmentBasePackShape` 生成，调整结构时须同步 Schema；纯测试会检查二者一致。检查命令（仓库根目录）：

```bash
bun run test src/shared/engine/combat-v6/equipment src/shared/forging/forging.test.ts
bun run lint
bun run build
```

新增部位、属性种类或效果机制仍需扩展代码。器蕴／器诀、其生成概率、材料增益、打造成本及命名库留到 G2。本轮没有新增阵纹获取、镶嵌或升级界面；图纸部位标签 `EQUIPMENT_SLOT_NAMES` 是独立的界面分类名称，不是模板属性来源。

## 已生成装备的影响

装备实例保存实际掷骰值，本轮既有参数完全不变，所以保留 V1／V2／V3 生成版本及存储格式。

当前编译器仍按现行模板名称、器胚字段及数值范围、附灵范围、阵纹允许部位校验实例。**缩小范围、删除字段／ID、更改标准名称或阵纹部位可能使旧实例不再通过校验；阵纹每级加成调整会影响已有阵纹的投影收益。** 单独递增 `contentRevision` 不会解决这个问题。概率和偏好权重只影响今后的抽样。上线后如需调整影响旧实例的字段，应先确定版本或实例校验策略，不能直接当作无影响改表发布。

确定性基线 `../generation-baseline.test.ts` 在 G1 搬迁前采集：六部位 × 三个器阶 × 256 种子，每个输入覆盖 V1、V2 和三组 V3 打造。摘要校验完整生成结果，包含下游器蕴、器诀及命名；不能为了让测试通过而随手更新基线。经确认的平衡改动才更新对应预期。
