# 器蕴、器诀与打造配置（38器诀精修版）

策划编辑 `equipment-special.json` 与 `equipment-forging.json`。两份配置均以 `$schema` 关联编辑器提示，运行时还会检查唯一 ID、引用、概率总和、部位池容量和成本表完整性。未知字段、无效值或缺失引用会使加载失败，不会静默回退。

## G2-A：特殊内容

`essences` 定义器蕴身份、修仙名称、`description`、适用部位（省略代表全部）、`stackPolicy`、可选冲突组与一个 `effect`。描述以 `{value}`、`{valueAbs}`、`{valuePercent}`、`{chancePercent}`、`{hpRatioPercent}` 等引用 effect 数字参数；Percent 为原值乘100，避免数值与文案分叉。未知占位符在编译时拒绝。

| effect.type | 参数 | 生效方式 |
| --- | --- | --- |
| `panelAdd` | `attribute`、`value` | 指定面板属性固定加值；暴击类数值为比例，0.01 表示 1 个百分点 |
| `requiredStageOffset` | `value` | 轻灵 -1 个小境界，只作用于自身，最低炼气初期；不改变打造门槛 |
| `rageGain` | `factor` | 战意获得倍率，当前激昂为 1.25；不同来源取最大倍率，不连乘 |
| `rageCost` | `factor` | 战意消耗倍率，当前归元为 0.8；不同来源取最小倍率，最终消耗向下取整 |

| `sealChance` | `side`、`value` | 封禁命中／抵抗概率；按共享封印公式尺度转换为点数后统一执行上下限 |
| `antiCrit` | `kind`、`value` | 降低受到对应类型伤害的暴击概率，固定伤害不受影响 |
| `defenseIgnore` | `kind`、`value` | 对应伤害类型忽视目标防御，与技能忽防加算并钳制到0—100% |
| `mpWaiver` | `chance` | 每次合法施法一次免法力判定；预检仍要求足量法力，不免气血和战意，不作用于捕捉 |
| `regeneration` | `levelRatio` | 回合结束按人物映射等级恢复气血，向下取整；不受治疗强度影响，不治疗伤势，不复活 |
| `revival` | `chance`、`hpRatio` | 死亡时判定复起，受禁复活／禁止回复约束；恢复量受伤势后的可回复上限约束 |

首批14种：藏锋、凝神、破禁、定魂、轻灵、激昂、归元、镇岳、守心、破甲、穿玄、澄念、回春、护命。绝杀、法术连击、神农不定义、不产出。归元／激昂仅腰带，可同件共存；澄念仅项链，护命仅法兵，其余六部位开放是本游戏选定规则。护命每次合法死亡20%触发、回复最大气血30%，不设单场次数限制；已有保命效果先让气血恢复后不重复复起。回春直接读取人物既有境界映射 `Unit.level`，系数0.5。

`stack` 允许同 ID 多件贡献；`unique`、`highest` 都会忽略后续相同 ID。`highest` 不代表所有属性都自动取最大值，战意倍率和等级偏移仍按上表规则聚合。相同 `conflictGroup` 下出现不同器蕴 ID 会拒绝装配。

## 器诀配置

完整清单、修仙名、数值及后续8种的证据缺口与确认适配见 [器诀精修规格](../../../../../../docs/combat-v6-equipment-arts-refinement.md)。现共38种（首批30种＋后续8种），取代9种Demo器诀；没有旧装备，不新增器诀数据迁移。

`arts` 定义稳定ID、修仙名称、参数化 `description`、`skillId`、战意 `rageCost`、目标 `target` 和类型化 `effect`。目标支持自身、友方单体／全体、敌方单体／全体。原版名称与设计解释仅记录在精修规格文档中，不进入运行时配置；玩家界面使用修仙名称。

| effect.type | 参数 | 结算 |
| --- | --- | --- |
| `heal` | `ratio`、可选 `capPerLevel` | 按每个目标最大气血比例治疗，不吃治疗强度／施疗加成，受减疗与伤势上限约束 |
| `revive` | `hpRatio`、可选 `capPerLevel` | 仅选择在场倒地／死亡友方，包含灵兽；受禁复活、减疗、禁止回复与伤势上限约束 |
| `cleanse` | `kinds`、`healRatio` | 解除名单中的全部可驱散控制，再按比例回复；不清禁复活 |
| `rageDamage` | `amount` | 扣目标战意至最低0，不受归元折扣影响 |
| `status` | `statusId`、`group`、`modifier`、`ratio`、`duration` | 同组取绝对比例更强者；等强取剩余持续更长者；不同方向组可并存 |
| `attack` | `kind`、`resultFactors`、可选 `defenseIgnore`／`mpDamageRatio` | 每个系数是一段最终伤害比例，逐段命中／暴击／护命；仍倒地即停止，不转火 |

| `restoreMp` | `ratio`、`casterLevelFactor`、可选 `capPerLevel` | 每目标最大法力比例＋施法者等级加值，按目标等级封顶后取整 |
| `massRevive` | `hpRatio`、`remainingHpRatio`、`remainingMpRatio` | 仅选可复活的在场倒地友方，施法者气血须严格高于剩余比例；全部复活后结算自损 |
| `dispelBuff` | `chance`、`artChance` | 普通／器诀增益逐状态独立概率驱散，不动不可驱散状态 |

`modifier` 支持物理／法术输出结果、物理／法术承伤结果、速度、受疗；`ratio` 为增减比例（-0.5即降低50%）。`duration` 为 `battle` 或1—99回合；有限期限包含施放回合，不吃延长增益，倒地清除。整场状态不使用巨大回合数模拟。速度取施放时有效速度快照，刷新排除同组旧状态，不重复滚高。

解控名单当前包含摄心、镇妖、错乱、百万神兵、泥沼、断脉及训练封法；同kind的进阶版本自动覆盖。休息／反噬、毒、减益和禁复活不在名单内。新增控制种类需由策划决定是否加入。

器诀拥有独立 `art` 身份：普通封法不限制器诀，封物理限制物理攻击器诀，完全禁行动仍生效；混乱和休息沿用V6规则。归元折扣通过人物技能覆盖生成，战斗入口展示权威实际成本。装备详情同时展示原价与归元后成本，避免把单件预览误当已穿戴组合。

文案从数值字段渲染：`{ratioPercent}`、`{hpRatioPercent}`、`{healRatioPercent}`、`{amount}`、`{term}`、`{hits}`、`{segments}`及新机制的数字字段（例如`{capPerLevel}`、`{casterLevelFactor}`、`{artChancePercent}`）。未知占位符拒绝加载。数值及文案变更通过重新构建／发布生效，不提供任意脚本。

`rageResource` 配置名称、初始值和上限（当前 0／150）；`rageGain` 配置伤害百分比尺度（100）。

战意由受击者获取。仅原有 `OnBeHit` 可触发的直接伤害贡献，按实际气血损失占最大气血的百分比取整；纯护盾吸收、持续伤害及钩子衍生伤害不额外贡献。激昂在基础值上乘1.25并向下取整，每次受击所得限制在0—100，不再限制每次行动总所得。战意总上限仍为150，器诀标价不变。

## G2-B：产出与打造

`generation.essenceCountProbabilities` 按 0／1／2 条填写，保持 `[0.82, 0.16, 0.02]`，单件最多两条、不重复；`artChance` 原值为 0.08。每个抽取池是有序 ID 列表：器蕴均匀不放回抽取，器诀均匀抽取一个；不存在隐含稀有度权重。

产出池引用 `equipment-special.json` 中的定义。基础生成与材料重抽都按部位筛选同一池；配置必须保证每个部位都有足够候选内容满足非零数量概率，不会默默降低条数。保留数组顺序才能保留固定种子结果。新增定义不会自动加入产出，需要明确加入池；从池中移除只停止新产出，保留定义仍可支持已有装备。

`forging.boostPerMaterial` 是每份材料的择优重抽概率增量，原值 0.018；范围 0～0.2，最多六位小数。每炉最多五份是现有炉位限制，因而总概率不会超过 1。炼器室 tooltip 与铸器碑读取同一数值。

`forging.costs` 按器阶列出 九个大境界的 9 行（内部器阶 10、30、50、70、90、110、130、150、170），每行填写：

- `spiritStones`：灵石数；`qi`：天地灵气数。
- `quantity`：材料总数，1～5。
- `rank`：最低材料品质，使用游戏现有品质枚举。

材料角色保持原规则：矿石改善器胚、天材地宝改善器蕴数量、辅助与妖兽材料改善已有附灵数值。第二版基础数值中，材料品阶先决定白字抽样区间，平均高出最低门槛两阶时达到强化表范围；参见 [基础数值规则](./README.md)。一次择优只增加一次额外抽样，取两次结果较高者；不保证生成更强装备，也不增加原本没有的附灵。独立随机流、取整、材料归类、图纸消耗一卷、物品命名和事务仍由原代码处理。

## 发布与验收

调整内容递增对应 `contentRevision`，通过重新构建／发布生效；它不是实例版本，也不是自动补偿机制。概率、池和成本变化影响新产出／新打造；器蕴及器诀效果变更会影响引用相同 ID 的已有装备重新装配。删除 ID、缩小适用部位可能使已有实例无法通过校验。生产内容调整必须明确这些影响；器蕴与器诀各自使用已确认产出池。

Demo器诀历史对照夹具已移除，当前38种器诀以精修数值与实战边界测试为准。G1 的 18 组生成摘要继续覆盖基础、特殊产出和打造流。修改数值属于平衡变更，不应只为测试通过而更新基线。

```bash
bun run test src/shared/engine/combat-v6/equipment src/shared/forging/forging.test.ts
bun run lint
bun run test
bun run build
```

文件职责：`special-pack.ts`／`forging-pack.ts` 加载校验；`special-compiler.ts` 将机制参数转换为内核定义；`special-content.ts`／`forging-content.ts` 提供已验证内容；`special-ids.ts` 保留稳定程序标识。Schema 从相应 `*PackShape` 生成，并由测试检查一致性。

## 既有装备迁移

`drizzle/0047_equipment_essence_refinement.sql` 保留装备、白字、绿字、器诀、阵纹与人物资源，只移除非腰带上的归元／激昂；按轻灵新门槛卸下不再满足要求的装备，物品仍留在原库存位置。刷新受影响角色的背包、面板和资源版本。旧战局与历史回放不改写，部署需停止写入并等待活动战局结束。

## 后续8种配置说明

后续8种使用用户确认的本游戏适配值，原版证据缺口保留在精修规格中。新增定义与产出池后总数38，器诀出现率仍为8%。弱点击破只忽视30%物防，不附加重伤；摧灵斩的 `mpDamageRatio` 取实际扣血量倍率，护盾与溢出不计。`capPerLevel` 均取目标映射等级。渡厄归生先完成全部合法复活，再按剩余比例扣自身资源；无合法目标时不扣费、自损或转普攻。荡尘咒以状态数据 `dispelClass` 区分器诀增益，无驱散数量上限。
