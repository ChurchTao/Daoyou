# 宗门内容数据包

当前已迁移 `methods.json`：五宗门各六本心法的 ID、槽位、名称、主心法标记和每级面板收益。编辑器通过同目录 Schema 提供字段提示，代码加载时严格校验。

- 每宗门六个槽位必须唯一，恰有一本主心法。
- ID 使用所属宗门的命名空间。ID 是技能归属和已学等级的引用键，不能当作显示名称随意修改。
- panel 使用现有战斗属性及 add／multiply 语义；具体成长计算沿用宗门编译器。调整系数会影响所有已学习该心法的人物。
- 改名和调已有系数直接编辑 JSON，发布需要重新构建／启动。
- `formatVersion` 表示结构格式，`contentRevision` 表示内容修订；不改写历史战斗快照版本。

`skill-learning.json` 按技能 ID 定义所属心法和解锁等级，包含基础技能、流派授予技能及节点被动。0 级用于现行被动，其他技能按等级解锁；仍同时受流派与经脉节点选择约束。改变所属心法会改变技能等级来源，改变解锁等级会立即影响已有角色可用技能。

所有学习关系必须引用同宗门的已有心法。内容加载时检查缺失关系与孤立配置；新增技能必须同时配置学习关系，不回退到代码默认等级。

`youdu-combat.json` 是技能／状态样板：维护幽都 10 个主动技能、7 个状态及基础技能的有序清单。节点对技能的授予与修改仍由流派定义决定。幽都现有流派没有战斗资源，因此样板没有新增资源字段。

- 技能可编辑名称、标签、目标、消耗、现有伤害／治疗／伤势／附加状态效果。效果数组顺序决定执行次序，不要随意排序。
- 状态可编辑毒伤比例、属性表达式、持续行动／复活限制及存续标记。状态持续回合数在施加技能中配置。
- 表达式沿用战斗内核的有限运算，如 `40 + floor(skillLevel * 1.35)`、`target.maxHp * 0.03`；不是 JavaScript。加载时检查变量名与语法，不允许任意函数。
- 首个样板仅接受当前已用字段和机制。新增原语需要代码扩展；未知字段、无效 ID、缺失学习关系与不存在的状态引用会阻止加载。
- 生效时已有角色使用新参数，历史战斗快照不重新编译；调整强度需另外验证平衡。当前迁移保持原参数。

`youdu-paths.json` 定义两条幽都流派、各七层三选一节点及被动。节点只引用技能／被动 ID，不嵌套复制完整技能；被动集中维护触发条件与现有钩子效果。基础技能仍在战斗包中，所属心法仍在学习包中。

- 节点 panel 为面板贡献，patches 复用现有 SkillPatchV6 操作，grantSkills／passives 为 ID 列表。
- 补丁和被动数组的顺序会影响结算，迁移保持原顺序。多段伤害的 hitIndex 从 0 开始。
- 幽都的 addPhysicalCoefficient 同样允许修改现有段或紧接着追加一段，禁止跳过索引制造空段；索引指向每个 physicalHit 内的伤害段，不是 effects 数组里的条目。
- 加载检查两流派各 21 个唯一层／槽位、唯一内容 ID、技能／状态／被动引用、未使用被动、表达式语法及部分补丁范围。每次变更仍需运行内容测试和战斗验收。
- 例如“济幽”的 4／3 倍增益在 JSON 使用完整小数 1.3333333333333333，不要为了显示好看而截断精度。

五宗门现有构筑内容均已接入配置，具体包见下文。代表性浏览器玩法验收与纯内核覆盖范围见[治理规划第37节](../../../../../../docs/combat-v6-build-content-governance-plan.md#37-当前逐项验收矩阵)。外围宗门组织系统仍保留，不能因为存在本包而删除。

`lingxiao-combat.json` 维护红尘剑宗的 10 个主动技能、10 个状态和剑意资源。基础技能顺序、节点授予技能引用与技能学习关系的规则同上；节点／被动参数由流派包维护。

- 多段物理伤害的 coeff 可以是数组；数组数量必须与 hits 相同。
- 剑意 current 为战斗初始值，max 为上限；技能 resourceRequirements 的门槛不能超过上限。
- modifyResource 的 amount 控制增量，mode 为 set 时直接设置数值；运行内核仍负责上限夹取。
- 伏锋的抢先行动、储存攻击目标和摄心的随机指令仍由既有状态机制执行。只修改配置不会新增原语。
- 表达式校验现由 `authoring-expressions.ts` 共用，幽都与红尘不互相依赖对方数据包。

`lingxiao-paths.json` 补齐红尘两流派、42 节点和全部相关被动。流派引用战斗包资源 ID，节点引用技能和被动 ID，学习关系继续由学习包管理。原宗门文件已收敛为 ID 与目录入口。

红尘的 addPhysicalCoefficient 可修改已有段，也可紧接着追加一段：断尘三叠的 hitIndex=3 表示追加第四段。不得跳过中间索引制造空段。剑意条件须引用已定义资源，其最低门槛不能超过上限；具体积累、扣除与钩子目标仍由原内核执行。

`wuxiang-combat.json` 维护无相禅宗的 10 个主动技能、6 个状态及“念”资源。治疗、护盾、复活、净化、法伤与无相状态沿用原内核原语。

- effects 是施法效果，successEffects 是施法成功后的效果；念增长放在 successEffects，不能移到普通效果列表而改变触发时机。
- requireAbsentStatusIds／requireStatusIds 决定是否处于无相；加载时校验条件中的状态引用。
- resourceCosts 是资源消耗，resourceRequirements 是门槛，两者都必须引用已定义的资源且不超过其上限。
- 护盾携带自身 ID、名称、种类和公式；周期、结算与取整由原内核负责。
- 无相节点／被动及节点的追加念效果由下述流派包维护。

`wuxiang-paths.json` 已补齐无相两流派、42 节点、相关被动和节点追加念效果，原宗门文件收敛为目录。流派 patches 与节点 patches 分别保留：例如慈航流派在无相状态下的复活比例，由流派补丁配置。

- setReviveRatio 的 whenStatusId／statusPresent 指定要修改的复活分支，不能省略后误改全部分支。
- appendSuccessEffect 保留“施法成功后”触发语义，不替换成 appendEffect。
- 吸取气血的 maxGainPerAction 是每行动上限表达式，与 power 分开配置；二者都校验表达式语法。
- 护盾持续时间补丁通过 barrierId 引用技能或节点中定义的护盾，引用不存在会停止加载。
- 此包 Schema 对重复结构使用引用，编辑器仍能补全各字段；节点／被动数组与同节点多项补丁的顺序保持原样。

`tianyan-foundation.json` 是天衍反应基础包：五行到法印／技能的映射、15 个状态、10 种有序反应、状态施加规则、衍数资源与每行动增长限制。

- oldElement → newElement 有方向，五种化生与五种冲克各占五项；同元素不是反应，未配置组合仍按原替换机制执行。
- mainFactor／defenseIgnore 控制反应被动，followPower／healingPower 控制追加效果。状态持续时间和命中方式在 statusApplications 中维护。
- reactionResource.amount 是每次反应增长量，maxGainPerAction 是每行动上限；两者与资源总上限分别配置。
- `tianyan-reactions.ts` 负责按原顺序生成提示、追加伤害／状态／治疗、移除旧印和资源增长，不在 JSON 中复制每个技能的完整反应展开结果。

`tianyan-skills.json` 维护 13 个主动技能：五行技能使用本体参数、附带效果与最终法印持续时间的简洁配方，其余八个技能维护现有目标、消耗与效果。五行反应只引用基础包，不在技能包中重复配置。

- elemental 的五行必须各出现一次；本体伤害 → 附带效果 → 反应 → 最终法印的顺序由编译器保留。
- baseSkillIds 控制基础技能有序清单，流派与节点授予的技能不因此自动成为基础技能。
- 衍数门槛和消耗不能超过已配置资源上限；学习归属继续引用学习包。

`tianyan-paths.json` 补齐两条流派、42 节点和非反应被动。反应增幅被动仍由基础包生成，修改反应倍率不需要同步修改流派包。

- appendReactionEffect 按指定化生／冲克反应生成带旧法印条件的追加效果，每个节点只编辑一份效果。
- multiplyReactionPower 只修改具有 followPower 的即时反应伤害，可限定反应类型；周期状态伤害不受该操作影响。
- setAllBarrierDuration 读取 barrierDurationTargets 的有序技能／护盾清单；单个护盾仍可使用 setBarrierDuration。
- 其余 patches 沿用已有技能补丁原语。引用、层／槽、表达式与未使用被动均在加载时校验，运行机制仍在代码中。
- 天衍内容迁移已覆盖技能、状态、资源、反应与流派节点；各宗门浏览器玩法验收仍待完成。

`jiujie-combat.json` 维护九劫十个主动技能与九个状态，技能中的特殊效果使用两种现有机制配方。

- fiveThunderBranches 读取 judgment 的有序分支和共用成功／失败效果。两个分支条件必须是同一状态类别的有／无，保持单次行动只抽取一个分支；chance 在 0～1 之间。
- detonation 读取引爆名称、电芒状态、最低层数与伤害公式；技能只配置目标数量。编译顺序仍为提示 → 追加伤害 → 消耗电芒。
- 电芒的三层协同规则仍受现有专属内容校验约束；变更该机制需同步调整代码及相关节点，不是单项平衡参数。
- 错乱的随机普攻目标、封法／封物理限制和五雷不可致死沿用原内核，不在配置中新增随机算法。

`jiujie-paths.json` 维护两流派、42 节点和被动。setRandomBranchChance／setRandomBranchFixedPower 必须引用目标技能中存在的 branchId，可单独修改受控目标分支。电芒层数条件不能超过状态上限；按层增伤的 factor 和吸血上限均校验表达式。九劫没有流派资源，resources 保持空数组。
