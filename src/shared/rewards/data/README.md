# 奖励配置

`tower.json` 定义幻境材料池和 C／B／A／S 四档里程碑奖励。具体奖励楼层由幻境 encounters 包引用档位。

- materials 按有序列表维护已注册固定材料 ID 和正整数权重；重复或不存在的引用直接拒绝。
- quantity 为抽中材料数量；spiritStonesPerLevel 乘以挑战大境界初期的战斗等级；reputation 为固定声望。
- 抽取仍调用原 rollDrops 与 SeededRng，保留池／组身份与随机调用顺序。非里程碑返回无奖励。
- 不修改已发放物品、已领里程碑记录或历史战斗数据。新增奖励类型需扩展代码，当前包只维护原有材料与资源奖励。

`wild.json` 定义野外区域对应的掉落池，组和条目的顺序会影响固定种子的结果，编辑时应有意保留。

- 每组 `chance` 为独立掉落概率，`fixed` 条目维护注册物品 ID、权重和数量上下界。
- `equipment`／`blueprints` 按 `equipmentLevels` 和有序 `slots` 生成装备／图纸条目；装备一次只能产出一件，图纸可配置固定条目的数量。
- 功法玉简使用 `fixed` 显式配置：首版 24 本各权重 100、组概率 3%；功法包不存产出权重或稀有度。
- 区域引用、等级／部位／条目／组重复、未知奖励及非法数量在加载时拒绝。奖励组身份保持既有值；调整条目时同步递增池版本；版本不等于数据包的 `contentRevision`。
- 加载和编译不抽随机数，物品生成继续由既有掉落与铸造函数负责。

`dungeon.json` 定义副本探索、战斗、通关三种来源的奖励。

- `materials` 是有序固定材料池，维护注册 ID 和权重。
- `sources` 的 `chance` 决定材料掉落概率，`quantity` 为命中后的固定数量；`experience` 与 `stones` 分别乘以角色战斗等级。
- 来源名称是流程契约；新增来源需要修改流程代码。随机流仍由副本种子与奖励 key 派生，入账去重和已有奖励记录保持原样。

`yield.json` 定义挂机历练的固定名额奖励。

- 名额保持 `floor(min(hoursElapsed, 24) / 3)`，每个名额调用通用掉落底座的一组必中奖励，材料／图纸／灵印互斥，每件数量固定为 1。24 小时合计 8 件，不按领取次数追加抽奖，也不保留不足 3 小时的材料名额。
- 首版品类权重为材料 75、图纸 20、灵印 5。品类内权重归一化，因此增加灵印条目不会增加灵印品类总概率；`books` 显式维护可产出灵印 ID 与权重，新注册灵印不会自动加入。
- 图纸按领取时角色境界，选择已开放且满足炼制门槛的最高道装档位，六部位等权。使用 `equipmentRealm.requiredLevel`，不是简单比较图纸档位数字；高于化神的角色暂时仍产出已开放的化神图纸。
- 材料品质和类型沿用历练规则及材料库匹配，仅对新奖励将材料数量固定为 1。抽取流由领取身份、池版本、名额和组 ID 隔离。
- 领取时生成全部物品事实，在资源、领取时间和 `yield.claimed` 同一事务中保存 `rewardSnapshot`。材料库读取失败时本次领取不入账、不推进领取时间。异步消费者只发送快照，不重抽；邮件仍通过现有消费去重事务创建，领取走统一库存。
- 事件的历史字段 `materialCount` 表示原材料名额总数；新事件要求快照件数与其相同。没有快照的旧队列事件保留原材料生成逻辑和数量，不重写历史邮件。接口返回 `rewardCount` 供领取提示展示总件数。
- 修改权重或条目时递增 `poolVersion`。已冻结的事件不受后续概率调整影响。本次无需数据库迁移。
