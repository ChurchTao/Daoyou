# 奖励配置

`tower.json` 定义蜃楼1–20层奖励（formatVersion 3），预览和结算均读取此配置。

- `floors` 必须恰好覆盖1–20层；`spiritStonesPerLevel` 乘以挑战大境界初期等级。普通层1–4／6–9／11–14／16–19的系数为200／300／400／500；金丹等级45，每周普通层合计252000灵石。关键层不发灵石。
- 5层：30声望、归元灵露×2，15%额外上品归元灵露×1。10层：50声望、随机普通传承灵印×1，8%额外随机上品传承灵印×1。15层：50声望、随机图纸×1。20层：50声望、上品归元灵露×1，50%额外随机图纸×1。
- 每个 `drops` 组独立抽取，`chance` 为0–1，`quantity` 为1–99。`item` 引用固定灵露定义，`pool` 引用本文件的 `pools`。池内物品等权，普通／上品灵印显式列出ID；新增物品不会自动进池。
- 图纸池显式列出境界与部位，运行时过滤未开放或高于挑战大境界的图纸。当前炼气至化神共五档开放，六部位齐全，因此可选境界和部位均等权；高境界角色仍只获得已开放图纸。维护池时保留至少一个金丹及以下可用档位。
- 修改规则递增 `contentRevision`；随机流由挑战种子、楼层、修订号和掉落组ID隔离。具体奖励在Redis终局快照中冻结后再提交SQL，重试不重抽。
- 每角色仍只有一条本周领取记录，`claims` 最多20层；跨境界重开与重复通关不重复发奖。资源、库存、claim与战斗凭据共事务，满袋溢出沿用储藏室。旧已领取事实与资产保留，不补发或改写；无需数据库迁移。

`wild.json` 定义所有野外寻觅节点共用的传承灵印掉落池（formatVersion 2）。

- 只允许一个 `books` 组，`chance` 为 3%；命中后产出 1 枚传承灵印，普通条目权重 24、上品条目权重 4。条目显式列出，新注册灵印不会自动加入。
- 青溪坡及所有新增野外节点均不再掉落材料、装备、图纸或功法玉简；不影响独立的副本、挂机奖励。
- 加载时拒绝非灵印、重复条目、额外奖励组和非 1 数量。修改条目或概率时同步递增 `poolVersion` 与 `contentRevision`；组身份与条目顺序影响固定种子的结果。
- 已冻结旧掉落池但尚未生成奖励的野外战局，抽取前过滤掉非灵印条目。已经记录的具体奖励和历史结算不重抽，不回收既有资产；无需数据库迁移。

`dungeon.json` 定义副本探索、战斗、通关三种来源的奖励（formatVersion 2），`dungeon.schema.json` 提供编辑器提示。

- `sources.*.chance` 是本次物品掉落概率：探索30%、胜利战斗60%、正常通关100%；`quantity` 是命中后的总件数，当前均为1。保持原掉落判定随机流，基础池品类调整不增加基础名额，也不改变同种子下是否掉落；额外养成奖励独立计算。
- `sources.*.weights` 是命中后每一件的品类相对权重，不要求合计100；0表示禁用，至少一类非零。首版材料／图纸／灵印分别为探索85／10／5、战斗70／20／10、通关50／30／20。调整品类分布仅修改这些权重，不改 `chance` 或 `quantity`。
- 每个名额在同一必中奖励组中互斥选择一件物品。例如配置8件，可能产出5材料＋2图纸＋1灵印；相同物品合并数量。配置不再接受固定 `materials` 列表；`books` 维护显式灵印ID和正整数权重，品类内归一化，增删条目不改变灵印总概率。灵印首版沿用普通24、上品4的单条目权重，新注册灵印不会自动加入。
- `sources.*.bonusChances` 是额外奖励的直接概率，四类互斥、合计不得超过1，余量为空；每个奖励节点最多额外1件，不乘基础池 `chance`，也不随基础池 `quantity` 放大。探索／战斗／通关分别为：普通归元灵露2%／10%／20%，上品归元灵露1%／2.5%／10%，上品灵印0.2%／0.5%／2.55%，图纸0.2%／1%／3%。
- 额外上品灵印从 `superiorBooks` 显式列表等权抽取；额外图纸沿用地图档位与六部位等权规则。与基础奖励同物品时合并数量。额外流单独使用 `bonusPoolVersion`，调整额外概率或条目递增此版本及 `contentRevision`，不改变基础池 `poolVersion` 和材料种子。
- 以5轮探索、2场胜利和正常完成为口径，每趟物品总期望：普通归元灵露0.5瓶、上品归元灵露0.2瓶、上品灵印约0.09007枚、图纸0.75张；这不是每趟保底，撤退不获得通关物品。
- 材料按副本地图境界使用与挂机一致的品质分布，从已发布材料库中匹配类型和品质；优先目标品质／类型，库中缺样本时按现有规则回退到邻近品质和其他类型。每个材料名额固定1件，保留名称、品质、类型、元素、描述至 `material.v1.instanceData`。高境界材料分布不受图纸化神开放上限影响。
- 图纸按副本地图对应等级选择已开放的最高可炼制档位，六部位等权；不读取角色等级。未开放的高境界副本暂时使用化神图纸，纯函数接受的1—4级使用最低炼气档位。
- `dailyExpFraction` 乘以玩家境界每日修为预算，沿用旧结算的危险度系数，再乘地图难度奖励系数；`stoneHours` 乘以地图境界每小时灵石基数，沿用旧结算的随机波动、危险度和地图难度系数。探索每轮分别取 0.03 日预算、0.65 小时，胜战每场取 0.075 日预算、1.3 小时；五轮探索与两场胜战合计为 0.3 日预算及 5.85 小时的灵石基数，再分别施加危险度和地图难度系数。所有境界的单次探索及胜战资源收益均高于旧 `等级×系数`。灵石随机流按副本种子与奖励 key 固定，重试不重抽。
- 正常通关另按旧 `RewardFactory.generateBaseRewards` 的评级公式发放灵石、修为及原有的 A/S 级感悟；通关物品节点不再叠加固定修为／灵石。中途退出仅领取已记录的探索与胜战奖励，不领取评级奖励。AI 评级只参与最终资源结算，不参与物品收益。
- 物品随机流包含副本种子、奖励key、来源、`poolVersion`、名额和组ID；与是否掉落的随机流分开。改权重或条目时递增 `poolVersion` 和 `contentRevision`，并同步维护编辑器Schema。
- 奖励先完成材料库解析，再写入已有 `v6Rewards` 保存具体 `ItemGrant[]`，相同key不替换已记录奖励；最终使用现有统一库存结算和事务去重，不发邮件。已记录奖励和历史结算不重抽；更新后尚未生成的奖励使用新配置。无需数据库迁移。

`story.json` 定义剧情幕的开幕物资和完成奖励。章节里只写奖励编号，具体内容在这里配置。

- 每一份 `payouts` 是一个通用掉落池：组之间独立，`chance` 为 0–1，组内按 `weight` 选一条，再在 `quantity` 闭区间取数量。固定奖励用 `chance: 1` 且上下限相同。
- `rewardId` 可以是已注册物品、`materials` 里的材料编号，或 `currency.spirit-stones`。材料发放为 `material.v1`，并带上配置中的名称、类型、品质、元素和描述。
- 抽取种子使用角色、奖励编号、池版本和组编号。同一角色同一份奖励只发一次；事务重试不会改结果。修改条目或概率时递增对应 `poolVersion` 与 `contentRevision`。
- 当前 `first-herbs` 必得翠芽草 3 株。

`yield.json` 定义挂机历练的固定名额奖励。

- 名额保持 `floor(min(hoursElapsed, 24) / 3)`，每个名额调用通用掉落底座的一组必中奖励，材料／图纸／灵印互斥，每件数量固定为 1。24 小时合计 8 件，不按领取次数追加抽奖，也不保留不足 3 小时的材料名额。
- 首版品类权重为材料 75、图纸 20、灵印 5。品类内权重归一化，因此增加灵印条目不会增加灵印品类总概率；`books` 显式维护可产出灵印 ID 与权重，新注册灵印不会自动加入。
- 图纸按领取时角色境界，选择已开放且满足炼制门槛的最高道装档位，六部位等权。使用 `equipmentRealm.requiredLevel`，不是简单比较图纸档位数字；高于化神的角色暂时仍产出已开放的化神图纸。
- 材料品质和类型沿用历练规则及材料库匹配，仅对新奖励将材料数量固定为 1。抽取流由领取身份、池版本、名额和组 ID 隔离。
- 领取时生成全部物品事实，在资源、领取时间和 `yield.claimed` 同一事务中保存 `rewardSnapshot`。材料库读取失败时本次领取不入账、不推进领取时间。异步消费者只发送快照，不重抽；邮件仍通过现有消费去重事务创建，领取走统一库存。
- 事件的历史字段 `materialCount` 表示原材料名额总数；新事件要求快照件数与其相同。没有快照的旧队列事件保留原材料生成逻辑和数量，不重写历史邮件。接口返回 `rewardCount` 供领取提示展示总件数。
- 修改权重或条目时递增 `poolVersion`。已冻结的事件不受后续概率调整影响。本次无需数据库迁移。
