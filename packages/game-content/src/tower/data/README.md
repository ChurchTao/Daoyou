# 幻境内容配置

当前内容为 `combat-v6-tower-v9`，周策略 schema 3。存储与硬切规则见 [逐层策略存储](../../../../../docs/tower-strategy-storage.md)。

## 祝福

`blessings.json` 保存十二项通用战斗加成：人物的物攻、法攻、全伤、暴击、双防、气血、承伤、速度、治疗，以及灵兽的双攻、速度、双防。各项可同时持有，每项最多三层，层数相加。效果不绑定某一种怪物机制。

入场及通关 2/4/6/8/10/12/14/16 层后选择，共九次，每次从尚未满层的祝福中给出四个。18 层后不再选择。节点来自 `choices.afterFloors`。满层项和无合法灵兽时的灵兽祝福不进入候选；候选保存后刷新不重抽。

## 敌人与周编排

生命使用固定 `damagePerRound × 类型 rounds × 楼层增长 × 阵容折价` 的整场预算，再应用成员份额与生命修正，不使用人物生命公式。参考构筑与验证边界见 [v8 血量规则](../../../../../docs/tower-health-v8.md)。

`encounters.json` 是当前境界基准、楼层增长、类型系数、准入及里程碑配置。攻击增长作用于超过参照防御的差值，不读取玩家战力追涨。敌人等级通过该层配置的境界阶段计算。

2026-10-24 配合四修 60→25 等效映射，将金丹／渡劫 `damagePerRound` 血量预算分别校准为 700／2250；攻击、防御、奖励与其他境界预算保持原值。该基准也供预设 PVE 敌人使用。七境界、双输出宗门、三种子及关键层回合窗口继续由 `game-rules/src/tower/health.test.ts` 验证，不放宽原通关与节奏要求。

2026-10-28 同境界圆满、本境道装和法术灵兽可以在机制轮转前清场，封印套路对这类角色命中约三成。蜃楼整场生命再乘 `scaling.survivalScale`（1.8），只作用于幻境编译，不改预设敌人共用的 `damagePerRound`。缚梦幻师使用各境界 `sealHit`，按圆满法术构筑校准到约 65% 命中；其他敌人仍用目录里的默认封印命中。

`enemies.json` 保存属性修正、词条兼容与行动周期；`mechanics.json`、`skills.ts` 保存既有机制参数和 V6 技能/状态；`generation.json` 保存候选、普通层、铺垫和后段周期引用。阵容份额在 `../formations.ts`。

4/9/14/19 层铺垫关联下一关键层；14 层展示 15 层主周期，其他铺垫依配置介绍主敌或单个辅助。15/20 层通过已有技能的周期编排产生差异，无独立调息技能。辅助只携带自身显式词条。

发布器保存完整 20 层策略和明确 `behaviorId`，每周 SQL 一行；开战根据配置编译敌人，不持久化完整 NPC。周抽取保留确定性轮转、合法组合、同周不重复、至少一个多敌关键层和近三周软避重。

## 状态与奖励

每场使用正常构筑加祝福，人物与合法灵兽满气血／法力迎战；单场刷新读取冻结 Redis 快照，保留战中消耗。公共战斗 UI 不增加塔专属操作。预览由同一策略和技能定义生成。

奖励配置仍为 `shared/rewards/data/tower.json`，每角色一个 SQL 本周领奖记录，最多20层 claim。硬切挑战与榜单保留 SQL 领取事实；奖励、claim、正常资源写回及战斗凭据继续共事务。

配置需构建／重启，不支持同版本周中热更。七境界代表构筑校准与剩余体验限制见 [数值设计](../../../../../docs/tower-scaling-design.md)。
