# 宗门组织目录

此模块负责宗门组织、准入、任务、经营与展示主题。宗门战斗内容和养成以 `combat-v6/content`、`combat-v6/sect-progression` 为准，不再提供历史进度水合、V5 编译器或选招策略。

## 目录职责

- `core/domain`：宗门身份与组织状态类型。
- `core/plugin`：`SectModule`、标准组织组合与准入策略；注册宗门不需要战斗实现。
- `core/runtime`：宗门注册表与组织状态校验入口。
- `core/validation`：静态定义及组织状态结构校验。
- `core/organization`：任务目录、组织策略、奖励、晋升和交付物规则。
- `core/presentation`：宗门场景主题与设施对话；没有旧战斗详情生成器或技能槽规范化。
- `content/productionRuntime.ts`：五宗组织模块与展示主题的生产组合根。
- `content/*/definition.ts`：组织身份与静态定义。不能当成 V6 战斗内容生成器。

## 战斗进度边界

六心法、双流派和七层经脉由 V6 定义提供。正式心法／经脉页面走 V6 接口，旧 progression 读取及其水合逻辑已删除。

战斗成长以 membership 为归属，个人功法、装备和灵兽以 cultivator 为归属。转宗由 `CombatV6SectTransfer` 在现有事务内折算宗门进度，不移动个人资产，也不恢复旧宗进度。领域表映射见 `docs/combat-domain-ownership.md`。

旧的 `core/authoring`、`core/compilation`、流派插件和 V5 对手生成器已删除。各宗目录下的旧 `DESIGN.md` 仅是历史设计说明，不能作为当前实现依据。

## 标准宗门任务

手动任务只在领取事务中生成。领取前的任务视图只包含任务类型、名称和通用描述，不生成或返回执行变体、交付要求、难度和奖励；领取时根据当前周期、身份与境界生成完整 offer，并将执行方式、要求、难度和奖励作为 v2 快照原子写入任务记录。领取后不能刷新或更换快照。

手动任务领取满 15 分钟后可以回到发放事务的 NPC 处放弃。放弃只允许作用于尚未完成的 active 任务，会删除当前任务记录、进度、执行会话和目标快照；随后可以在同一周期重新领取，并生成新的任务快照。已完成待领奖或已结清的任务不能放弃。

任务修为继续使用境界每日预算。日常周期倍率为 1，周常周期倍率为 3；easy、normal、hard、elite 分别取得每日预算的 5%、8%、12%、18%。灵石与贡献公式为：

```text
境界灵石保底 = roundTo100(
  (境界序号 + 1) × 1,000 × 周期倍率 × 贡献难度倍率
)
倍率灵石 = ceil((修为 × 5) / 100) × 100
最终灵石 = max(境界灵石保底, 倍率灵石)
贡献 = round(贡献基数 × 贡献难度倍率)
```

贡献难度倍率依次为 1、1.15、1.35、1.6。清扫山门、巡视矿场、宗门小比和悬赏令的最低难度依次为 easy、normal、hard、hard；交付要求生成的难度只能继续提高最低难度。

交付任务每次都生成核心限制：丹药必有最低品质、目标丹类、功效和品相；法宝必有最低品质、部位和未装备要求；材料必有数量、最低品质和类型。复合丹药只要实际 operation 投影出的功效满足目标丹类对应功效，即使持久化的主丹类不同也可提交；不能仅凭主丹类推断功效。完美词条与元素仍是可选的额外条件。丹药品相要求按下品 30%、中品 45%、上品 20%、完美 5% 生成，完美必须精确匹配，其余均表示最低品相。

常规宗门任务不奖励道心感悟，不按交付物市场估值追加补偿；长老试炼只提供晋升资格。

### 战斗任务

生产任务领取时冻结 `schemaVersion: 2` 的原生 V6 对手，每次挑战冻结本人当前构筑。使用公共回合战斗页面与客户端 AUTO；小比采用满资源隔离，其余任务结算现实资源，胜利后仍通过组织领奖流程发奖。

矿兽与长老化身由 V6 Host 生成，同门小比和跨宗悬赏由 V6 原生角色投影生成。旧目标快照仅解析名称、境界、来源等摘要，主动剥离 `combatant`；不能恢复或继续 V5 战斗。维护脚本仍直接检查原始任务 JSON，不依赖退役的生成器。

## 扩展约束

- 普通宗门复用标准组织模块；组织差异通过目录中的主题和现有组织契约表达。
- 战斗技能与节点只在 V6 内容体系扩展，不向本目录恢复效果、编译或选招逻辑。
- 不复制 V6 定义到组织模块，不建立 V5 到 V6 通用效果转换器。
- 未知宗门、未知历史配置版本或非法历史状态仍明确失败。
- `core` 不依赖 `content`，测试夹具不进入生产目录。
- 历史表按发布计划保留，本阶段不生成 DROP 或批量修改已有角色数据。
