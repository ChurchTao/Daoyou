# 解谜场景插画

## 用途与边界

场景插画是云游探秘解谜副本的**底图**：衬在开局题签和案情板“地点”页后面，让玩家一眼认出“这是什么样的地方”。它从属于文字，正文调查区不放底图。一张图对应一类地貌（`DUNGEON_SCENE_KIND_VALUES`：洞府、山门残殿、古墓、古塔碑林、山林药园、水泽海岛、草原祭坛、魔域裂隙、地底秘窟、冰窟），由多个节点共用，因此画的是这类地方的**典型气象**，不画某个节点的具体地标、人物或事件。

- 节点到类别的对应以 `packages/game-content/src/world/data/map.json` 中各节点 `dungeon_config.scenario.scene` 为准；为某类出图前读取属于该类的节点设定（`setting`、`places`、`objects`），提取它们共有的空间与器物，不取某一节点独有的地标。
- 不画人物、妖兽、文字、题签、印章、边框或界面元素；不画能被误读为线索的具体物件（尸骸、钥匙、信件、机关部件）。

## 笔墨语言

继承写意墨像与水墨地图的同一套笔墨：暖灰宽笔墨面、少量浓墨支点、中淡墨、飞白与留白。场景插画比地图更近、比立绘更远，是“一眼的气象”而非细节图。

| 维度 | 原则 |
| --- | --- |
| 构形 | 以几块有方向的墨面建立空间骨架：洞口、殿檐、塔身、林带、岸线、冰壁等主结构用实笔，其余散入留白。不铺满画面，不做远中近三层都精描的风景画。 |
| 浓淡 | 整体偏淡：画面大部分为中淡墨与留白，浓墨只出现在一两处结构支点。因为要叠在文字下面，浓墨面积要小、位置要靠边，不落在画面中央偏上的文字区。 |
| 彩墨 | 可按地貌身份加极少量低饱和彩墨（如冰窟的淡青、魔域的淡赭紫、药园的淡石绿），用于辨识而非渲染；不加光效、发光、雾气特效。 |
| 气氛 | 来自空间开合与虚实（幽深、空旷、压抑、苍茫），不靠题字、飘带、粒子或电影光照。 |
| 纸感 | 由笔墨本身承担，不叠加噪点、裂纹、做旧纸张贴图。 |

## 构图与叠放

- **留出文字区**：画面中央偏上约一半面积保持近乎留白，主体结构放在两侧或下缘，像一幅“边角之景”。界面会在这片留白上叠放标题与正文。
- **宽幅**：横向构图，按宽屏 16:9 与窄屏竖向裁切都成立——主结构不要只放在会被窄屏裁掉的左右边缘外侧；关键结构离边缘留出余量。
- **浓淡上限**：在页面纸色背景上，以 100% 不透明度叠放时，文字区的墨色不深于极淡灰；页面不靠整体降低透明度来“融入”，浓淡由素材本身承担。
- **透明底**：交付的底图是真实透明素材，只有墨迹有颜色，中央留白区与墨迹以外完全透明，叠在任何页面背景上都没有矩形边。生成时可以画在均匀的暖白纸色上，再以画面自身纸色为基准做“去纸色”（color to alpha）：按各通道比纸色暗多少得出不透明度并反推墨色，纸色处透明、淡墨与飞白半透明。不靠 CSS 混合模式或遮罩掩盖底色。

## 设计与制作

1. 明确类别、属于该类的节点及其共有空间；用一句话交代“地貌身份 → 空间骨架与留白 → 笔墨与彩墨”。
2. 使用当前可用的图像生成工具制作栅格美术，需要时遵循 imagegen 的工具流程；不用代码图形冒充水墨。可附写意墨像的冻结基准作笔墨参考，标明只借用笔墨语言，不迁移人物。
3. 查看结果，针对主要偏差修正（多为：中央太满、浓墨太多、写实风景加滤镜、出现人物或文字）；不靠堆叠形容词。

## 交付

- 正式素材：`apps/web/public/assets/mystery/scenes/{scene}.webp`（带透明通道），键名与 `DUNGEON_SCENE_KIND_VALUES` 一致；在 `apps/web/src/routes/game/dungeon/components/mysteryArt.ts` 登记后才会显示，未登记的类别不显示底图。
- 按实际显示宽度与设备倍率选择分辨率与压缩，检查压缩后飞白与淡墨是否糊掉。
- 项目内只保留生产素材；母稿、提示词与中间版本不入库，交付后清理临时文件。

## 验收

同时看独立画面、叠上标题与几行正文后的效果、窄屏裁切后的效果。

1. **辨识**：遮去名称，能否从空间与器物认出是哪一类地方？与其他九类是否区分得开？
2. **从属**：叠上文字后，标题与正文是否清楚可读？浓墨是否没有落在文字区？
3. **笔墨**：是否仍是暖灰宽笔、飞白、留白的同一体系，而不是写实风景或做旧滤镜？
4. **干净**：没有人物、文字、印章、边框、可被当成线索的物件；在深色背景上检查透明通道，没有残留纸色、灰边或矩形边。
5. **裁切**：宽屏与窄屏裁切后主结构都还在，画面不失衡。
