# Daoyou Backend API Security

Follow the affected controller or transport entrypoint through its guard, parser and owning application service. Paths below are relative to `apps/api/src` unless specified. Read the relevant section below and the shared API and verification rules in [AGENTS.md](../../../AGENTS.md).

## HTTP, identity and authorization

- `auth/access.guard.ts` defaults to `user`. Choose `@Access('public' | 'user' | 'active' | 'admin' | 'account-admin')` based on the endpoint. `active` supplies only an `activeCultivatorRef` in addition to the user. Check ownership where a service reads or mutates a resource. `admin` accepts `ADMIN_USER_IDS` or legacy `ADMIN_EMAILS`, while `account-admin` requires `ADMIN_USER_IDS`.
- Keep login, signup, password reset, OTP and ALTCHA flows in `lib/auth/handler.ts`. Run Better Auth's raw Node handler before business body parsing. Preserve individual `Set-Cookie` headers in HTTP guards and both accepted and rejected native WebSocket handshakes. `realtime/realtime.adapter.ts` owns upgrade admission and pending handshakes. Feature services own identity and connection quotas.
- Use `http/json-body.ts` for business JSON. Keep its parameter factory synchronous because Nest passes a factory's return value to the first pipe without awaiting it. Read raw bytes in that pipe after guards. The reader leaves content encoding untouched. Business bodies have a 128 MiB limit and the webhook has a separate 256 KiB limit.
- Use `http/first-query.ts` for business queries. It reads the original URL with Express query parsing disabled, avoiding Express's 1,000-key cap. Query objects keep the first decoded key, named reads prefer a literal key over encoded aliases, and malformed UTF-8 escapes are preserved. Preserve each route's existing parse and validation error contract.
- Keep `NotFoundModule` last in `AppModule.imports` so concrete routes win. Keep authorization fallbacks limited to their existing namespaces.
- Internal HTTP jobs use `@Access('public')` with `InternalCronGuard`, which checks the Bearer secret when configured. Missing `CRON_SECRET` fails production startup validation. Non-production without a configured secret allows the request.

## LLM requests and jobs

- All model calls use server-configured credentials and endpoints owned by `lib/llm/providers.ts`. BYOK is retired: HTTP/WS entrypoints ignore old `x-llm-*` headers, CORS does not allow them, and browser startup deletes the legacy `daoyou_llm_config` storage item. Do not restore shared BYOK schemas, request-context model credentials or client-side model settings. Preserve server provider API keys/base URLs and the separate `VITE_API_BASE_URL` deployment setting; client input cannot choose upstream endpoints or credentials.
- Model calls directly use native `AiService` from `llm/llm.module.ts`; constructor injection uses explicit `@Inject`, and ordinary application functions receive dependencies from their Nest boundary. Do not restore `aiClient`, legacy route/metrics types, old observation routes, global service locators or a generation compatibility facade. `LLM_PROVIDER`, `LLM_ADVANCED_PROVIDER` and `LLM_DEBUG` no longer have runtime readers.
- Every call explicitly selects a named model and a stable `label`. Ordinary scenes use `alibaba.fast`; dungeon outline/text/review require configured `alibaba.advanced`. Aliases read per-provider `*_FAST_MODEL` / `*_ADVANCED_MODEL` variables; defaults live in contracts `llm/config`. No default alias, automatic supplier selection or advanced-to-fast fallback. Keep `LLM_PROVIDER_FACTORIES` and provider adapters for server endpoints and credentials.
- Use native resilience policies: a shared bulkhead of 64 with no queue, retry up to 3 attempts only for retryable provider errors/timeouts, and model attempt deadlines. Composed model resilience replaces call-level retry/timeout settings; shorter business deadlines use abortSignal. Honor provider retry-after up to 30s. The small `llm/call-options.ts` helper only combines AbortSignals for the full operation deadline, including retries and stream consumption. Abort streams in finally. Long non-streaming requests use the provider-owned undici fetch without the default 300s headers deadline.
- Default thinking is disabled through provider options; dungeon outline/review explicitly enable it with Alibaba budget 4096. Structured output uses native schema validation; keep stricter local result validation, existing deterministic fallbacks and business review/retries. The old generic output-correction retry is retired. Array generation uses an object `{ elements: [...] }` schema.
- The native global `onUsage` hook stores completed model steps in `wanjiedaoyou_ai_usage_events` for `/admin/ai-usage`. New scenes need a stable `label`, not a business wrapper; blank labels become `unlabeled`. Failed, cancelled, interrupted or invalid-output calls may consume tokens without a usage event. Do not interpret these steps as business request counts or failure rates. New events and queries are server-only; preserve legacy `credential_source`/`byok` database constraints and rows without editing migration `0074`. Omit prompts, generated text and keys from events.
- Load `app_settings.ai_model_pricing_v1` once at startup through `llm/model-pricing.ts`, match exact native provider/model IDs, and configure native `AiModelDefinition.pricing`. Missing rules use an operational estimate of CNY 1/2 per million input/output tokens; omitted cached-input pricing uses the input rate. Admin edits at `/admin/ai-usage` require restarting all API instances. Store native `cost`, currency and the matching startup snapshot, distinguishing configured/default estimates; do not mutate live pricing or mix a new snapshot with an old cost. Do not duplicate the cost formula, restore retired hardcoded quotes or recalculate historical rows. Preserve historical unpriced costs as `null` and aggregate each currency separately. See the development guide for configuration and collection limits.
- Define prompt templates in `apps/api/src/prompts/*.md`, render through `lib/prompts`, and keep scene orchestration in the owning feature. When adding a prompt scene, check its `id` header, usage `label`, caller and output schema together.
- Treat model output as untrusted. Bound state-changing numbers in the schema and guard them at the service or resource boundary. Route unattended generation through `isBackgroundLlmEnabled()` and follow the explicit-run requirement in [AGENTS.md](../../../AGENTS.md).

## Combat and runtime boundaries

- Build combat units server-side from the authenticated actor through `combat/application/CombatV6BuildService.ts`. Preserve participant checks, visibility rules, legal commands, `expectedRevision` and Redis CAS. Use the owning mutation flow and check mode-specific exceptions such as dungeon recovery before reusing an occupancy lock.
- Keep terminal settlement and replay archival in `runtime/messaging/combatV6Messaging.ts` and the projectors. Preserve retry and idempotency semantics across delivery.
- Use `lib/redis`, `lib/nats` and `lib/admin/smtp.ts` for shared infrastructure. Runtime drains request and messaging work before closing database and Redis connections. Production requires `REDIS_URL`. Readiness requires an active Redis connection, including in non-production.

## Verify the changed boundary

Run lint and build, then follow [the local verification procedure](../../../docs/testing.md) for affected behavior. Check auth cookies or WS admission when changing session handling, server provider selection and ignored retired model headers when changing LLM boundaries, and configured and unconfigured secret behavior when changing cron access. For request adapters and mutations, submit the complete client payload through the local route and check committed values and subsequent resource reads.
