# 水墨技能图腾

## 风格与固定参考

技能图标是一枚有明确主体的水墨纹样：**可辨认的形象或器官作为中心，辅助形与主体咬合成完整印记，以粗厚墨面、重复节奏和大块负形表达技能。** 简洁来自结构概括，不等于几条任意笔划；图腾感来自整体构形，不靠外加边框、细纹或装饰。

以下三枚是用户于 **2026-10-05** 验收通过的固定基准。开始设计、生成或风格评审前，用图片查看工具打开 [组合与小尺寸预览](references/approved-preview.png)，并查看相关独立图；首次使用本 skill 或建立一批新图时同时查看三枚：

- [观照万象：连体神目纹](references/all-seeing-baseline.webp)
- [嗜血追击：接续兽爪纹](references/bloodthirsty-pursuit-baseline.webp)
- [出奇制胜：藏云法芒纹](references/surprise-spell-baseline.webp)

它们固定的是主体层级、墨笔尺度、浓淡和彩墨关系，不要求新技能复制眼、爪、云或相同外轮廓。给生成工具提供参考时明确区分“构形／笔墨参考”和“编辑对象”。不要把最近生成的未验收稿当作唯一风格参考；普通任务不替换这些基准，用户明确接受新基准时才更新。用户当前要求优先于既有基准。

## 全系列保持的关系

| 维度 | 设计要求 |
| --- | --- |
| 主体 | 第一眼能命名为眼、兽爪、盾、焰、咒纹等有语义的形象；不要只有难以解释的斜线、双刀形笔势或括号。主体由当前技能决定。 |
| 整体 | 主体与行为线索形成紧凑完整的纹样。连接、对扣、包裹、接续或重复都可用；附属短勾与角从主结构衍生，避免漂浮装饰。瞳孔等必要独立形不要求与外框连通。 |
| 节奏与负形 | 以少量粗钩、块面和大孔隙建立节奏；留白参与构形，缩小时仍能分开器官或主辅关系。对称由含义决定，动势可以不对称。 |
| 笔墨 | 暖炭墨与暖灰墨为主，粗厚墨面承担结构；局部灰洗和方向明确的飞白表现干湿。避免均匀矢量细描边、满面裂纹噪点、写实材质与浮雕体积光。 |
| 彩墨 | 少量沉稳矿物彩墨落在识别支点，与墨色衔接；缩小后不能只剩灰墨而丢失关键主辅关系。色相由技能决定，不规定固定比例，也不以换色代替形状区别。 |
| 轮廓 | 与相邻技能先有主体、外形或运动关系的区别，再有色彩区别；不能把所有技能装进同一圆环、方框或角冠。主体完整，不以裁断或大面积外圈空白适配格子。 |

不把基准的笔画数、角数、爪趾数、色面比例、对称方式或具体余白推广为全系列参数。武器、兽首、元素、星形是否适用取决于技能语义，不一概禁用。

## 从技能含义到图腾

1. **核对事实**：先读取当前技能定义与实际效果。灵兽以 `packages/game-content/src/beasts/data/skills.json` 为入口，必要时沿 `effect` 核对运行规则；文案或旧图不能覆盖机制。只做美术时不改技能行为。
2. **提取识别主体**：确定最重要的含义，选一个能被直接命名的主体，再选必要的行为线索。区分“击倒后追攻”和“吸血”、“晚入场的首法增强”和“隐身后攻击或雷属性攻击”等容易误读的关系；藏势等美术比喻不能替代触发条件。
3. **组织成纹样**：用连接、包裹、对扣或前后接续表达关系，先让轮廓成立，再转译成宽笔墨面。重复基本形要服务主体或动作，不增加无意义角勾；不要把所有数值、时序条件和目标都塞进图标。
4. **检查同组辨识**：与已有图标并排，避免跨机制只换颜色。基础／高级同家族有意共用主体时，沿用当前分级约定，不把合理复用当作错误重复。

生成前简要说明“机制依据 → 主体 → 构形关系 → 彩墨支点”。使用 [提示词模板](references/prompts.md)；三枚的机制、采用方案与研究依据见 [验收案例](references/approved-designs.md)。回溯本轮精确提示词时再读 [生成记录](references/approved-prompts.json)。

用图像生成工具制作栅格水墨，同时遵循当前 `imagegen` skill 的工具流程；不要用代码绘制的 SVG／Canvas 冒充水墨生成稿。修正时针对一个主要偏差，例如补足爪掌识别、减少云瓣或加强法芒对比；不要靠追加纹理、光效和装饰掩盖构形问题。

## 视觉验收与防漂移

把独立图、固定基准和同批图并排检查，再在游戏纸色 `#f8f3e6` 上按 **24、32、40px 实际尺寸**查看；只放大缩略图不能替代小尺寸验收。

- **主体**：遮住名称后能否说出主要形象？兽爪要能读到掌与爪尖，不能退化成双刀；法芒不能被云纹压成装饰点。
- **整体与区别**：是否读成一枚完整纹样？相邻图的轮廓与主辅关系是否容易区分，而非靠颜色猜技能？
- **负形与墨彩**：关键孔隙是否仍分得开，浓墨是否堵住结构？飞白有行笔方向，彩墨保持层级，不能变成浅色发光芯或写实高光。
- **语义**：主体和动作是否支持实际机制，是否误导为回血、特定元素或实体武器？无法清楚绘出的时序／数值由说明文字承担。
- **技术**：外底及设计为留白的孔隙真实透明，边缘完整无脏底；没有烘焙纸纹、棋盘纹、文字、印章或徽章底盘。检查 alpha 和纸色实图，不能只凭存在 alpha 通道判断合格。

典型偏离：任意笔刷符号、只改颜色的同形图、全套同一外框、器官被纹样淹没、碎卷太多、长尖拖尾、满面噪点、装饰性发光。未满足时指出具体差距并定向修正；不要把提示词声明当作验收结果。

## 交付与接入

- 候选与提示词记录保存在项目输出目录，不依赖工具默认目录；保留真实透明度，可以做等比缩放与压缩。生产图标沿用项目常用的 256×256 透明 WebP，具体按实际显示和包体取舍，工具母版尺寸不是规范。
- 图标保留完整轮廓和适当安全空间，按同组视觉尺度检查；不要套用灵兽头像必须裁满画布的规则，也不硬性规定统一余白百分比。
- 用户已授权接入或替换时，遵循 [统一图标约定](../../../docs/game-icons.md)：资源进入 `apps/web/public/assets/icons/`，名称与路径在 `registry.ts` 注册，配置使用 `icon:名称`，业务渲染交给 `GameIcon`。设计候选任务不自行替换生产素材或玩法字段。
- 默认正常强度显示，由素材承担浓淡，不能统一降透明度或加混合模式来掩盖问题。交付说明采用的主体、提示词记录和小尺寸验收结果；接入后再检查实际页面。
