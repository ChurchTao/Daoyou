# 灵兽物种设计

仅制作或评审头像时使用 [写意墨像](../daoyou-ink-portraits/SKILL.md)；本技能规范物种形态与天赋设计，不替代头像的固定画风参考。

物种由外形、习性、天赋和资质成长分布定义。个体的战斗用途由实际资质、技能、玩家加点和传承灵印培养共同决定。

## 使用入口与事实边界

- 对照 `packages/game-content/src/beasts/data/species.json` 核对现行名单、资质、成长、出生池和 ID。查阅相关境界的 [首批设计基准](references/first-release.md) 或 [炼虚至渡劫扩展基准](references/later-realms.md)，了解形态、平衡取舍与历次确认。跨境界比较时结合两份基准。区分设计已确认、代码已实施和平衡已验证。
- 实施配置时使用 [daoyou-game-core-domain](../daoyou-game-core-domain/SKILL.md)，按改动范围核对 `packages/game-rules/src/beasts/` 的生成、投影和培养，以及 `combat/wild/` 的野外入口。改动持久化时使用项目数据层技能。基准与配置有差异时，先区分待实施的设计与已失同步的表格。
- 从 `packages/game-content/src/beasts/data/skills.json`、同包的 `beasts/skill-compiler.ts` 和运行时确认技能效果。原作技能的适配差异见 `docs/combat-v6-beast-classic-skills.md`。

## 妖灵传承与技能文案

- 培养概念为妖灵传承，入口为「领悟传承」。传承灵印以所载技能为单件名称，以「普通／上品 · 传承灵印」展示类型，见 [物品预览分类基准](../daoyou-item-preview/references/type-baselines.md)。所载技能获取时已确定，同传承同品级才可堆叠。

- 技能名与天赋文案使用 `beasts/data/skills.json` 的 `name`、`flavorText`。旧称对照见 `docs/combat-v6-beast-skill-copy.md`。
- 从灵兽的血肉、灵息、感官与魂魄本领出发，不套用修士功法命名；不要仅凭技能名称附加元素或血脉条件，技能不绑定物种：物种仅决定出生候选，获得后不设置物种生效门槛；文案不承诺未实现效果。

## 生灵层次与辨识度

- 境界表示玩家首次开放、适宜驾驭的阶段，不是物种的永久培养上限；不要将其直接当成灵兽自身境界名称或猜测等级映射。使用当前配置的境界称呼，具体开放分布见设计基准。
- 从山野开灵逐步发展为天赋稳定、身体结构或生态特殊、血脉深厚的生灵。以形态、习性和天赋来源说明该生灵为何适合该境界，不只提高体型与数值。
- 梦幻西游端游用于玩法与生态设计灵感，《凡人修仙传》用于修仙生灵层次参考。原创内容不要标为小说原设；不照搬梦幻名称后加“灵”“玄”“仙”等前缀。
- 命名直观、顺口，外形和习性有具体依据；避免堆叠玄奥词汇。高阶物种也不必全是巨兽，不提前将普通可捕捉物种设成世界观中的顶级存在。
- 辨识度和记忆点是命名的核心标准：先确定生灵最值得记住的形态、习性或类别意象，再提炼名称；仅有命名依据不等于抓住了主要特征。不要求固定字数，也不为改变字数堆词。
- 将完整名单并排审查：只看名字能形成什么画面、读后能复述哪个特征、与其他物种是否重复同一记忆点。避免批量套用颜色／元素加普通动物的构思；不要把多目、多尾等结构变化变成新模板。已有设定有特点时提炼名称，设定本身重复时再重做形态或生态，低阶物种也可朴素而鲜明。
- 对比已有物种的整体轮廓、身体结构、栖息地、习性和天赋来源。不能仅换颜色、放大体型、升级名称就视为新物种。已淘汰方案及原因见设计基准，不因换名重新引入同样的问题。
- 描述只承诺已有能力。火、水、雷的外观不自动附赠灼烧、麻痹或元素克制；异虫、灵目、灵魂体来历不自动产生吞噬法宝、复制技能、吸魂等新机制。

## 物种与培养路线

- 用资质、天赋和习性描述培养可能。各物种共享可选加点方案，避免固定攻宠、法宠、耐宠、辅助宠标签及按这些角色配齐境界名额。

## 资质与成长

- 每种明确攻击、防御、体力、法力、速度五项资质，即 `attack / defense / health / mana / speed`，再独立列出成长范围。不要引入第六资质，也不要与角色永久属性混用。
- 用不同优势、短板、区间宽度区分物种；不要全物种套统一比例，也不要让高境界物种所有资质全面超过低境界。
- 相邻境界允许重叠，低境界优秀个体可以在某项资质超过高境界普通个体。成长不保证随境界严格递增，也不消除资质短板。
- 比较平衡时使用当前共用面板投影，在相同等级、可比加点与技能条件下检查。成长影响属性贡献，最终伤害还受战斗公式和技能影响。
- 如需调数，标明相对基准的差异和依据，不为适配旧配置或追求整齐而悄悄改值。

## 天赋、出生技能与传承灵印空间

- 每种天生技能全集为3至6项，其中必带技能为0至2项，按物种特点决定，不机械填满上限。必带在生成与洗炼时保底获得，之后可被传承灵印覆盖，不是受保护的独立天赋格。
- 必带之外提供有习性依据的候选池，默认使用非高级技能；用户明确确认的高级候选按设计基准保留，仍采用相同候选概率，不自动改为必带，也不据此普遍升级其他物种的候选。天生全集是必带与候选的并集，二者不重复；多数物种收敛为3至4项，少数可达5至6项。
- 满天生技能不等于最优成品，允许全部天生技能同时出现。不默认赠送连击、必杀、噬血、偷袭全套，或群法、灵法连击、灵法会心、灵法精通全套。多技能个体仍应有传承灵印调整价值。
- 不故意用被核心压制、无效恢复或同族低级版本占格。混合天赋可以保留培养分歧，逐项核对触发条件，不将效果自动延伸到不适用的攻击或法术，也不为消除培养取舍而补成完整组合。
- 必带全部获得。每个候选独立以 1/2 判定是否出生，互不影响，并按候选表顺序收录；不按物种配置数量或权重。全部候选同时出现、以及一个候选都没有，概率都是 (1/2) 的候选数次方。无隐藏保底、组合权重或附加抽签。
- 出生实际技能数就是个体格数，范围从必带数量到天生全集数量。无必带物种允许0技能、0格，仍可普攻。捕捉、初领与洗炼采用同一规则；捕捉保留遭遇时的技能，洗炼重抽技能和格数。传承灵印对0技能个体允许学习一个技能并开启第一格；已有技能时仅随机替换、不再扩格，不改变资质。融合另按[宝宝体系与融合设计](../../../docs/combat-v6-beast-fusion.md)，不把出生上限当作融合个体的总格数上限；普通物种设计任务不顺带实施融合。
- 技能数量与资质、成长独立抽取：高成长不保底多技能，多技能也不扣资质。不得新增“综合品质”关联这些结果。
- 新生成规则取代旧捕捉附加技能抽签，不能叠加旧概率；免费初始伙伴同样按所属物种表生成，不另限一技能。

## 开放与存量

- 物种携带境界对应主人境界，成年遭遇等级由栖息地配置。稀有身份使用物种的 `rare` 字段。每个位置按区域概率选择稀有或普通种群，与变异独立。现有区域与例外见对应设计基准。
- 物种 ID 与展示名称分离。更名保留稳定 ID，新增物种分配独立 ID；整体替换物种时按已确认的存量方案处理，具体映射写入设计基准，不因英文 ID 语义过时重写存量数据。
- 区分新生成个体与已保存个体。改动资质、成长或技能池时保留既有个体的实际抽取结果，存量调整按本次设计决定处理。
- 涉及宝宝身份、点数、归元或融合时查阅 [宝宝体系与融合设计](../../../docs/combat-v6-beast-fusion.md)。`pseudo_baby` 和 `wild` 对玩家都显示「野生」，内部点数规则仍有区别。变异仅出现在宝宝上，界面单独显示「变异」标签。等级与修为展示、丹药和灵果见 [修为养成规则](../../../docs/combat-v6-beast-cultivation.md)。

## 交付与审查

按任务范围输出需要的部分；完整新物种设计应能回答：

1. 开放境界、名称、形态、栖息地和习性；为何适配生灵层次，与已有物种何处不同。
2. 五项资质上下界、成长上下界；优势、短板、个体跨度及相邻物种重叠。
3. 必带与候选技能如何体现物种特点，哪些搭配有实际效果，玩家还能如何通过传承灵印培养。
4. 是否涉及新增机制、存量影响或基准变更；区分设计已确认、代码已实现、平衡已验证。

人工核对技能触发条件和互斥组合。技能池大小、重复与同族高低级组合由 `packages/game-domain/src/beasts/pack.ts` 校验。更新参考表时逐项对照配置。
