# 灵兽物种设计

仅制作或评审头像时使用 [写意墨像](../daoyou-ink-portraits/SKILL.md)；本技能规范物种形态与天赋设计，不替代头像的固定画风参考。

物种由外形、习性、天赋、资质与成长分布定义；具体个体的战斗用途由资质、技能、玩家加点和传承灵印培养共同决定。本技能规定通用设计方法与约束；具体物种名单、数值、定稿名称和 ID 映射保存在设计基准中，不写入规范正文。设计已确认不代表代码已实现或平衡已验证。

## 使用入口与事实边界

- 设计、扩充或审查物种时，读取 [设计确认基准](references/first-release.md)，对照完整名单检查形态重复、数值跨度和天赋组合；具体名单、境界分布、区间、出生概率及 ID 以基准为准。
- 后续用户明确修改设计时，以新要求为准，同步更新相应基准并说明改动；不要把本技能变成额外审批流程。未被要求改变的已确认规则继续沿用。
- 仅要求设计或整理规范时，交付设计或文档，不顺带修改游戏逻辑。配置实施同时使用 [daoyou-game-core-domain](../daoyou-game-core-domain/SKILL.md)，持久化改动使用项目数据层技能。
- 实施前核对 `src/shared/engine/combat-v6/beasts/` 的内容、生成、投影与培养调用，以及 `wild/` 的野外身份和捕捉入口。旧代码中的定位、四技能模板或捕捉加技能规则不能反过来覆盖已确认设计；列明差异后在任务范围内实现。
- 可用技能与真实效果以 `beasts/data/skills.json`、`beasts/skill-compiler.ts` 和运行时为准，适配差异参照 `docs/combat-v6-beast-classic-skills.md`。不要仅凭梦幻西游原技能名称推断本游戏机制。

## 妖灵传承与技能文案

- 培养概念为妖灵传承，道具统一名为“传承灵印／上品传承灵印”，入口为“领悟传承”。具体技能只在预览与确认中展示，不拼入道具名称。所载技能获取时已确定，同传承同品级才可堆叠，不增加鉴定或随机开印机制。

- 技能名与天赋文案以 `beasts/data/skills.json` 的 `name`、`flavorText` 为准；完整新旧对照见 `docs/combat-v6-beast-skill-copy.md`。历史迁移记录中的原作名或旧称不能用于新设计。
- 从灵兽的血肉、灵息、感官与魂魄本领出发，不套用修士功法命名；不要仅凭技能名称附加元素或血脉条件，技能文案不引入物种限制或未实现效果。

## 生灵层次与辨识度

- 境界表示玩家首次开放、适宜驾驭的阶段，不是物种的永久培养上限；不要将其直接当成灵兽自身境界名称或猜测等级映射。使用当前配置的境界称呼，具体开放分布见设计基准。
- 从山野开灵逐步发展为天赋稳定、身体结构或生态特殊、血脉深厚的生灵。以形态、习性和天赋来源说明该生灵为何适合该境界，不只提高体型与数值。
- 梦幻西游端游用于玩法与生态设计灵感，《凡人修仙传》用于修仙生灵层次参考。原创内容不要标为小说原设；不照搬梦幻名称后加“灵”“玄”“仙”等前缀。
- 命名直观、顺口，外形和习性有具体依据；避免堆叠玄奥词汇。高阶物种也不必全是巨兽，不提前将普通可捕捉物种设成世界观中的顶级存在。
- 辨识度和记忆点是命名的核心标准：先确定生灵最值得记住的形态、习性或类别意象，再提炼名称；仅有命名依据不等于抓住了主要特征。不要求固定字数，也不为改变字数堆词。
- 将完整名单并排审查：只看名字能形成什么画面、读后能复述哪个特征、与其他物种是否重复同一记忆点。避免批量套用颜色／元素加普通动物的构思；不要把多目、多尾等结构变化变成新模板。已有设定有特点时提炼名称，设定本身重复时再重做形态或生态，低阶物种也可朴素而鲜明。
- 对比已有物种的整体轮廓、身体结构、栖息地、习性和天赋来源。不能仅换颜色、放大体型、升级名称就视为新物种。已淘汰方案及原因见设计基准，不因换名重新引入同样的问题。
- 描述只承诺已有能力。火、水、雷的外观不自动附赠灼烧、麻痹或元素克制；异虫、灵目、魂生来历不自动产生吞噬法宝、复制技能、吸魂等新机制。

## 取消物种固定定位

- 不给物种贴固定攻宠、法宠、耐宠、辅助宠标签，不按这些角色每境界各配一只，也不以隐藏评分恢复同样的分类。
- 可以说明各项资质的高低、天赋习性及多种培养可能，不规定唯一最优路线。
- 不按物种强制指定加点方向。实施时检查 `role`、`allocation` 及其调用，按已确认方案取消定位标签和物种绑定的培养方向，各物种可选择相同加点方案。

## 资质与成长

- 每种明确攻击、防御、体力、法力、速度五项资质，即 `attack / defense / health / mana / speed`，再独立列出成长范围。不要引入第六资质，也不要与角色永久属性混用。
- 用不同优势、短板、区间宽度区分物种；不要全物种套统一比例，也不要让高境界物种所有资质全面超过低境界。
- 相邻境界允许重叠，低境界优秀个体可以在某项资质超过高境界普通个体。成长不保证随境界严格递增，也不消除资质短板。
- 基准数值已获用户确认，但不等于通过平衡验证。比较时使用当前共用面板投影，在相同等级、可比加点与技能条件下检查；当前成长影响属性贡献，不能简单当作最终伤害倍率。
- 如需调数，标明相对基准的差异和依据，不为适配旧配置或追求整齐而悄悄改值。

## 天赋、出生技能与传承灵印空间

- 每种天生技能全集为3至6项，其中必带技能为0至2项，按物种特点决定，不机械填满上限。必带在生成与洗炼时保底获得，之后可被传承灵印覆盖，不是受保护的独立天赋格。
- 必带之外提供有习性依据的普通候选池；候选均为非高级技能。天生全集是必带与候选的并集，二者不重复；多数物种收敛为3至4项，少数可达5至6项。
- 满天生技能不等于最优成品，允许全部天生技能同时出现。不默认赠送连击、凶猛、噬血、偷袭全套，或群法、灵力相续、灵涌、增伤全套。多技能个体仍应有传承灵印调整价值。
- 不故意用被核心压制、无效恢复或同族低级版本占格。混合天赋可以保留培养分歧，逐项核对触发条件，不将效果自动延伸到不适用的攻击或法术，也不为消除培养取舍而补成完整组合。
- 先按物种概率抽额外技能数量，再从候选池等概率、不重复抽取；每种概率见基准。必须给全部候选同时出现保留非零概率。少技能个体为常态，不随境界机械提高常见格数，无隐藏保底、组合权重或附加抽签。
- 实际技能数就是个体格数，范围从必带数量到天生全集数量。无必带物种允许0技能、0格，仍可普攻。捕捉、初领与洗炼采用同一规则；捕捉保留遭遇时的技能，洗炼重抽技能和格数。传承灵印对0技能个体允许学习一个技能并开启第一格；已有技能时仅随机替换、不再扩格，不改变资质。为后期合宠留空间，但不提前实现合宠或额外扩格，不把出生上限当作存量或未来培养的总格数上限。
- 技能数量与资质、成长独立抽取：高成长不保底多技能，多技能也不扣资质。不得新增“综合品质”关联这些结果。
- 新生成规则取代旧捕捉附加技能抽签，不能叠加旧概率；免费初始伙伴同样按所属物种表生成，不另限一技能。

## 等级与修为

- 灵兽自身仅显示数字等级，取消独立境界别名；物种携带要求继续表示主人境界。归元为0级、0修为、五项基础属性均为10，初始领取等级不受此规则改变。
- 升级曲线及丹药／灵果喂养按 [修为养成规则](../../../docs/combat-v6-beast-cultivation.md)。丹药遵循统一品相、契合与槽位增幅公式，不另设品相插值；野外暂不奖励修为。

## 开放与存量

- 每个大境界初期开放基准表对应物种，进入对应境界野外捕捉池，不另设物种稀有概率层级。不据此虚构玩家境界与数值等级的映射。
- 物种 ID 与展示名称分离。更名保留稳定 ID，新增物种分配独立 ID；整体替换物种时按已确认的存量方案处理，具体映射写入设计基准，不因英文 ID 语义过时重写存量数据。
- 新方案只影响之后生成的个体。已有资质、成长、技能、技能格与已分配属性保留，不重抽或以移除定位为由重置。

## 交付与审查

按任务范围输出需要的部分；完整新物种设计应能回答：

1. 开放境界、名称、形态、栖息地和习性；为何适配生灵层次，与已有物种何处不同。
2. 五项资质上下界、成长上下界；优势、短板、个体跨度及相邻物种重叠。
3. 零至两个必带、天生全集、普通候选池、额外数量概率、常见及满技能数；玩家还能如何通过传承灵印培养。
4. 是否涉及新增机制、存量影响或基准变更；区分设计已确认、代码已实现、平衡已验证。

审查概率和为100%、不放回抽取数量不超过候选数、必带与候选不重复、无同族高低级冗余和互斥无效组合、必带0—2项、天生全集3—6项、满天生技能概率非零、无必带时可生成零格。对所有技能检查本游戏真实作用，不将“名字合理”视为机制可用的证明。

只改本技能及参考文档时做技能校验、表格一致性和差异检查；不为文档变更运行全量游戏测试。涉及配置或逻辑时再按领域技能执行相应验证。
