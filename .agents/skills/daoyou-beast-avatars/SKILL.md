# 灵兽头像

## 固定参考与适用边界

生成或评审前，用图片查看工具打开 [雷鹏 A 版基准](references/thunder-peng-a-baseline.webp)。这是用户于 2026-09-15 从三张候选中选定、随后要求接入游戏的头像冻结副本。保持它独立于生产素材；普通头像生成和文件替换不更新基准。用户明确调整系列美术方向时再同步基准与规范。

参考图用于约束体积、细节密度、边缘、光照和完成度，不要求复制鹰首、侧脸方向或蓝白配色。生成工具支持参考图片时，将它明确标为**风格参考**，不是要保留身份的编辑对象。未验收的新图不接续成为唯一参考。

- 物种身份来自当前 `src/shared/engine/combat-v6/beasts/data/species.json`，必要时对照 [灵兽设计基准](../daoyou-beast-design/references/first-release.md)。只改头像时不改变物种、数值、技能或玩法能力。
- 本技能负责彩色灵兽头像；玩家、NPC、BOSS 墨像遵循 `daoyou-ink-portraits`，不将其灰墨、飞白、减笔要求套到灵兽头像。
- 已有动物 emoji 和早期 SVG 可以继续存在，但不作为新生成头像的风格基准，也不因使用本技能而自动启动全物种重绘。

## 美术定义

**以可信动物结构为基础的半立体彩色国风游戏头像：有自然的体积、毛羽层次与神态，细节为小尺寸识别服务。** 以固定参考的实际效果为准；允许清晰的羽毛、眼睛与喙部刻画，避免仅凭“简洁图标”四字压成几何标志。

| 维度 | 系列保持一致的要求 |
| --- | --- |
| 造型 | 解剖可信，适度强化耳、角、喙、眼等辨识特征；主体首先是有生命感的动物，不是徽章、纹样或机械装饰。 |
| 体积 | 柔和明暗塑造额头、面颊、颈部和肩部；哑光有机材质，避免塑料高光、金属全身或照片级微观纹理。 |
| 毛羽鳞甲 | 用有走向的层叠块面组织细节，再点缀少量细毛；缩小后仍能读出主要结构，不把全图铺成均匀细线。 |
| 轮廓 | 清楚、自然，关键部位完整；保留少量毛羽边缘，避免粗黑描边、硬直几何切面和过多细碎尖刺。 |
| 光照 | 默认柔和左上主光，温和的中性偏暖高光与冷部阴影；亮部有细节，暗部不糊成一团。 |
| 色彩 | 由物种设定决定两三种主色，适度降低饱和度，在米白纸底上清楚可见；统一色彩关系，不统一物种颜色。 |
| 神态 | 眼睛与头部姿态传达机敏、沉稳、凶悍等物种气质；不全员凶猛，也不默认巨大萌眼。 |
| 异兽特征 | 将特殊颜色、角、灵目或微光融入身体；特效只作少量辅助，不堆光环、粒子、悬浮元素符号。 |

国风来自修仙生灵设定、节制的色彩与插画气质，不额外添加人类冠饰、铠甲、书法、印章或水墨滤镜。借鉴 emoji 的紧凑构图和生命感，不复制其鲜艳塑料质感。

## 构图与物种差异

- 默认正方形、透明底，主体约占画面 80%–90%；按实际轮廓留出呼吸空间，不把尖耳、喙或角裁掉来凑占比。
- 禽兽优先紧凑头部或头肩像，脸部是第一识别中心；允许侧脸、三分之二侧面或近正面，避免为了对称而退回徽章式展翅全身。
- 蛇蛟可用盘曲躯体；螳螂、蝎和蝶保留镰足、尾刺、翼等关键结构。构图服从物种辨识，不强迫所有物种套大头模板。
- 原生画面不带圆框、底座、纸张背景或光晕；界面现有底纹与容器由 UI 承担。

### 雷鹏的已选方向

A 版为朝右的锐利侧面头肩像：苍青后掠头羽、银白颈羽、深紫肩羽，琥珀眼、短而有力的钩喙。眼部或羽缘少量冷色亮光提示雷息。头像不必画出完整巨翼，也不升级为凤凰、鲲鹏或真龙。以上配色与形态仅属于雷鹏，不推广为其他灵兽的固定元素。

## 生成与接入

1. 看固定参考和物种事实，确定本次需要保留的两三个辨识点。需要生成时遵循 imagegen 技能，使用 [提示词骨架](references/prompts.md)，将风格段保持稳定，仅调整物种与构图。
2. 候选数量按用户要求；未指定时先完成单个样本。用户仅要求预览时交付候选；已要求替换时沿用该授权完成接入，不额外制造审批环节。
3. 默认交付 **256×256、真实透明的 WebP**。生成原图可更大，导出时高质量等比缩小，保留 alpha；原稿和未选候选不进入生产目录。质量 90 是当前雷鹏的导出起点，可按边缘与体积检查调整，不是固定质量分数或文件大小门槛。
4. 这类带毛羽和柔和明暗的头像使用栅格素材，不为统一管理而转成 SVG。自动描摹会形成色块并增加路径；不要将位图嵌入 SVG 冒充矢量。用户明确要求矢量试验时可提供独立对照，不自动替换正式素材。
5. 接入遵循 [统一图标规范](../../../docs/game-icons.md)：素材集中放在 `public/assets/icons/`，由 `src/react-app/components/ui/icons/registry.ts` 注册稳定的 `icon:名称`，`BeastIcon` 取值后交给 `GameIcon` 渲染。格式变更不新增协议、页面分支或第二份注册表。
6. 记录采用的提示词、风格参考与最终文件。新稿未达标时说明主要差距并针对性修正，不通过连续改变画风词汇来掩盖偏差。

## 验收与防漂移

把候选与固定参考并排查看，同时检查独立 256px 图和页面中的约 30px 列表、48px 移动详情、72px 桌面详情；尺寸以当前组件实际值为准。

- **先认物种，再看细节**：缩小后还能认出主体与关键特征，眼神、口鼻或虫体结构不被装饰淹没。
- **同系列质感**：体积光、明暗跨度、材质概括和细节密度接近基准；不得一只几何扁平、一只塑料卡通、一只写实海报。
- **设定一致**：颜色、身体结构、角／眼／翼数量与物种事实一致；高境界不自动意味着更花、更亮、更多装饰。
- **真实透明**：核对 alpha，并在米白纸底和深底检查边缘；无烘焙棋盘纹、白边、脏色与方形背景。不能靠 CSS 降透明度或混合模式补救。
- **页面与交付**：正常 opacity 下与 emoji 混排时大小协调、不裁切或挤压。检查注册路径、图片加载、WebP 尺寸与体积；涉及接入代码时运行 lint/build 和针对性浏览器检查，纯美术或文档改动不机械运行全量游戏测试。

不合格信号：对称几何徽章、强描边剪纸感、全身过小而面部难辨、密集微纹理、羽毛被描摹成破碎色块、悬浮闪电抢主体、不断用未验收图替代原始参考。
